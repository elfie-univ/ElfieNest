# ElfieNest Developer Tools

> 中文版：本文件 · [English](README.md)

`devtools/` 是与普通用户产品隔离的模块实验台。它们不会作为用户导航或生产
服务入口，也不应依赖普通用户页面才能工作。

## 统一入口

先准备仓库锁定的 Python 环境，再查看可用工具：

```bash
./elfienest.sh version
./developer.sh --help
```

三个实验入口启动统一 Developer Tools HTTP 服务：

| 命令 | 首次打开 | 本地默认 | 用途 |
| --- | --- | --- | --- |
| `./developer.sh elfie-lab` | `/elfie/experiment` | HTTP `127.0.0.1:9001` | 单精灵实验 |
| `./developer.sh brain-eval` | `/elfie/evaluations` | 同上 | 批量评测与报告 |
| `./developer.sh nest-lab` | `/nest/experiment` | 同上（Godot WS 为内部 `9002`） | 精灵巢与 Godot Runtime 实验 |

资产预览使用 Nest Lab（`./developer.sh nest-lab`，`/nest/experiment`）。
独立的 `/assets/design` 页面、设计工作区和离线资产 CLI 已移除。后续资产创作使用
`godot_project/` 中现有的正式 GLB 资源、sidecar 元数据、场景和脚本；
通过 Nest Lab 预览这些正式资源的变化。

`./developer.sh brain-trace` 是不启动网页的后端采集工具。`list` 列出隔离 Lab 数据根中的
精灵和已保存粮食；`collect` 在同一条真实 Brain 链路上执行消息序列，并将模型调用、记忆
召回、Context、Reasoning、Decision、Receipt、Settlement、状态差异和持久化证据写入
`build/brain-trace/<run-id>/`。模型和记忆可以分别选择 `real` 或 `mock`：真实记忆总是在
精灵快照副本上运行，模拟记忆使用真实 Memory 算法和 typed fixture。该工具只采集数据，
不做分析、评分或诊断，也不修改源精灵。

```bash
./developer.sh brain-trace list --data-dir /tmp/elfienest-devtools
./developer.sh brain-trace collect \
  --data-dir /tmp/elfienest-devtools \
  --elfie-id <elfie-id> \
  --memory real --model mock \
  --messages-file messages.jsonl
```

正式 App 使用 HTTP `8000`、Godot WebSocket `8765` 和管理 WebSocket `8766`，与 Lab
默认端口完全分离。三个命令都会复用同一个 HTTP 服务；启动器会先正常终止**当前工作区的
默认 Developer Tools 实例**，等待端口释放后再启动并打开对应页面；
它不会删除 Lab 数据、不会终止正式 App，也不会终止其他项目或未知程序。若默认端口属于
未知进程，命令会明确报错而不是强杀。

显式 `--port`（Nest Lab 还包括内部 `--godot-ws-port`）仅用于诊断并行实例；默认使用一个
HTTP 端口，Nest 的 WebSocket 默认随 HTTP 端口加一且不作为页面入口。

## 数据隔离

统一入口默认把 Web 实验台数据放在 `${ELFIE_DEV_HOME:-~/.elfienest-dev}` 下的独立子目录。
未传 `--data-dir` 时，精灵库沿用 Elfie Lab 的 `ELFIE_LAB_DATA_DIR` 配置（如有）；
三个页面共享同一个 Elfie Lab 存储实例。显式 `--data-dir` 仍覆盖默认目录。
为一次实验提供显式临时目录更容易清理：

```bash
./developer.sh elfie-lab --data-dir /tmp/elfienest-devtools --port 9001
```

Elfie Lab 会在隔离的 Lab 数据根中保存粮食及其专属模型连接。粮食表单明确分成两种连接方式：
**本机 Ollama** 默认使用 `http://127.0.0.1:11434`，只检测这个明确地址、不扫描端口，也不显示
API Key；高级设置可覆盖本机回环地址和端口。**自定义 OpenAI 兼容接口**填写 API URL，并可选填
API Key，因此也支持不鉴权的私人部署。两种方式都由用户明确填写模型 ID 和各角色模型。模型
冒烟请求失败时会在当前表单显示原因，且不会落盘。编辑粮食时可以修改名称、模型列表和角色
分配，已保存的连接方式、URL 与密钥状态保持只读。不得把任何实验数据、密钥或本机配置复制到
Git 跟踪文件。

Elfie Lab 还提供独立全屏的**批量评测**工作区：全局表格把每次执行保存为一份不可变报告，
配对 A/B 报告放在可展开父行下，单份详情和双份对比都在宽右抽屉中查看。快速检查运行 3 个场景，
标准评测运行 8 个场景；Food 配对会给两个候选克隆同一份冻结精灵快照，报告对比明确区分严格
配对、多变量观察和条件不兼容。这两套预设属于探索评测，不要求 Godot 评测场景。具体使用循环，
以及 Lab 快速反馈与正式晋级证据的边界，见
[Brain 评价工作流](../docs/zh/developer/engineering/brain-evaluation.md#11-在-elfie-lab-做日常版本评测)。

## 三个入口

本地 FastAPI 服务会一直运行到进程退出；日常只需要下面三个无参数命令：

```bash
./developer.sh elfie-lab
./developer.sh brain-eval
./developer.sh nest-lab
```

一个服务提供三个同源稳定地址：
`http://127.0.0.1:9001/elfie/experiment`（单精灵实验）、
`http://127.0.0.1:9001/elfie/evaluations`（批量评测）和
`http://127.0.0.1:9001/nest/experiment`（精灵巢实验）。左侧窄导航在三页之间切换，直接刷新
任一地址会保留当前页面；批量评测内的
报告列表、单份报告和对比报告仍然是同一页面中的列表与右侧抽屉，不额外拆成顶层页面。

三个入口启动后都会自动打开网页，并自动复用或更新同一份
`build/components/godot-web/` 导出物：缺失或 Godot 源码变化时才重新导出，未变化时
不会重复编译。macOS 会自动发现标准 Godot 安装位置；只有自动发现失败或多版本并存时，
才需要通过 `--godot` 或 `GODOT_BIN` 指定构建工具。浏览器每次启动使用新的本地运行 URL，
避免旧工作区页面缓存遮住新版界面。床位分配、随机游走、暂停、继续和重置
只作用于这一次 Lab 进程的场景状态；新建精灵保存到共享实验库，重启后可继续复用。

Nest Lab 默认打开大幅庄园监控画面，底部是一行贴边铺满宽度的级联操作栏。
第一个下拉菜单选择“视角／动作”，后续下拉内容随选择变化，用 `>` 分隔。窄屏只横向
滚动中间操作区；时间光照、播放／暂停、运行记录固定在右侧。播放／暂停切换随机游走，
运行记录切换右侧半透明浮层，不挤窄画面。
光照下拉只显示“实时／白天／晚上／深夜”。动作、位置、固定机位、场景对象和组合演示
使用两级级联：点击左列分类展开右列，点击具体项目才选中；支持按分类或项目名称搜索。
这些控件保持紧凑宽度，只显示选中项目名，弹出菜单独立适配内容宽度，长选项可以换行。
固定机位与动作位置都把同编号的卧室、露台放在同一个 `M01 卧室与露台` 分类中。
时间、视角类型和播放方式等短菜单保留普通下拉。

“视角”分固定机位（带复位）和精灵视角（选择精灵、跟随／第一人称），不显示画面定格。
跟随旋转保留镜头与几何体的间距，并限制相对精灵的高度和距离。实时光照在本地时间
午夜前保留晚间灯光，00:00–06:00 进入安静时段。
视角和精灵动作共用当前精灵及同一个选择器；列表最后一项打开“管理精灵”弹窗。
统一 Developer Tools 的 Nest Lab 自动读取同一数据根下单精灵实验已保存的精灵，
复用原 ID、名字和已解析外貌，服务重启后也会重新载入，场景最多容纳 32 只。
单精灵实验新增的档案会随场景列表刷新出现。已保存精灵只可从场景移除，不删除或
重新生成其原始档案；服务重启时会重新载入已保存精灵。
弹窗支持按名字（可选）、物种、年龄、性别创建并保存实验精灵，调用 Elfie Lab 的同一个
创建和存储流程。新建的 ID、档案与外貌同时供单精灵实验和 Nest Lab 使用，刷新或重启
不会重新生成。默认使用全局开发数据根；显式 `--data-dir` 使用指定本地根，两者不会
自动复制或合并。年龄范围沿用 Genesis 创建规则；场景重置和移除不删除原档案。

“动作”中的精灵动作使用一个分组动作下拉框；需要目标时，再显示一个按场景分组的位置
下拉框。选择动画或最终位置即提交，并切到所选精灵的跟随镜头；组合演示和穿门演示同样
自动跟随，不需要执行或停止按钮。切换动作会自动取消旧动作，
在收到其终止回执后启动最后一次选择；连续选择会替换尚未启动的动作。Lab 可预览任意
床位，不改变正式床位归属。单次坐卧预览直接定位到正式场景的目标接近点，再播放动作。
位置在同一个级联控件中按卧室与露台编号、主楼楼层和户外分组，只选择明确位置，不提供随机项。
坐点目录包含客厅左右单人沙发、主楼其他楼层座椅，以及八个露台中的沙发、单人椅和坐墩等。
新增家具检查点只在 Nest Lab 开放，直接就位后调用正式动作流程，不作为普通随机游走目标；
正式世界原有锚点继续接受完整的路线检查。
主楼长沙发提供中间及两个独立侧边坐点，运行时拒绝重复占用同一个坐点；户外长凳复用
正式坐姿与起身过渡。场景对象选中后自动切到对应门或水景的观察机位；喷泉、湖面
选中即独立播放，不再显示额外的播放／暂停菜单。门名按卧室编号和入口左右门显示中文，
保留开启、关闭和自动感应；关门继续检查防夹碰撞。已有精灵被选中时，“自动感应”会演示穿门并跟随精灵。
“组合演示”在一个分组下拉框内提供起床后二楼巡检、大厅巡检后入睡、建筑环线、林间
小路、湖边平台、顶楼到一楼挥手和沙发座位巡检。正式运行时从真实几何和导航生成路线，
不连通时禁用并显示原因；切换到新动作会取消组合演示。时间光照独立提供实时／白天／晚上／深夜预览；手动精灵动作
可恢复暂停的模拟并接管随机游走，运行记录显示实际结果。工作台不另写动画、寻路、家具
或水景效果逻辑，世界配置失败时禁用相应操作。

三个页面共用 `devtools/web/` 的 React + TypeScript + Vite 源码；启动时会按源码
摘要自动复用或构建 `build/components/devtools-web/`。如需单独检查该产物，可运行：

```bash
./developer.sh build-devtools-web --ensure
```

Brain Eval 的显式 `catalog`、`capture`、`compare`、`calibrate` 子命令仍用于批量工具链；
不带子命令时只打开上面的批量评测页面。显式动作在一次性 Elfie Lab 状态中运行真实 Brain
装配，只把产物写入
`build/brain-eval/<run-id>/`。先阅读
[Brain 评价工作流](../docs/zh/developer/engineering/brain-evaluation.md)；只有 Fixture、
事件/故障 Adapter、成功判据和证据路径都存在时，目录中的场景家族才算完成自动化。

## 边界

- 不修改或复用 `app/interfaces/web/static/` 的普通用户页面；
- 不把工具挂到生产启动入口或普通用户导航；
- 不用生产数据库、Owner 会话或默认用户数据做实验；
- 不把 `ElfieNestEngine`、Godot 或产品鉴权变成单模块调试的必要依赖；
- 不允许 Brain Eval 读取生产 `ELFIE_HOME`、写到 `build/brain-eval/` 之外，或让未校准
  Judge 触发自动晋级；
- 对工具行为的测试放在 `test/devtools/` 的镜像路径。

精灵动作下拉菜单提供坐下并起来、上床睡觉并起床两种完整流程，不拆分睡姿菜单。
底层保留仰睡及左右侧睡动画，通过认证的 `use_anchor` 指令的命名 `furniture_cycle`
选项触发，沿用目标校验和取消机制；Lab 预览不改变床位归属。正式实现位于
`godot_project/runtime/actor/`，Lab 只保留控件与摄像头
观察。三处沙发接触点属于庄园元数据，不建立动画专用的重复场景。流程失败显示在运行
记录中；仅有动作素材不能证明当前精灵与家具已经适配。
