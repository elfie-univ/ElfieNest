### ⚠️ 衍生/复杂情绪（2种）- 可考虑移除或简化

| 情绪 | 英文 | 分析 | 建议 |
|------|------|------|------|
| 无聊 | boredom | 派生状态（低唤醒+负面效价），非原始情绪 | ⚠️ 可移除 |
| 依恋 | attachment | 复杂社会情绪，需要认知加工 | ⚠️ 可移除 |

**为什么可以考虑移除？**

1. **boredom（无聊）**:
   - 不是基本情绪，是低唤醒+负面效价的组合状态
   - 可以通过其他情绪组合表达（如：低快乐+低兴趣）
   - 在大模型输出时，不需要单独的情绪维度

2. **attachment（依恋）**:
   - 复杂社会情绪，需要依恋理论支持
   - 可以通过情绪间相互影响系统模拟
   - 例如：fear高时，自动产生"寻求亲近"的行为倾向

**但是**，如果你认为这两个对精灵行为很重要，可以保留。这是设计选择问题。

## 三、刺激类型映射系统 - **不需要** ❌

### 你的判断是正确的！

**为什么不需要StimulusType系统？**

1. **职责已分离**
   ```
   外部输入 → [感知层/sensors] → EmotionInput(emotion, intensity) → EmotionSystem
   ```
   - 感知层负责："被骂" → 悲伤+35, 恐惧+20, 愤怒+15
   - 情绪系统负责：处理情绪演化、相互影响

2. **情绪间相互影响可以替代**
   - 不需要 "被骂 → 悲伤+35, 恐惧+20, 愤怒+15"
   - 只需要 "被骂 → 悲伤+35"，然后：
     - 悲伤高 → 通过抑制/增强影响其他情绪
     - 恐惧和愤怒通过情绪间相互影响自动产生

3. **避免过度设计**
   - StimulusType会引入额外抽象层
   - 难以维护（需要定义22种刺激类型）
   - 大模型难以理解复杂的映射表

**结论**: **不需要实现StimulusType系统**，现有架构已经足够。

## 五、最终建议

### 建议1: 简化情绪类型

**方案A: 只保留6种基础情绪**（推荐）
```python
EMOTION_CONFIGS = {
    "happiness": {...},
    "sadness": {...},
    "anger": {...},
    "fear": {...},
    "surprise": {...},
    "disgust": {...},
}
```

**方案B: 保留8种**（如果boredom和attachment对精灵行为很重要）
- 维持现状

### 建议2: 不添加新功能

**原因**:
1. 当前系统已经足够简洁
2. 情绪间相互影响系统已能处理复杂情况
3. 上层大模型会处理情绪→行为的映射
4. 不需要StimulusType增加复杂度

### 建议3: 如果需要更多情绪动态

**扩展情绪交互规则**即可：

```python
EMOTION_INTERACTIONS = {
    # 现有规则
    ('fear', 'anger'): {'type': 'transfer', 'threshold': 70, 'rate': 0.1},
    ('happiness', 'anger'): {'type': 'inhibition', 'rate': 0.3},
    ('sadness', 'attachment'): {'type': 'enhancement', 'rate': 0.2},
    
    # 可选扩展
    ('surprise', 'fear'): {'type': 'enhancement', 'rate': 0.15},  # 惊吓增强恐惧
    ('disgust', 'anger'): {'type': 'transfer', 'threshold': 60, 'rate': 0.1},  # 厌恶转化为愤怒
}
```
