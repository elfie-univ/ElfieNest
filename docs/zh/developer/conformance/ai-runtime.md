# AI Runtime 实现一致性台账

> 这是当前 `ai_runtime/` 迁移包和
> [模型、Food 与工具行为契约](../contracts/ai-runtime)的临时实现差距台账，只记录
> 当前未达标项；目标所有权只由[系统架构契约](../contracts/system)定义。

## 状态规则

- `open`：契约尚未实现，或当前实现存在安全问题。
- `in progress`：已有本地实现，但验收条件还没有全部通过。
- `closed`：代码、局部测试、架构测试和端到端契约全部通过。
- 除非设计契约明确要求兼容，否则增加兼容分支不能算作修复。

相互关联的区域存在差距：

## 迁移分组

这些分组表达依赖顺序，不授权合入半成品阶段。每个合并的迁移切片都必须保持产品可运行，
并通过自己的聚焦验收门，后续切片才能依赖它。

实施遵循“先建立新事实源、再切换全部调用方、最后删除旧实现”。新旧代码可以在一个
尚未合并的切片中短暂共存，但同一事实只能有一个活动写入者。若旧读取器需要跨合并切片
保留，必须有明确缺口条目与删除门，不得产生新数据；替代链路通过后立即删除，不能成为
永久兼容层。

### 阶段一：单一事实源与报告数据库

范围：

- 让 v2 Provider 连接成为 `providers.yaml` 唯一 Schema，先切换调用方，再删除旧
  bundle 写入器；旧 Provider 事实接口只有在调用方全部切换后才能删除；
- 新增 `reports/ai-runtime.sqlite`、显式 Schema 初始化、WAL、report run、不可变
  observation 和当前/历史时点/指定 run 查询；
- 用 Report Repository 和派生证据查询替换 YAML Provider/模型报告与
  `model_evidence.yaml`；
- 按契约整理 `runtime/runtime.json`、locks 和路径帮助器；
- 删除旧根级报告的事实读取；精灵级 `food_policy.yaml` 从本阶段起禁止新增写入，
  旧读取只临时保留到阶段四替代链路通过验收。

验收门：

- 修改 Runtime 或 Tool 设置时，Provider 和粮食文件字节完全不变；
- 单项、局部批量、完整批量和历史时点报告测试通过；
- 架构测试拒绝已删除写入器、旧报告事实路径和任何新增 `food_policy.yaml` 写入。

关闭或推进：AR-001、AR-002、AR-008、AR-013、AR-014。

### 阶段二：Provider 清单、发现与模型矩阵

范围：

- 实现 `official`、可选 `remote_catalog`、`bundled_catalog`、`manual` 四级发现和
  无损合并；
- 远程服务器尚不存在时先建立可配置 Client 边界，当前保证官方与安装包内置路径可用；
- 增加连接启停、归档/恢复、受保护删除，以及模型隐藏/退役/引用保护；
- 验证结果写入 report run，只有最近验证通过的模型可以进入粮食；
- 完成连接卡片动作、统一搜索产品选择器、正确本地品牌资源、当前连接模型页和
  “全部验证”矩阵。

验收门：

- 同产品两个账号以可读不可变 ID 共存；
- 四级发现回退全部有测试，刷新不丢手工模型；
- 单项验证只改变一个矩阵对象，“全部验证”生成一个完整 run；
- 浏览器测试验证 `[模型] [验证] [修改] [更多]` 和统一添加流程。

关闭或推进：AR-003、AR-012、AR-015、AR-016、AR-019。

### 阶段三：粮食领域、生命周期与 Owner 流程

范围：

- 用稳定套餐替换固定粮食和 `ExecutionProfile`；粮食只保存 Primary、Reasoning、
  Vision、Tool 和恰好一个可选 Fallback 模型引用；
- 第一行初始化永久保底粮、第二行初始化永久常用粮；增加启用状态、自定义粮归档/恢复
  和受保护删除；
- 根据 Provider 清单和 SQLite 观测派生本地性与粮食健康，不保存旧状态；
- 实现单个/多个/全部连接生成范围、保底粮本地优先、最近验证过滤、diff 预览、手工
  调整角色和显式保存；
- 保底粮/常用粮全局可见，只有自定义粮配置用户权限。

验收门：

- 干净数据根只有两份永久系统粮食；
- `nest.db.food_packages` 不含模型能力、上下文、输出或工具权限事实；
- 不可用模型不能被选择或生成；
- 浏览器测试覆盖行顺序、范围生成、五角色、生命周期、权限和动态健康。

关闭或推进：AR-004、AR-005、AR-007、AR-020。

### 阶段四：精灵路由与安全工具执行

范围：

- 精灵页只提供一个主粮字段，候选为用户可见、启用、健康且非保底的粮食；
- 保持 API、CLI、Owner 投影和 Runtime 调用方统一读取数据库粮食仓储；旧
  allowed/fallback 字段和全部 `food_policy.yaml` 读取已经删除；
- 把 `coarse/focus` 改为 Primary/Reasoning/Vision/Tool 语义角色请求；
- 统一解析主粮、可选角色到 Primary、一个可选套餐 Fallback、全局保底和类型化
  `no_available_food`；
- 安全搜索和只读文件同时进入普通与结构化皮层，绑定精灵工作区，并实现超时/条目/
  字节裁剪；
- 代码执行和技能修改在后续隔离契约完成前保持关闭。

验收门：

- 修改主粮无需重建精灵即可生效；
- 结构化与普通生成共用同一角色/回退解析器；
- 端到端测试证明安全工具调用和有界回注；
- 主粮与保底不可用时返回契约规定的精确结果。

关闭或推进：AR-006、AR-008、AR-009、AR-010、AR-011、AR-017。

### 阶段五：契约验收与清理

范围：

- 实现干净临时 `ELFIE_HOME` 的 13 步验收场景；
- 增加 Provider、模型矩阵、粮食和精灵流程的浏览器交互检查；
- 删除断言固定粮食或旧 UI 的过时测试，改为契约测试；
- 运行局部测试、架构测试、完整前后端质量门和敏感信息扫描；
- 每个一致性条目只有拿到验收证据后才能关闭。

验收门：

- 13 步契约全部通过，且没有旧文件或旧回退读取器；
- 一致性台账不存在 open 条目；
- 当前代码和中英文镜像都符合行为契约 1.5；
- 所有权和迁移步骤不重新创建目标 `ai_runtime/` 或
  `infrastructure/ai_runtime/` 模块。

关闭：AR-018 和所有剩余条目。
