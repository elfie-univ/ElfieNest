# ADR-0022：基于证据的任务收敛与不可变治理两阶段流程

- **状态：** 已接受
- **日期：** 2026-08-16
- **范围：** 实现完成、Conformance 收口与仓库质量门禁

## 背景

主路径和部分测试通过时，崩溃、安装、跨平台或恢复验收仍可能未完成。仅靠文字规则，
无法阻止半成品被汇报为已完成。

## 决策

- 每个实现任务使用一个紧凑的 `task-closure.json`，记录改动范围、契约/Conformance
  引用、证据和残余。
- 状态只有 `not_started`、`implementing`、`verifying`、`complete`、`blocked`。
  `complete` 必须同时具备代码、自动化测试、可重放运行场景、所需平台/安装证据，且
  residual 为零。
- `scripts/check_task_closure.py` 在完整提交门禁前运行，拒绝未完成行、未归属改动、
  宽泛范围和仍开放的列举 Conformance 行。
- 根目录 `AGENTS.md` 与贡献者测试说明属于同一治理面；修改其中的完成规则时，必须随
  本双语 ADR 一起交付，并与受保护实现保持可分离审查。
- 修改收敛技能或门禁本身时分两阶段：先提交治理-only 的分类器/ADR/测试注册，再提交
  受保护的检查器、集成和行为测试。不可为了合并两阶段而削弱不可变基础治理检查。

## 结果

完成声明必须有证据，环境限制必须明确标记为阻塞。治理变更多一个 bootstrap 检查点，
但局部通过不能再伪装成已经收敛的交付。
