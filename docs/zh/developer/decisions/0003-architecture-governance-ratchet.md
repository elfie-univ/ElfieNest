# ADR-0003：契约驱动的架构棘轮

- **状态：** 已接受
- **日期：** 2026-08-10
- **范围：** 仓库架构治理

## 背景

ElfieNest 经历过多轮重构。只有目标架构文字，无法阻止后续产品变更或编码 Agent 恢复
反向依赖、削弱评判自身代码的测试，或把临时迁移路径变成永久所有权。一次性清理整个
仓库又会破坏持续可运行的产品。

## 决策

架构由一套相互连接、带版本的体系治理：

- 契约定义长期所有权、依赖和 authority；
- ADR 解释有意变更；
- 根和子 `AGENTS.md` 把规则转成本地编码指引；
- 机器可读注册表关联契约、中英文镜像、ADR、规约、Scanner、测试和一致性台账；
- 精确 Baseline 只容纳已经登记的债务，并且只能缩减；
- CI 对 Pull Request 和受保护分支 Push 都使用基础提交中的不可变 Scanner 检查候选
  生产代码，并拒绝治理与生产混合变更；
- 生产根目录分类覆盖所有被跟踪的非文档文件，不限于源码后缀列表；
- 产品迁移只能删除精确 Baseline 条目，治理变更不得修改旧 Baseline，标记 `closed`
  的一致性条目必须已经机器清零；
- 迁移使用持续可运行的纵向切片，同一事实始终只有一个活动 authority；
- 债务清零后删除 Baseline 和一致性台账，永久保留 Scanner 并进入 deny-all。

宏观架构 v1 正式冻结。以后若修改宏观架构，必须先建立新的独立 ADR，同步升级契约
版本，并使用治理专用提交；产品迁移只能在此之后另行进行。

## 后果

架构变化必须先经过明确治理审查，再进行产品迁移。产品清理可以渐进完成并暂存已登记
旧债，但不能新增债务，也不能合入不可运行的半迁移。真实契约变化需要维护注册表和
Scanner 测试；这项成本是有意的，因为它让变更可见，并阻止自我批准式退化。

被拒绝的方案包括：只写文档不做门禁、每个 Feature 自己维护可变 allowlist、允许产品
变更修改评判自己的 Scanner、永久保留空 Baseline，以及要求应用运行前一次性迁移全仓。
