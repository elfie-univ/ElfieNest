# ADR-0017：分离内置默认配置与用户配置

- **状态：** 已接受
- **日期：** 2026-08-15
- **范围：** 全仓配置位置、加载与打包

## 背景

现有应用默认值分散在包内 YAML、硬编码字典和领域构造器中，加载器普遍从
`__file__` 推导路径；用户文档则已经位于 `${ELFIE_HOME}/configs/`。发行打包只收集
部分 package data，因此源码位置、安装位置和有效值规则没有形成一份统一契约。

如果安装时把全部默认值复制进用户目录，就会形成两份长期副本，模糊版本所有权，并
可能覆盖用户修改。即使只移动文件，只要允许每个消费方直接读取 YAML，路径和合并
逻辑仍然会继续散落。

## 决策

采用两个持久配置根：

- 仓库 `config/` 是不可变、随版本管理的内置产品默认配置源码，发行时只 staging 一次
  到 `resources/config/`；
- `${ELFIE_HOME}/configs/` 继续作为可写的用户配置与 Secret 来源。

首次运行只创建目录，不复制默认值。有效值由文档专用的强类型 Infrastructure Adapter
生成。用户值只按该文档声明的策略优先：系统与工具设置按 Schema 字段覆盖，Provider
目录通过校验后整文档替换，仅内置文档继续只读，连接与 Secret 继续仅属于用户。

根 `config/` 是非 Python 资源根，不是第五个系统 authority。语义模型仍归 App、Elfie、
Nest、Models 或 Tools 所有；Infrastructure 负责技术加载与写入，Bootstrap 只负责装配。

首轮迁移严格限定为结构整理。现有物种声明、外观 Profile 与 Genesis 行为不在本次迁移范围内，
继续保留在当前 Profile 所有的源码中。本决策不增加物种字段、规范化、发现、注册、资源或行为。

## 决策更新：登记 Schema 与执行边界

登记文档元数据是文档 ID、固定相对路径、版本、Schema、写入策略、重载边界和失败策略的
唯一权威。内置源和用户源在返回文档前完成校验，语义所有者拒绝其自有记录中的未知字段。
少量明确声明的透明扩展桶可以保留其他既有消费者拥有的数据，但这不等于允许在已拥有的
section 中增加任意字段。

生产调用方只能使用已注册文档 ID 和 resolver 拥有的根目录。测试和开发工具可以注入隔离根
目录进行沙箱测试，但必须复用登记的文件名和校验器，且绝不能默认读取生产 `ELFIE_HOME`。

## 后果

- 源码默认值只有一个可见位置，安装应用只有一份受 manifest 覆盖的副本。
- 业务和领域代码不再拥有文件路径、YAML 解析或通用合并行为。
- 必需内置数据缺失会成为构建/启动缺陷，不再被重复硬编码默认值隐藏。
- 用户配置在应用升级时保留，内置默认值永远不能覆盖它。
- 配置管理一致性台账现在作为等待治理专用删除的 ready 收口记录保留；它不能被用来
  授权新增散落配置。

本 ADR 改变了已冻结的系统根结构，因此在产品迁移前先修订双语 System 契约，并注册
新的配置管理契约及其治理产物。本决策变更不包含任何产品实现。
