# ADR-0041：隔离资产设计工作台与保存的设计资产

**状态：** 已接受
**日期：** 2026-10-22
**范围：** Developer Tools 资产设计预览与资产工作区存储

## 背景

房屋、房间、露台和家具需要一个稳定的本地界面来查看已保存的资产库，同时不能让
这个界面变成第二套产品 Runtime。工作台还需要明确区分可编辑源资料、已发布版本和
未登记工作材料。任意目录扫描或第二个预览页面都会让资源的权威来源不清楚，也可能
让资产审阅依赖生产服务或 Godot 状态。

## 决策

Developer Tools 的 `/assets/design` 路由及其现有查看器是唯一的资产预览界面。工作台
不复制查看器、不启动临时模型网站，也不拥有 Elfie、Nest 或 Godot Runtime 的生命周期。

可携带的设计工作区根目录是 `devtools/asset_design/assets/`。`catalog.json` 是加载投影；
每个有所有者的对象把公共元数据保存在 `object.json`，每个已发布版本把文件登记和
版本详情保存在该版本的 `version.json`。源资料、已发布快照和参考图都保存在规定的
对象目录内。只有显式登记到目录的文件才能进入预览；目录扫描不能静默把工作稿提升为
可用版本。

资产工作台规则由根目录及作用域内的 `AGENTS.md` 执行。本 ADR 记录长期边界；当前
作用域规则仍是贡献者需要遵守的可执行指引。

## 后果

无需加载生产数据或第二套 Runtime，就可以从可携带资产工作区重新打开页面。新的或
修改过的 GLB 必须先显式登记，才能影响页面；旧版本和未登记工作材料在审阅前继续
留在本地。目录、对象元数据和版本元数据拥有清晰的归属路径，因此遗漏排查和工作区
迁移都可以重复执行。
