# ADR-0026：SQL 边界扫描器忽略 Python docstring

- **状态：** 已接受
- **日期：** 2026-08-20
- **范围：** 仓库治理与应用层 SQL 边界验证

## 背景

应用层 SQL 边界测试会解析 Python 模块，并在所有字符串常量中搜索 SQL 关键字。这条
规则能够正确阻止可执行 SQL 进入 `app/bootstrap`、`app/features`、
`app/interfaces` 或 `app/orchestration`，但 Python docstring 本身也是字符串常量。
因此，一个以普通英文动词 `Select` 开头的 docstring 会被报告为 SQL，即使该模块既不
包含查询，也没有导入 `sqlite3`。

只改写当前这一句话可以让测试通过，却会让以后任何模块、类、同步函数或异步函数的
docstring 再次触发相同误报。

## 决策

扫描器把 Python 模块、类、同步函数或异步函数拥有的第一个字符串表达式识别为该所有者
语义上的 docstring，并且只从 SQL 字面量匹配中排除这个 AST 节点。其他所有字符串常量
仍然参与扫描，应用层直接导入 `sqlite3` 也仍然被拒绝。

回归测试必须同时证明边界两侧：四种受支持 docstring 作用域中的 SQL 类文本不会被误报，
而相同文本出现在普通运行时字符串中时仍然构成违规。底层架构契约保持不变：SQL 只能
存在于获准的持久化层。

## 后果

应用代码文档可以使用普通语言，而不会产生错误的 SQL 所有权报告。扫描器仍然对可执行
字符串字面量和具体 SQLite 依赖采取 fail-closed 策略，也不新增路径白名单或 Baseline
例外。

被拒绝的替代方案包括：逐个改写 docstring、对所有字符串放宽 SQL 关键字模式，以及把
受影响的应用文件加入白名单。
