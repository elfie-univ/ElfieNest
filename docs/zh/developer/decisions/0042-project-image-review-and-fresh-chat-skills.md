# ADR-0042：项目级轻量读图与干净重开技能

**状态：** 已接受
**日期：** 2026-11-05
**范围：** 编码代理指令与可复用项目技能

## 背景

图片密集的编码对话可能在触发基于 token 的历史压缩前，已经积累较大的请求字节量。
同时加载全部参考图及其放大副本也会重复视觉输入。新开对话本身不能控制之后加载的
图片数量和体积。

读图流程和干净重开流程需要随 ElfieNest 分发，使贡献者在检出相应项目版本后即可
复用。只安装在用户目录中的技能不能提供仓库级分发。

## 备选方案

- 保留用户级副本：本地可用，但不能随项目分发。
- 依赖反复压缩或 fork 对话：两者都不能保证新请求不包含历史图片。
- 将流程与辅助脚本作为项目技能纳入版本控制，并在根 AGENTS 中保留简短指引：采用。

## 决策

将 `lightweight-image-review` 和 `worktree-fresh-chat` 及其可执行辅助脚本存放于
`.agents/skills/`。根 `AGENTS.md` 将本地图片检查和用户明确要求的干净重开路由到
对应技能。

图片检查先读取元数据，再加载有体积约束的总览或标号拼图。每次工具结果中新增的
Base64 图片载荷以约 2 MB 为目标；需要细节时读取原生分辨率局部，避免重复加载
放大副本，并保留源文件。有损预览不能证明精确色彩、透明度、像素细节或最终视觉
验收已经通过。

干净重开必须由用户明确要求。它创建全新对话，将现有 Worktree 保存为执行工作目录，
保留 Git 状态，不携带旧消息或图片。它不归档旧对话，也不转移托管 Worktree 的
所有权。系统指令和自动记忆注入仍遵循应用正常行为。

## 影响

包含此版本的项目 checkout 可以发现这些技能；其他分支和电脑需要先同步这些文件。
辅助脚本使用已有的 Codex、Node、Git 和 Pillow 环境，不安装依赖、不修改应用配置。

这些属于代理工作流规则，不是应用级图片硬限额，也不保证端到端延迟降低。它们不改变
产品架构、公开协议、永久数据契约或 CI 策略。现有验证、Git 授权和受保护主线交付
要求继续适用。
