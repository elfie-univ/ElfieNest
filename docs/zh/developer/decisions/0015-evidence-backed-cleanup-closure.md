# ADR-0015：清理收口必须具备目录盘点与残留证据

- **状态：** 已接受
- **日期：** 2026-08-14
- **范围：** 全仓清理完成声明、一致性收口及受治理源码范围

## 背景

多次迁移在部分测试通过后被报告为已经完成，但实际并未把批准目标与完整源码树逐项
对账，仍残留未分类目录、兼容壳、旧调用方以及 Godot 开发/导出材料。测试只能证明它
断言的行为，不能证明请求范围内的每个路径都已经盘点，也不能证明被替代线路已经消失。

一致性生命周期还存在第二个缺口：治理变更分类器排除了删除路径，而只观察候选分支的
注册表测试无法在台账文件和注册项同时删除后继续检查它。开放或证据不足的台账因此可能
在基线门禁没有拒绝的情况下消失。

## 决策

测试、构建、干净工作区或推送成功，都不能单独支持“清理完成”或“已经符合契约”的
结论。

每个清理切片必须把批准目标与精确范围的递归目录盘点对比；盘点包括已跟踪、未跟踪、
被忽略和空路径。每个路径都要归类为目标源码、保留内容、开发输入、生成物、当前一致性
债务或已经证明可删除的候选。审查还要按需追踪 Import、动态启动目标、场景/资源、导出
输入、CLI/脚本和文档引用，并把已完成、保留及剩余项分别报告。

一致性行第一次标为 `closed` 时，必须在一个简洁证据单元格中包含以下稳定字段：

- `target=`：精确治理条款或已经接受的归置；
- `inventory=`：已经审查的源码/运行范围；
- `references=`：调用方、场景、导出及替代线路证明；
- `verification=`：正向与反向行为检查；
- `residuals=`：相关残留为零，或明确说明范围外残留。

单独的测试结果不能填满这五类证据。人工审查判断证据含义，治理检查器验证字段存在及
状态变化。

不可变基线分支检查器必须纳入删除路径，对比基线与候选的一致性注册项，要求双语状态
一致，并拒绝删除任何基线中尚未全部关闭或缺少完整逐行证据的台账。为了让最后一笔产品
变更先通过、随后再独立治理删除，全 closed 台账只允许带明确 `收口状态：ready` 标记
短暂保留。删除变更必须同时删除双语文件和注册项，且不能混入产品文件。

受契约保护的清理根目录还要使用结构范围 Scanner：每个直接结构条目都必须归类，未知
条目直接失败。开放清理行拥有的路径可以缩减或修改，但不能新增文件；临时路径仍存在时
不得关闭对应行。

## 后果

今后的清理工作具有可见且不可被方便测试子集代替的完成定义。Scanner 无法判断全部
语义价值，因此维护者审查仍然必要；但未审查目录和基线台账删除不会再静默消失。

证据直接保存在一致性行中，不新增会话日志或工作流台账。台账合法删除后，永久结构与
依赖门禁继续保留。确有必要新增结构类别时必须经过治理审查，不能静默扩大大杂物目录。
