# ADR-0023：分级验证与精确快照复用

- **状态：** 已接受
- **日期：** 2026-08-16
- **范围：** 本地提交、功能分支推送和受保护主线验证

## 背景

完整 pre-submit 门禁是正确的最终发布后盾，但每次普通提交都运行它，会重复执行与改动
无关的测试和工具链工作。仓库需要一个更小但安全的反馈循环，同时不能让本地通过结果
削弱不可变基础检查或受保护主线门禁。

## 决策

- 根据改动路径分类候选，并选择 G1 提交、G2 推送或 G3 主线验证。未知可执行路径、治理、
  工具链、锁文件和交付改动自动升级到 G3。
- G1 执行改动文件的差异/密钥/质量检查、确定性的受影响测试和 task-closure `progress`。
  G2 追加质量基线以及受影响的 API、持久化、架构或文档集成检查。G3 保留现有完整
  `pre_submit_gate.sh` 和 task-closure `complete` 检查。
- 只为精确候选快照复用成功的确定性结果。缓存键覆盖规则/检查版本、级别、基础 SHA、
  候选内容、锁文件、工具链和选择规则。命令结束后指纹不一致就作废；失败和真实 Provider
  证据不能作为通过结果缓存。
- 缓存只写入被忽略的 `build/validation-cache/`，使用原子写入，不包含源码或敏感信息。
  GitHub CI 仍验证最新 commit SHA，并继续作为受保护主线的权威门禁。

## 影响

普通提交得到聚焦反馈；Provider/模型改动只选择其 API、持久化和验证测试，不再默认跑全仓。
治理和未知改动仍然有意保持高成本。相同候选已有成功结果时完整门禁只运行一次；主线交付
绝不会因此绕过完整门禁。
