# ADR-0023：分级验证与按检查复用证据

- **状态：** 已接受
- **日期：** 2026-08-16
- **修订：** 2026-08-17
- **范围：** 本地提交、功能分支推送和受保护主线验证

## 背景

完整 pre-submit 门禁是正确的最终发布后盾，但每次普通提交都运行它，会重复执行与改动
无关的测试和工具链工作。仓库需要一个更小但安全的反馈循环，同时不能让本地通过结果
削弱不可变基础检查或受保护主线门禁。

## 决策

- 根据改动路径分类候选，并选择 G1 提交、G2 推送或 G3 主线验证。未知可执行路径、治理、
  工具链、锁文件和交付改动自动升级到 G3。
- G1 执行改动文件的差异/密钥/质量检查、确定性的受影响测试和 task-closure `progress`。
  G2 追加质量基线以及受影响的 API、持久化、架构或文档集成检查。G3 保留现有完整
  `pre_submit_gate.sh` 和 task-closure `complete` 检查。
- 把级别视为一组必需检查，不把级别本身放进单项测试检查身份。可复用确定性测试检查按命令、作用域
  输入内容与模式、相关不可变基础提交和本机工具计算，使 G2 可以直接消费 G1 的聚焦测试
  通过证据，不再启动同一命令。
- 把本地 G3 pytest 后盾拆成保守注册的顶层稳定测试包。测试包只有在通过记录、覆盖率片段、
  产物摘要、匹配的 coverage/pytest 版本和可读覆盖率数据都一致时才能复用；输入还要从测试
  与共享 `conftest.py` 推导本地 Python import 闭包。G3 合并全部片段并只执行一次全仓阈值。
  此前完整执行同一测试包会使用相同证据，更窄的 node 或文件不能证明更大的测试包；未知可执行
  输入使所有包失效。
- 保留精确候选复用，并为其余昂贵 G3 后盾单独计算指纹。只有根目录
  `task-closure*.json` 验收矩阵不进入后盾指纹，因为每个候选都会重跑其范围、密钥和
  closure `complete` 检查；源码、测试、依赖、工具链、普通文档和门禁规则仍然作为
  fail-closed 后盾输入。
- 发生失败后先只重跑精确失败 node；只有修复或依赖边界需要时，才扩大到所属模块和受影响
  集成。完整 G3 后盾只对最终可执行候选运行一次，不在每次修复编辑后重跑。
- 缓存键覆盖规则/检查版本、基础 SHA、所选候选内容、本机工具链和相关执行环境。同一次
  运行的测试包共享仓库快照，但接受缓存命中前仍复核当前签名。命令结束后指纹不一致就作废；
  失败和真实 Provider 证据不能作为通过结果缓存。直达 main 后盾时复用有效测试包，
  `--no-cache` 会继续透传以执行干净重放。
- 缓存只写入被忽略的 `build/validation-cache/`，使用原子写入，不包含源码或敏感信息。
  失败永远不是通过；同键强制重跑失败时删除旧证据。GitHub CI 仍验证最新 commit SHA，
  并继续作为受保护主线的权威门禁。

## 影响

普通提交得到聚焦反馈；Provider/模型改动只选择其 API、持久化和验证测试，不再默认跑全仓。
开发过程中已经完整通过且输入未变的测试包，不会仅因进入提交、推送或本地 G3 阶段就再次
运行；更窄的修复检查仍保持窄范围，不能满足更广覆盖。治理和未知改动继续 fail-closed。
同一可执行后盾已通过后，仅修改 closure 证据不再重跑未变化测试包、依赖安装和文档构建，
但当前候选检查仍会执行；受保护交付仍必须通过最新 SHA 的 CI。
