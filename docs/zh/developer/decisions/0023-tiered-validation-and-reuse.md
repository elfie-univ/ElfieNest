# ADR-0023：分级验证与按检查复用证据

- **状态：** 已接受；受保护主线 G3 前置要求由 ADR-0027 部分取代
- **日期：** 2026-08-16
- **修订：** 2026-08-22
- **范围：** 本地提交、功能分支推送和受保护主线验证

## 背景

完整 pre-submit 门禁是正确的最终发布后盾，但每次普通提交都运行它，会重复执行与改动
无关的测试和工具链工作。仓库需要一个更小但安全的反馈循环，同时不能让本地通过结果
削弱不可变基础检查或受保护主线门禁。

## 决策

ADR-0027 只取代“每次受保护主线合并必须等待完整 G3”这一要求。本地受影响验证、按检查
证据身份和可复用完整测试包继续有效；完整 G3 改为在 main 接受后及手工/发布验证时执行。

- 根据用户要求的 Git 动作和改动路径选择 G1 提交或 G2 推送验证，不要求用户或代理主观
  标注任务大小。未知可执行路径、治理、工具链、锁文件和交付改动通过精确候选 CI 全选
  Lane 来 fail-closed，不因开始 Push 就在本地启动全仓。
- 根目录或任意子目录的 `AGENTS.md` 都属于治理输入。本地受影响验证只选择其直接治理和
  架构检查，精确 PR 候选在远端仍全选 Lane；因此产品目录下仅规则修改不会启动该产品的
  本地测试套件。
- G1 执行改动文件的差异/密钥/质量检查和确定性的受影响测试。G2 追加质量基线以及受影响
  的 API、持久化、架构或文档集成检查。full 模式保留现有完整 `pre_submit_gate.sh` 后盾，
  供合并后、手工和发布执行。
- 把级别视为一组必需检查，不把级别本身放进单项测试检查身份。可复用确定性测试检查按命令、作用域
  输入内容与模式、相关不可变基础提交和本机工具计算，使 G2 可以直接消费 G1 的聚焦测试
  通过证据，不再启动同一命令。
- 把完整 pytest 后盾拆成保守注册的顶层稳定测试包。测试包只有在通过记录、覆盖率片段、
  产物摘要、匹配的 coverage/pytest 版本和可读覆盖率数据都一致时才能复用；输入还要从测试
  与共享 `conftest.py` 推导本地 Python import 闭包。full 模式合并全部片段并只执行一次全仓阈值。
  此前完整执行同一测试包会使用相同证据，更窄的 node 或文件不能证明更大的测试包；未知可执行
  输入使所有包失效。
- 保留精确候选复用，并为其余昂贵 full 后盾单独计算指纹。源码、测试、依赖、工具链、普通
  文档和门禁规则仍然作为 fail-closed 后盾输入；只有缓存规则明确处理的生成物或忽略路径
  才能排除。
- 发生失败后先只重跑精确失败 node；只有修复或依赖边界需要时，才扩大到所属模块和受影响
  集成。完整后盾只对已接受 main tip 或显式发布候选运行，不在每次修复编辑后重跑。
- 缓存键覆盖规则/检查版本、基础 SHA、所选候选内容、本机工具链和相关执行环境。同一次
  运行的测试包共享仓库快照，但接受缓存命中前仍复核当前签名。命令结束后指纹不一致就作废；
  失败和真实 Provider 证据不能作为通过结果缓存。直达 full 后盾时复用有效测试包，
  `--no-cache` 会继续透传以执行干净重放。
- 缓存只写入被忽略的 `build/validation-cache/`，使用原子写入，不包含源码或敏感信息。
  失败永远不是通过；同键强制重跑失败时删除旧证据。GitHub CI 仍验证最新 commit SHA，
  并继续作为受保护主线的权威门禁。

## 影响

普通提交得到聚焦反馈；Provider/模型改动只选择其 API、持久化和验证测试，不再默认跑全仓。
验证跟随受影响行为和用户要求的 Git 动作，不再依赖人工任务大小。子目录代理规则在本地
保持治理范围，远端精确候选仍通过全 Lane fail-closed。
开发过程中已经完整通过且输入未变的测试包，不会仅因进入提交、推送或 full 后盾阶段就再次
运行；更窄的修复检查仍保持窄范围，不能满足更广覆盖。治理和未知改动继续通过候选全选 Lane
fail-closed。受保护交付仍必须通过最新 SHA 的 CI。
