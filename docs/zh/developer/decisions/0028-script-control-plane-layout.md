# ADR-0028：按职责拆分脚本控制面

- **状态：** 已接受
- **日期：** 2026-08-23
- **修订：** 2026-08-23，由 ADR-0029 修正交付边界
- **范围：** 仓库脚本所有权、稳定入口与治理切换

## 背景

`scripts/architecture/` 在一个扁平目录中同时积累了架构 Scanner、数据库盘点、变更策略、
验证路由、证据缓存和 Git Hook 安装。目录名称已经不能描述真实内容；同时，稳定命令、
单项检查和一个被产品消费的 Godot Adapter 又混在 `scripts/` 根目录，职责和路径稳定性都
难以判断。

切换发生时，旧分类器会拒绝所有同时包含治理与实现路径的候选，因此迁移被拆成多个 Pull
Request。ADR-0029 后来确认这是过宽的 PR 级控制：不可变基础规则可以阻止自我批准，不需要
把每个本地审查边界都变成 main 交付边界。

## 决策

- `scripts/` 直接子文件只保留有意承诺的高层命令或 import 契约。
- 契约注册、变更策略、代码/依赖边界和持久化门禁进入 `scripts/governance/`。
- 单项质量检查、验证规划/执行/缓存和受管 Git Hook 进入 `scripts/quality/`。该目录的
  变更仍属于治理变更，因为它会改变评判候选的机制。
- 可替换的 Bootstrap、构建、发布和人工诊断辅助实现保留在 `scripts/internal/`。仓库内
  调用方可以直接使用，但其路径不是对外兼容契约。
- 具体 Godot 物种验证 Runner 归入现有 Infrastructure Artifact 所有者，不再让产品依赖
  `scripts/` 下的便利模块。
- 在不可变基础保护下，通过逻辑分离的本地 commit 和最终旧路径清理完成切换；不新增兼容
  Wrapper，也不保留两份物理实现。历史上的多 PR 执行不是可复用交付要求。
- `scripts/README.md` 和 `scripts/README_zh.md` 长期作为精炼的双语目录地图与脚本归置
  指南。

## 影响

根目录成为小型控制面板，治理策略与质量执行能够直接区分，`internal` 表示兼容性边界，
而不是保密或禁止仓库内调用；切换结束后不保留长期旧路径。后续工作可以在一个长期功能
分支上用不同本地 commit 分开治理与实现；只要实现仍通过不可变基础规则，最终使用一个
Pull Request。

## 切换状态

已完成。受保护 `main`、普通调用方、CI 与本地门禁现在只使用目标布局；临时不可变基础查找
和调用方回退已经通过独立治理与产品变更删除。退役路径只保留在历史背景和显式 fail-closed
拒绝规则中，不再是可执行回退或合法所有权位置。
