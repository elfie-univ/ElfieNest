# ADR-0017：主人聊天采用完整回复投递

- **状态：** 已接受
- **日期：** 2026-08-15
- **范围：** 模型/Food/工具行为契约与主人聊天投递

## 背景

之前曾将聊天链路实验性改为 Provider 流式调用，希望在模型完整返回前让 Web 客户端
显示部分文本。受控本地测试以及使用已配置远程火山引擎模型进行的五组配对请求没有显示
有意义的延迟改善；观测差异处于网络和 Provider 波动范围内，而流式请求增加了独立的
HTTP 传输、SSE 解析和临时 UI 投递路径。

这个实验还在现有持久化会话消息之外增加了第二种实时消息形态，但没有减少模型推理、
结构化输出处理或模型调用次数。

## 决策

主人聊天采用完整回复投递：

- 一次普通模型请求产生一条完整回复；
- 完成的精灵回复只持久化一次；
- 已授权 Web 客户端接收一条普通 message 事件；
- 临时 message_delta 事件和流式专用标识符不属于当前聊天协议。

结构化 JSON 和工具调用生成仍然等待完整结果。延迟观测可以继续记录首字和总耗时作为
模型证据，但观测结果不会改变产品投递契约。

Provider 流式调用不作为默认性能优化。未来若再次提出流式方案，必须重新修订契约，并
用受控基准证明它带来有实质意义的用户可见收益，同时不能削弱结构化输出、持久化、授权
或前端隐私边界。

## 后果

实验性的流式实现和临时聊天协议已移除。Web 客户端直接渲染持久化的完整回复，不再需要
流式缓冲区，也不需要在部分回复和最终消息之间做协调。

真正的速度优化继续聚焦模型请求本身：上下文和提示词长度、串行模型调用、模型选择和
可复用的 Provider 连接。此次回退不改变现有完整回复聊天行为或结构化模型契约。
