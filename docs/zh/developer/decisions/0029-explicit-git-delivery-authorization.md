# ADR-0029：显式 Git 动作授权与单 PR 交付

- **状态：** 已接受
- **日期：** 2026-08-23
- **范围：** 编码 Agent 的 Git 授权、Pull Request 生命周期与候选证据复用

## 背景

ElfieNest 曾把一条有价值的规则——用户已经授权某个动作后，不要反复确认该动作内部步骤——
错误泛化成“已批准实现计划可以一次授权 commit、push、创建 Pull Request 和合并 main”。
与此同时，治理分类器把本地审查边界当成强制 Pull Request 边界，导致一个脚本目录任务作为
同一个用户任务和同一个最终验收边界，却通过七个 Pull Request 才进入 main。

这既不是受影响测试质量所要求的，也无法在多人并发开发中扩展。Pull Request 是对 main
变更的提案，不是每个本地 commit 的 checkpoint。计划、ADR、技能和历史上下文只能描述
工作，不能授予外部写权限。

## 决策

- 使用六级显式动作：实现允许本地工作和合理本地 commit；commit 只留在本地；push 只更新
  当前功能分支；create-PR 创建或复用一个 PR 后停止；merge-main 才使用该单一 PR、CI 和
  原生 merge queue；孤立的完成/交付不授予 Git 动作。
- 授权绑定当前任务、仓库、分支、动作和冻结候选 SHA；成功或取消后即消费，目标、范围或
  候选变化时失效。merge queue 的合成 SHA 不属于新候选。
- 功能分支可以跨会话、跨天保留。多个聚焦 commit 和 push 不会创建 Pull Request。一次
  明确主线交付请求最多创建或复用一个 PR；多个 PR 必须事先批准准确数量与边界。
- 本地 commit 可按审查职责拆分；只要产品改动仍通过不可变基础规则，治理敏感 commit 与
  产品 commit 可以进入同一个最终 PR。依赖放宽基础规则才能通过的产品改动仍会被拒绝，
  只有通过上述显式例外才能使用多个 PR。
- 分离功能分支 push/恢复和 main 交付。普通 Git 技能不含 PR、队列或 main 写入；窄 main
  技能处理“只创建”和“合并 main”两种模式，冻结一个 head SHA、实时检查规则与审查，并
  在用户停止时退出队列。ElfieNest 不允许直接 push main。
- merge-main 在创建单一 PR 前，通过受信任 main Workflow 验证冻结 SHA。只有全部选中 Lane
  与聚合门通过后才发布可复用证据。只有精确候选、基础治理指纹、Manifest 版本、候选工具链
  指纹和受信任 Workflow 身份完全一致时，PR 才能跳过这些 Lane；否则正常运行选中图。
- 十分钟交付 SLO 从用户放行稳定最终候选开始，到该候选在 main 上完成核验为止。不能因为
  实现被拆成多个 PR 就重新计时。CI 记录它能观察的区间；交付操作者记录用户放行边界。
- 机器检查建立技术证据，不等于用户验收。需要的界面、行为或文档审查在 create-PR/main
  交付前完成；本地 commit 和功能分支 push 仍可用于迭代。

## 被拒绝方案

- **让已批准计划授权整条 Git 链：** 通过抹掉动作边界减少询问，会在验收前修改 GitHub。
- **每个治理/产品 commit 都创建一个 PR：** diff 较小，却把内部顺序变成重复排队和移动
  main 抖动。
- **PR 前验证后，创建 PR 时无条件重跑：** 候选没有变化，却把主要延迟支付两次。
- **使用自然语言分类器推断远端意图：** 会增加另一个模糊 authority。显式命令和结构化技能
  边界更简单、可审计。

## 影响

大多数实现会话不会创建 PR。贡献者可以 checkpoint 或共享功能分支，而不占用 main。最终
交付只有一个可见候选、一个 PR、一张受影响验证图和一次短队列写入。

证据复用增加一份很小的可信身份协议和七天 Artifact。任何身份组件无法证明时，安全结果是
PR 正常运行选中 Lane，而不是复用证据。候选变化后需要新的用户主线指令，不能自动修复并
再次排队。

源码契约要求 live 维护者审查规则，但源码文件不能启用或证明该外部设置。live ruleset 与
真实非作者批准尚未满足前，窄 main 技能 fail closed；不能声称审查门已经生效。
