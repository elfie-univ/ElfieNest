# ADR-0006：Elfie 生命系统所有权与单一身体权威

- **状态：** 已接受
- **日期：** 2026-08-12
- **范围：** 一只 Elfie 的稳定 Profile、Brain 系统、Genesis 与具身权威

> **后续细化：** ADR-0033 已取代本文关于“创建来源”的较早表述。现行契约把 Profile
> 严格限制为外部客观档案，由 Genesis 独占语义编译，并在提交后移除创建输入绑定。
> 本文只保留为历史证据，不是现行规则。

## 背景

ADR-0005 确立了一只 Elfie 内部的 Ports/Adapters 方向。它的所有权表有意遵循当时的
实现：Profile 仍保存人格、能力和运行限制；聚合认知仍有一部分位于
`elfie/brain/` 之外；Body 契约也保留了未来多身体并发的可能。

后续经过审查的 Elfie 故事和大脑十系统设计给出了更精确的生命模型。一只 Elfie 只有
一份连续身份和一个 Brain，拥有两条独立对外线路、三类认知事件来源和唯一的当前具身
权威。稳定客观身份不同于会变化的自我模型，创建期生成也不同于日常认知。如果继续让
这些边界保持隐含，后续 Brain 实现会保留错误所有者，并在完成后再次迁移。

## 决策

把 Elfie 内部架构契约升级到 2.0：

- 经 ADR-0033 细化后，Profile 只拥有不可变的外部客观身份、稳定年龄/出生与个人出身锚点，
  以及最终虚拟外貌。创建来源只属于创建事务；Profile 不拥有它，也不拥有人格、记忆、
  能力、权限、运行限制、当前身体或当前状态。
- Brain 拥有十个概念系统：事件工作区、自我定位、自我认知、情绪、能量、动机、
  记忆、思考中枢、跨回合活动和心智整理。Skills 属于 Brain 的思考中枢侧。
- 十系统是概念所有者，不等于十个进程、数据库或必须预建的目录。只有出现真实状态、
  契约或行为时才建立对应包。
- 通信事件、具身事件和内部触发作为不同来源进入 Brain。每个被接纳的 Turn 只有一个
  来源域和一个允许的响应范围；跨域后果必须形成后续 Turn。
- Brain 的外部决定只允许通信指令、神经系统指令、跨回合活动请求或 No-op。Model、
  Skill、Tool 调用仍是内部认知操作，不是新的对外生命线路。
- 一只 Elfie 可以知道多个已授权身体候选，但虚拟具身与实体具身在运行时互斥。除明确
  的切换事务外，任何时刻只有一个选中身体拥有传感与动作权威。Headless 只是确定性
  开发/测试替身，不是第三种产品身体。
- `genesis/` 拥有创建期规则和临时初始化 Bundle。它把产物分别提交给 Profile 与 Brain
  的权威所有者，之后不保留第二份副本，也不成为第六个运行器官。
- `Elfie`、`ElfieFactory` 继续作为薄聚合边界。私有认知协调归入 Brain；应用
  Bootstrap 仍负责构造技术 Adapter，Lifecycle Orchestration 仍拥有系统 Runtime 的
  start/stop/restart。

本决策改变 `elfie/` 内部所有权，但不改变系统根模块、Infrastructure 依赖方向、Nest
authority、生产组合或系统级 Port 语义，因此系统契约继续保持 1.3。ADR-0005 仍是已
接受 Ports/Adapters 方向的历史依据；当其中 Profile、Brain 或身体激活表述与本决策
冲突时，以 2.0 契约和本 ADR 为准。

## 后果

当前源码会在独立纵向实现切片关闭登记缺口前保持有意不完全合规。特别是：根部认知
协调应随真实行为实现移入 Brain；Profile 数据只能在新所有者成立后迁移；初始化必须
转为 Genesis，且不能保留双 authority 或兼容存储。

本治理变更不移动产品代码、不修改持久数据，也不创建空 Brain 包。之后另行生成执行
计划，对照已接受目标与当前调用方，把每项缺口转换成可独立看到结果、可回退的开发阶段。

明确拒绝：永久把 Profile 当成所有稳定配置的容器；为架构图预建十个空包；让
Model/Tool 循环成为隐藏通信或身体渠道；允许虚拟和实体身体同时激活；把 Genesis 当作
日常 Runtime；以及等完整 Brain 做完后才一次性清理全部所有权。
