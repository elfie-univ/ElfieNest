# ADR-0009：原子化零债务治理收口

- **状态：** 已接受
- **日期：** 2026-08-12
- **范围：** 仓库治理，以及已完成的架构或行为迁移

## 背景

架构棘轮已经规定如何缩减债务，也要求删除空基线和已完成的一致性台账，但没有把
“最后一个债务清零”定义为一条显式流程，同时更新注册表、架构测试、索引、链接和局部
`AGENTS.md` 指引。结果是多组已登记规则已经清零，临时治理产物却继续存在，App
Scanner 甚至仍允许已退役的 Feature 目录。

## 决策

最后一笔产品迁移与治理清理仍保持为两类独立变更。产品迁移删除最后一个生产违规和
基线条目后，必须立即进行一笔独立治理收口，并原子完成：

- 检查当前活动工作区并删除所有退役物理路径，包括不会出现在 Git diff 中的空目录、
  未跟踪目录和被忽略目录；
- 用永久 Scanner 的 deny-all 模式证明债务为零；
- 运行每个待关闭契约在注册表中拥有的全部架构测试；同时关闭多个契约时必须运行完整
  `test/architecture/`，不得用人工挑选的测试子集代替；
- 删除空基线和全 closed 的中英文一致性台账；
- 删除它们在注册表、测试、索引和链接中的绑定；
- 从局部 `AGENTS.md` 删除迁移期说明和已退役缺口引用，只保留长期防回退边界；
- 同步更新双语契约和聚焦测试，并在删除临时产物后复跑同一组 Scanner 与架构测试。

注册表只有在至少一条一致性记录尚未 closed 时才能引用该台账，只有在精确基线仍含
至少一个债务条目时才能引用该基线；机器测试执行这两个条件，并保证 CI 的全量测试任务
覆盖完整架构套件，不能把人工选择的局部测试当作收口证据。已退役 App 目录不再被永久
目录 Scanner 接受。

本次收口不改变模块所有权、authority 或依赖方向，只确认 System、App、
Model/Food/Tool 债务以及 Elfie 已完成的 Ports/Adapters 切片已经清零。Elfie 2.0 后续
生命系统缺口继续保留在活动一致性台账中，本决策不得隐藏这些开放项。

## 后果

临时债务机制不能静默变成永久文档或回退 allowlist。最后一笔迁移会多出一个很小但
强制的治理后续；收口后仓库只保留一套最新质量体系：契约和局部指引描述目标，Scanner
和测试执行目标，只有真实开放债务才拥有台账或基线。

被拒绝的方案包括：把空基线当作无害占位、把全 closed 台账当作当前文档、只依赖人工
搜索，以及让测试继续要求已退役债务产物存在。
