## 1. 整体流程与最终结果

Genesis 做两件事：先准备可反复使用的生成资料，再为每次领养生成一只身份、外貌、人格和过去相互一致的精灵。

~~~text
第一阶段：准备资料，一次准备、多次领养
① 撰写基础资料
   世界设定 + 物种资料 + 外貌规则/资产
        ↓
② 整理并形成生成资料
   居民知识 + 世界空间、物种外貌、个体生成规则（人读源稿）
        ↓
③ 编译、对照、校验、发布
   config/genesis/ 下的一份版本绑定 GenesisSourcePackage

第二阶段：生成个体，每次领养执行
① 用户选择与候选生成
        ↓
② 接受候选，冻结身份、外貌与人格锚点
        ↓
③ 建立人生骨架与可行活动（LifeContext）
        ↓
④ 生成个人知识、关系、经历与自我（PersonalGenesisPlan）
        ↓
⑤ 联合校验、提交并完成入驻
   Profile + Selfhood + Memory 等最终结果
~~~

两阶段只通过**已发布资料包**衔接。第二阶段不读未发布源稿；提交后的精灵也不再依赖创建资料。

| 最终所有者 | 保存什么 |
| --- | --- |
| Profile | 稳定身份、姓名、物种、适用的性别、年龄/来源锚点及最终虚拟外貌 |
| Selfhood | 不可变身份核心，以及有界人格、价值与交互/表达倾向 |
| Memory | 本人实际掌握的知识、生活事实、认识的人、关系、亲历与来源证据 |
| Body/Brain 对应所有者 | 既有契约要求的身体/感知约束和能力起点；不凭生活技能授予工具权限 |

Genesis 不负责日常学习、实时巢状态或持续生成新经历，也不接管 Godot 的几何、移动和渲染。

## 2. 第一阶段：准备并发布生成资料

### 2.1 第一步：撰写基础资料

造物者写清三类设定：

- **世界**：区域、聚落、地点、道路、自然、社会、历史、赴地背景与未知边界。
- **物种**：身体、感知、生命周期、生活条件与能力范围。
- **外貌**：生命阶段、体型比例、脸部、毛色/标记、可用参数与资产。

资料可附地图、表格和图片；影响后续生成的事实要有出处和审阅责任。此时不写某只精灵的家庭、职业、人格或记忆。

### 2.2 第二步：整理并形成生成资料

把基础资料整理成四类**人读源稿，以 Markdown 为主**：

| 源稿 | 要讲清什么 |
| --- | --- |
| 居民知识 | 居民可知的具体事实，以及听说、亲历、未知等认识边界 |
| 世界与空间规则 | 哪里可以出生、居住、通行和生活；地图、物种分区、道路及耗时依据 |
| 物种、生命阶段与外貌规则 | 可以生成哪些身份、年龄和外貌组合，需要哪些资产 |
| 个体生成参数与约束 | 本世界的亲属年龄、学习年限、赴地条件、概率与预算；整体算法由本文定义 |

四类是内容职责，不强制拆成四个文件。世界、物种和外貌中的可知事实进入居民知识；参数与约束进入规则源稿。本文定义怎样组合这些资料生成个体，源稿不再复制完整流程。缺失条件和来源矛盾在这里解决。

| 文件 | 持有的内容 |
| --- | --- |
| 本文 | 两阶段流程、生成算法、职责、依赖顺序与验收 |
| Elfaria 生成参数与约束（`elfaria-generation-rules`） | 人读数值和适用条件；已登记规则与待编译参数分开 |
| 地理资料（`elfaria-geography-source`） | 地点、空间关系、网格与路径的人审来源 |
| 居民知识（`elfaria-resident-knowledge`） | 逐单元原文、取得条件和难度 |
| `program.yaml` 及其成员 | 源稿经校验后形成的版本绑定机器配置，第二阶段的唯一输入包 |

**居民知识：一段一个单元，需要限制时才加中括号。**

居民正文中的每个独立段落或列表项都是一个完整知识单元，**不论有无标签**；标题、编写说明和来源附录不算知识。正文直接写事实；不同取得条件不能整体表达时，由作者拆分，不由编译器按句子切碎。

使用现有标签：地点、路线、职业、经历、掌握难度。无标签即无附加限制；多个条件标签表示同时成立，可替代路径须另行写明。地点外观与内部、路线部分与全程要区分清楚。这里只写人读标签，机器字段在第三步转换。

本步交付源稿、附件和来源/覆盖说明：造物者资料按源章节绑定，居民知识按正文单元对应；未知或排除内容须说明理由。稳定单元锚点及 ID 对应关系由这份说明承载，规则见 6.4.5；此时不生成 YAML。

### 2.3 第三步：编译、对照、校验、发布

1. **编译**：居民知识逐项转成知识 YAML；空间、物种、外貌和个体规则转成相应配置，绑定来源与稳定 ID。
2. **对照**：检查“基础资料 → 人读源稿 → 配置”的覆盖；不得丢失、重复、改写事实或扩大知识范围。
3. **校验**：检查字段/单位/引用、未知与权限边界，并证明每个可领养物种和生命阶段都有合法人生及赴地路径。只有字段、没有所需地理和规则数据，不能通过。
4. **发布**：冻结版本、成员清单与摘要，形成不可变的逻辑资料包；更新资料必须发布新版本。

包入口固定为 `config/genesis/program.yaml`，其余 YAML 和资产由清单引用。
共享生成策略的数值、预算和版本归入口规则；地理、知识、物种与外貌数据归对应成员。
算法语义由本文说明并由 Genesis 实现，配置不存可执行代码、提示词或某个人的家庭/人生结果。
不隐式扫描源 Markdown；来源路径用于溯源，运行只消费包内已编译数据。目录与发布规格见 6.4。

## 3. 第二阶段：生成具体精灵

### 3.1 第一步：用户选择与候选生成

依据已发布资料和用户偏好，每批目标生成 5 位彼此可区分、后续人生确实可行的候选；随后邀请其中 1～3 位，不把邀请人数当作候选总数。

**先解析选择，再生成实际个体。**

物种、生命阶段、性别、外貌方向/优先项和已注册扩展选项先校验；“不限”在这里解析成实际值，未注册自由文本不能变成新规则。没有可行组合就解释原因，不偷改用户硬选择。

候选依次确定实际物种、年龄/阶段、性别、已支持外貌、人格锚点和原生名。外貌使用同一个实际年龄；差异要能在已支持参数和人格方向上体现，不能只换随机种子。有限预算内不足目标数量，就展示实际数量或返回无解。

年龄按整数本地年，必须满足 `2 ≤ a ≤ T−4`，T 为物种生命终点。未指定阶段时使用青春期偏重的阶段权重，
只在有合法年龄的阶段归一化；指定阶段时仅在其合法交集中抽取，空交集明确不可选，不擅换阶段。
四年余量只限制领养年龄，不改变亲属寿命；阶段权重见参数源稿 11.1。

五个相处问题**只用于受控推导候选人格**，不直接决定出生地、家庭资源或社会阶层；接受后下游只拿冻结锚点，不再拿原始答案。人格倾向不能绕过年龄、训练或职业资格。

**展示前证明可行，不提前编人生。**

每个候选至少存在一条合法的出生、照护与赴地路径；选择学习或职业时另证其可行性，不要求幼龄候选已经结业。展示只描述已确定的身份、外貌与人格方向，不预告尚未生成的家庭或职业。外貌能力和命名校验见 6.5.1。

### 3.2 第二步：接受候选并冻结身份、外貌、人格锚点

用户完成邀请、回信确认和命名，从愿意接受邀请的候选中确认一位；这些交互属于本步，不另增阶段。

邀请沿用现有 Adoption 的确定性匹配规则，回复为“愿意”或“再想想”；**回复状态由程序决定，模型只负责措辞**。同一邀请重试复用同一结果，已公布的回复不能被重抽改写；具体匹配与无有效回复处理见 6.5.1。确认领养不等于建立多年信任。

接受时原子检查候选有效期、摘要、资料包可用性及领养资格，并形成唯一预约，冻结：

- 候选身份、年龄、外貌、人格锚点及最终显示名；
- 精灵/预约标识、领养关系引用、幂等键和时间锚点（含规则所需的出生时期）；
- 资料包、策略、编译器及初始化映射版本、种子和私有创建工作区。

这些技术输入只放创建封套 `GenesisCompileEnvelope`。重复点击、恢复和重试只能继续这一次预约，不能换候选或重抽身份。原始问卷和邀请原文不进入人生轨迹、叙事模型或长期个人记忆。

### 3.3 第三步：建立人生骨架与可行活动

在冻结的四类输入上构造人生，先确定可行结构，再按时间落实事件。

| 输入 | 下游作用 |
| --- | --- |
| 物种 | 出生资格、生命周期、外貌、文化吸引；不固定职业 |
| 性别 | 本人/亲属/伴侣身份与称谓；不决定职业、迁居或探险倾向 |
| 实际年龄 | 家庭代际、生命状态、学习年限、累计接触与出行机会 |
| 大五人格 | Selfhood 映射及社交/探索/风险倾向；不替代技能和权限 |

**出生与住所 → 唯一家庭图与照护 → 生活/学习背景和接触机会 → 有目的的访问机会、路线与停留 → 赴地安排。**

家庭时间锚点先成立；依赖实际学习或出行的职业、接触和好友保持待实现状态。
第四步形成好友后可有限补充其家庭，再回验骨架，不能改写冻结输入或已成立事实。

**出生地怎样影响后续资料。**

从已确认的可居住网格/地点中，按用户选择的物种均匀抽取允许区域，再在该区域内均匀抽取网格；区域名单是硬约束，不按镇中心、村落或逐格人口调权。绑定公共区域/聚落及合法私人住所。使用的是 Elfaria 地理资料，不是用户现实定位。

出生地给出当地的家庭、设施、教育和劳动机会；这些条件与年龄共同决定后续选择。它不直接决定人格、职业，也不自动赋予全区域知识。抽样分布、私人地点和路程计算见 6.5.2。

**生活轨迹必须在时间与空间上成立。**

- 家庭先生成去重的关系图与生命时间，学习和工作必须有可达场所、导师及足够年限；未适龄或无资历者保持学习/无职业状态。
- 迁居有原因和连续时间线，不能同时在远处上学、工作。能力来自物种边界与实际训练，不由模型直接赋值。
- 日常可达不等于实际去过；地点区分听说、看见外观、进入、使用，路线区分部分和全程。接触事实必须有活动或行程支持。
- 赴地年龄至少 2 岁，并满足照护、本人同意和一次 3 个本地日的简单准备；不设置课程/模块体系。真实入驻、房间、当前位置和后续动作不由生成器提前虚构。

年龄采用简化口径：**在 Elfaria 生活了 5 年，就按 5 岁理解**，不按当地日长换算。到地球后每过一个地球年加一岁；本地日历用于生活/旅行时序，不另改年龄。缺少精确生日时保留未知，显示用日期须标“年龄投影”。

结果为 `LifeContext`：已确定的身份/家庭锚点、居住和照护，以及学习/职业、活动/行程、赴地的**受约束计划与事件槽位**。
计划必须区分待实现和已验证事实；槽位限制时地人、前提与结果，不能充当访问或结业证据。算法与结构见 6.5。

#### 3.3.1 第三步交付的数据结构与顺序

第三步沿五个方向构造一份逻辑骨架，继续由 `LifeContext` 承载，不复制公共世界图。
顺序固定为：出生住所 → 家庭照护 → 成长居住 → 学习工作 → 公共活动 → 旅游探索 →
赴地安排 → 骨架检查。公共事件与旅游共用固定生活区间之后的时间预算。

| 骨架字段 | 交付内容 |
| --- | --- |
| identity/origin | 冻结身份、实际年龄、时间锚点与出生住所；未知生日不得虚构 |
| family_graph | 冻结家庭算法的完整结果、人物、婚姻与出生锚点 |
| people/relationships | 共享人物身份、已成立亲属边和待落实接触边 |
| groups | 有来源的核心家庭、扩展家庭分支与成长、学习、工作、活动群组；重叠成员引用同一人物 |
| partner_sibling_families | 复用冻结婚育方法，在上层补配偶兄弟姐妹的伴侣与子女；不继续展开 |
| places/routes/place_relations | 公共地点和连接引用、私人地点及其接入关系 |
| life_segments | 连续住所、照护、学习和工作区间、参与者、年度时间占用 |
| place_links | 个人与地点的用途、时间区间、确定或待落实状态及来源 |
| activities | 具体事件实例、活动时段、地点、人物、路线、前提、依赖和允许结果 |
| knowledge_nodes | 相关知识节点、关系、取得条件与前提；不代表本人已经掌握 |
| decisions | 不适用、未选择或排除的结果与依据 |

人际、地点、熟悉地点、知识及事件网是共享身份和引用的五种视图。第三步只将住所等确定
锚点标为已成立，将接触和活动标为待落实或排除；第四步按时间检查前提、落实活动，再
确认访问、相识、资格及知识事实。熟悉度和记忆图谱必须有实际接触或公共知识来源支持。

验收第三步必须查看固定输入和种子对应的真实骨架：人物关系、地点与路线、连续生活
区间、活动状态、知识依赖及排除原因。自动校验引用、唯一性、年龄和时间冲突；样本效果
另行目视审查，不能用最终 Bundle 校验替代骨架验收。

人物姓名在整张图中从配置词库统一分配。公共活动的参与与接触人数分别抽样，允许零接触、多人接触和复用已有联系人。Group 至少包含三名不同成员；一人或两人的参与保留为活动或直接关系。群组成员不自动成为朋友。组内逐对亲属称谓尚未补全。第四步经 Bundle 将已成立的人物边和群组交给 Memory，保留父母子女、兄弟姐妹、伴侣与同伴角色及来源。

### 3.4 第四步：生成个人知识、关系、经历与自我

沿人生时间线完成：**当时知识与前提校验 → 落实事件与接触 → 更新知识/关系与好友 → 合并事实时间线
→ 筛选本人履历 → 详细故事与自我投影 → 最终知识复核**。

这里必须走到故事与知识实际形成，不能停在人物图或履历点；第三步的计划不自动变成经历。

**知识只取本人有资格掌握的整条内容。**

无条件、无难度的知识必得；有条件先检查实际生活证据，有难度再按固定概率抽取。每条知识只有“取得完整正文／未取得”，不生成删节版；同一知识只用一个稳定随机值，重试或多个事件不能反复抽奖。听说、传说和未知边界按原文保留，难度不是事实可信度。

按时间记录已知内容：事件只能使用发生前已掌握的知识；新知识在学习或事件之后才可使用。不能以事件结果满足它自己的前提，也不能把领养时知道的事倒推成童年就会。必修培训和必达知识不得概率漏掉。

若事件没有取得后续职业必需的能力，就使依赖该能力的选择失效，回到第三步有界重算；不能靠补写故事保住不成立的职业。

**人物与经历从已有生活中产生。**

人物来自家庭、邻里、学习、工作和赴地接触槽位；年龄、地点、能力和关系方向必须相容。熟悉不等于信任，知道公共人物不等于认识本人，同名也不能跨精灵合并。

人物随家庭、学习和实际接触形成，不凑人数、不强造创伤。先保证必要事件及所有实际访问、重要关系变化都有经历依据，重复日常访问可按时期合并；再挑关键履历展开故事。
培训、出发、抵达和领养按实际发生顺序形成完整 Episode。每段写清时地人、过程、结果与影响。
通常至少五段，幼体按实际生活减少，不设固定上限。住所、学习等非叙事生活事实仍须完整保留，不能替代必需事件的 Episode。

**自我与介绍分别处理。**

Selfhood 接收完整的身份核心和有界人格/价值/表达倾向，使用其所有者审阅的确定性映射；不能把故事、问卷或当前情绪塞进去，也不能反向改写已接受的人格锚点。经历与可变的人生认识归 Memory。

个人介绍只需回答：我是谁、来自哪里、过去与谁生活、一件确有的经历、为何来到这里；幼龄无适用经历时省略，不编造。程序先给规范摘要，模型可润色；经验证的经历措辞随对应 Episode 保存，欢迎页短介绍只临时投影已提交事实，不另存一份传记。

本步输出 `PersonalGenesisPlan`，汇总知识、人物/关系、事件、Selfhood 与提交证据。字段、知识时序和 Memory 交接见 6.5。

### 3.5 第五步：联合校验、提交并完成入驻

**先校验完整人生，再一次对外可见。**

联合检查冻结身份、时空可行性、人物关系、知识资格/取得时间、事件因果和最终所有权。通过后形成一次性 `GenesisBundle`，分别交给 Profile、Selfhood、Memory 及已登记的其他所有者。Memory 正式入口只接收知识、关系、经历三类 Seed；地点和生活命题须先归入这三类，不能另开写库入口。

**“完成生成”不等于“完成入驻”。**

Admission 协调三项持久结果：最终个体资料、Adoption 领养关系/额度、Nest 接纳/床位。三者都确认、资料可重开后才标记 `committed`，正式欢迎并开放交互；账户额度不是 Nest 床位。

最终文件已发布但 Nest 尚未接纳，仍是“入驻处理中”。只有上述提交已完成、后续运行连接失败，才显示“已入驻、正在连接”，并从最终所有者恢复。

接受后由同一预约驱动后台可恢复任务，前端显示当前阶段；关页再回来继续同一次创建。失败区分可重试和终止，不能以“重试”为名另造一只。成功或终止后清除问卷、封套、人生计划、Seed 和源包绑定，只保留正式事实/证据与最小技术回执。发布、取消和崩溃窗口见 6.7。

## 4. 共同边界

### 4.1 版本与确定性

同一预约固定输入、身份/时间锚点、包、策略、编译器、所有者映射版本和种子，得到相同结构化事实或相同失败。措辞不决定事实；恢复复用已暂存文本。无解只在有限预算内回溯未冻结选择，不改身份和用户硬约束，算法见 6.6。

新包只影响未来候选；旧包须保留到相关预约结束。摘要不符或所需版本不可用时停止，不自动换包。显式撤销与最终激活按 6.7 的同一提交边界判定先后：撤销先发生则不再激活并补偿，激活先发生则保留已提交精灵，不刷新、重生或删除。

### 4.2 模型只表达，不决定事实

每次只给模型一个已批准的叙事视图、允许事实及引用，不发送完整计划、种子、隐藏坐标/权重、未选知识、邀请原文或其他精灵资料。用户字符串与源正文都是数据，不是指令。

输出逐项检查实体、数字、时间、引用和禁止事实；不能证明的细节丢弃，失败用规范摘要。模型不决定身份、人生、知识、关系、参数或权限；关键词检查不能代替事实校验。

### 4.3 提交后只认最终所有者

App 展示档案可读 Profile；普通 Brain 只读 Selfhood、Memory 和当前状态，**不读 Profile、Canon 或创建资料**。记忆沿正式 Memory → RecallBundle → Reasoning 路径使用，保留来源、时间与未知边界。

删除创建工作区/旧源包后仍可恢复，正式 Memory Evidence 不随临时资料删除。正常重启检查当前合法快照，不按出生时清单重建已经学习/变化的记忆。运行时资产仍由既有 resolver 解析最终外貌，资产缺失要报错，不能重抽外貌。

没有真实感知、工具结果或动作回执，就不知道当前位置、天气、当天活动或其他精灵状态；生成故事不能补这些实时事实。

### 5.3 怎样证明完成

- **覆盖**：每个发布物种 × 允许生命阶段 × 至少三个固定种子，另测年龄端点、明确/不限选项、概率 0/1、零权重和条件反例。结构约束全通过，越权知识与重复提交为零。
- **分布与体验**：出生分布、候选差异和知识比例使用事先审阅的样本量/容差，不测后改阈值；性能、冷启动、取消、并发和每个发布中断窗口分别验收。
- **记忆闭环**：验证三类 Seed 到最终记录/Evidence，再到正式 Recall；包括同义问法、稀有知识、人物/地点引用与时间先后，不只搜原文。断源测试保留必要运行时资产，资产缺失另测明确诊断。
- **证据与隐私**：发布保留清单/摘要/双向覆盖；隔离测试保留合成输入、版本、种子、各步摘要及恢复/召回结果。真实创建结束后只保留最终事实和最小回执，不把问卷、计划或种子留在日志、备份和错误附件。
- **收口**：在对应 Conformance 按 target、inventory、references、verification、residuals 记录证据和剩余项。设计审阅通过、资料可发布、代码/运行验收完成是三种状态，不能混称“最终完成”。

### 6.4 第一阶段编译规格

#### 6.4.1 包结构

`program.yaml` 是唯一入口，其他成员只由清单显式引用，不隐式扫描目录。

~~~text
config/genesis/
├── program.yaml            # 清单、共享规则、策略、来源覆盖
├── knowledge/
│   ├── elfaria.yaml        # 居民知识逐项投影
│   └── geography.yaml      # 地理网格、地点与道路的单一机器事实源
└── species/
    ├── catalog.yaml        # 身份、状态、成员引用
    └── <saevi|tovren|myelle>/
        ├── species.yaml    # 共同身体与感知边界
        ├── generation.yaml # 生命周期、生成资格与先验
        ├── appearance.yaml # 外貌参数、组合约束、资产绑定
        └── assets/*.png    # 展示资源，至少头像和全身
~~~

| 成员 | 必需信息 |
| --- | --- |
| `program.yaml` | `document_kind / schema_version / program_id / program_version / status / sources / manifest / coverage / rules` |
| `knowledge/elfaria.yaml` | 文档/知识版本、状态、来源摘要与 `knowledge[]` |
| `knowledge/geography.yaml` | 10×10 分区、区域规则、地点、路网、抽样与通行规则及来源 |
| `species/catalog.yaml` | 文档/目录版本、技术 ID、正式显示名、状态及三个成员引用 |
| `species.yaml` | 版本、身份、身体/感知边界及资产语义引用 |
| `generation.yaml` | 版本、生命阶段、物种出生资格及必要先验 |
| `appearance.yaml` / 资产 | 版本、控制范围、组合约束、可区分展示资源与 3D 语义绑定 |

地图/道路归共享地理成员，通用人生策略归入口规则；物种成员只加物种约束，不复制地图或个人事实。Godot 几何/导航/渲染、Selfhood 模板、Memory Retention、工具权限、Nest 当前状态和运行时默认值不搬进包。

物种目录、技术物种 ID 和 Godot 包 ID 统一使用 `saevi / tovren / myelle`。英文显示名为 Saevi、Tovren、Myelle；中文显示名为赛维、托伦、米耶尔。

#### 6.4.2 知识字段与标签转换

~~~yaml
document_kind: resident_knowledge
schema_version: 2
knowledge_id: elfaria
knowledge_version: <version>
status: draft
source:
  path: <resident-knowledge-source>
  sha256: <source-digest>
knowledge:
  - id: <stable-id>
    topic: <审定的小主题>
    description: <complete resident-facing fact>
    eligibility: <optional declarative rule>
    mastery_difficulty: <optional difficulty>
~~~

每个居民正文单元映射一条记录，无标签列表与段落同样处理。`topic` 是审定的组织字段，不改变源事实；`description` 保留完整原文。允许规范化换行、列表符号和标签前缀，不改词句、事实或认识边界。不在 `description` 中添加标题或主题文字、空属性、生成默认值或部分正文。

| 人读标注 | 机器表示 |
| --- | --- |
| `[地点：镇中心]`、`[路线：镇中心—Saevi 部落中心]` | `place / route`：登记 ID 和所需接触强度、路段范围 |
| `[职业：医者]`、`[经历：赴地]` | `vocation / experience`：实际工种/熟练程度或活动完成状态；培训也归 experience |
| 多个条件 / 明确的可替代路径 | `all / any`；不得推测替代路径或合并不同正文 |
| `[掌握难度：中等]` | `mastery_difficulty`；概率表归版本化策略，不是资格或 Confidence |
| 无标签 | 省略限制字段 |

`eligibility` 只允许以上四类叶子的声明式布尔树。名称须唯一解析到登记 ID；看外观、进入、使用及部分/完整路线分别判定。空树、未知操作符、悬空 ID、歧义、循环依赖或不支持的难度均阻止发布，返回源稿修正；居民稿不维护机器条件程序。

#### 6.4.3 必需规则与数据

参数与适用条件统一见生成参数源稿（`elfaria-generation-rules`）。
既有规则与新增设计参数分开登记；只有由已发布 Program 绑定且被 Genesis 强类型输入消费的部分才生效，未编译部分不能混记为已发布覆盖。

所有规则须有稳定 ID、来源/版本、可用状态、单位及可验证引用。

| 集合 | 必需内容 |
| --- | --- |
| 世界/地图 | 区域—聚落—地点层级，地形、居住区、已知/未知范围与地图注册 |

出生区域严格按物种允许名单；中心不额外增加抽样概率。只在镇中心确认的设施不能复制到每个部族中心；缺数据时拒绝不成立的人生路径，不补造地点、师傅或联系人。

#### 6.4.4 地理事实源、派生与通行

`knowledge/geography.yaml` 唯一持有区域矩阵、地点、道路及通行规则；
`program.yaml` 只绑定成员与策略引用，不复制地图。网格矩阵、16 条路链、渡口清单和具体数值
统一在地理资料（`elfaria-geography-source`）维护，本文不再抄一份。

地理成员组织为元数据、分区矩阵、区域规则、地点、空间关系、命名路线别名、路网、抽样/通行规则、验证摘要。
`parent_id` 表示公开容器层级；“位于中心”“公开入口”等明确空间语义另存为关系边。区域规则派生地形、可居住性、出生资格和物种名单；地点、路线别名和路网派生地点引用、主路节点和渡口。
`program.yaml` 只保留 `place_registry_ref`、`route_aliases_ref` 等引用及生成策略，不重复地点或路线行。
不复制 100 份人口记录；同格多地点不合并，镇/湖等范围对象用区域或格集合表示。

路网由有序旱路链、规则允许的区内小路和水路组成；相邻不自动连路，不用像素、公里或直线距离补边。
骨干链每对连续节点计一跳，不插入未声明格；水路按声明的水域跳数与渡运条件计时。
求路流程：解析宿主格/地点 → 构造合法网络 → 校验通行方式/权限 → 最短合法耗时路径；
等价路径按稳定边 ID 决胜，返回格序列、边 ID、步行日/水行日，无解返回 unreachable 与原因。
地下与云冠城不从地表图获得进入路径，同格地点之间不另造距离。

发布验证覆盖：矩阵完整唯一、物种资格、地点/节点引用、链和渡口派生边数、全部可出生格可达性、
通行单位与例外权限。具体期望值取已审阅地理版本，并叠图人工对照；图片不反向推导路网。
地图登记版本、父图/覆盖范围、坐标单位、边界/锚点、图层/资产来源与审阅状态；
示意图明确不可测距，子图不套父图整幅边界。未知区域保留未知，不成为合法人生的补路来源。

年龄采用 3.3 的一对一口径；日历和旅行用本地单位，不能用日长重算年龄或把领养日伪装成本地生日。


地点分层必须区分公开地理容器、文化区域与抽样子区。城镇的直接分区取审定清单；城镇中心与出发设施可同属一个居住分区，不能互为父子。技术区域代码不作为额外一级公共分区，外部区域不挂到镇内；私人家乡/住所挂到实际所属地区或村落。地点至少说明稳定 ID、名称、区域/场所类型、父级、描述、范围或锚点、通行条件及来源。区域可补地貌、居住资格和物种构成；人口与抽样策略引用已有规则，未知人数、面积和轮廓保持未知。范围归属不代表去过，公开地理知识也不授予受限地点内部知识。

#### 6.4.5 来源、稳定 ID 与发布

`coverage` 复用第二步的来源/覆盖说明，保存造物者**源章节 ID → 规则/成员引用**，以及居民**知识单元 ID → 源稿锚点 → YAML 单元 → 保留/未知/排除结论**。造物者来源绑定是章节粒度，不宣称逐事实 ID 覆盖；不另建平行账本。

居民源稿用紧邻单元的不可见 HTML 注释 `<!-- unit:<stable-anchor> -->` 固定锚点，锚点不属于正文/标签，也不产生知识。编译器只消费已审阅的锚点—ID 对应表；缺失、重复或无法定位时停止，不能由行号、段落序号或全文哈希重新造 ID。排版/重排保留 ID；语义修改升级版本，拆分/合并/删除在同一覆盖说明中记录旧新关系，供后续创建使用。

源资料发布对照同时证明“造物者源章节 → 规则/成员”和“每个居民正文单元 → YAML”。居民知识逐项区分完整保留、等义整理、缺失、失真和有理由排除；原稿到 YAML 不做措辞改写。漏项、重项、孤儿项、无源章节或来源摘要不符均阻止源资料发布；生产激活另需强类型消费者与语义/可行性验收。

`manifest` 显式列出相对路径、类型、成员版本、字节摘要、来源/覆盖引用与发布状态；二进制资产绑定所属成员版本。不同成员可有不同版本，但 Schema 必须兼容。拒绝缺件、重复路径、未声明必需资产、绝对路径、`..` 越界、符号链接逃逸和运行时网络补件。

总包摘要由规范入口内容及排序后的成员摘要计算，排除自身摘要；入口不递归列为自己的成员。源稿摘要只用于审阅溯源，发布包运行所需内容必须自足。接受冻结整个包及成员摘要，不只冻结知识文件。

物种技术 ID 与正式显示名由 catalog 映射；源包发布不改变物种可领养状态。`draft` 不可领养，`published` 须资料/校验/展示资产齐备，`retired` 不再新领养但已有 Profile 的运行资产仍须可解析。

### 6.5 个体生成算法与最终交接

本节展开第二阶段的后三步。候选年龄在 3.1 确定；3.2 冻结的四类输入不得回溯。
**第三步建立家庭与生活骨架，第四步按时间落实事件、取得知识并生成故事，第五步检查最终物化结果。**
下文公式定义算法；具体概率、倍率、人数和阈值统一取自参数源稿第 11 节（`elfaria-generation-rules`）。
`elfaria-genesis.v10` 通过 `config/genesis/family.yaml` 和强类型消费者激活家庭策略；尚无 Program 绑定和强类型消费者的参数仍是目标设计，由 ELF-019 跟踪。四个生命阶段使用统一语义：`childhood` 是需要照护的幼年期，`adolescent` 是青春期，`mature` 是可以结婚、生育和参加活动的成熟期，`elder` 是需要照护且不参加福利活动的老年期；只有青春期和成熟期产生福利活动年龄年。物种成员只提供左闭右开年龄区间，生命终点不作为存活年龄抽样值。

#### 6.5.1 候选、名字与邀请

外貌使用已发布支持集和同一实际年龄，遵守[外貌设计](../../designs/elfie/embodiment/virtual-appearance-generation.md)与物种资产契约。
原生名稳定抽取，显示名由用户确认；校验长度、Unicode、控制符和保留词。名字是数据，不是身份键。

保留 Adoption 当前匹配语义：邀请 1～3 位候选，稳定评分与 0.8 门槛决定愿意名单；
全未命中时在公布前用稳定保底评分选一位，绑定策略版本。模型仅表达回复，不作情感承诺。
相同邀请复用原结果；不得改写已公布的“再想想”。仅有效 accepted 候选可预约；
过期、包撤销或无有效愿意候选时返回重新选择，不制造保底回复。邀请匹配不进入个人记忆。

#### 6.5.2 出生、生活背景与人物属性

按物种允许区域均匀抽区域，再在该区域均匀抽合法网格。若合并为一次抽样，
各格权重须等价于“区域等权 × 区内格等权”，不能改为全图网格等权。
区域、公共上级地点和私人住所保持一致；私人住所只实例化许可原型，不新增公共村落或道路。
没有合法照护/人生/赴地组合则有限回溯，不吸附到最近地点。

人物骨架包含稳定 ID、姓名/称呼、物种、性别、出生时间、生命状态与适用死亡时间、住所、
亲属关系、相识时间和接触依据。关键人物补稳定性格、习惯/目标；普通人物简述。
精确生成事实与本人所知分开，不熟的人可只知道年龄段或称呼，未知字段留空。

生活背景给出居住、照护、学习、劳动与接触机会；职业必须有真实师傅、足够学习年限和能力证据。
不套性别分工，不按物种指定职业。四类输入的作用见 3.3，参数单位见源稿。

#### 6.5.3 家庭图、生育与生命状态

**结婚抽样。** 先抽取一次终身未婚结果（配置概率为10%）。其余人只在物种的 `mature` 阶段抽一个整数结婚年龄，区间内按 `exp(-0.5*((年龄-峰值)/标准差)^2)` 归一化；当前统一策略把峰值放在成熟阶段前四分之一，避免把峰值错误放在成熟期中点。家庭配置提供归一化峰值和标准差占阶段宽度的比例，因此不同物种只提供自己的阶段边界，算法不再复制物种专属婚龄参数。抽完才与当前年龄比较；抽到未来年龄表示现在未婚，不能作为已发生事件保存。只改变当前年龄不能重抽结婚年龄。已知子女的父母跳过未婚抽签，在满足锚定出生约束的婚龄中按同一曲线条件抽样。

**伴侣年龄策略。** 双方结婚时都须处于物种 `mature` 阶段，伴侣减本人年龄使用家庭配置的 `[-2, -1, 0, +1, +2]` 年龄差和 `[1, 2, 4, 2, 1]` 相对权重。先过滤寿命边界和已有子女出生约束，再将伴侣婚龄曲线权重乘以配置的年龄差权重后归一化。伴侣受约束后的总体分布不要求与本人原始婚龄曲线完全相同。双方共享一个结婚时间，策略不因性别而改变；只考虑一次结婚，不增加离婚或再婚。

**从已知孩子反向生成父母。** 这一步只生成父亲、母亲和父母结婚年份，不抽父母的子女总数，也不生成兄弟姐妹。给定孩子出生年份 `C`，先按婚后出生间隔分布抽 `t`，再计算 `formed_year=C−t`。然后按结婚年龄曲线抽父亲结婚时年龄，并限制 `a_father+t` 与物种生命边界合法，最后反推 `birth_year=formed_year−a_father`。母亲复用固定结婚年份的伴侣抽样器，使用伴侣年龄差曲线，并要求她在 `C` 年同样处于合法生育年龄。已知父母关系跳过终身未婚抽签。只有父母对固定后，才调用共享子女算法生成兄弟姐妹。

**唯一家庭网，按需显示为家庭树。** 每对父母共用一份子女集合，兄弟姐妹从该集合派生；
不分别从父亲、母亲、手足入口重抽。核心圈为本人、双亲、手足、伴侣、子女。
按下表有限展开，不对每个新人物递归补核心圈。

| 相对本人的人物 | 展开与截止 |
| --- | --- |
| 本人 | 必有双亲身份；手足由父母子女集合派生，伴侣/子女按年龄与抽样生成；在世、认识、同住分别判断 |
| 双亲 | 复用子女，可补祖父母/外祖父母；双亲当前已老年时默认不再向上，实际照护/接触所需祖辈例外 |
| 已展开的祖辈 | 补齐该对祖辈子女，先包含已有父亲/母亲，得到叔伯姑舅姨；不补曾祖辈 |
| 本人伴侣 | 复用共同子女；父母/手足仅在实际接触需要时补具体人物 |
| 本人手足 | 补适龄伴侣和子女，到侄甥止；不补手足伴侣家族 |
| 本人子女 | 补适龄伴侣和子女，到孙辈止；不补子女伴侣家族 |
| 叔伯姑舅姨 | 仅对有限的实际往来家庭补伴侣/子女；堂表亲不再展开，其余保留本人已知摘要 |
| 重点好友 | 仅补适龄伴侣/子女；父母/手足默认已知摘要，不继续展开 |

祖辈未实例化时，不为凑堂表亲补整族；确有重要共同成长关系时只补最短亲属连接，
仍限于祖辈/孙辈边界。好友母亲确曾照护本人，可以照护者身份加入，不触发全家展开。
摘要与具体人物复用同一家庭事实：排行、子女总数和身份不能重新抽样；未知不写成没有或已故。
生成家族全集不等于本人认识全部人，认知分别为实际认识、仅听说、未知。

**每对伴侣先抽子女计划，再投影到当前。** 按配置的 0/1/2/3 分布抽取 `K`，概率为
10%、20%、40%、30%。`K` 是本次生成的终身子女计划数，不是当前已经显示的孩子数。
已有孩子先加入，占用 `K` 个名额和各自出生年份；剩余 `K−m` 个出生年份再无放回抽取。
结婚后第 `t` 年的权重使用家庭配置的递减抽样器（已发布值为 `w(t)=0.75^(t−1)`），候选年份使用物种的有限年份范围。
最终按出生年份排序，抽样顺序不决定排行。

出生年份抽完后，再计算当前有效生育年数。分别把父母的生育年龄上限换算成最后合法出生年份，
取父亲上限、母亲上限和当前年份的最小值。结婚当年不生育，因此
`N=max(0, effective_end−formed_year)`。死亡时间仍是硬边界。只保留 `t≤N` 的计划孩子；
未来或超过当前有效窗口的计划不落入当前家庭，所以实际孩子数可以小于 `K`，不能因为晚婚回头重抽 `K`。

1. 固定主角出生时间；根据已知孩子反向生成父母和父母结婚年份，再将主角加入双亲的共享子女集合。
2. 抽 `K`；先加入已知孩子，再抽剩余出生年份。
3. 按逐年递减权重无放回抽出生年份，再计算父母共同的 `N`。
4. 只保留 `t≤N` 的孩子；最后生成未知性别，已知性别保持不变。
5. 标记该家庭集合已完成；祖辈家庭同样先放已有父亲/母亲再补手足。

`K` 是计划数，`N` 是当前有效生育年数，实际孩子数是满足 `t≤N` 的计划年份数量。
同一家庭同一年不生成两个孩子。所有亲子边检查无环、唯一生物学父母；照护另建关系，
直系与手足不得配偶互配。

**伴侣、生命状态与迁居。**

先复用已有伴侣；未配对者从合法年龄起，按每个完整年的条件概率抽至首次配对。
同一时段最多一位伴侣，首版不扩展再婚谱系。结伴迁居要有合法住所、时间和路线，不按性别指定谁离开。

自然死亡在老年期之前的概率为零。物种配置分别保存寿命中位数与硬上限：Saevi 为15/17个本地年，Tovren、Myelle 为20/22；老年起点和成熟期结婚、生育边界保持不变。设老年起点 E、中位数 M、硬上限 T，累计死亡概率在 E..M 为 `0.5*((a-E)/(M-E))^4`，在 M..T 为 `1-0.5*((T-a)/(T-M))^2`。指数从统一家庭寿命策略读取；F(M)=0.5、F(T)=1。本切片不生成意外或疾病死亡。

先确定锚定出生/必要照护等事实所需的存活年龄 L，再按寿命分布 F 条件抽一次死亡年龄 D：
`F(D)=F(L)+u×(1−F(L))`，u∈(0,1)。L≥物种生命终点为无解。
主角固定当前在世；亲属按 D 派生在世/已故，不为后续故事重抽。
只有已发生且本人知情的死亡才写入死亡时间/享年；在世者的未来 D 只是生成期约束，不进入个人记忆。
反向构造父母要把已锚定孩子的出生纳入 L，再用死亡时间限制可选生育、结伴和同行。

幼年期内各段经历均须有实际照护者；缺口先由已有家人承担，不能成立则有限回溯。
远居、失联、死亡分别表示；未知死因不编造。姓名与性格填充不改变时间事实。

#### 6.5.4 接触人物、好友与重要性

熟人来自共同生活、学习、工作和活动。同一人可有多个角色；
成长伙伴和邻里按实际共同生活产生，师傅/同门要求实际学习，旅伴要求实际行程。
没有年龄与时间条件时不凑数。补好友家庭只补必要关系与接触，不启动新一轮全量人生生成。

好友概率采用累计接触模型：

`H=Σ[β×实际接触年数×频率倍率×兴趣/目的匹配倍率×外向倍率]`

`Pfriend=1−exp(−H)`

频率、匹配度和 Big Five 均使用 0～1；E/O/N 分别为外向性、开放性、神经质。
各时期接触量累加，近期频率降低不使历史机会倒退。相识时固定随机值 u，
累计概率首次超过 u 的时刻才成为好友；不在每年重复抽累计概率，不倒填好友时间。
在形成的好友中按当时重要性选最多两位重点人物，平分用稳定 ID 决胜；无合格者不补。

初始重要性 `I0=R×exp[−λ(d−1)]`。d 为业务关系层级：核心亲属与直接熟人是 1，
由其引出的下一层关系为 2；直接熟人使用较低 R，多条路径取最大有效初值。
角色映射固定为：父母/伴侣/子女使用核心基准，手足使用手足基准，成长伙伴与师傅使用各自基准；
其余实际认识的同门、同事、旅伴、交换伙伴、非亲属照护者使用普通直接熟人基准。
祖辈从父母、侄甥从手足、孙辈从子女向外逐层衰减，旁支伴侣/子女从该分支入口衰减；
好友亲属从好友基准衰减。仅听说者不参与共同活动，未知者不形成初始关系记忆；多角色取最大有效值。
好友晋升只提高一次基准。共同事件更新 `I_next=1−(1−I_prev)×exp(−w)`；
日常接触按年/阶段汇总，同一事实只更新一次，文本拆篇不加分，情感正负与重要性分开。

可选活动参与率由可行性、目的匹配、事件前重要性共同决定（参数见源稿）。
先有活动机会，再选参与者、记录共同事件并更新重要性；别人的婚育/死亡由其生命史决定，
不由主角的重要性创造。补入好友家庭后只复核事实兼容性，不回填早期好友关系。

熟人使用随年龄和外向度变化的软预算，优先限制可选旁支；不填满配额，不删除必要核心家人。
核心事实超额时显式保留；生成骨架人数、实际认识人数与仅听说人数分开统计。

#### 6.5.5 公共地理与个人地点认知

地理图区分包含、相邻、实际通路、可观测关系。从它形成居民公共视图：
公开名称、层级与公开空间关系，不含隐藏地点、私人坐标、内部通道或受限细节。
全员取得合资格公共基线，至少听说其存在；地方外观、详细路线与传统仍按各知识条件取得。

私人住所、出生地及实际抵达后的精灵巢挂接公共网络，地球与新家知识按培训/抵达时序取得。
地点分开记录听说、路过、看见、进入、使用证据，以及次数、停留、最近接触和经历引用。
熟悉权重可随接触提高，但不改变接触类别；听说多次不等于亲自进入。

地理配置、居民目录与个人记忆共用地点身份。Genesis 把已发布的全部公开地点节点和已审定的全部地点关系写入初始 Memory 图谱，
包括 `located_in` 宿主关系和登记的空间谓词。每个 PlaceSeed 带有该精灵自己的熟悉度重要性：公开基线保留但低显著度，
居住地、必经赴地设施和实际接触地点提高本地值；每个已实现的 Episode 还会为实际地点写入带证据的 `visits` 边，Episode 继续保存措辞、时间和路线语境。行程使用的路线 ID 保存在 Episode 元数据中，
路线几何和代价仍由地理配置负责。Genesis 不另建手写的个人地图，也不把完整生成地图泄漏给居民；初始验收必须检查地点节点、关系、访问证据和路线引用，
不能只凭原文声称图谱完整。

公共基线由居民知识单元 A-01、A-01-02、B-01、B-02、B-03、B-05、B-05-02、B-05-03、B-06、B-06-16
中的公开命题构成，保留各单元全文与未知边界。期望网络包含：母星/地球与有限联系、迷雾镇与外部未知区域，
四类居住区域、三个部落中心与镇中心，广场/古树/长老院/学疗院/百业街、赴地基站、地下入口/地下城，
祖树、回澜丘/河湾、澄心湖/湖心岛、天镜湖/瀑布/云冠城。只建立上述单元明确支持的包含、方位、观测与通行边界；
不复制完整路网、私人住宅、长老屋内部或未登记的深层路线。
地球新家仅在抵达后沿 E-08-02/03 增补实例事实；未知外部区域使用未知范围，不虚构城市节点。
公开节点通过已登记地点 ID 对齐；源稿未提供的必需公开命题必须先补源与发布，不能让提取器猜补。

#### 6.5.6 访问机会、行程、次数与停留

四个宏观区域为森林、平原、山地、混合居住区，镇中心是具体地点组。
混住区居民不等于镇上居民；求学可在本村，诊疗/公共事务不要求人人进镇。
先按生活背景确定目的与可选目的地，联合访问属于同次机会的组内处理。
普通中心访问从有现实前提的赶集/交换、探亲/交往、观光三类中分配机会：初始等权，
不适用项权重为零，其余归一化；全为空则该场景无机会。求学、诊疗、公共事务只由真实生活需要建立专门槽位，
不因中心存在就产生需求；专门槽位占用的行程不再重复计入普通机会。必需赴地单列。
自然景观以观光为主目的，同行探亲/交换可作附带目的；地下访问只由合资格活动触发。
同一目的地在本地中心与镇中心类别重叠时，优先使用镇上居民、镇外进镇、本地中心、其他中心的唯一适用基准。

文化吸引映射：Saevi 家庭文化对应祖树，Tovren 对应回澜丘/河湾，Myelle 对应天镜湖山地组。
这只是访问倾向；物种不自动授予信仰或知识。混住区仍使用本人的文化背景，地理距离另算；
回澜丘/河湾作为平原景观组，机会率采用参数源中的平原景观行，与湖组分别抽样。

每个地点组只抽一次是否访问：

`p=地点基准概率×距离因子×区域因子×物种因子×年龄因子×人格因子`，各因子都在 `[0,1]` 内。

若访问，再抽访问次数：

`N=0（U_visit≥p）；否则 N=ceil(K×U_count^m)`

`U_visit,U_count~Uniform(0,1)`；`K` 是配置的可行访问次数上限，`m` 是配置的次数幂指数。
幂指数使多数正次数靠近 1，少量样本延伸到 `K`。年龄因子是当前年龄中符合出行条件的年数占比，
不把年数直接乘进概率；距离因子为 `exp(−往返通行天数/τ)`。区域、物种和人格倍率先归一化到 `[0,1]`，
再与地点基准概率相乘。一次多目的行程仍只算一趟。

将抽出的访问分配到符合条件的年龄，再按路线、权限、照护和可用天数校验；只有合法行程才算实际访问，
未能成行的抽样保留为未实现，不得反复重抽直到成功。
行程记录起止时间、多目的、同行者、实际道路段、通行天数、停留与接触层级。
次数按有效行程累计，同一多目的进镇只计一次；反复日常活动可合并表示但保留次数和时期。
可选跨区旅游受时间上限约束；迁居、长期学习和赴地单列，仍检查时间冲突。

| 地点组 | 同一次机会内的处理 |
| --- | --- |
| 镇中心 | 先抽镇中心行程次数；附带公开点最多挂到其中一趟，再验活动/路程时间；进入内部地点仍须符合资格 |
| 湖组 | 先到湖边，再抽湖心岛机会，另验渡运与停留；不能跳过前置地点 |
| 天镜湖山地组 | 同一观景点实际视域内的湖、瀑布、远处云冠城可共同记录；依可见性，云冠城不进入 |
| 地下 | 入口参观与实际进入分开；具体活动窗口、培训、许可与专用路线齐备才进入 |
| 必需赴地 | 当时住处 → 赴地基站 → 培训 → 实际出发与抵达；镇中心并非必经，其他公共设施不保证全员访问 |

沿途只补真实路段上实际接触的地点，不把跨区等同于逛遍景点，也不按跨格线段补未登记中间地点。
镇上长住和求学可产生多次日常机会；游览时间取实际空闲时间，不把全部居住日当游览日。
看见外观、进入和使用分别累计；完整行程仍按 6.4.4 的唯一路网和单位校验。

#### 6.5.7 事实时间线与个人履历

家庭图先提供候选生命事件；实际接触、学习、劳动、行程与赴地按时间落实并合并。
第三步的活动槽位必须经第四步的前提/结果校验后才进入事实时间线，不能由“计划去”推导“已去过”。
新增好友家庭必须复用已知相识事实，不改本人年龄或既有行程。

对每个候选履历点依次处理：

1. 按事件身份去重，限定发生时间在本人出生至当前之间。
2. 事件时关系已成立；相识、子女出生等建立关系的事件可在边界进入；排除好友相识前婚育。
3. 有亲历、共同生活获知或明确转述渠道；转述另记获知时间。本人出生只作身份起点，不编感官回忆。
4. 本人可知的必要事实直接保留：初识、学习完成、伴侣形成、子女出生、实际访问、照护变化、赴地/抵达。
5. 重要性达到源稿阈值的人物，其符合前述条件的婚育、死亡、重要关系变化保留简要履历。
6. 其他事件按最终重要性、事件类型与目的关联度稳定抽一次，按发生时间排序并保留获知时间。

出生前或相识前的事件不进入初始个人履历；知道父母生日不等于经历其出生。
不能形成有效记忆的幼年期事件须有适用的后来获知依据，人物属性不冒充亲历。
同年事件保留因果先后；参与活动用事件前重要性，筛选回忆才用最终重要性。

#### 6.5.8 知识取得与时间回流

世界知识来自原居民目录，个人知识来自本人可知的家庭/生活事实与已验证事件；故事不是新知识事实源。
按时间执行 `known_before → 验证事件前提 → 实际事件/学习 → 新知识与关系变化`。
同一事件内学习也有先后；未取得后续职业的必要能力时，使依赖项失效并按 6.6 回溯，不能用剧情补资格。

| 条件 / 难度 | 取得规则 |
| --- | --- |
| 无条件、无难度 | 确定取得；受众不符须修上游条件，不能暗删 |
| 有条件、无难度 | 完整条件满足即取得 |
| 无条件、有难度 | 稳定概率抽取 |
| 有条件、有难度 | 条件满足后用同一稳定概率抽取 |

逐单元核对完整原文与资格：地区看实际居住；景点/路线区分路过、看见、进入、使用和实际路段；
职业看真实学习与能力；赴地/新家看培训、出发、抵达各自状态。
不凭标题、地名出现或关键词放行，不把完成学徒经历等同于掌握全部专业知识。

每条知识保存完整原文、稳定身份、来源边界、取得时间或未知时间，以及相关人物/地点/经历引用。
无标签基础知识在领养完成时全覆盖，但时间未知的知识不能支持必须证明的早期技能。
中等难度等参数见源稿；每个知识 ID 只用一个稳定随机值，多次访问、回溯或重写故事不重抽。
条件中间失败只回溯依赖项，不为获得目标知识倒造经历。

交给 Memory 时，来源归因与 Episode 的经历类型必须分开。Genesis 是来源，不是
`genesis_knowledge_episode` 这类经历类型。表示已取得知识的 `KnowledgeSeed` 使用注册的
`learning` 类型；个人 `EpisodeSeed` 则使用描述其实际经历的类型。初始化永远不是经历类型。只保留有依据的
取得/发生时间：Genesis Bundle 或提交时间不等于知识取得时间；没有时间证据时明确传递“时间未知”，不得编造出生时间或创建时间。
Memory Architecture 定义注册词汇，并继续复用已有的 `event_kind` 表示；本设计不增加重复的来源或标题字段。

Genesis Program 会在每个 `EpisodeTheme` 上声明受支持的 `event_kind`，编译时原样传到
`EpisodeSeed` 并写入 Episode。当前 Program v4 的主题使用 `outing`、`learning`、`activity` 或
`life_event`；`KnowledgeSeed` 使用 `learning`。不能用主题名、来源标签或初始化状态替代经历类型；不支持的类型必须在写入 Memory 前校验失败。

对个人 `EpisodeSeed`，有值时会把 `result` 或 `impact` 写入可选的 Episode `summary_text`；完整种子措辞仍保留在 `content_text`。`KnowledgeSeed` 在 Genesis 编译阶段从审定正文生成有界、来源内的首句概括，并在初始化时写入 `summary_text`；完整知识正文仍写入 `content_text`，不会用概括替代或截断正文。这个生成是确定性的来源投影，不是另起一个模型事实源；实时对话闭合路径是否生成模型概括仍是另一条能力。

履历与故事可使用事件当时已知的参考知识；最终再按实际事实复核资格与正文。
初始必需知识缺失时不得以等待夜间整理代替完成检查。


个人知识采用“原子事实 + 小主题组织”。先逐单元判定资格与取得时间，再将已获得正文按审定的小主题（bucket）分组；不按 A/B 等大章直接拼成长篇，也不从编号猜主题。主题成员清单与顺序由居民资料编译产物登记、Program 引用。每个成员保留稳定 ID、完整正文、来源、条件、确定性、取得时间和证据，主题标题与层级只是派生组织，不成为第二事实源。

生成时可按主题向既定 APSO 入口提交带成员边界的完整材料；Memory 仍需形成可逐事实追溯的证据，并保存主题成员关系。超出已配置篇幅上限时按完整成员拆成有序段，不能截掉正文、用摘要替代原文或重新抽资格。未知/传说/条件限定不因合并变成确定事实；不同取得时期的内容不能被倒灌到早期经历。

Recall 命中一个成员后，在预算内按同组关联度展开已获得的其他成员，去重并保留来源；整组可容纳时完整返回，超限时返回相关完整成员和未展开数量/可继续检索标识。不能宣称一次命中永远返回全部知识。Lab 默认按主题阅读，并能展开原子成员及其资格、来源和证据。创建链按主题、取得年龄、阶段和可检索状态合并为完整的 learning Episode。Program 将分组限制为 4,000 字符，并只在完整成员之间拆分；单条超过上限的原文仍完整保留。成员元数据保存来源、认识状态和精确正文区间。Recall 在预算内展开已取得的同主题分段，省略数量按分段计。长主题拆分、未获得成员隔离、时间过滤、重试去重与断源重开仍需验收。

已取得且明确掌握的居民事实可通过审定的 `graph_nodes`、`graph_assertions` 初始化实体和事件骨架。`entity_level` 区分种类（如中继树、树脂）与具体个体；后续整理只合并类型、作用域和层级一致的节点。关系在初始化时就关联到合并 Episode 中的完整成员正文区间。未知或未取得的事实不能生成这部分骨架。

Elfaria 和地球是两个独立的星球实例。抵达投影包含“地球 → 主人家 → ElfieNest”的包含关系与明确居住关系，不推断房产所有权。路线关系保留未知的物理距离，区分本地日行程成本与跨世界通行。抽象格网不是居民坐标，也不能换算公里。已知抵达时间保留时间戳；其余经历保留年龄或相对先后与有依据的时长，不编造日历日期。初始 Selfhood 保留身份和人格；个人偏好、习惯与立场需要后续经历证据。

#### 6.5.9 详细故事、Selfhood 与介绍

履历决定发生了什么，故事表达如何经历、感受及影响：

1. 所有保留履历先有简要叙述；每个实际到访和必要关系变化有经历依据，重复日常活动按时期合并。
2. 从成长/照护、关系、学习/劳动、代表性访问、赴地/抵达中选适用主题，优先覆盖阶段与关键人物。
   通常至少五段，幼体按实际减少；必要事件必须覆盖，不凑职业、创伤或故事数量。
3. 其余点按事件重要程度、相关人物重要性、目的关联度的加权分排序；各项归一化，
   无人物事件的人物项取 0。先满足覆盖，再避免篇幅只集中于同一人或地点。
4. 基于冻结的年龄、人物、地点、行动、结果和知情方式，结合大五人格与稳定人物特征表达。
   不增加改变关系、能力、职业、访问范围的事实；确需新增事件先回到事实校验。
5. 按 episode_id/fact_id 对照事实，简述与详述复用事件身份；措辞与拆篇不再次提高重要性。

模型可选，规范摘要独立可用；经验证的措辞与对应 Episode/Evidence 一同提交。
提交前对知识资格、人物生命状态与时间线再复核，未知祖辈故事、已故人物同行等不得因润色混入。

Selfhood 按所有者版本交付完整强类型状态：

| 层 | 初始化内容 |
| --- | --- |
| identity_core | ID、显示名、正式物种、来源世界/区域及固定居民角色，与 Profile 一致 |
| adaptive_self | 有界 Big Five、交互/应对/表达倾向、规范/价值、可选语言标记，经闭集映射初始化 |

不放经历全文、百科、当前关系/情绪/能量、权限、问卷、包绑定或最终提示词；
不增加运行时人格成长通道。缺字段、越界、未知映射或正式投影失败即阻止提交，
不用默认 0.5、Profile 回读或模型修复兜底。给模型的文字是 Selfhood 的派生输出。

欢迎介绍只临时组合最终档案、自我与记忆的授权投影：我是谁、来自哪里、与谁生活、
一件真实往事及为何到来；不适用内容省略。投影版本/哈希只在创建期绑定计划，
不新增长期传记，也不让普通 Brain 绕读 Profile。

#### 6.5.10 中间结构、Memory 交接与覆盖

以下是设计职责，不宣称当前类型已支持所有字段。私人 ID 由精灵 ID 与稳定槽位派生，
公共身份使用已登记 ID；领养者只沿产品真实关系引用，不合并同名或制造跨实例私交。

| 产物 | 必需内容 |
| --- | --- |
| LifeContext | 冻结身份引用；出生/住所；唯一家庭图与照护；居住区间；学习/职业计划；行程机会与赴地安排；允许事件槽位 |
| Event slot | 稳定 ID、时段/时长、地点/人物、知识与能力前提、允许结果、后续依赖；完成前不是事实 |
| PersonPlan / RelationshipPlan | 唯一人物、生命/住所/接触事实；双方 ID、方向/角色、熟悉度、Trust、Importance、变化依据 |
| EpisodePlan | ID、发生年龄/时段、时长、时地人、实际路线 ID、目的/行动/结果、感受范围、影响、关系前后值、前置/新得知识、因果引用、证据 |
| PersonalGenesisPlan | 已验证知识与生活事实、人物/关系、履历/故事、Profile 结果、完整 Selfhood、本地证据、提交映射及语义摘要 |
| GenesisBundle | ProfileDraft、SelfhoodState、三类 Memory Seed、契约要求的其他启动 Seed、InitializationManifest |

不适用项明确为空；未完成的学习/职业不写成可用能力，详情文本不复制整份 LifeContext。
三类 Seed 是提交职责分类；**知识和经历沿既定 APSO 入口，关系直接初始化并保留 APSO 依据**，
不因分类名称而新开图谱写入接口。Memory 负责自己的提取、去重和物化，Genesis 只给受证输入。

| 内容 | 正式输入职责 | 必须形成的结果 |
| --- | --- | --- |
| 选中居民知识 | KnowledgeSeed：稳定 ID、完整正文、取得阶段/类别与本地证据 | 知识事实及 Evidence；条件性、传说与未知边界保留 |
| 本人已知生活命题 | KnowledgeSeed 的个人事实投影，使用个人命名空间 | 住所、学习、自我认识等有主体/关系/客体及时间依据的事实 |
| 人物与关系 | RelationshipSeed：唯一人物、角色/方向、熟悉度、Trust、Importance、共同上下文 | 人物节点、关系与证据；APSO 备份复用同一身份，不重复计数 |
| 关键经历 | EpisodeSeed：完整摘要/采用措辞、时地人、结果、影响、因果 | ClosedEpisode 与受证命题 |
| 已知/接触地点 | 随三类输入携带稳定地点 ID、名称/别名、种类、归属、公开性与可知描述 | 地点与有依据的空间/接触关系；听说不生成到访 |

个人生活命题不能变成长篇传记；经历保留完整 Episode。PlaceSeed/SelfModelSeed 即使用于编译，
也不是第四种正式输入。若当前契约不能承载个人事实，先完成所需正式设计与实现，不能强塞旧接口。
本地 source_ref 指向提交后仍存在的 Evidence/事件；知识 ID 不是运行时回读资料包的外键。
证据不保留条件树、概率、随机数、整份源稿或本人未知家族成员。

Genesis 给出受规则约束的 Importance 与适用 Confidence；Episode 不设 Confidence，
Trust 与 Confidence 分开。Memory 拥有正式 Retention、索引、强化与衰减。
Memory 的版本化准入策略当前为 `retention_profile=genesis`、`half_life_days=3650`；
这些值由 Memory 契约决定，Genesis 不自行定义保留天数。创建输入成功提交或终止失败后必须删除；
普通 Brain 运行只读取 Selfhood、Memory 与当前 Brain 状态。
别名、检索词、地点简介、人物能力和 Evidence 只能来自已选内容，不夹带未取得知识。

InitializationManifest 保存预期所有者、输出 ID/数量/摘要及检查结果；包、策略、种子只绑定 Envelope，
不逐 Seed 复制。正式 Memory submission 在自身事务内完成记录和 marker，App 不绕入口改库。
逐项对照“计划保留 → 实际经历/关系/地点/知识 → 可召回事实”；提取未结束、关系缺失或重复时不宣布完成。
修复仅限对应输入/物化结果，不换种子重造人生，不以虚构访问补节点；提交与恢复见 6.7。

### 6.6 确定性与有界失败

**随机与摘要**

算法固定为 `sha256-domain-v1`：对 `[算法版本, master_seed, 领域, 稳定对象/槽位ID, 领域策略版本, attempt_id, draw_counter]` 的规范 JSON 做 SHA-256。UTF-8、Unicode NFC、无额外空格、非 ASCII 直接编码；摘要按大端无符号整数解释。种子为 32 字节的小写十六进制，计数从零开始。

候选、年龄、外貌、人格、命名、出生、家庭、学习、职业、迁居/行程、人物、事件和知识 ID 各用独立领域。知识 `attempt_id=0`；回溯只重判资格，不重抽掌握概率。禁止进程随机哈希、无序遍历或共享推进的全局随机流。

离散项按稳定 ID 排序，用非负整数累计区间，总权重 `W∈[1,2^64−1]`。摘要整数须小于 `2^256−(2^256 mod W)` 才取模 W；拒绝时只增加本次 counter，受有限抽取预算限制。固定概率用审阅后的整数分子/分母同法判定，0/1 直接处理；非法/全零权重发布时拒绝。
6.5 的指数因子、条件寿命及幂函数访问次数抽样另须绑定数值精度、概率量化和抽样算法版本，采用固定测试向量；
不得交给未固定版本的默认随机库。语义策略与确定性实现一起校验后才可激活。

语义摘要统一 NFC、对象键排序、集合按 ID 排序、时间线保序、数字声明整数精度/单位、时间声明时区/精度，拒绝 NaN/Infinity。包含冻结身份、学习/事件的业务状态和发生时间；仅排除摘要自身、创建任务的非语义状态/技术完成时间、耗时、机器路径、日志及模型措辞。经历发生时间与数据库写入时间分开。源字节、语义内容、模型投影和最终文件摘要分别命名；模型投影绑定不可变 Plan，不能反过来影响 ID 或事实。

**回溯与错误**

回溯顺序：本槽位其他合法选项 → 直接上游未冻结选择 → 更上游生活骨架。修改后只作废依赖它的行程、人物、知识、事件和自我投影；`attempt_id` 稳定递增，预算固定。身份、年龄、外貌、人格锚点和用户硬选择不可回溯，也不能临时扩大预算或换种子。

| 错误 | 处理 |
| --- | --- |
| 输入/候选无效 | 接受前返回可修正原因，不建预约 |
| 包、版本、引用或必修内容错误 | 定位成员/规则并停止；不替换为别的包 |
| 约束无解 | 有界回溯后返回矛盾条件、规则 ID 和阶段，不套默认人生 |
| 模型投影无效 | 丢弃文本，用规范摘要，不重抽事实 |
| 存储/进程暂时失败 | 保持预约身份，核对已完成结果后继续 |
| 所有者校验/输出冲突 | 阻止可见，核验后决定恢复或终止 |
| 完整入驻后的连接失败 | 保持 committed，从最终所有者恢复 |

用户看到阶段、可重试性与可操作原因；日志只记脱敏错误码/规则 ID，不把技术故障写成人生经历。所需原编译器/映射版本不可取得时明确阻塞，不静默使用新版本。

### 6.7 入驻发布、恢复与清理

**发布顺序**

~~~text
reserved → compiling → staged → publishing → committed
~~~

1. **预留**：Adoption 原子预留成员额度，Nest 经自己的边界预留可用床位/接纳容量，均绑定同一预约；任一失败则撤销另一预留。Admission 不把两类额度合成自己的事实。
2. **暂存**：在私有工作区生成所有者资料。Memory 的正式 submission 将预期记录和 completion marker 在一个事务中提交；这里的提交不代表产品已经入驻。
3. **核验**：重开各所有者，校验引用、时序、知识、Selfhood 可投影性及清单/摘要；创建输入与最终文件分离。
4. **发布协调**：先将合法最终文件树在同一文件系统原子发布，再由 Adoption 幂等落定领养关系/额度、由 Nest 经 nest_session 幂等落定居民接纳/床位与持久状态；每项确认都绑定同一精灵/预约和执行身份。文件存在或单项落定不代表整体激活。
5. **最终激活**：三类持久结果全部核实，且资料包未先被撤销，Admission 才原子写入 `committed`；这是唯一产品可见点，随后才能欢迎、装配和启动 Runtime。
6. **清理**：成功或确定终止后清除创建输入/中间产物；失败待恢复时只在受限私有工作区保留必要资料。

这是跨所有者的有界协调，不是假定多个数据库能做一个事务。调用不确定时查询相应所有者的实际完成结果，不凭超时推断失败。Nest 接纳事实由 Nest 产生，Adoption 所有权由 Adoption 产生，App 仅协调确认和必要补偿；技术确认不成为第二份业务账。

预留与执行中状态保存在独立预约记录，不用最终业务表的 `pending/draft` 冒充完成；最终表只写本所有者已经落定的事实。App 统一按 `committed` 控制名单、归属授权、正式居民计数、Nest 快照装配/恢复、欢迎、Recall 入口和 Runtime；未激活结果只供协调器核验或补偿，读不到完成状态就不开放。容量核算仍计入有效预留，不把它算成正式居民。Nest/Elfie 不反向读取 Admission，App 通过既有边界提供已激活对象；禁止扫描最终目录或直接读局部完成记录绕过检查。

资料包撤销登记与 `committed` 判定须经过同一可串行化提交边界，按包可用性修订和预约执行令牌确定先后，不能先检查可用、再无条件提交。撤销先发生则保持不可见并补偿已落定项；激活先发生则只完成恢复/清理，不追溯撤销精灵。包可用性仍归配置发布所有者，判定所需包绑定只保留到预约终态；不把包依赖带入正常运行。

入驻成功命题在暂存时仅为待发布事实，与 Admission committed 同时对外生效；失败不能留下一段可召回的“已经入驻”。房间感知、身体位置和动作须等真实运行事实，床位分配不等于已经走到床边。

**并发、取消与恢复**

每次推进使用预约状态原子比较及递增执行令牌；所有发布写入校验令牌，失去令牌的旧执行者不得继续。锁过期只允许恢复同一操作。额度/床位预留、消费和释放分别幂等；处理中同一键配不同输入摘要拒绝，已 committed 的键只返回原结果。

| 中断窗口 | 恢复方式 |
| --- | --- |
| 编译未完成 | 使用同一 Envelope/Seed 和原版本继续，不换身份 |
| Memory 已暂存、其他资料未齐 | 核对 marker/清单，补完同一 Bundle 或清理确认无效的私有暂存 |
| 最终文件已发布，关系或 Nest 接纳未完成 | 保持 publishing，核对文件及各所有者回执，补完缺项；不能称为单纯连接失败 |
| 三项已落定，Admission 尚未 committed | 核验身份、Schema、完整性后重新通过撤销/激活判定；未撤销才记 committed，否则补偿，不凭局部回执直接激活 |
| committed 后 Runtime 失败 | 只从最终所有者重开，不需要 Envelope 或重新占用床位/额度 |
| 提交成功但清理中断 | 保留最小待清理状态，幂等清理，不回滚合法精灵 |

发布栅栏前取消，停止执行并清理私有结果、释放预留；栅栏后先核实是否已提交。确定未提交且要终止时，由各所有者补偿已完成的关系/额度/接纳，再清理或隔离未完成资料；补偿未确认前保持恢复状态，不能宣称已取消。已 committed 的移除另属产品操作，不能借取消 Genesis 删除。

重试耗尽区分可恢复暂停和确定终止；只有后者清理输入。候选有效期只约束接受前输入，不因恢复耗时推翻已接受预约或已完成发布。最终路径存在但完整性不明时隔离核验，不直接删除、覆盖或再造一只。同文件系统原子发布不可用时提前报环境错误，不降级成暴露逐文件复制。

**完整性与最小回执**

Memory marker 只证明自己的 submission 原子完成，不证明整个入驻；Admission committed 才控制整体产品可见性。两者用预约/输出标识交叉核验，marker 不可召回。

语义摘要只覆盖声明的业务输出与必要资产引用，排除回执/marker 自身；文件校验单独进行，不用数据库字节哈希冒充语义摘要。初始清单用于未完成发布恢复，不用于要求运行后的 Memory 永远等于出生快照。

`GenesisCommitReceipt` 只保留精灵/预约 ID、单向幂等键摘要、输出 ID/摘要/Schema、编译器修订、完成状态/时间与必要清理状态。它不保存输入摘要、包绑定、Seed、问卷或可重建人生的内容；正常恢复不得读取它来重新生成精灵。
