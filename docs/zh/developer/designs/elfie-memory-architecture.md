# Elfie Memory：经历记忆、个人知识图谱与混合检索

> 状态：实施目标；当前分支已实现先保存来源的 SQLite、整理、检索和迁移路径；剩余验证与生产切换状态记录在一致性台账中。<br>
> 性质：Memory 语义与访问方式的跨版本目标设计<br>
> 范围：本文是 Memory 语义及类型化访问契约的权威；当前实现状态以代码和一致性台账为准。

## 1. 核心决定

Elfie Memory 由两种互补的记忆表示和一种访问方式组成：

1. **Episodic Memory / Episode Timeline（经历记忆 / 经历时间线）**：按时间顺序记录完整、有边界的经历。
2. **Personal Knowledge Graph（个人知识图谱）**：记录精灵从这些经历和批准知识中沉淀出的语义结构。
3. **Hybrid Graph/Text Retrieval（图谱/文本混合检索）**：联合召回图结构、文本和来源证据。

前两项是记忆的表示，第三项是使用它们的方式。

核心规则是先保存来源：

> Episode 必须保存完整的捕获内容。整理过程从这份完整内容中提取、归并知识，不能用几个抽取出来的事实替换 Episode。

```text
上游事件边界已经形成的完整事件
        ↓
完整 Episode（时间、细节和证据）
        ↓  后台 / 夜间整理
实体消歧、命题抽取、关系归一化和冲突处理
        ↓
Personal Knowledge Graph（语义骨架）
        ↓
混合检索
        ↓
相关图子图 + 支撑经历 + 来源链
```

## 2. Memory 的边界

Memory 通过现有 Brain 边界接收一个有界、已经形成的事件，或一个明确批准的种子。它不直接读取 Profile、通信历史、世界运行时状态或其他模块的数据库。若某个来源有意义，应由拥有该来源的边界提供带来源的事件或引用。

Memory 拥有：

- 完整 Episode 及其生命周期；
- 个人图谱中的节点、带限定信息的关系和命题；
- 图断言的证据与来源链；
- 用于召回这些记录的图、文本和向量索引；
- Memory 记录的整理和保留语义。

Memory 不拥有当前位置、实时身体状态、当前情绪、进行中的计划或承诺、权限和外部行动。拥有者提供的这些状态可以作为带来源的证据参与整理，但不能因为模型提到过就变成 Memory 的事实权威。

## 3. Episodic Memory / Episode Timeline

Episode 是一个有意义、有边界、已经闭合的事件或场景，不是一轮聊天，也不是几个关键词的摘要。相关回合或观察由上游事件边界先聚合，再交给 Memory。

Episode 可以表示：

- 一段对话或关系事件；
- 一次学习过程；
- 一次身体或环境经历；
- 包含文字、音频、视频或图片的感知；
- 一次有意义的情绪或社会事件。

Episode 的概念记录包括：

- 稳定 ID 和发生时间或时间范围；
- 参与者、地点、物品和场景上下文；
- 完整的原文/转写；大型媒体可以通过持久引用保存，但不能省略被捕获的学习内容或事件内容；
- 可用的媒体引用及其转写/特征；
- 精灵观察到、被告知、推断或感受到的内容及其归因；
- 来源 ID、隐私范围、细节级别、生命周期和版本。

“今天学到了牛顿第一定律”因此会生成一个学习 Episode，其中保存完整解释、学习上下文和来源。牛顿第一定律本身再被投影为知识图谱中的规范知识对象。如果某条种子知识已经批准并且必须立即可用，可以在捕获时建立初始图投影，但完整来源 Episode 仍然必不可少。

捕获和整理阶段必须保留完整内容。以后 Episode 的细节可以按照保留策略压缩、归档或遗忘；如果图谱仍依赖它，就要保留可审计的来源存根或摘要校验值。摘要或图断言不能抹掉解释其来源所需的证据链。

## 4. Personal Knowledge Graph

知识图谱是精灵自己、带来源的世界理解。它不是客观的万能数据库，也不能静默继承大模型的任意常识。

### 4.1 节点

节点是异构的语义锚点，典型类型包括：

- 精灵、人、宠物和群体；
- 星球、地点、设施和物品；
- 概念、食物、物种和文化观念；
- 物理规律、理论和其他可复用的知识对象；
- 情绪和主观体验；
- 为了图导航而投影出的事件或 Episode 引用；
- 需要自身身份的命题节点。

节点具有稳定身份、类型、规范名称、别名、描述和作用范围。节点可以通过 `part_of`、`subtype_of`、`generalizes` 等关系表达大小和层级。图谱不把每个词都拆成节点，只抽取可复用的语义单元，完整表述仍留在节点描述或来源 Episode 中。

### 4.2 关系和命题

简单事实可以用带类型的有向关系表示：

```text
地球 --has_shape--> 球体
主人 --helped--> 精灵
```

关系或 Claim 还要带上时间、上下文、视角、极性、认识状态、可信度、有效期和冲突组等限定信息。

当一个命题自身拥有条件、描述、版本或证据时，它应成为一个命题/知识节点，而不是被强行压成一句边：

```text
NewtonFirstLaw --part_of--> ClassicalMechanics
NewtonFirstLaw --related_to--> Inertia
NewtonFirstLaw --has_condition--> NetForceIsZero
```

节点可以保存完整文字、公式和适用条件。简单事实和带限定的 Claim 共用同一张图，不需要为每一种特殊情况再造一套知识类型。

### 4.3 证据和多种表述

证据是图断言到来源的一级关联。它记录 Episode 或种子 ID、来源模态、文本片段或媒体指针、时间、说话者/视角、抽取方法，以及支持还是反驳该断言。

“牛顿第一定律”的多种表述应归并到同一个规范节点，再挂上别名、描述和多条证据，而不是生成七个互不相干的节点。独立证据的一致支持可以提高派生支持度；不能只按被使用次数增加真值。

如果两个来源互相矛盾，就保留带各自证据、视角和有效期的不同 Claim 或关系版本。没有某条边表示“尚未记录”，不表示“明确为假”。

### 4.4 经历、媒体和情绪

Episode 仍然是叙事细节和原始感官材料的存放处。图谱可以投影出事件节点并建立如下关系：

```text
Episode E42 --involves--> 主人
Episode E42 --felt--> 安心
主人 --helped--> 精灵       [证据：E42]
```

`安心` 节点可以连接许多历史 Episode，从而支持联想式检索。柔性的相似性更适合由文本/向量索引补充；明确的情绪、因果和社会关系放在图中。当前实时情绪没有对应的拥有者事件和来源时，不得被写成历史 Episode。

### 4.5 思维导图视图

思维导图是选定图邻域的展示方式，不是另一套事实源。它可以把“我的星球”或“我的关系网”展示成聚焦的层级结构，而底层图仍保留交叉连接、环、限定信息、冲突和证据。不需要单独持久化一套思维导图事实。

## 5. 整理流程：先 Episode，后知识图

对一个已经闭合的 Episode，整理完成以下语义工作：

1. 保存完整 Episode 和全部来源引用；
2. 从完整内容中抽取提及、事件、概念和候选命题；
3. 处理别名、共指和实体身份；
4. 归一化谓词，决定使用直接关系还是 Claim 节点；
5. 合并相容断言，保留独立证据并记录冲突；
6. 更新派生摘要和可重建的检索索引。

这是一条整理流水线，不是关键词准入。大模型可以在后台提出抽取、消歧或摘要建议；确定性代码负责 ID、作用域、约束、证据绑定、版本和最终写入。热检索不需要调用大模型。

夜间整理适合做深度批处理，但不是 Memory 唯一的更新时机。上游一旦闭合事件，Episode 就应有界地保留下来；已批准种子可以立即建立图投影，普通语义合并则可以异步进行。

知识图是持久化、带版本的投影，可以依据 Episode 和证据重新对账。它不能成为丢弃经历线的理由。

## 6. 图谱/文本混合检索

以下是检索策略，不是存储层：

- **Basic/Text Search**：查精确名称、罕见词、原话、细节故事和来源/媒体引用，使用词法、全文和可选向量索引。
- **Local/Graph Search**：从命中的实体或命题出发，沿有界的、带类型的路径扩展，返回相关人物、地点、概念、事件和支撑 Episode。
- **Global/Community Search**：回答“我的故乡是什么样”“我和主人长期关系如何”等全局主题问题，使用图上的主题/社区摘要，但摘要必须能回溯到图断言和 Episode。

不是每个问题都需要三种策略。Basic 和 Local 是最小有用组合；等图谱积累到足够材料后再加强 Global。路由器可以运行多个策略并融合结果。

上层消费的是有界的 `RecallBundle`，包括：

- 相关图节点、关系和带限定信息的 Claim；
- 支撑它们的 Episode 片段和媒体引用；
- 时间、视角、可信度和冲突状态；
- 足以审计每条重要断言的来源 ID 和证据链。

图遍历负责明确关系和多跳联想；文本和向量检索负责改写、罕见细节以及尚未完全规范化的信息。二者不能互相替代。Memory 的检索本身保持确定性、由索引驱动；生成是另一层工作。

## 7. 持久化与运行时原则

逻辑上的知识图不等于物理上必须使用专门的图数据库。可以用带节点、边、Episode 和证据索引的嵌入式关系数据库实现同一逻辑模型；专用图引擎不是前置条件。

持久化存储是事实源，内存只保存有界的工作集：

- 热点节点和邻接页；
- 最近查询的局部邻域；
- 全文/向量索引缓存；
- 少量派生摘要。

Episode、图断言和证据必须可跨重启恢复。媒体和大型原始载荷按需加载。缓存失效只能导致重新读取持久化数据，不能导致记忆丢失。

第一版应先选择简单的本地方案：嵌入式持久化数据库，加全文索引和可选向量索引，用邻接索引支持有界图遍历。只有在代表性查询和增长基准证明需要时，才评估嵌入式图存储。不能把整个终身图谱或所有媒体一次性装入内存，也不从头实现图数据库引擎。

## 8. 不可破坏的不变量

1. 每个学习内容在抽取前都完整存在于来源 Episode 中。
2. 每个持久图断言都有来源；模型输出本身不是证据。
3. 规范化只合并身份，不合并互相矛盾的视角或无关实体。
4. 冲突 Claim 必须保留来源、时间和视角并可见。
5. 图摘要和向量相似度不能在没有明确状态的情况下压过来源证据。
6. Episode 是详细的历史线；知识图是结构化语义投影。
7. 进行中的计划、承诺、权限和实时状态仍归各自拥有者。
8. Memory 不直接读取 Profile 或通信历史，也不凭空生成当前世界事实。

## 9. 第一版实施设计：SQLite

本节是现有 SQLite Adapter 的可施工目标。它固定最小物理结构和运行契约，但不把 SQL 暴露给领域层或上层。Adapter 内部可以使用 SQL、递归 CTE 或其他查询实现；调用方只能使用类型化 Memory Port。

### 9.1 持久化事实源

以下是持久化事实表。JSON 只用于有界、不可查询的元数据，不能用来隐藏图边或来源证据。

| 表 | 必须承担的职责和字段 |
| --- | --- |
| `episodes` | 一个已经闭合的经历：`episode_id`、唯一 `idempotency_key`、发生起止时间、完整 `content_text`、派生 `summary_text`、事件类型、来源/媒体引用、重要度、细节级别、生命周期、整理状态、重试/租约字段、内容哈希和时间戳。 |
| `nodes` | 规范语义锚点：`node_id`、可扩展 `node_type`、规范名称和归一化名称、派生描述、作用域、状态、置信度、有限属性、`merged_into` 和时间戳。 |
| `node_aliases` | 用于消歧和检索的别名：节点、别名、归一化别名、作用域、来源证据和置信度。允许歧义别名，不能只按文字强行映射。 |
| `node_descriptions` | 同一节点的不同有来源描述：节点、文本、语言/类型、证据引用、置信度和时间戳。规范描述从这些记录派生，不能替代它们。 |
| `episode_mentions` | Episode 到节点的提及关系：Episode、可为空的已解析节点、解析状态、角色、原文表面形式/片段和置信度。它在保留歧义提及的同时负责从图节点找到来源经历。 |
| `assertions` | 带限定的有向事实或 Claim：主语、谓词、节点对象或带类型（可选单位）的字面量对象、极性、认识状态、视角/上下文、有效时间、置信度、支持度、冲突组、指纹、生命周期和时间戳。不对裸主语/谓词/对象三元组设置唯一约束。 |
| `evidence` | 来源锚定：Episode 或批准种子引用、摘录/媒体定位、模态、片段、说话者/视角、捕获时间和整理运行信息。 |
| `assertion_evidence` | 断言与来源的多对多关联，立场为 `supports`、`contradicts` 或 `context`。 |

`episodes_fts` 和 `nodes_fts` 是可重建的词法投影，不是事实。当前 Adapter 使用带索引的候选过滤和确定性的 Unicode 词法评分；未来可以替换为 SQLite FTS5 或向量索引，而不改变 Memory Port。检索投影索引规范化原文，不能复制媒体载荷或无界元数据。大型媒体只保存持久引用并按需加载。语义节点不再由若干子表分别作为权威；`node_type` 加经过校验的属性可以覆盖人物、地点、概念、定律、情绪等类型。

这三个子表/桥接表按数据基数拆分，不是额外增加一层语义抽象：

| 数据基数 | 物理选择 |
| --- | --- |
| 一个节点 → 一个当前规范摘要 | 保留在 `nodes.description` |
| 一个节点 → 多个别名或有来源描述 | 使用 `node_aliases` / `node_descriptions` |
| 多个 Episode ↔ 多个节点 | 使用 `episode_mentions` 桥接表 |

只有不同且有意义的别名或描述才落表。归一化后重复的值直接复用已有行，未提升为语义描述的所有原文仍保留在来源 Episode 中。`episode_mentions` 只记录有语义意义的提及、角色和片段，不记录每个词；第一版每个 Episode 初始上限为 128 条，超出时明确报告，但完整来源文本仍可检索。

第一版 SQLite 采用小而固定的类型约定：ID 和归一化名称使用 `TEXT`，时间使用规范化的 UTC `TEXT`，分数使用有界 `REAL`，布尔值使用 `INTEGER`，有界元数据使用经过校验的 JSON 文本。复杂的 Assertion 对象应成为 Claim/知识节点，不能用无法检索的任意嵌套 JSON 代替图结构。

### 9.2 约束和索引

- `episodes.idempotency_key` 唯一；完整来源内容不可为空并记录哈希。重复提交同一闭合事件时返回已有回执。
- Assertion 必须且只能有一种对象形式（节点或带类型字面量）。指纹包含归一化主语、谓词、对象、限定信息、极性和视角；完全相同的指纹可幂等处理，但不能合并不同时间范围或互相冲突的视角。
- 谓词注册表由 Memory 领域代码版本化维护。注册表外的谓词必须被拒绝或保留为未解析候选，不能静默归一化成泛化边。
- 外键默认限制删除。遗忘是生命周期转换；只要图断言仍依赖来源，就保留证据或替换成可审计的摘要存根。
- 被合并的节点保留原行、别名和证据，并通过 `merged_into` 指向规范节点；身份消歧不物理删除节点。
- `node_aliases` 按归一化别名建立索引，允许同一个表面形式对应多个作用域内的节点。`node_descriptions` 按节点/语言/类型/内容哈希去重；`nodes.description` 只保存当前派生规范摘要。
- `episode_mentions` 具有稳定的提及 ID；在 `resolution_state=unresolved` 时允许 `node_id` 为空。未解析原文仍可检索，并可在后续整理中再次处理。
- 必要索引包括：Episode 生命周期/下次重试和时间；节点归一化名称/类型/状态；别名归一化值；Assertion 的主语/谓词和对象/谓词；冲突组；按节点和 Episode 的提及；按 Episode 的证据；按 Assertion 的证据关联。
- FTS 覆盖完整 Episode 文本、Episode 摘要、节点规范文本、别名和有来源描述。每个派生索引都必须声明来源和重建命令。

SQLite schema 版本记录在 `PRAGMA user_version`。多记录写入由 Adapter 所有的显式 Unit of Work 管理；调用方仍需要同一事务时，Repository 方法不能自行提交。文件数据库启用外键、WAL 和有界 busy timeout；写入串行化，读查询不能等待模型或其他外部服务。FTS 更新必须与来源行在同一事务内完成，或者在确认事务前写入可重建标记。

### 9.3 类型化 Memory Port

第一版只有以下语义操作可以跨越 Memory 边界：

- `record_episode(ClosedEpisode) -> EpisodeReceipt`：先保存来源、支持幂等的捕获；
- `recall(RecallRequest) -> RecallBundle`：有界的 Basic/Local 检索和来源链；
- `run_consolidation(ConsolidationRequest) -> ConsolidationReceipt`：后台内部入口，返回数量和失败 Episode ID，不产生外部行动；
- `get_episode(EpisodeId)`、`get_evidence(EvidenceId)`：供 Memory 所有者和诊断进行有界来源查看，不是原始表/边 API，也不能绕过普通召回上限。

保留和索引重建属于 Adapter/维护操作，不是上层图 CRUD。任何调用方都不能收到 SQL 行、表名、嵌入式边 JSON 或无界图对象。
上面列出的操作是对外的语义表面；整理过程可以在 Adapter 内部使用私有 Unit of Work，但不能因此把原始节点/边 CRUD 扩展到 Port 上。

### 9.4 写入和整理契约

1. 上游事件边界提供一个经过校验、已经闭合的 `ClosedEpisode`；Memory 不负责判断原始回合是否属于同一事件。
2. `record_episode` 在一个事务内校验并提交完整 Episode、幂等键和来源引用，然后更新可重建文本投影。它不调用模型，也不从不完整载荷写入图事实。
3. 有界 Worker 按状态、`lease_owner` 和 `lease_until` 原子领取待整理 Episode；过期租约可以被重新领取。在写事务之外读取完整来源。启用模型时，模型只返回带来源片段的候选提及、描述和 Assertion；它们是提案，不是事实。
4. 确定性校验检查片段、类型、作用域、对象形状和允许谓词。消歧使用规范/归一化名称、别名、兼容类型和作用域；只有一个明确候选时才合并，歧义情况保留未决提及或新候选，不能盲合并。
5. 一个写事务插入/更新节点、描述、提及、Assertion 和证据。相容 Assertion 通过指纹共享并增加证据；矛盾 Assertion 保留在同一冲突组中。只有事务提交后 Episode 才标记为 `consolidated`。失败只更新重试信息，不能损坏来源 Episode。
6. 整理可以连续小批量运行，并由夜间任务补漏。事务中不得等待模型、网络、设备或世界运行时。重试必须幂等；第一版不要求持久化原始模型输出。

没有模型时，捕获和 FTS 仍然可用，批准种子仍可投影；普通语义 Assertion 等待后续整理。模型失败不能退化成关键词准入，也不能把无来源提案变成事实。主人的明确纠正会作为有来源 Episode 保存；只有经过同样的限定和可审计冲突策略，才能让旧 Assertion 被替代。

### 9.5 检索契约

上层调用类型化的 `recall(RecallRequest) -> RecallBundle`。请求可以包含文本、种子节点 ID、节点类型、关系白名单、时间范围、检索模式和限制；不能包含 SQL 或 GQL。第一版使用以下安全默认值，后续只能依据评测样本调整：

| 限制 | 默认值 |
| --- | ---: |
| 词法种子命中 | 20 |
| 种子节点 | 8 |
| 图跳数 | 2 |
| 每个展开节点的邻居数 | 12 |
| 图节点 / Assertion 总数 | 40 / 80 |
| 支撑 Episode / 证据项 | 8 / 24 |
| 渲染后的 Bundle | 12,000 字符（硬上限） |

确定性流程为：

1. Basic/Text 使用 FTS 查精确名称、别名、罕见词和原文；
2. 命中的节点和 Episode 提及成为种子；
3. Local Graph 只在跳数、关系类型、方向和数量限制内扩展；
4. 为选中的 Assertion 获取来源 Episode 和证据；
5. 先按精确别名/文本命中排序，再按路径长度、证据支持/置信度、时间/重要度排序，最后用稳定 ID 打破平局；冲突状态不能被隐藏。

遍历维护 visited 集合，同一路径不会重复访问节点，并返回显式路径。因此别名歧义或互相竞争的关系可以被展示，不能静默选一个。Episode 摘录只在来源边界截断；Bundle 还具有字符/Token 预算，截断时报告 `truncated=true` 并保留来源 ID。

Global/社区检索属于后续模式，不能成为第一条垂直切片的依赖。向量可以改善改写和近义词召回，但不能替代 FTS、图边或来源证据。

`RecallBundle` 使用稳定分区，包含焦点节点、带限定的 Assertion、路径、Episode 摘录、证据、不确定性/冲突、查询限制和来源 ID。确定性渲染器使用稳定的带标签格式，以便复用提示词缓存。它不从图节点编造故事：图提供结构，Episode 提供细节，证据提供依据，推理层负责最终叙述。

逻辑上的 Bundle 形状如下（具体领域类型由代码定义）：

```text
RecallBundle {
  focus_nodes: [{id, type, label, description}],
  assertions: [{id, subject, predicate, object, qualifiers, status, evidence_ids}],
  paths: [{node_ids, assertion_ids, hop_count}],
  episodes: [{id, occurred_from, occurred_to, excerpt, detail_level}],
  evidence: [{id, source_id, span_or_locator, stance}],
  conflicts: [{assertion_ids, reason}],
  limits: {requested, returned, truncated}
}
```

这是 Memory 对上层承诺的完整载荷；它不重新定义推理系统的其他输入或决策契约。

### 9.6 保留、恢复和迁移

- 持久化存储按精灵隔离并跨进程重启保留；内存缓存有界且可以丢弃。
- Episode 细节只能依据明确的保留策略归档或压缩。只要图断言仍依赖来源，就不能让全部可审计来源消失。
- 开发迁移使用新的目标数据库和一次性导入器：先导入当前事件/经历内容为 Episode，再导入实体为节点、边为 Assertion、来源链接为证据。嵌入 JSON 中的重复边不能成为第二事实源。
- 导入校验来源数量、内容哈希、ID 映射、证据覆盖、图断言和重新打开数据库后的恢复行为。旧库在校验通过前作为备份保留；不引入长期双写或回退读取器。
- 当前边 upsert 可能已经覆盖冲突版本。导入器必须报告无法恢复的历史，不能自行编造。

#### 当前结构到目标结构的映射

- `entities` 映射到 `nodes`；`aliases_json` 拆到 `node_aliases`；`people`、`known_elfies`、`concepts` 和 `places` 的子表内容转为经过校验的 `node_type`/属性。
- `events` 中完整的行以及经历节点映射到 `episodes`。如果旧行只有摘要、没有完整来源，就作为明确标记的不完整旧项导入并报告，不能冒充完整 Episode。
- `entity_edges` 映射到 `assertions`。旧的裸三元组覆盖无法逆转，丢失版本必须报告。嵌入 `memory_edges` JSON 只用于诊断比对，随后作为重复表示忽略。
- `source_evidence_links` 在目标可以解析时映射到 `evidence` 和 `assertion_evidence`。`memory_notes` 只有存在持久来源引用时才导入，否则只进入迁移报告，不成为图事实。

切换顺序是：停止新的 Memory 写入，快照旧库，导入全新的目标文件，运行数量/哈希/证据/重开检查，切换注入的 Adapter，并在验收报告签署前保留旧快照。检查失败时继续使用旧 Adapter；导入器不得原地修改源数据库。

### 9.7 阶段门

每轮实现只有在代码和可重放证据都具备时才能关闭：

1. Episode 来源完整性、幂等和重启恢复；
2. 有来源的抽取、规范化、合并和冲突保留；
3. 罕见词、人物关系网、知识对象和时间范围经历的 Basic + Local 检索；
4. 稳定的 `RecallBundle` 组装，且没有无来源断言；
5. 代表性数据量下的延迟、有界内存、重试和保留检查；
6. 迁移数量、哈希和证据对账。

第一版的可测量门槛是：

| 门槛 | 初始目标 |
| --- | --- |
| 来源完整性 | 所有接受的 Episode 在写入、重试和重开后 100% 保留原始内容哈希 |
| 图谱有来源 | 夹具中的持久 Assertion 100% 至少关联一条可解析 Evidence；无来源断言必须被拒绝 |
| 检索 | 罕见词 Episode Recall@5 ≥ 0.90；夹具中的关系路径精确率 = 1.00；严格遵守所有上限 |
| 延迟 | 10,000 Episodes、50,000 Nodes、200,000 Assertions 夹具上，Basic + Local 纯数据库 p95 ≤ 150 ms |
| 迁移 | 可迁移来源 Episode 的内容哈希 100% 匹配；每个跳过/不可恢复项都按 ID 报告 |

自然语言的生动程度在这些结构性门槛之后评测，不能用它掩盖存储或来源链缺口。

未解决的 P0 设计问题会阻止实现。P1 只有在台账记录负责人、延期理由、替换触发条件和评测缺口后才能延期。
