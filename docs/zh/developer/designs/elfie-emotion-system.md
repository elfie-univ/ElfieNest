# Elfie 情绪系统设计

> 状态：已接受的首版设计<br>
> 规范边界：[Elfie Brain 内部架构契约](../contracts/brain)<br>
> 当前差距：[Elfie 情绪一致性台账](../conformance/elfie-emotion)

## 目的与边界

Emotion 刻画的是 **Elfie 自己的短期情绪**，不是主人或其他对象表现出来的情绪。
他人的情绪只是观察证据；只有经过“对 Elfie 的直接影响”或按关系权重计算的共情评价后，
才会改变 Elfie。Emotion 可以有界影响注意、回忆和表达，但不能创建 Goal、消息或身体动作。

首版只保存六个通道，不再维护第二套状态空间：

`happiness`、`sadness`、`anger`、`fear`、`surprise`、`disgust`。

每个通道都是 `[0, 1]` 的绝对存量，多个通道可以同时存在。因此混合情绪不需要 Episode
列表、VAD 单点或固定的单标签赢家。主情绪、次情绪、活跃情绪和趋势都只是派生投影，
不是额外保存的状态。

## 输入契约

每个已准入原因产生零个或多个稀疏 `AffectiveAppraisal`。每项评价只能选择一个由宿主
信任的 Scope，并只填写确实受影响的通道：

- `direct`：事件直接改变 Elfie 自己的处境；
- `indirect`：其他对象的状态通过宿主解析且绑定版本的关系权重影响 Elfie；
- 每个 Effect 包含 `channel`、`increase|decrease`、`1..100` 语义强度和置信度；
- 省略的通道保持不变；没有证据时宁可返回空评价，不猜测；
- 模型只返回语义强度，不能返回存量增量或最终值。

一次事件可以提升多个通道，同时直接消耗另一些通道。这是首版唯一的通道耦合方式。
首版不存在“恐惧存量自动产生愤怒”之类的隐藏存量矩阵，否则程序会制造事件评价没有
提供的新原因。

## 状态更新

语义强度由程序通过配置 Knot 校准，再乘来源、置信度和关系权重；模型不负责数值更新。
同一事件、同一方向的证据用 noisy-or 合并，避免弱信号稀释强信号：

```text
P = 1 - product(1 - positive_i)
N = 1 - product(1 - negative_i)
drive = positive_gain * P - negative_gain * N
```

正 Drive 饱和趋近上限，负 Drive 直接消耗当前存量：

```text
drive > 0: x' = 1 - (1 - x) * exp(-drive * dose)
drive < 0: x' = x * exp(drive * dose)
```

校准后相等的正负 Drive 相互抵消。重复准入的观察仍有意义：它会刷新或增强情绪，但
趋近 `1`，不会无限增长。Emotion 不再执行第二次事件去重；准入、聚合和去重只属于
Event Workspace。

没有新正负 Effect 时，每个通道按自己的参数指数回归人格基线：

```text
x(t + dt) = baseline + (x(t) - baseline) * 2^(-dt / half_life)
```

半衰期让恢复立即开始，但每次减少越来越小；持续刺激可以刷新存量，Decrease Effect
可以比自然恢复更快地消耗存量。Surprise 使用很短的半衰期，持续型情绪使用更大的值。
具体 Gain、半衰期、阈值、来源权重和强度 Knot 是版本化运行配置，不是架构常量。

## 人格影响

大五人格在硬边界内，小幅、确定性地影响各通道的基线、正向 Gain、负向 Gain 和半衰期。
基线是可见的绝对存量，也是自然回归目标；派生当前情绪时不能再把它减掉。人格只是气质
先验，不是第二个情绪事实源。

## 一个 Turn：稳定、快速、复核

每个已准入 Frame 都由 Coordinator 执行一次帧内内存事务：

1. 先推进自然恢复，捕获快速反应前的稳定 Anchor；
2. 执行确定性快速评价并提交临时候选；
3. 给模型的是 **快速反应前的稳定情绪自然语言描述**、当前事件和宿主可信候选 Scope，
   绝不能发送快速反应后的临时存量；
4. 只接受绑定已提供 Scope ID 的结构化稀疏模型评价；
5. 从同一个快速反应前 Anchor 重新计算复核候选，并原子替换临时候选。

有效的显式空评价会撤销这一 Frame 的临时快速效果；模型反馈缺失、无效或调用失败时保留
快速结果。对持续存在的同一因果身份，可以保留模型纠正并用于后续已准入观察，避免每个
Turn 都重新产生不受抑制的同一快速反应。Frame 重放复用同一事务，不重复施加快速效果。

宿主必须独立于快速关键词命中提供慢模型可选 Scope；否则快速漏检后，慢模型也无法纠正。
当前实现缺口记录在 `EMO-002`。

## 给推理和表达的投影

`EmotionSnapshot` 始终携带六个绝对值，但自然语言投影保持稀疏：

- 只有达到各自激活阈值的通道才进入候选；
- 最强活跃通道是主情绪；
- 次情绪和其他活跃通道只有达到相对主情绪的配置比例才出现，并受最大数量限制；
- 只有变化达到配置阈值才显示趋势。

这样既不会为了凑固定数量制造噪音，又能表达绝对强度和混合情绪。Expression Mapper
可以读取完整快照供未来具身表达使用，但不拥有情绪状态。

## 生命周期、来源与模态

实时存量、持续原因纠正和 Frame 事务都只存在于进程内。睡眠和进程重启把六通道重置到
人格基线并清空临时指导。Emotion 不拥有数据库、Checkpoint 或历史变化事件账本。
快照只能保留一个很小的近期来源事件身份列表，供进程内追溯；Memory 可以另外保存已完成
经历及其历史情绪色彩。

首版评价社交文本、物理触碰、执行结果和显式内部/模型评价。感知边界继续保留类型化音频
和图像/视觉传输，但首版不实现音频/图像情绪评价，也不保留无调用的 Detector 占位代码。
未来 Detector 必须向同一评价边界输出类型化观察证据；它不能直接修改实时存量，不能把
被观察对象的情绪等同于 Elfie 的情绪，也不能在未检测到结果时伪造 `calm`。

## 验证

确定性测试覆盖六通道完整性、正负更新、饱和、自然恢复、人格边界、重复准入事件、
稳定/快速/复核替换、结构化 Scope 校验、进程重置和 Prompt 投影。语义评价效果必须使用
全新、独立盲测集做统计门禁；当前质量和 Scope 覆盖缺口继续留在一致性台账，不能用单元
测试通过代替。
