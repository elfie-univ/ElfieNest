# 外观实验——第二阶段：花纹、标记与候选差异性

**状态：** 局部区域与安全标记能力已接入正式实现；后续跨身体纹样结论已记录，但明确暂缓。

**日期：** 2026-08-17

## 为什么要记录

第一阶段已经确定了当前可接受的基础：基于原始毛发源贴图做有界的相对明暗迁移，保留深色
面部特征和浅色区域，避免叠加一层造成灰雾的宽泛遮罩。在受控对比下，产品视角估计评分为
狐狸约 8.8/10、狗约 8.4/10。

本记录把后续实验的过程、结论和上限保存下来，避免之后找不到。这里仍然只是验证，不会把
实验图直接变成生产着色器，也不修改 GLB、场景几何、BlendShape 或脸型。

## 明确否决的路线：此前的 UV 遮罩原型

之前做过前视图和侧视图的 UV 遮罩实验。经视觉复核，当前不采用这版：眼睛/鼻子保护范围
容易变大，狐狸白色区域仍有残次，侧视图尾巴和边缘结果也不稳定，没有达到产品标准。
已审核图片继续作为历史证据保留，但被否决的渲染脚本已经删除，避免它再次成为第二条换色
路径。默认运行时也不绑定这些遮罩资产。

这不代表纹理空间遮罩原理绝对不可行，只代表这批手工遮罩质量不够，不能当成成品方案。

## 实验方法

直接使用 Godot 中原始的狗、狐狸场景，在真实 Godot OpenGL/Metal 渲染器下用固定的
512×512 领养卡片镜头渲染。随后由临时实验工具在渲染图上应用第一阶段已经接受的相对换色，
再应用按物种定义的天然区域遮罩。这样不用启动服务，也不改 GLB，就能快速、可重复地验证
组合规则。

这个工具故意只是可行性验证工具，不是生产实现：

- 能证明参数组合和拒绝规则可以表达；
- 颜色区域内部仍保留原始渲染的毛束、高光和细节；
- 区域坐标绑定当前正面镜头，不能证明多角度 3D 稳定；
- 生产接入仍需为每个物种设计并审核语义区域/UV 区域数据。

固定镜头的第二阶段工具已在审核后删除，避免它继续形成第二套换色实现。下方已提交图片是
历史证据，不再是当前可重放入口。当前 V9 验收渲染使用
`godot_project/scripts/test/render_production_appearance_candidates.gd`，其色调迁移全部委托给
唯一的正式实现
`godot_project/runtime/actor/actor_appearance.gd::ActorAppearance.apply`。

## 实验结果

### 1. 已接受的基础结果

![第一阶段基础结果](../../../../public/assets/appearance-experiments/phase-2/01-accepted-baseline.png)

原始渲染以及银灰、奶油、深棕/深栗色迁移后仍然有毛发质感，作为后续实验的统一起点。

### 2. 大块天然区域花纹

![大块天然区域花纹](../../../../public/assets/appearance-experiments/phase-2/02-large-natural-patterns.png)

当前按物种验证的天然区域是：

- 狗：胸口围兜、窄额头 blaze、脚掌袜套；
- 狐狸：胸口、脸下半部/嘴套、耳内。

颜色区域内部仍能保留原始毛发细节，机制可行。狗的额头边界目前仍是固定正面镜头下的实验
遮罩，不是最终美术；正式实现必须让边界跟随真实毛流/UV，而不是屏幕空间形状。

### 3. 花纹颜色槽排列

![颜色槽排列](../../../../public/assets/appearance-experiments/phase-2/03-color-slot-permutations.png)

同一花纹布局可以交换主色和副色而不改变花纹形状。因此花纹数量不能简单算成“花纹数 ×
颜色数”：每个花纹有自己的颜色槽，组合量还要乘上槽位分配、颜色兼容性和可选强调色。
对比度过低的组合应在生成阶段过滤掉，不要展示给用户。

### 4. 局部标记

![局部标记](../../../../public/assets/appearance-experiments/phase-2/04-local-markings.png)

原型覆盖了月牙、折线、十字、星点簇、短划线和简单外星符号六类标记，并测试了额头、脸颊、
胸口位置。标记可以确定性生成，也能进入候选外观键。当前黑色符号只是控制性证明，后续还
需要做大小、边缘柔化、沿毛流融合和物种风格化。

### 5. 安全区验证

![安全区验证](../../../../public/assets/appearance-experiments/phase-2/05-safe-zone-validation.png)

额头、脸颊、胸口三个合法位置可以生成；眼睛/鼻子请求被拒绝并且不生成标记。这验证了关键
规则：生成时只从允许的语义区域中选择，禁止区域在渲染前直接拒绝，不需要生成截图后再让
大模型检查。

### 6. 五候选差异性

![五候选差异性](../../../../public/assets/appearance-experiments/phase-2/06-five-candidate-diversity.png)

每个物种都能通过毛色、区域布局、颜色槽和局部标记组合生成五个明显不同的候选。这证明了
当前领养场景的“五个不要一样”可以做到。但这不是“几千个永远不会相似”的统计保证；规模
扩大后仍需要可见外观键历史，加上感知相似度检查或更严格的颜色/布局配额。

## 阶段结论与边界

五项请求均通过技术可行性验证：

1. 大块天然区域换色；
2. 花纹颜色槽排列；
3. 局部标记；
4. 生成时安全区约束；
5. 五候选可见差异性。

当前产品安全边界是：

- 继续以第一阶段的“原始源贴图相对换色”作为视觉基础；
- 狗和狐狸共用外观协议，但每个物种拥有自己的区域定义；
- 暂不把已否决的 UV 遮罩资产或固定镜头的图像空间遮罩接入生产运行时；
- 正式实现现在只使用经过审核的13个语义区域，并对禁区、颜色槽兼容性和确定性外观键做自动
  检查；多角度渲染继续作为必须提供的视觉验收证据。

### 暂缓的跨身体纹样后续实验（2026-08-18 至 2026-08-19）

后续实验尝试让一套稀疏外星纹样连续跨过后脑、后颈、后背、上臂和大腿。实现使用预先绘制的
1:2画布、按物种裁切的后半身体 Mask、头/肩/胯分段锚点，并把结果烘焙回原始 UV。最佳背面图
已经能看出方向，但侧面的上臂和大腿仍出现拉伸、突然截断和碎线。二维身体投影无法提供参考图中
那种沿四肢局部方向自然延伸的连续性。

结论：保留文字结论与视觉方向，但删除重复实验脚本和画布，避免它们再次成为第二套生产 Shader。
正式产品不生成身体纹样参数，`ActorAppearance` 也不消费该功能。重新启用前，必须重新开展基于
三维解剖路径或等价3D到UV烘焙的实验，并通过狗和狐狸的五视角审核。该暂缓决定不重新打开已冻结
的 V9 明暗迁移和13个正式区域。
