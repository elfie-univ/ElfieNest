# Developer Tools

## 入口

统一入口是：

```bash
./developer.sh --help
```

实验页面由同一个 HTTP 服务承载；资产设计另有独立启动入口：

| 命令 | 初始页面 | 关注点 |
| --- | --- | --- |
| `./developer.sh elfie-lab` | `/elfie/experiment` | 单只精灵的档案、感知、决策和回合 |
| `./developer.sh brain-eval` | `/elfie/evaluations` | Brain 批量评测与报告 |
| `./developer.sh nest-lab` | `/nest/experiment` | 固定房间、临时角色、Godot 事件与语义移动 |
| `./developer.sh asset-design` | `/assets/design` | 独立房屋与家具资产预览；HTTP `9001` |

房屋资产设计保留已确认的资产库布局和右侧完整 3D 控制栏。源码位于
`devtools/asset_design/web/`，通过 `devtools/asset_design/assets/catalog.json` 读取已登记
的模型、测量数据和图片。新资产版本复用同一查看器，不生成专用 HTML 页面。独立入口
不启动实验状态或 Godot，也不构建实验前端。使用 `./developer.sh asset-design`
打开独立页面；原实验服务和菜单不挂载该页面。布局基准和只读边界测试位于
`test/devtools/asset_design/`。本地资产
缺失时页面显示空工作台；设计资产、索引和确认记录统一保存于
`devtools/asset_design/assets/`，需要与工具一同版本管理；`build/` 只放临时产物。

顶部一行切换三维模型、图片和参考对照，三种模式共用同一内容分类：园区总览、建筑本体、
家具布置、家具和室外环境。主楼各层与独立家具部件直接列在菜单中，小屋二层露台在右侧
选择 M01–M08 或八间合看。右边的“版本”菜单仅列当前对象的模型版本，从新到旧排列。
图片模式隐藏模型版本控件，保留内容对象与小屋编号，显示对应参考图；没有图片时保持
当前对象并显示空状态。返回三维时恢复原版本，不切换到其他对象或最新稿。
图片及对照只使用明确关联且已登记的本地图片，不从混合导出标题推断图片归属。
设计页标题区右侧的删除按钮直接移除当前保存版本或图片，并切到同组下一个可用版本。
删除版本包含部件导出。独占的模型与图片产物移到 `build/asset_design/cleanup/`，同时保存原目录
索引、标记和带文件哈希的清单用于恢复；共享文件及源文件、数据和辅助构建输入保留。
删除的编号同时从清理标记中移除，无须另行标记或弹窗。历史版本仍可从版本菜单选择。
未知编号、跨站来源和不安全路径会被拒绝；写入失败会回滚目录索引、标记与移动的文件。
园区整体也可选择模型实际包含的一楼、二楼、三楼和屋顶；切换对象保留仍然有效的楼层。
整体园区菜单优先列出整合条目，将历史建筑样板后置，并明确标注“本组最新”。已有资产
书签仍可选择；未指定版本时优先打开首个可用整合条目。
图片分为设计参考、模型截图、布局尺寸和对比资料，材质
贴图保留在资产文件中。对照使用明确关联的参考图或标明的手动选择；主楼楼层参考不会
自动匹配小屋露台。其他模型文件从资产文件区预览。主楼各层和家具部件在内容菜单选择，小屋编号在右侧选择，可用
楼层从模型标签读取，小屋可以合看。视角区位于显示勾选和尺寸辅助下方，一行提供
`− / 适配 / ＋`，下方保留方向按钮；图标按钮保留无障碍名称。
内嵌模型区与紧凑操作栏共用同一网格行，始终保持同高。查看器上报实际控件和底栏高度，
避免操作按钮溢出到底栏后面；窗口过矮时只滚动外层页面。模型信息、下载和可展开的操作
说明放在独立底栏。
桌面端查看模式按钮与靠右的分类、版本选择组成紧凑单行。版本说明默认显示一行，
可点击展开或悬停查看全文。
对象、楼层、剖视、显示开关、光照、视角、图片
与手动参考选择保存到地址中；视角按钮不改变其他选择。


对象审阅沿用一个分组内容菜单：园区总览、建筑本体、家具布置、家具套装，以及有已登记
内容时出现的室外环境。楼层、露台位置和套装部件在右侧选择，不重复列入顶部分类。
原始导出归入相应内容分类的历史版本，历史整套模型只供查看，原文件全部保留。
对象版本按选定部件的几何、材质、贴图、变换和语义标签归组；导出中重复携带的副本不会
新增对象版本。每组保留首次出现的来源和全部副本路径，标题与版本顺序属于对象本身，
不沿用整份导出的名称。已确认内容继续使用原确认文件预览。局部默认打开最新不同内容候选；确认只
采用当前对象，可以选回旧版。采用版本由最后一次确认操作决定，不取最大版本号；按钮
明确显示确认范围，参考显隐不扩大确认范围。

仅有源文件的版本也可选择并下载原文件。补充分件文件直接在同一查看器预览，文件预览不参与对象确认。
数量与大小在读取目录时按已登记、实际存在的文件路径去重统计。

参考家具或建筑使用对应对象当前采用的版本，本次查看期间固定，刷新后读取后续确认。
建筑尚无确认记录时，使用最新建筑版本并标明未确认；查看或确认家具不会连带确认建筑。
实时总图按原始 GLB 部件及原有变换组合已确认建筑、已定位家具布置和室外环境。小屋
本体和一层卧室布置各共用一个对象，确认后按源模型的八个位置与朝向复用，位置选择只改变查看。
二层八处不同的露台活动布置分别保留 M01–M08 确认范围；主楼家具各层和套装部件也分别确认。
全部楼层、全部露台只供合看，需选择具体范围后才能确认。未确认
或对象内容已改变的对象不混入总图，并提示状态；同一 GLB 中其他对象的改变不会使本对象
确认失效。参考内容变化只提示组合待检查，不把对象改成未确认；需要时沿用原确认按钮
执行参考组合检查。没有园区定位
的独立样板保留为对应分类的历史版本；确认单件家具不会自动替换已布置组合中的全部实例。
已保存效果图仍是历史图片。

确认记录和参考源哈希以原子写入方式保存在隔离资产根的 `adoptions.json`，确认
不改写目录索引或资产版本。同一对象的并发确认发生冲突时需刷新，不同对象可以分别确认。
对象内容哈希用于识别确认，整份文件哈希仍用于校验预览下载。内容分类名称后的括号显示
去重后的模型版本数，仅源文件记录单独计数；内容相同的历史模型只显示一个选项，原文件、
确认记录及原链接仍保留。当前确认组合不计入历史版本数。执行
`.venv/bin/python3 -m devtools.asset_design.reindex --report build/asset_version_audit/objects.json`
可盘点已有导出；检查后为同一命令添加 `--apply`，将核验原确认来源哈希、备份确认文件，
并为当前确认及其参考补充对象哈希。历史确认条目原样保留，不改写或删除模型。
无法识别的内容会列入待检查项，并阻止应用此次整理。
确认过的来源及固定的历史参考不能经清理接口删除。查看方案为临时数据，服务重启后需
重新打开。室外模型通过节点 `design_role: landscape`、`design_role: environment` 标签
或对应目录分类登记；不把无标签的展示背景推断成花园模型。

它们可以复用底层库和同一份 Godot Web Runtime，但不能依赖普通用户鉴权、
`ElfieNestEngine` 或生产数据才能启动。启动实验页面时会自动检查该
Runtime；只有缺失或 Godot 源码发生变化时才重新导出。

Elfie Lab 与 Nest Lab 的浏览器壳共用 `devtools/web/` 的 React + TypeScript + Vite 工程。
前端产物只生成到 `build/components/devtools-web/`，不会写回或提交到源码目录；启动命令会
按前端源码摘要自动复用或重建它。Nest Lab 的相机按钮只发送总览、活动区、宿舍、传送室和
还原视角这些受限意图，Godot 仍是相机变换的唯一事实源。

Nest Lab 在浏览器中嵌入已导出的固定房间。开发者可修改床位数、添加 Saevi/Tovren、开启
Python 定时选择语义锚点的随机游走，或暂停、继续、重置实验。Godot 负责几何、渲染、
路径与碰撞；Lab 只发送 v2 语义命令并记录 Runtime 事实。两种 Lab 都使用与正式桌面
运行相同的 Godot Web 导出物；只是各自提供隔离的网页外壳、数据根和本地协议入口。

本机端口固定分层：正式 App 为 `8000` / `8765`，三个页面入口共享 HTTP
`127.0.0.1:9001`；Nest 页面的 Godot WebSocket 是内部 `9002` 监听，不是第二个网页。
直接使用任一默认命令会安全重启当前工作区共享服务；只有显式传入端口时才保留并行实例，
且未知端口占用者不会被终止。

Elfie Lab 首次启动直接读取隔离 Runtime `nest.db` 中的粮食目录。数据库会初始化两
个系统粮食，它们在页面配置 Ollama 或 OpenAI 兼容 Provider 前显示为未配置；页面不会
注入额外的模拟粮食行。配置表单只保存选择的模型和连接，第一次真实回合才会尝试连接模型。

## 资产合并原则

家具、房间和完整建筑均按以下原则处理：

- 按独立功能、运动和显隐边界分组，不按颜色或制作细节分组。始终一起使用的静态
  部件可以合并；门、抽屉、可独立控制的灯光、建筑模块和楼层显隐边界分别保留。
- 床体、床垫、被子和每只枕头分别独立。包边、缝线和固定装饰归入所属物件。
- 不同颜色与表面质感可通过顶点颜色和 PBR 贴图图集合到一个网格中。保留颜色、
  粗糙度、金属度、法线、发光、纹理重复和边缘留白，不默认把全部表面改成同一种材质。
- 分别统计功能部件、网格对象、材质图元和三角面。仅放进同一个父组，或把多个材质
  放进一个网格，并不会自动减少绘制批次。透射或透明效果可能仍需独立绘制。
- 先优化组，再按另行确认的范围减面。保留坐标、尺寸、法线、拓扑、动画部件归属和
  查看器使用的标签。
- 保留已确认基准，生成新的本地版本。验证几何、材质贴图映射和独立部件，再在现有
  资产设计页面用相同视角与光照比较新旧效果。
- 在资产验证产物中记录实测数量、外观变化和贴图显存成本。绘制批次减少不能单独
  证明拖动交互已经加速。

## 数据根

共享交互服务默认使用 `${ELFIE_DEV_HOME:-~/.elfienest-dev}`，并分别在
`elfie_lab/`、`nest_lab/` 下写入自己的配置、会话和调试数据。它绝不以
`${ELFIE_HOME:-~/.elfienest}` 为默认值；若把生产根显式传给 Elfie Lab 的 Runtime
配置，会被拒绝。

Brain Eval 的显式产物动作会为捕获创建一次性 Runtime 状态，且只把可再生成产物写入
`build/brain-eval/<run-id>/`。它会拒绝生产 `ELFIE_HOME` 和该构建树之外的输出路径。
设计原理和批量操作分别见
[Elfie Brain 评价与进化系统](../designs/elfie/brain/elfie-brain-evaluation-system)与
[Brain 评价工作流](./brain-evaluation)。

本地验收可同时隔离两类数据：

```bash
ELFIE_HOME=/tmp/elfienest-production \
ELFIE_DEV_HOME=/tmp/elfienest-developer \
./developer.sh brain-eval
```

独立对象以 `devtools/asset_design/assets/<对象目录>/source/model.glb` 作为可编辑构建输入。
每份已发布的 `versions/vNNN/model.glb` 仅包含该对象的几何、材质、贴图、层级及所需定位和尺寸参照。
目录索引显式记录对象和版本；旧整套导出只作为归档来源保留，不再扫描生成对象版本。
全部楼层和露台合看通过对象引用组合，不另行导出混合模型。

停止资产服务后，执行 `.venv/bin/python3 -m devtools.asset_design.object_assets split`
提取并校验已有不同版本。只有内容指纹一致才将当前确认指向独立文件，保留确认历史和
版本编号；全部验证通过后才归档已确认对象的更早版本。旧独立版本使用无损 `.glb.gz` 压缩，恢复时
先校验文件哈希再解压。原文件保留原位，目录索引、确认
记录、历史清单备份及验证报告位于 `build/asset_design/backups/object-split-*/`。

修改单个对象的 `source/model.glb` 后，在资产服务停止时执行
`.venv/bin/python3 -m devtools.asset_design.object_assets publish --object building:pod`。
内容未变不生成版本；内容变化只生成该对象的新版本，需单独确认。建筑和家具范围不得
混入彼此。构建不读取旧整套导出或旧构建脚本。执行
`.venv/bin/python3 -m devtools.asset_design.object_assets restore --object building:pod --revision 31`
可恢复某个已归档的独立版本，恢复操作不改变当前确认。


资产内容菜单分别列出主楼各层和独立家具部件；小屋二层露台共用内容入口，在右侧选择
M01–M08。三维、图片和对照模式保留内容对象与小屋编号，返回三维时恢复原模型版本；
图片模式隐藏模型版本选择。目录中的 `imageReferences` 将已登记图片关联到对象 ID：
设计参考跨模型版本使用，检查截图保留来源版本。共用露台概念图不自动绑定主题与小屋编号。

## 可移植设计资产工作区

设计过程独立于 Godot 最终导出。`assets/buildings/{central,pod}/` 保存建筑，
`assets/layouts/central_floor_N/`、`pod_bedroom/`、`terraces/M01/` 保存布置，
`assets/furniture/` 保存套装与部件，`assets/landscape/site/` 保存庭院。
每个对象的 `source/model.glb` 与 `source/build.json` 是编辑输入；
`versions/vNNN/model.glb` 为版本快照，`version.json` 为该快照的登记副本，
`versions/vNNN/images/` 存模型截图，`references/` 存跨版本参考图。
加载与归属的事实源是根 `catalog.json`，确认事实源是 `adoptions.json`；不从文件名推断确认。

停止资产服务后，编辑所属对象的 source，再发布并登记图片：

```sh
.venv/bin/python3 -m devtools.asset_design.object_assets publish --object layout:central:2 --image build/new-render.png --reference build/new-reference.png
.venv/bin/python3 -m devtools.asset_design.workspace scan
./developer.sh asset-design
```

发布按内容去重、自动选择版本目录并登记图片归属；新内容仍须单独确认。
`scan` 检查索引中的文件和已确认模型，成功后生成 `build/asset_design/catalog.json` 缓存。
换机须先取得真实设计资产文件，再启动同一入口，无须旧 `build/asset_previews/`。
`workspace organize --from-root ... --root ...` 是显式一次性整理命令，目标必须不存在，
校验复制内容并保留原目录。历史整套导出、日志及旧修复过程留在本地 build 作为恢复材料，
不作为新工作区运行输入；迁入的历史脚本仅作来源资料，不是可移植生成器。
大于 Git 托管单文件上限的二进制资源需要配置 Git LFS 后才能提交和换机获取；
只有代码和指针、没有真实大文件内容，不能算恢复成功。
