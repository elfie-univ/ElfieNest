# 核心配置：模型和粮食

完成首次配置只是把 Nest 的基础设置建起来。管理员还要完成模型和粮食的核心配置，之后才适合邀请大家使用。

ElfieNest 故意把这部分能力叫作**粮食**：这是给普通用户看的友好说法，表示 Elfie 用来思考、
聊天，以及在启用时使用工具的能力。你不需要学习背后的技术细节，只要决定能力从哪里来、
准备好粮食，并保持它可用即可。

## 先把这个故事记住

- **模型服务**是能力的来源：可以在这台电脑上运行（本地 Ollama），也可以由网络上的服务提供
  （远程订阅）。
- **粮食**是从可用模型里准备好的日常选择，告诉 ElfieNest 平时用什么能力来对话和完成可选任务。
- **常用粮**是日常吃的粮，必须有一个能工作的**主要模型**。
- **保底粮**是最后的备用粮，是系统的后手，普通用户不能直接选择它。

如果没有可用的模型，或者没有启用且带有主要模型的粮食，Elfie 就没有力气正常回复。这就是为什么
要先完成本页，再开始领养和聊天。

## 谁需要做这件事？

普通成员可以跳过本页。Nest 所有者或管理员应当先完成一次；以后模型服务、模型或粮食不可用时，再回来
检查和修复。

## 管理员准备清单

### 1. 先决定能力从哪里来

| 选择 | 适合什么时候 | 需要注意 |
| --- | --- | --- |
| **本地 Ollama** | 希望数据尽量留在本机，或不想过度依赖网络 | 电脑要有足够的磁盘和内存；需要下载模型；本地服务必须保持运行 |
| **远程订阅** | 不想在本机保存模型，希望直接使用在线服务 | 需要联网；可能受服务商规则、账户额度或费用影响；对话内容会发送给该服务商 |

两种方式可以同时保留，互相作为备用。首次配置里的本地选项不是必选的；即使关闭它，管理员之后仍可添加远程连接。

### 2. 添加并检查模型服务

打开“**管理台 → 模型订阅**”。

- 远程服务：选择受支持的服务商，填写连接或授权信息，然后保存。
- 本地服务：打开 **Ollama** 卡片；需要时先安装或启动，再在“**模型**”里下载推荐模型。
- 打开该连接的“**模型**”列表，确认至少有一个模型可用。添加或修改连接后，点击“**验证**”（或“**批量验证**”）。

只有可用、近期验证通过的模型，才能拿来准备粮食。连接虽然保存了但还没有验证，也不能算作可以日常使用。

### 3. 为 Elfie 配置粮食

打开“**管理台 → 粮食策略**”。

1. 先检查**保底粮**。它是最后的备用；本地安装可能会自动准备一份，但仍要确认它已经配置并启用。
2. 再检查日常使用的**常用粮**。为它配置能工作的**主要模型**，然后启用并保存。推理、视觉、工具和备用能力
   是可选项，按 Nest 的需要再添加。
3. 只有需要不同的速度、质量或能力组合时，才添加自定义粮食。粮食可以对所有人可见，也可以只对指定用户可见。
   使用“**生成预览**”时，先看清候选变化，再保存。

编辑时页面可能会显示模型的技术名称，那是给管理员看的；普通成员只需要认识粮食名称。没有主要模型、被停用，
或它依赖的服务不可用的粮食，都不能给 Elfie 提供能量。

### 4. 检查核心配置是否完成

回到“**管理台 → 状态监控**”，点击刷新。一个可以开始使用的状态通常是：

- “**系统健康**”显示正常；
- “**模型服务**”显示服务运行/验证正常，并且至少有一个可用模型；
- “**粮食策略**”里有已启用的常用粮，也有已经配置好的保底粮。

有了 Elfie 之后，再打开 TA 的档案检查“**主粮**”。所有者可以从管理员允许且健康的粮食中选择一份。如果档案提示“当前没有可用主粮”，
就回到粮食策略修复，或联系管理员。

## 核心配置完成以后

所有者现在可以[领养 Elfie](./adoption)、创建成员账号，并邀请大家[开始聊天](./run)。如果之后聊天没有回复，先看[故障排查](./troubleshooting)：
先检查模型服务，再检查粮食，最后检查 Elfie 的主粮。
