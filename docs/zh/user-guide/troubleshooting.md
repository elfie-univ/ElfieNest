# 故障排查

先按你看到的现象查找对应小节。不要把删除 Nest 数据目录当成第一步。

## 安装程序打不开

确认安装包与你的电脑匹配，并且来自[官方 Releases 页面](https://github.com/elfie-univ/ElfieNest/releases)。
正式 macOS Workflow 安装包必须先通过签名和公证才允许发布；如果仍提示“身份不明的
开发者”，请停止操作。Windows 预览包仍可能显示发布者警告。提示指向未知文件或未知
发布者时，请询问提供安装包的人。

## 应用一直停在“正在启动”

第一次打开时先多等一会儿，然后只关闭并重新打开一次。检查托盘里是否已经有另一个 ElfieNest 在运行。如果仍然无法启动，请保存错误页面截图，
交给 Nest 管理员。

## 应用提示数据目录来自旧版本

应用会先打开数据恢复页面，不会启动 Core 或 Godot。点击“**备份旧数据并创建新环境**”后，应用会把完整旧目录保留在页面显示的备份位置，并在原路径创建新的正式环境。旧账号、Elfie 和历史数据不会自动迁移。确认不再需要前，不要删除旧备份。

## 首次配置失败

回到锁定的设置页，点击“**从失败阶段重试**”。向导会保留已经完成的选择。如果是本地模型阶段失败，可以先关闭本地离线保障，再让管理员按[核心配置](./ready)
改用其他模型来源。

## 无法登录

确认登录账号和密码与创建时完全一致。管理员可以进入“**管理台 → 用户管理**”重置成员密码。不要把密码放进截图或聊天里。

## 消息发出去了，但没有回复

这通常表示当前没有能工作的粮食。如果你是普通成员，请让管理员按下面的顺序检查：

1. 打开“**管理台 → 状态监控**”并刷新。如果显示“**尚未配置模型服务**”或“**0 个可用模型**”，继续检查模型订阅。
2. 在“**模型订阅**”里确认远程连接已经验证通过；如果使用本地 Ollama，确认服务正在运行并且已经安装模型。远程服务还要检查网络、授权和服务商账户额度。
3. 在“**粮食策略**”里确认已启用的**常用粮**带有健康的主要模型。如果粮食显示未配置、停用、降级或不可用，先修复连接、重新验证，或换一份粮食。
4. 打开 Elfie 的档案检查当前主粮。所有者可以换成另一份对自己可见且健康的粮食。如果页面提示“当前没有可用主粮”，管理员必须准备或启用粮食。

服务恢复期间不要反复发送同一条消息。已经发出的消息可能会保留在聊天记录里，只是回复会延迟。

## 模型连接验证失败

检查服务商、连接地址和授权信息，然后保存并再次点击“**验证**”。远程服务要检查网络和服务商账户；本地 Ollama 要先启动或重启，并确认已经安装模型。
连接可以在修复期间保留，但只有验证成功后，才能拿来准备日常粮食。

## 粮食显示不可用或降级

打开“**粮食策略**”查看状态。可能是服务商离线、模型被停用，或某个可选能力暂时不可用。管理员可以修复模型连接、换一个可用模型，或保存另一份健康的常用粮。
保底粮只是最后备用；如果它从未配置好，或没有可工作的模型，也无法解决问题。

## 本地 Ollama 已停止或不存在

进入“**管理台 → 模型订阅**”，打开 Ollama 卡片，按页面显示选择“**安装**”“**启动**”或“**重启**”，再进入“**模型**”下载推荐模型。
如果安装或下载仍然失败，先检查磁盘空间，也可以让管理员改用远程模型来源。

## 3D 档案或房间打不开

3D 视图和聊天是分开加载的。点击“**重试 3D**”；如果仍然不可用，可以继续阅读文字档案和使用聊天。有些手机设备不能运行 3D，但不影响聊天。

## 手机二维码无法打开

让手机和电脑连接同一个局域网，重新生成二维码，并确认手机可以访问二维码显示的地址。如果对话框提示“当前服务只允许本机访问”，请让管理员开启局域网访问。
不要把二维码转发到 Nest 之外。

## 关闭窗口后应用还在运行

这是桌面应用的正常行为：关闭窗口会把应用隐藏到托盘。想停止本地服务，请在应用菜单或托盘菜单选择“**退出 ElfieNest**”。

## 需要求助时应提供什么

提供页面上显示的错误文字、应用版本和出现问题的步骤。截图很有帮助，但不要包含密码、API 密钥、一次性授权码，也不要把整个本地数据目录发出去。
