## 1. 生成目标与整体流程

Genesis 生成的是一只**外在、内在与过去均已成立**的 Elfie，不只是记忆或人格。最终并列产物如下：

| 方面 | 创建时必须确定 | 最终所有者 |
| --- | --- | --- |
| 对外身份与外貌 | 稳定 ID、正式物种、最终名字、适用的性别与年龄锚点、来源锚点、可重现的虚拟外貌 | Profile |
| 内在自我 | 已冻结人格锚点、价值/表达和初始自我认识；物种先验不能替代个体人格 | Brain / Selfhood |
| 生活与认知 | 家乡、生活轨迹、实际知道的知识、认识的人与关系、关键经历及其来源 | Brain / Memory |
| 先天与初始能力 | 物种身体/感知限制及经人生证明的训练水平，只按各最终所有者的已登记入口形成初始值；不擅自授予工具权限 | Body / Brain 等对应所有者 |
| 入驻后的身体与生活 | 已提交外貌供虚拟身体使用；当前地点、身体状态和后续活动由各运行时所有者产生 | Body、Nest、Godot 等；不是 Genesis 虚构的当前事实 |

### 1.1 两条流程及唯一汇合点

```text
第一阶段：准备资料（资料变更时发布，不按个体重复）
造物者世界设定 Markdown ──┬──→ 世界/物种/空间/人生生成规则 ─┐
                            └──→ 居民知识 Markdown → 精简知识 YAML ─┼→ 已发布 GenesisSourcePackage
物种资料与已审核外貌资产 ──────────────────────────────────────┘              │
                                                                             ↓
第二阶段：创建个体（每次领养）                                     用户选择与冻结的候选
                      ↓
身份/外貌与 LifeContext（出生、家庭、学习、职业、时间线、活动地图）
                      ↓
按人生地图取得知识 → 人物/关系 → 关键经历及知识回流 → 自我介绍的事实投影
                      ↓
联合校验 → Profile + Selfhood + Memory 提交 → 正式欢迎入驻与首次互动
```

两条流只在发布的资料包处汇合。第一阶段的 A 类构造/生成规则和 B 类居民知识是**职责**，不是
`world/`、`species/`、`knowledge/` 三个并列的知识权威。世界设定提供作者事实和生成约束；
居民知识 Markdown 提供人读答案；精简知识 YAML 逐项保留它的描述和必要限制；程序按规则生成个体差异。
七层世界设定是世界因果顺序，不是另一个领养步骤表。

### 1.2 两阶段的工作与交付

| 流程 | 顺序 | 交付与完成条件 |
| --- | --- | --- |
| 资料准备 | 世界设定 → 居民知识 → 配置编译/审阅/发布 | 一份版本固定、来源完整且所有引用有效的 `GenesisSourcePackage` |
| 个体创建 | 候选生成与接受 → 冻结身份 → 生成人生 → 生成知识/关系/经历/介绍 → 校验提交 | 一只可以从最终所有者恢复的完整 Elfie；创建输入随后销毁 |

候选阶段的简短招呼可以用于选择，但不能冒充完整人生自我介绍。正式自我介绍必须从已确定的生活轨迹、
知识、人物与经历投影；不能先写一段故事，再反过来为它制造人生。欢迎时机见第 6.2 节。

## 2. 设计定位、边界与不可变原则

Genesis 的目标不是让模型临场编出一个角色，而是把已经确认的世界、用户领养选择和受控随机性，
在一次创建事务中编译成一只内部一致、可以校验且提交后自足的 Elfie。主数据流只见第 1.1 节；
下面列出贯穿两阶段的约束，不再另画一条“第三流程”。

全流程遵守以下原则：

1. 世界事实由人工确认的世界资料定义；程序和模型都不能新增 Canon。
2. 居民可知知识与生成器专用事实严格隔离；人口密度、底层物理参数和精确采样坐标不能泄漏给 Elfie。
3. 用户选择是 Genesis 的正式输入；`any` 等偏好必须先解析为实际候选值，不能成为 Elfie 的真实身份。
4. 身份、地点、人物、时间线、知识接触、关系变化和事件结果由确定性程序生成；模型只实现语言表达。
5. 相同创建输入、时间锚点、目录版本、生成策略版本和 Seed，在同一次未完成创建事务中必须得到相同结构化结果；这个确定性只服务候选生成、失败恢复和测试，不授权提交后重造同一 Elfie。
6. 问卷、领养选择、资料包绑定、Seed、LifeContext 与 PersonalGenesisPlan 都是创建期临时输入或中间产物；成功提交或终止失败后必须删除。
7. 提交后事实只归 Profile、Selfhood 和 Memory 最终所有者；普通 Brain 运行只读取 Selfhood、Memory 与当前 Brain 状态，不读取 Profile、Canon、Genesis 资料包或创建回执。
8. Canon 或生成规则升级只影响未来创建；既有 Elfie 的学习、修复或迁移必须以最终所有者为输入另行设计，不能重放 Genesis。
9. 年龄采用一对一的地球年龄口径：Elfaria 生活了几岁，来到地球后就按几岁理解和显示。这个简化只用于年龄与生命周期，不改写 Elfaria 的昼夜、季节和天文设定。

范围覆盖新领养 Elfie 的资料准备、候选身份与虚拟外貌、LifeContext、领养前知识/人物/经历、初始
Selfhood/Memory、一次性发布和入驻展示的事实来源。Genesis 负责确定并交付外貌数据，不接管 Godot 的
模型、材质或渲染实现。运行期持续学习与压缩、真实 Nest/Godot 观测和身体、实时天气与活动、
多 Elfie 共享关系、向量数据库、
第二套存储及既有 Elfie 数据迁移均不属于本文；需要时分别立项，不能借 Genesis 顺带实现。

本设计不规定具体概率和评分数值。它们必须作为第一阶段发布的版本化策略数据存在，由程序校验，
不能散落在代码或模型提示词中。

## 3. 第一阶段：资料准备与源包发布

### 3.1 CreatorWorldSkeleton：造物者世界骨架

阶段 0 从造物者角度描述世界如何成立，包括底层参数、因果链、生态、地理、人口、社会、技术和历史。
每项设定必须属于以下一种可审查类别：

- **居民可观察**：居民能够通过生活、教育、记录或传闻接触；可以进入阶段 1。
- **生成器专用**：只用于保证世界和随机生成一致，例如精确人口权重、适生网格和深层机制；不能进入阶段 1。
- **尚未确定**：不得由阶段 1、配置作者、程序或模型补写。

发布审查为需追踪的作者事实分配稳定 `creator_fact_id`（可以记录在独立覆盖清单，不强制把世界设定
Markdown 改成逐句卡片）。所有居民可观察项必须映射到阶段 1 的知识锚点，或带理由标为 `deferred`；
生成器专用和尚未确定项不得进入居民知识。这张覆盖关系用于发现遗漏，不进入 Elfie 记忆。

地图同时具有两种表达：居民能使用的地名、路线与相对远近属于可观察层；精确采样坐标、密度权重和
尚未公开区域属于生成器专用层。

### 3.2 ResidentKnowledgeBaseline：居民知识人读稿

阶段 1 整理**居民可能知道的具体答案**，不描述任何具体 Elfie 的家庭、职业、熟人或个人故事。
现行人读稿按 A 天地与时序、B 地域与空间、C 生命与生存、D 通信与情绪、E 社会/历史/跨世界联系五个主题、
26 个核心知识点组织。主题是阅读导航，不是给每条知识附加的 `domain` 字段。无标签段落为公共知识；
仅在确实改变知晓资格或比例时标地点、路线、职业、经历、掌握难度。完整性由逐项原文映射、
作者设定来源、居民问题覆盖和未知边界共同证明，不沿用旧稿的数量门。

每个知识点用居民能够理解的现象、经验、制度或传闻表达，不使用“系统设置”“当前未定义”“参数值决定”
等造物者语言。地图知识只写居民可能知道的地点、方向、通行条件和相对时间，不写生成器坐标或人口底数。

一个独立的正文段落或带标签的列表项对应一条机器知识；同一小节可以有多条。稳定 ID 由小节号和项序
确定，例如 `B-04` 与 `B-04-02`；标题只用于人读导航，不进入机器知识条目。某一项如果同时包含公共
概况与受限细节，应**先在 Markdown 中分项**，再机械转换；不能在 YAML 中自行切句、重写或补充事实。
来源覆盖关系可以在发布校验中维护，不要求把作者侧 `creator_fact_id` 塞进每条精简知识或 Memory。

### 3.3 GenesisSourcePackage：发布的静态输入

#### 3.3.1 目标物理结构、版本与现状

目标是一个 `config/genesis/` 包，**不再嵌套 `elfaria/` 总目录**；`knowledge/` 和 `species/` 只是
按资料职责分组，不产生独立 Genesis。`program.yaml` 是唯一包入口：

```text
config/genesis/
├── program.yaml                 # 包清单、跨物种世界生成规则、策略与来源覆盖
├── knowledge/
│   └── elfaria.yaml             # 一份居民知识；不按 A–E 主题再拆文件
└── species/
    ├── catalog.yaml             # 物种发布状态和成员引用
    └── <package>/
        ├── species.yaml         # 正式身份、物种身体/感知边界
        ├── generation.yaml      # 生命周期、可行出生区域与个体先验
        ├── appearance.yaml      # 候选外貌参数与已审核资产的语义绑定
        └── assets/*.png         # 物种展示用头像/全身图等随包资源
```

展示用图片随物种包列入摘要；运行时 3D 工程和纹理仍在其既有所有者目录，不能因为 Genesis 使用
外貌参数而复制 Godot 资产，也不能在新旧 species 包各留一套独立维护的展示图。
`config/brain/selfhood.yaml`、`config/brain/energy.yaml`、Brain 推理宪章、Memory 的准入/Retention
策略和 `config/nest/defaults.yaml` 属于**下游最终所有者或运行时默认值**，不是 Genesis 的居民知识
或世界生成规则，不搬进此包。Genesis 仅按其强类型入口交付对应 Seed；尤其不在 `program.yaml`
复制 Selfhood 模板、Memory 半衰期、工具权限或 Nest 当前状态。外貌的 Godot 资源仍归
`godot_project/characters/`，`appearance.yaml` 只保留经审核的语义绑定。
现行配置契约仍注册 `config/world/elfaria.yaml` 和 `config/species/`；当前代码仍由旧加载器组装
`GenesisSourcePackage`。`build/genesis/` 中已有同类草稿文件，但 `program.yaml` 仍引用旧知识版本，
整个目录尚未发布或接入生产。目标路径、注册和加载只能在配置契约升级、单一路径切换与验证后落地；
不能靠本文把草稿说成已迁移完成。

#### 3.3.2 文件责任与数据形状

| 文件 | 必需的逻辑字段 | 只负责什么 |
| --- | --- | --- |
| `program.yaml` | `document_kind/schema_version/program_id/program_version/status`、`sources`、`manifest`、`coverage`、`rules` | 一次发布的总清单；共享地点/路线、适生网格与人口权重、家庭/学习/职业原型、命名、关系、经历、赴地规则、生成策略 |
| `knowledge/elfaria.yaml` | `document_kind/schema_version/knowledge_id/knowledge_version/status/source/knowledge[]` | 人读居民知识的逐项机器投影；不保存生成器权重或第二份物种百科 |
| `species/catalog.yaml` | `document_kind/schema_version/catalog_version/status/species[]` | 物种包列表、技术 ID/正式名映射、发布状态和三个成员文件引用 |
| `<package>/species.yaml` | 版本/正式身份、身体与感知先验、可赴地边界、资产语义引用 | 物种的**共同**事实；不得写个人职业、人格、知识清单或故事 |
| `<package>/generation.yaml` | 版本、年龄阶段/范围、出生区域资格与相对权重、必要个体先验 | 该物种的生成约束；不得复制居民知识描述或替代全局空间图 |
| `<package>/appearance.yaml` 与 `assets/` | 版本、控制项/范围、外貌组合约束、调色板、受控展示图片与 3D 资产语义绑定 | 候选外貌的确定性生成输入和展示资源；Godot 仍负责实际几何和渲染 |

`program.yaml` 的 `rules` 不是一段可执行脚本，而是经强类型校验的命名记录。实现可以沿用现有类型名，
但逻辑字段必须覆盖下列输入；没有数据时不能用代码默认值悄悄补成“真实世界”：

| `rules` 成员 | 最小必需信息和发布校验 |
| --- | --- |
| `places` / `routes` | 稳定 ID、父子关系、居民称呼、地点类型、道路端点与路段、通行方式/季节/许可；端点存在且道路图连通，居民旅行时间与生成用成本分层 |
| `population` | 地图/网格版本与摘要、可居住单元、父聚落与地区、道路接入、有效人口权重；权重非负且物种可行集合非空，不把中心和村落双重加权 |
| `life_archetypes` | 适用物种/阶段/地区、家庭照护角色、可行学习和职业路径及权重；未适龄者有非职业路径 |
| `names` | 正式物种名系、候选名和私人人物名的词库/构词与去重边界；生成结果不能复用物种名冒充每人的原生名 |
| `relationship_archetypes` | 关系角色、接触前提、年龄/地点/能力、数量与显著性约束；不能无接触地生成熟人 |
| `episode_themes` | 年龄与生活阶段、已具备知识/人物/地点前提、事件可变项、禁止项和数量约束；赴地关键事实必须可成立 |
| `earth_arrival_rules` | 已发布物种/阶段资格、同意/照护前提、必修培训模块与所引用的已审阅知识 ID |
| `generation_policy` | 分领域策略版本、命名 Seed/加权选择算法、出生与行程预算、难度到取得比例、人物/经历数量、回溯上限和校验规则 |

单个网格至少可解析 `cell_id/region_id/parent_settlement_id/habitable_area/road_access_id/
population_weight`，单条道路至少可解析稳定端点、长度或经审定的旅行成本、地形和通行条件；
物种 `generation.yaml` 至少给出 `stage_ranges`、允许的出生地区/网格选择条件和相对权重。
同一关系不可既在世界规则又在物种文件各设一份互相矛盾的总权重：全域人口和道路由 `program` 拥有，
物种文件只增加该物种的资格/相对因子，发布时合成为一个有效抽样分布。`mastery_difficulty` 的取值
映射只在 `generation_policy`，不向每条知识再补概率字段。

`program.yaml` 的 `manifest` 固定所有成员路径、文档版本和内容摘要、源 Markdown 摘要、引用关系与发布
状态；`sources` 指向同包的 knowledge 和 species，不允许隐式目录扫描。包内每个独立数值策略都需在
`rules` 或物种 `generation.yaml` 中声明来源、单位、范围和版本；具体概率、数量、采样算法的取值
由经审阅配置提供，不能藏进提示词或编译器常数。逻辑包只接受整体 `published` 状态且成员版本一致；
被接受候选冻结的是这一整包而非单个文件。技术 ID `fox/dog/cat` 与居民正式名 `Saevi/Tovren/Myelle`
通过 catalog 映射，不把形态近似名当作物种身份。物种世界存在与产品可选择是不同状态；Myelle 当前
未开放运行时选择，不能因世界设定存在就进入候选池。

#### 3.3.3 精简知识 YAML 的精确合同

```yaml
document_kind: resident_knowledge
```

存在的 `eligibility`/`mastery_difficulty`；没有 `title`、`domain`、`group/defaults`、`full/partial`
变体、空数组、空属性或再次生成的描述。无标签即不写限制。若 Markdown 在一段中有多个事实，
这些事实须完整保留在该条 `description`；要细分受众就先在 Markdown 中分项，禁止 YAML 自行概括。

`eligibility` 是声明式布尔树：`all` 中每项同时成立，`any` 中任一支成立，允许必要的有限嵌套；
叶子仅为已登记的 `place/route/vocation/experience`。同一项中多个 Markdown 标签默认映射为 `all`，
确有独立取得路径时优先拆成独立子项；不得用一个宽泛的 `any` 绕过专业或地点硬门。
`mastery_difficulty` 不是资格、地点或经历，只控制已符合资格者中**取得这条完整描述**的比例。
掌握概率映射、稳定独立 Seed 和失败时的保守处理在 `GenerationPolicy`，不写进知识正文。

转换器按稳定段落/列表项定位，逐项比较去掉标签后的原文与 YAML `description`（只允许 Markdown
换行、列表符号、标签前缀的规范化，不允许重写词句或标点）。逐项比对 ID、标签类型/值及 `all/any`
关系；双向保证无漏项、重项、孤儿项或增补事实。`source.sha256` 必须等于当次人读稿；没有原文依据的
机器知识不得发布。当前草稿有 161 个条目、49 个带 `eligibility`、3 个带 `mastery_difficulty`；
这些只是待校验的现状数量，不是永久配额，也不证明逐项等价已经通过。

#### 3.3.4 生成规则、空间及来源覆盖

`program.yaml` 的共享规则含稳定地点/道路 ID、可居住网格、人口权重、道路接入与旅行成本、设施/许可、
家庭/学习/职业原型、名字、关系槽位、经历主题、赴地课程和分领域 `GenerationPolicy`。物种特有
生命周期、允许区域与相对分布在对应 `generation.yaml`；它只能约束世界规则，不能自建第二张地图。
`SpatialPopulationModel` 引用已审定地图和几何摘要，供**历史出生和活动**抽样，不是 Nest/Godot
当前空间或路径权威；生成用的公里坐标、密度和路线成本不进入 Elfie 记忆或叙事模型。

发布校验要同时覆盖“作者设定 → 居民知识”和“居民知识 → 精简 YAML”：前者区分可观察、生成器专用、
尚未确定并记录有理由的延后项；后者对现行居民正文实行逐项完全映射，不把 `deferred/excluded` 当作
掩盖漏转的常规出口。`CoverageManifest` 与转换校验属于包/发布报告，不复制到每条知识或最终 Memory。
所有地点、路线、职业、经历标签都必须可解析到生成规则中的唯一稳定 ID；未知标签、悬空引用、
互斥资格或未发布成员阻止发布。

#### 3.3.5 赴地资格与必修培训

`EarthArrivalRules` 是赴地资格的前置条件。只有规则列出的物种和生命阶段可以进入候选；需要照护或共同
同意的阶段必须满足相应条件。不存在 `participated: false` 的已抵达 Elfie：所有抵达者都完成必修培训，
但强制参加只保证最低掌握，不保证扩展内容完全相同。培训只能引用 `KnowledgeCatalog` 中已经审阅的知识
和程序，不得自行发明新的地球事实或世界设定。

## 4. 第二阶段前半：候选、外貌与 LifeContext

### 4.1 输入、预约与数据结构

个体创建前半包含“生成候选—冻结接受结果—生成生活背景”三个连续动作。候选集由 `AdoptionSelection`、一个
已发布的 `GenesisSourcePackage`、`master_seed` 和策略版本生成。它们只在候选请求和未完成创建事务中
存在；不能在用户看到候选后改用新目录重新解释同一候选，也不能在成功提交后继续保留。

- `AdoptionSelection`：用户选择的物种、生命阶段偏好、性别偏好、外貌方向、外貌优先项、五个相处情境答案及已注册扩展选项 ID；
- `CandidateCoreResolution`：程序生成有限候选，每个候选拥有实际物种、实际生命阶段、精确年龄、性别、外貌基因、人格锚点和原生名；外貌选择是生成输入，不是由人格或职业回推的装饰；
- `AdoptionDecision`：用户选择的候选 ID、最终显示名、领养家庭引用、可选邀请证据引用，以及应用补入的 `adoption_anchor_at`；
- `AcceptedGenesisReservation`：App 以一次 compare-and-set 冻结被接受候选的最终身份、领养家庭引用、`elfie_id`、私人命名空间、预约 ID、幂等键、领养时间和事务状态。它不保存原始答案；资料包、策略、Seed 与必要输入摘要放在同一私有工作区的 `GenesisCompileEnvelope`，只服务未完成事务。一个候选会话只能成功接受一次；事务内重试返回同一预约。

v0.1 的 `custom/CFHO` 不再作为独立的开放输入通道。既有调用方必须把值映射为注册、类型化、版本化的
选项 ID；无法映射就明确拒绝。扩展字段必须进入创建期规范化输入，只能影响声明过的个体差异，不能携带
模型指令、覆盖 Canon、改变已接受身份或绕过资格规则。

只有有效的 `AcceptedGenesisReservation + GenesisCompileEnvelope` 可以继续生成 LifeContext。配置更新、
进程重启或重复请求都不能改变本次事务中的身份和输入；预约过期或引用包不可用时明确失败，不换用模型
或其他版本补齐。成功提交或终止失败后，两者都必须删除；以后恢复 Elfie 不得再次需要它们。

五个相处问题只参与候选人格的受控推导。候选被接受后，Genesis 只接收冻结的人格锚点，不把原始答案
复制进 LifeContext；成功提交后答案不再属于这只 Elfie 的任何持久记录。它们不能直接决定出生地、家庭
条件或社会阶层。邀请原文若由产品另行保存，仍归领养互动证据所有；Genesis 只能接收“邀请已被接受”
这一创建期结构化事实，不能把原文用作生成指令、世界事实或领养前人生依据，也不能暴露给叙事模型。
显示名按长度、字符和保留词规则校验；所有用户字符串都作为结构化数据传递，不能拼进系统指令。

LifeContext 的逻辑结构为：

```text
LifeContext
├── identity
│   ├── species_id / gender / life_stage
│   ├── age_years_at_adoption / adoption_anchor_at
│   ├── original_name / display_name
│   ├── appearance_ref
│   └── personality_anchor
├── origin
│   ├── birth_region_id / birth_settlement_id / birth_cell_id
│   ├── childhood_home_place_id
│   └── predeparture_home_place_id
├── household
│   ├── archetype_id / member_roles
│   └── care_and_trade_context
├── learning
│   ├── path_id / institution_ids
│   └── apprenticeship_ids
├── vocation
│   ├── vocation_id / proficiency_band
│   └── workplace_place_id
├── mobility
│   ├── residence_periods / daily_activity_areas
│   ├── journey_legs（阶段、目的、起止点、完整路线与耗时）
│   ├── place_encounters（听说/经过/外观/进入/使用）
│   └── route_traversals（走过的路段与是否走完整程）
├── earth_transition
│   ├── curriculum_version / completed_module_ids
│   ├── departure_place_id / route_id
│   └── earth_household_ref / invitation_accepted
└── content_hash
```

`GenesisCompileEnvelope` 单独保存本次事务需要的 `reservation_id/candidate_id/idempotency_key`、规范化选项
摘要、SourcePackage/策略绑定、`master_seed`、命名子 Seed 和中间输出哈希。它不是 LifeContext 的一部分，
不会进入 Profile、Selfhood、Memory 或长期回执。

`birth_cell_id` 等精确采样字段只供生成和校验，不会原样写入精灵记忆。Profile 只接收契约白名单内的
客观身份、稳定年龄/出生锚点、不可变个人来源 ID/冻结标签与最终虚拟外貌；附近地点、熟悉路线、迁居、
培训、出发、抵达和领养经历分别进入 Memory。

LifeContext 的 `content_hash` 对不可变语义字段的规范序列化内容计算。规范格式固定 UTF-8、Unicode
正规化、键顺序、集合排序、数值与时间编码；不得包含本机绝对路径、遍历顺序或隐式系统时间。
Plan 和 Bundle 遵循同一规则。哈希排除哈希字段自身，以及 `status`、校验诊断、`committed_at` 等
事务字段，避免自引用和恢复漂移；这些字段只在创建工作区审计，不改变同一次创建的语义哈希。
模型生成的 `narrative_projection` 同样不进入事实语义哈希；它单独记录 `projection_hash`、模型与投影
策略版本，并反向绑定不可变的 `plan_hash`。稳定 ID、幂等键和事实节点只能由结构化创建输入派生，不能由
措辞派生；成功提交后只保留最终对象 ID 与摘要，不保留可重算这些对象的输入。

年龄直接使用地球年龄口径。程序按物种生命周期生成整数 `age_years_at_adoption`：在 Elfaria 生活了 5 年，
就按 5 岁理解，不再把 196 个本地日、40 小时本地日换算成另一套年龄。候选展示的年龄在接受后保持不变；
以后每经过一个地球年增加一岁。`adoption_anchor_at` 只用于稳定计算当前年龄。界面需要生日时可以从年龄
生成明确标注为“年龄投影”的日期，但它不是 Elfaria 的精确历史生日，也不能写进个人亲历。

### 4.2 候选外貌与人格的冻结边界

候选生成按物种已发布的 `generation.yaml` 与 `appearance.yaml`，结合精确年龄、性别和用户四项外貌选择
确定最终虚拟外貌；`any` 只在候选阶段解析。五个相处情境只对人格锚点作有界映射。选择候选后，
Profile 所需的外貌基因、可解析形态、物种资产 ID 和外观资源引用，与身份/年龄/人格锚点一起冻结；
最终入驻不能重新抽外貌或换成另一套默认皮肤。外貌包括体型、比例、脸部、毛色/区域/局部标记等
已获准的语义参数；具体可见性和已延后的解剖跨区花纹服从现行
`Virtual Appearance Generation` 设计与物种资产契约，不在 Genesis 中复制渲染实现。
五候选之间的可见差异需要通过已审核的外观组合约束验证；出生地、职业、道德和个体知识不能由毛色、
耳形、地球动物形态或物种刻板印象推出。物种只提供身体、感知和生活区域先验，不决定这个人的人格。

### 4.3 确定性生成顺序

程序按以下因果顺序生成，后一步只能读取前一步已经确定的事实：

1. 根据用户偏好生成候选核心；用户已选物种必须保持一致，生命阶段、性别或外貌若选择 `any`，则在各候选中确定实际值，不把 `any` 写入候选。
2. 在候选核心内按物种生命周期和年龄分布生成地球口径的 `age_years_at_adoption`、人格和外貌，用户接受后全部冻结在 `AcceptedGenesisReservation`。
3. 按物种、出生时期和区域人口权重选择出生宏观区域。
4. 按聚落占比、适生单元和密度权重选择出生聚落及有效地点；不得在整个多边形内均匀撒点。
5. 在出生地和物种允许范围内生成家庭与照护结构。
6. 按年龄、地点、家庭和设施可达性生成学习、学徒和知识接触路径。
7. 按年龄、学习经历、地方劳动结构和家庭传承生成职业；人格只能在已经可行的选项之间作有限权重调整，
   外貌不得参与；未到适龄者显式为学习或无职业状态。
8. 根据出生地、职业、年龄与路线成本生成按阶段排列的迁居、出发前住处、日常活动区、实际行程与接触层级；出生地不等于出发前住处，路线可达不等于实际走过。
9. 对已经通过 `EarthArrivalRules` 资格门的候选，无条件加入必修培训、准备、出发和抵达上下文；个体只在培训细节、联系人和主观反应上存在差异。
10. 执行地点、年龄、职业、设施、时间和引用完整性校验，失败则整份 LifeContext 不得发布。

每一步只能从满足后续硬约束的可行集合中选择。若局部选择仍导致无解，使用稳定 `attempt_id` 做有界
回溯；穷尽后返回带理由码的 `UNSATISFIABLE`。同一未完成事务恢复得到同一结果或同一失败，不能无限换 Seed，
也不能让模型补造家庭、职业或地点。

所有条件关系都必须在已发布源包中明确声明。程序不能从模型常识或地球人口经验自行推断“某种性别、外貌、
物种或家庭更适合某种职业、阶层或地区”；未获世界资料支持的相关性一律不存在。外貌只影响虚拟形象，
人格也只能在已通过年龄、地点、学习和能力硬门的选项之间作有限权重调整。

公开区域、聚落和机构引用 `PlaceCatalog`，居民可理解的路线引用 `RouteCatalog`；隐藏路径、坐标和成本
不得写入 Memory。家庭住所、小作坊等只属于这只 Elfie 传记的地点，可以从
已批准原型确定性实例化为 `private_place_id`，但必须挂在一个公开父地点下，并使用预分配的 Genesis
私有命名空间；最终 ID 随对应 Memory 对象保存，最小 `GenesisCommitReceipt` 只记录输出对象 ID/摘要。
它们不是新的公共地理 Canon，也不能被另一只 Elfie 因同名自动共享。

所有随机选择使用从 `master_seed` 派生的命名子 Seed，例如：

```text
candidate / age / birth_region / birth_cell / household
learning / vocation / residence / mobility / relationships / episodes
```

`GenerationPolicy` 按 age、origin、household、learning、vocation、mobility、relationship、episode、
knowledge 等领域分别版本化。子 Seed 由稳定标签和对应领域策略版本派生，不依赖函数调用顺序；包的总
版本号不直接参与所有随机分支。以后新增一个职业选项不能改变已经确定的出生地、家庭或人格；只有相关
目录或领域策略版本变化时，对应分支才允许变化。

Seed 派生算法、伪随机算法和加权选择算法本身也必须有版本号；禁止使用进程随机哈希、无序容器遍历
或未记录的运行时默认行为。一次未完成事务的恢复必须复用预约中的 `adoption_anchor_at`，不能拿“现在”
替代；已提交 Elfie 不提供 Genesis 重放入口。

LifeContext 完成后必须满足：所有地点可居住、所有家庭和职业符合年龄、全部引用有效、行程的时间与通行
条件可行、没有把隐藏人口总数或坐标变成个人知识，并且同一未完成事务恢复得到相同哈希。

### 4.4 出生地：网格、物种范围与加权抽样

生成器使用世界设定第 8.4.1 节批准的历史地图：辖域网格（首版示例为 10 公里见方）、适生区、道路图、
聚落及人口密度。每个候选网格至少有稳定 `cell_id`、区域/父聚落、可居住范围、接入道路的入口、
按地形计算的道路代价、相对人口权重和物种可行性；中心坐标只供计算。物种的**可出生范围和相对分布**
来自其 `generation.yaml`，人口/聚落权重来自同一世界空间模型。物种常见区域只提高合乎来源的权重，
不自动变成唯一出生地或身份限制；世界没有审定的区域/物种组合不能靠随机算法创造。

抽样先过滤不可居住、不允许该物种、没有可行接入路或与年龄/家庭硬约束矛盾的网格，再以已审定的
`cell_population_weight × species_region_factor` 在**剩余有效网格**中归一化加权抽样。人口权重
已经包含聚落层级时，不再叠乘一次“村落/中心概率”，防止双重偏置；若数据源分层给权重，发布器
必须先计算单一有效权重并校验总和、分布和村落占多数/中心极少数这一世界约束。
网格选定后，在它登记的可居住聚落/家庭点内实例化出生住处或私有地点；不能在整个区域多边形内均匀
撒点。坐标或网格不存在可用家庭/道路接入时，这个网格必须在抽样前排除，不允许事后把出生地挪到
别处。固定 Seed、排序、权重版本决定可重放的结果；若可行集合为空，明确 `UNSATISFIABLE`。

出生的历史地理只产生带居民称呼的出生地、家乡与个人经历；`birth_cell_id`、精确坐标、人口底数、
采样权重、模型里程属于创建期隐私/生成数据，既不进入 Memory，也不交给叙事模型。

### 4.5 活动地图：半径、行程与知识资格

每段生活先有居住点、年龄、照护/学习/职业职责，再由可通行道路图求范围：住处到道路的接入路段
加实际路径代价，按平原、森林、山地速度及负重、坡路、渡运/季节、休息与露营条件换算。
`daily_activity_area` 只包含在该阶段可用时间预算内**能去且能回来**的地点；偶发长途以具体
`journey_leg` 记录目的、同行者、交通/许可、去返时段与停留，不能因同属一地区就纳入日常半径。
无审定短途/渡运时间时只能保留相对远近或区间，不能生成虚假的精确分钟。跨适生区成功往返、
云冠城普通地表进入或无窗口的深层地下进入不得生成人生经历。

求得“可达集合”后仍须按生活/工作/事件条件选出**实际行程**。`place_encounter` 区分仅听地名、
路过附近、看见外观、真正进入与实际使用；`route_traversal` 记录完整路段与仅走过的一段。
地点内部知识不能由外部可见授予，路线全程耗时不能由到过终点或走过部分路段授予。赴地去镇中心的
行程发生在具体年龄阶段，不能倒灌为童年镇内知识；知识取得阶段和 Episode 年龄必须落在相应行程之后。
若事件需要新行程，须回到地图增加并校验，不能让故事直接产生一个未获许可的地点访问。

`place` 标签只给地点名时，必须能唯一解释需要哪种接触层级；同一粗地点若同时有“入口外观”和
“内部细节”，发布前须回到居民 Markdown 明确更细地点或必要的接触限制，再机械更新 YAML。
不得由模型读描述猜“看过”和“进入过”的差别，也不得在程序里按知识 ID 藏特殊放行。

## 5. 第二阶段后半：PersonalGenesisPlan 与完整人生

个体创建后半的临时编译输出为：

```text
PersonalGenesisPlan
├── profile_plan
├── selfhood_plan
├── personal_knowledge_manifest
├── relationship_plan
├── episode_skeletons
└── final_owner_commit_plan
```

这些结构只在创建期决定最终值，本身不是提交后的事实所有者。`profile_plan` 只能复制契约白名单内的
客观身份、稳定年龄/出生锚点、不可变个人来源 ID/冻结标签和最终虚拟外貌；`selfhood_plan` 从已冻结人格
锚点生成受控表达、价值和自我认识。Episode 可以解释或强化某些倾向，但不能反向改写已被用户选中的
人格，也不能为每个性格特征强造一段决定性童年原因。

### 5.1 个人知识编译：以精简 YAML 为唯一居民知识输入

知识编译器只接收已发布的精简 `KnowledgeCatalog`、已确定的 `LifeContext`、赴地规则和
`GenerationPolicy`，不接收造物者全文、旧版 `WorldKnowledgeFact` 的第二份描述或模型自行补全的
世界事实。一条 YAML 描述是一个不可任意改写的居民知识单位；个体差异首先是**有没有取得这一条**。

```text
完整人生地图（地点接触、实际路线、工作/学习、特殊经历及发生时间）
              + 精简知识条目
              ↓
无标签 → 全体直接取得原文
有标签 → all/any 条件按已发生的人生事实求值
有掌握难度 → 仅对已符合资格者做独立、可重放的比例选择
              ↓
按取得时间与来源写入个人知识 → Memory
```

| 条目情况 | 判定 | 结果 |
| --- | --- | --- |
| 无 `eligibility`、无 `mastery_difficulty` | 公共知识，不另设年龄、曝光或抽样门 | 每只已入驻 Elfie 得到完整 `description` |
| 只有 `eligibility` | 所有叶子从人生地图的实际事实求值 | 条件真则取得完整原文，假则不写入 |
| 只有 `mastery_difficulty` | 以策略中的该难度比例、独立 `knowledge_id` Seed 抽样 | 命中取得完整原文；未命中不写入，也不编造学习事件 |
| 两者都有 | 先资格，后难度；难度不能突破资格硬门 | 只有两者通过才取得完整原文 |

这一首版规则也适用于允许领养的幼年个体；若某段内容不应被幼体或某类居民直接掌握，必须先在
**人读知识稿**明确必要限制并重新发布，不能在编译器中偷加年龄漏项或隐含随机门。
无标签项只保证**领养时已经知道**，不伪造“某年某人教过我”的具体来源；其创建期来源记为
`public_baseline`。过去某段 Episode 若需引用该知识，仍须有该阶段可成立的普通学习/生活背景，
不能因为入驻时已知就倒灌成幼时已知。

地点叶子匹配实际居住/到访与该知识要求的接触层级：地区标签可由该地区的真实居住或停留满足，
具体设施则须实际到达相应外观或内部层级。仅听地名、住在同一**大地区**或接近入口不等于进入设施内部；
父地区匹配不向全部子地点自动继承。
路线叶子匹配**实际走过完整相关路线**及所需方向/区段，不能把到过端点等同于走过道路。
职业叶子须匹配实际承担的工作对象、所学手艺和能力范围，不能只凭一个宽泛的职业名授予全部专业知识。
经历叶子须有按年龄、地点和资格可成立的已发生事件；`赴地` 条目须在培训、出发或抵达相应事实
成立后取得。多个限制同时出现时默认 `all`，不允许一个低概率把不可能接触的事实放行。
地点或职业标签若过粗到无法判定这些条件，必须在**人读 Markdown** 中细化必要标签，重新编译 YAML；
不能把额外语义暗藏于知识 ID、模型推断或无来源的程序例外中。

`GenerationPolicy` 只定义 `mastery_difficulty` 的概率表、稳定 Seed 派生与校验版本，不为无标签
公共知识额外引入 `exposure`、`partial` 或 `reference_only`。知识选择使用
`master_seed + knowledge_id + knowledge_policy_version` 派生独立随机流；增删其他知识条目不得
改变这一项的结果。若难度值没有策略定义，发布失败；缺失标签匹配事实则保守地不取得，而非让模型
补造经历。

`PersonalKnowledgeEntry` 的事实正文就是 YAML `description`；还记录 `knowledge_id`、取得阶段/
时间、合法来源（公共传播、实际地点/路线、工作、特殊经历或赴地培训）以及 Memory 所需的来源 Evidence
和受控重要性信号。被拒条目与判定理由只保留在创建期 `KnowledgeDecisionTrace`，不进入最终 Memory、
模型或长期回执。Memory 的检索索引可以从已选原文和正式名称派生，不能另手写同义事实或让索引绕过
未选条目。当前首版只产生“完整取得/未取得”两种结果；Memory 类型未来即使支持更多掌握状态，
也不能反向要求源 YAML 发明 `partial` 文案。

文本中的事实、地方信念、传说与未知保持原句的语气：“居民流传某说法”不等于“说法客观发生”；
知道某个地点存在不等于亲临；知道某种操作存在不等于会操作。存入 Memory 的命题必须以原句
作为可追溯依据，不能由模型改成更强断言。公共知识的取得不制造个人亲历；具体 Episode 带来的
新知识也必须先通过地点、职业/训练、经历资格及时间校验，不得为补知识反向写故事。

知识与故事按两遍收束：先按出生至出发前的生活事实选基础知识，生成人物和 Episode 后，再把
**实际发生且已校验**的行程、培训与经历带入条件求值，形成最终知识清单；同一条只写一次，
取最早合法取得阶段。Episode 在发生时只能引用此前已经取得的知识；若某 Episode 的前置知识不成立，
应换可行事件或报无解，不得强行补齐前置知识。

Memory 语义参数仍依最终记录类型归属：Node/Assertion 的 Confidence 反映身份解析或命题证据，
不是知识“抽中”的概率；Importance 来自身份、家乡、安全、关系和故事相关性；Retention 由 Memory
准入策略从来源类别及有界显著性信号解析，Genesis 不直接选半衰期。Episode 本身没有 Confidence。
现行 Genesis 准入返回 `retention_profile=genesis`、`half_life_days=3650`；这是十年半衰期，
不是永久保留或预定删除日。

### 5.2 人物与关系计划

关系生成器先根据 LifeContext 确定槽位，再实例化人物。槽位来自家庭、邻里、学习、职业、地方公共生活、
赴地培训和地球领养关系；不是每只 Elfie 复制同一组固定角色。

`PersonPlan` 至少包含：

```text
person_id / generated_name / species_id / age_band_at_genesis
home_place_id / vocation_id / competency_ids
relationship_role / familiarity_at_genesis / trust_at_genesis / importance
shared_context_ids / eligible_episode_theme_ids
source_ref / version
```

名字由 `NameRules` 确定性生成并去重，模型不能创建或修改人物名。`GenerationPolicy` 按生命阶段和
实际交往范围规定人物数量与显著性：有足够生活史的个体可以有约 10～20 个已认识的人物，其中少数高
显著人物可反复出现在经历中；年幼或长期生活范围狭小者不得为了达到同一人数制造职业关系或陌生熟人。
弱关系只保留真实发生的接触，不强行写入 Episode。外部领养家庭不是“领养前熟人”，信任从初识状态开始。

领养前人物 ID 使用 `elfie_namespace + relationship_slot_id` 派生，只在本次 GenesisBundle 内表示同一人；
名字相同不能触发跨 Elfie 合并。领养家庭引用使用外部已存在的家庭/联系人 ID，不伪装成领养前人物。
只有未来经过批准、拥有独立权威 ID 的公共角色才可以跨 Elfie 引用；当前本地生成的亲友全部是私人角色。

每个关系槽位使用由稳定槽位 ID 派生的独立 Seed；增加一种无关关系原型不能重排已有家庭、导师和朋友。

校验必须证明人物与 Elfie 在相应时间和地点有接触可能，年龄与角色合理，导师具备相关知识，家庭关系
符合世界设定，并且不同人物没有因重名或复用 ID 被错误合并。

人物的学习/职业能力只支持其**实际参与**的教学、工作和故事，不使 Elfie 自动得到该人物所知的全部
知识。若计划中的受教事件需要导师，必须先有在对应时空可接触且具备相关手艺的具体人；找不到则换
可行事件或报无解，不能仅用“认识一位老师”替代真实学习。

### 5.3 经历骨架与知识回流

每只 Elfie 生成**最多五段**可召回的关键经历；数量由生命阶段与已成立的生活史决定，不能让一岁幼体
拥有不合年龄的三段职业里程碑，也不能把完整人生误解为必须把每天的活动都写成 Episode。主题从
`EpisodeThemeCatalog` 中按 LifeContext 选择，可以覆盖归属、
照护、第一次责任、学习与失败、合作、分歧与修复、职业里程碑、旅行、赴地决定、告别和抵达；不要求
每只 Elfie 使用同一组主题。

`EpisodeSkeleton` 至少包含：

```text
episode_id / episode_slot_id / theme_id / temporal_order / life_stage
age_years_at_event / duration_band
place_ids / person_ids
goal / obstacle_class / event_facts / outcome
feeling_range / long_term_impact
relationship_before / relationship_delta
knowledge_before_ids / knowledge_acquired_ids
predecessor_ids / causal_links / forbidden_fact_ids
source_ref / version
```

生成顺序固定为：

```text
按时间已取得的基础个人知识
→ 人物与初始关系骨架
→ EpisodeSkeleton
→ 经历中真实获得的行程、知识与关系变化
→ 最终个人知识清单和关系计划
→ 规范叙述与自我介绍投影
```

这样避免“故事依赖尚未掌握的知识”和“为了补知识反向编故事”的循环。经历可以成为合法学习来源，
但必须具备相应人物、地点、年龄和事件；不能借一段故事越过专业知识硬门。

所有 Episode 必须发生在当前年龄之前或抵达时，`age_years_at_event` 必须落在对应生命阶段；
`duration_band` 与前后地点之间的路线时间必须相容。赴地培训与抵达是硬约束，
但它们可以合并进一段经历；离开 Elfaria 的阶段使用这只 Elfie 的实际阶段，不能固定写成成熟期。
若有两段以上 Episode，至少形成一条“过去经历 → 后续选择或关系”的因果链，并在可行时复用
高显著人物；极年轻个体不为满足形式要求伪造长期关系。

每个 `episode_slot_id` 分别派生主题选择和事实实例化子 Seed；增加一个无关主题不能重排已有经历。
Episode 中生成的人名、小地点、物件和局部事件只在该 Elfie 的私人记忆中成立，不能被提升为公共历史、
新地理、物种规律或另一只 Elfie 的共同过去。

Episode 使用版本化的 Importance 与由 Memory 解析的 Retention；它本身没有 Confidence。Episode 中形成的事件命题和
最终关系分别物化为带来源 Evidence 的 Assertion，再计算各自的 Confidence、Importance 与 Retention。
关系 Trust 和经历中的情绪强度仍是独立语义，不能替代这些参数；模型措辞不参与评分。

### 5.4 规范人生叙述、自我介绍与模型的边界

程序先从 EpisodeSkeleton 生成确定性规范摘要，作为 Memory 的权威内容。模型只能接收专门的
`NarrativeProjectionInput`；这个白名单类型只容纳：

- 已取得的居民知识原文和取得时序；
- 已确定的人物、地点、时间顺序、事件事实、结果、感受范围和影响；
- 明确允许的感官线索、措辞要求和可引用 `fact_id`；
- 禁止新增事实清单。

模型只能返回每段经历的自然叙述、感受表达和整体自我介绍的措辞，不能新增或改变名字、数字、
物种、地点、职业、技术、时间、事件、结果、关系变化和知识。模型看不到造物者骨架、人口权重、精确
坐标、Seed、未选知识、邀请原文或其他 Elfie 的计划；实现也不能把 LifeContext 或完整 Plan 直接序列化
给模型。

自我介绍是**这只 Elfie 已生成完整人生的有界投影**，至少能回答自己是谁、来自哪里、过去与谁生活、
一件真实经历以及现在为何来到这里；不要求把全部知识和每段故事都在欢迎页朗读。投影只引用
`LifeContext/PersonalGenesisPlan` 中已校验的事实 ID，提交后也可以从最终 Profile/Selfhood/Memory
按相同选择规则临时生成；不能从候选人格标签套一段通用传记。若尚无完整人生，就不能展示声称来自
完整人生的介绍。短版规范介绍由程序生成，模型语言润色是可选的，不成为提交完整性的硬依赖。

模型按 `episode_id/fact_id` 返回句子，程序校验实体、数字、引用和禁止项；任意自由文本都不能被证明与
结构化事实完全等价，因此它永远不是事实权威。通过校验的措辞若被采用，就作为对应 Episode 的第一人称
Memory 内容与结构化事实、Evidence 一起提交；否则直接使用规范摘要。欢迎页短介绍临时投影自已提交
事实，或在未发布工作区预览同一投影，不能作为独立长期展示资产、第二份传记或新的 Recall 来源。
模型/投影版本和 `projection_hash` 只存在于未提交创建工作区；事务内重试复用已生成草稿，成功提交后
草稿随 Plan 删除，运行时只看到最终 Memory。

## 6. 第二阶段收尾：GenesisBundle、提交与入驻

### 6.1 Bundle 与最终所有权

收尾环节把已校验计划转换为现有 Genesis 语义边界：

```text
ProfileDraft
SelfhoodSeed
KnowledgeSeed[]
RelationshipSeed[]
EpisodeSeed[]
其他已登记最终所有者的启动 Seed（仅在其契约要求时）
GenesisCommitReceipt（最小技术回执）
```

最终所有权固定为：

| 内容 | 最终所有者 | 不得混入 |
| --- | --- | --- |
| 技术 Schema 修订、稳定 ID、最终名字、正式物种、适用时的固定性别、稳定年龄/出生锚点、不可变个人来源 ID/冻结标签、最终虚拟外貌 | Profile | 世界知识、资料包/生成来源、问卷、Seed、人物关系、传记、人格、能力/权限/预算、当前身体或运行态 |
| 人格锚点、价值、表达、身份认同和自我认识 | Selfhood | 问卷答案、资料包/策略/Seed 绑定、世界知识、个人 Episode 全文 |
| 个人已知知识、人物关系、领养前经历及来源证据 | Memory | 生成器权重、未选知识、模型猜测 |
| 物种身体/感知初始约束、经验证的训练或能量初值（如对应所有者契约需要） | 对应 Body/Brain 所有者 | 直接塞进 Profile、Memory 的百科字段，或由 Genesis 自行授予权限/预算 |
| Elfie/预约 ID、幂等键摘要、最终所有者 Schema 修订、输出对象 ID/摘要、编译器修订、完成状态和时间 | GenesisCommitReceipt（Profile 外） | 问卷、世界知识、资料包/策略绑定、Seed、LifeContext、Plan、模型草稿或可重建人生的信息 |
| 最终采用的第一人称叙述 | 对应 Episode Memory | 独立展示资产或第二份事实副本 |
| 候选接受、额度和发布状态 | Adoption / Admission 持久记录 | 精灵记忆和模型 Prompt |

`master_seed`、子 Seed、问卷/选项、资料包与策略绑定没有提交后的所有者。当前 Profile 或其他持久对象
若仍保存这些字段，属于实现偏差，必须迁移删除，不能把旧 Schema 当作继续保留它们的理由。

### 6.2 提交、恢复与欢迎时机

Memory 的一次 Genesis submission 在自己的 Unit of Work 内原子提交，但 Profile、Selfhood、Memory、
领养关系和 Runtime 不伪装成一个跨存储事务。App 使用可恢复的发布状态机：

1. `AcceptedGenesisReservation` 以 `reserved` 状态冻结最终候选身份、额度和幂等键；资料包、策略、Seed 与输入摘要只在同一私有创建工作区的 `GenesisCompileEnvelope` 中存在。
2. 在同父目录的未发布工作区构建 Profile、Selfhood 和 Memory；Memory 只在全部预期记录与 completion marker 同一提交成功后可见。
3. 重开整包并校验引用、年龄、因果、知识权限和输出哈希；成功后把临时工作区原子改名为最终工作区，并把 Admission 状态推进为 `committed`。
4. 只有 `committed` 记录可以被产品入口列出和恢复；Runtime 注册在持久提交之后执行，失败时只从 Profile、Selfhood、Memory 和必要运行态恢复。
5. 崩溃恢复只处理仍未完成的同一预约；有效最终工作区可以补完 `committed`，无效结果必须清理并释放预约额度；不同摘要复用同一幂等键必须拒绝。
6. `committed` 或终止失败落定后，删除预约、CompileEnvelope、LifeContext、Plan、问卷、Seed、资料绑定和模型草稿，只留下最终所有者与最小 `GenesisCommitReceipt`。

Memory 参数按最终记录类型传递，不能给三类 Seed 机械套同一字段：

| 输入 | 最终参数 |
| --- | --- |
| `KnowledgeSeed` | 知识 Node/Assertion 各自的 Confidence、Importance；Memory 解析 Retention |
| `RelationshipSeed` | 人物 Node 与关系 Assertion 各自的 Confidence、Importance；Trust 单独保存；Memory 解析 Retention |
| `EpisodeSeed` | Episode 的 Importance；Episode 本身没有 Confidence；Memory 解析 Retention |
| Episode 内事件命题 | 派生 Assertion 的 Confidence、Importance，并保留 Episode Evidence；Memory 解析 Retention |

物化层只能校验和保存编译结果，不能用 Trust、情绪强度或任意默认值重新猜测。Memory 返回的
`half_life_days` 使用 UTC 24 小时日，与 Elfaria 年龄口径无关。

这里的 `genesis` 是 Memory 的事件来源类别，不等于可重建创建过程的资料绑定、永久保留承诺或预定删除日期。Memory 的准入合同必须接收经过范围校验的逐项
类型、来源类别与有界显著性信号，同时继续标记 Genesis 来源；`retention_profile` 和
`half_life_days` 只由 Memory 返回并持久化，Genesis 不得绕过 Memory 直接改库。Profile 正式承载
`age_years_at_adoption + adoption_anchor_at`；若旧界面仍需要 `birth_at`，只能把它作为年龄显示投影，
不能把投影日期写成 Elfaria 的精确亲历。

规范化领养选择、原始问题答案、被接受候选的生成输入、资料包/策略绑定和 Seed 均不进入 Profile、
Selfhood、Memory 或长期回执。若邀请原文由产品另行保存，它仍归领养/通信证据所有；Memory 只保存实际
发生的邀请、接受、抵达或领养事件，不复制创建参数。已提交 Elfie 不要求保留旧
`GenesisSourcePackage`，也没有“按旧包重放人生”的恢复路径。

正式“欢迎入驻”与首次可交互状态只在 `committed` 且最终所有者可重开校验后出现；Runtime 若尚未就绪，
应展示“已入驻、正在连接”的真实状态，不把尚未发生的房间活动写成记忆。当前产品界面的欢迎/命名页
在提交前显示候选阶段的通用 `personal_story`；这是**现状与目标的差距**，不是完整人生已生成的证据。
目标设计把该阶段明确视为“确认候选/命名”，正式入驻介绍只从已生成的人生投影。

同步还是后台准备不能从候选生成耗时推断。实施前测量实际领养链路的候选/画像、LifeContext 与
知识关系经历编译、可选模型润色、图片处理、工作区落盘/重开/发布、Runtime 注册及前端渲染各段耗时，
记录完整点击至可交互的分布（包括 p95）、失败率、恢复与重试耗时，并由产品确定可接受等待预算。
若完整编译与提交落在预算内，确认后等待一次提交，再展示正式欢迎和短自我介绍。若超预算，App 可把
同一预约交给后台**继续编译与发布**，界面显示候选已确认、入驻准备中及可恢复的失败/重试状态；
用户离开页面或重启后仍凭预约继续，不能并行创建第二只 Elfie。准备中可以表达“欢迎你即将来到这里”，
但不能标记“已入驻”、开放与这只尚未完成的 Elfie 聊天或展示伪完整自我介绍。
无论哪条路径，结构化完整人生和最小初始 Memory 都先于 `committed`；较慢的非权威语言润色可以
跳过而采用规范叙述，不能把事实编译延后到已入驻之后。达到预算的具体阈值由测量与产品验收确定，
本文不凭缺失数据编造秒数。

### 6.3 运行时知识路径

Genesis 提交后，Reasoning 只能通过正式链路获得初始知识：

```text
Selfhood ───────────────────────────────┐
source-first Memory → bounded RecallBundle ├→ Brain / Reasoning
当前 Brain 状态与本轮权威输入 ──────────────┘
```

只有 `recall_eligible` 的 Episode、Node、Assertion 与 Evidence 可以进入 `RecallBundle`。创建回执、
CompileEnvelope、Seed、生成权重、DecisionTrace、未采用草稿和未选知识都不可召回。普通 Brain 不读取
Profile、GenesisSourcePackage、造物者骨架或居民公共知识文档；Reasoning 也不能用模型
训练中的地球常识补写 Recall 中缺失的 Elfaria 事实；没有可靠召回时按未知、听闻或需要请教回答。

Genesis 只提供领养前历史和已经完成的抵达事实。没有当前 Orientation、感知、工具结果或动作/通信回执时，
当前位置、天气、当天活动、正在进行的动作以及其他 Elfie 的状态一律未知；历史地点和旧 Episode 不能被
推断成当前状态，模型也不能补写。

## 7. 完成门与系统性校验

### 7.1 验收矩阵

设计实现后必须以全部已发布的“物种 × 允许生命阶段”和多个固定 Seed 组成生成矩阵。以下门禁全部是硬门：

| 校验域 | 必须证明 |
| --- | --- |
| 来源与覆盖 | 世界作者事实分类可追溯；居民 Markdown 的每个独立段落/列表项与精简 YAML 的 ID、完整描述和必要标签逐项双向相等；没有孤儿项、重项或未审阅生成权重 |
| 包与配置 | `program.yaml` 的每个成员、摘要、版本、发布状态和跨文件引用闭合；未发布物种不进入候选；生产只加载一套已注册的 Genesis 包 |
| 隔离 | 生成器专用字段、未选知识、其他 Elfie 数据和未分配的赴地课程内容不会泄漏到模型或 Memory |
| Profile | 只含契约白名单内的冻结外部客观档案；不含世界观、问卷、Seed、生成来源、人格、能力、关系、经历或运行态 |
| 外貌 | 已接受候选的年龄/性别/外貌基因与提交后的 Profile 和 Godot 语义配置一致；可见变化与物种资产已验证，不能由外貌反推职业人格 |
| 隐私 | 邀请原文和完整临时人生包不进入模型、最终所有者、长期回执或普通日志；诊断只暴露脱敏 ID、理由码和哈希 |
| 预约与确定性 | 候选接受只产生一个冻结预约；同预约、同版本和同 Seed 的 LifeContext、事实 Plan、输出 ID 和语义哈希完全一致 |
| 用户输入 | 物种、实际阶段、性别、外貌和人格与最终候选一致；`any` 不会成为身份值；未注册扩展输入会被拒绝 |
| 时间 | Elfaria 年龄与地球年龄一对一；Episode 年龄、持续时间以及出生、迁居、培训、出发和抵达顺序成立 |
| 空间 | 物种允许网格及加权出生分布符合审定人口边界；村落为主、中心极少；实际住处有道路接入；日常往返预算、远行、季节/许可、人物接触在地图与时间上成立 |
| 空间权威 | Elfaria 历史生成地图不成为 Nest/Godot 当前空间权威；私人地点只在本 Elfie 命名空间成立 |
| 条件公平 | 所有身份到地区、家庭、学习和职业的相关性均有显式规则来源；没有地球常识或模型偏见暗中参与 |
| 知识 | 无标签项全体原文取得；有标签项按 `all/any` 与人生中实际地点层级、完整路线、具体职业手艺和已发生经历过滤；难度只控制合格者比例；时间正确、未选项不可召回 |
| 关系 | 人物 ID 唯一、角色和年龄合理、跨 Episode 复现只在可行时发生、同名不合并、私人关系不跨 Elfie 共享 |
| 经历 | 数量不超过五且适合年龄；多段经历有因果链；事件不使用当时未取得的知识、不虚构不可达行程和许可 |
| 记忆参数 | Episode 无 Confidence；Genesis 生成 Node/Assertion 的 C/I 与 Episode 的 I；Memory 策略独占解析全部 R/H，物化层不覆盖 |
| 模型与介绍 | 模型只接收白名单投影输入；失败时使用规范摘要；欢迎页介绍从已生成的整个人生投影而非候选通用文案，不形成第二事实源或独立资产 |
| 运行时 | 身份人格只来自 Selfhood，初始知识只经 Memory → `RecallBundle` 进入 Reasoning；Profile、资料包、创建回执、排除知识和地球先验不能成为旁路；无当前权威时保持未知 |
| 提交 | Memory submission 原子，Admission 可恢复，半套初始化不可见，事务内重试幂等，目录升级不覆盖既有 Elfie；成功或终止失败后创建输入全部删除 |
| 断源恢复 | 删除创建工作区和被引用的旧资料包后，已提交 Elfie 仍能只靠 Profile、Selfhood、Memory 与必要运行态恢复；最小回执不能重建人生 |
| 体验与耗时 | 实际领养路径逐段计时，记录 p95/失败与恢复；同步或后台准备均保证正式欢迎发生于完整提交后，准备中不暴露半只 Elfie |
| 模块所有权 | LifeContext、知识过滤、人物、关系与故事只由 `elfie/genesis` 生成；App 只协调，Infrastructure 只加载/保存强类型值 |

### 7.2 反事实与故障验证

验收不能只比较节点数量。至少直接检查 LifeContext、个人知识逐项选择理由、关系图、Episode 因果、
最终 Memory/Recall 内容和模型不可见字段；使用固定 Seed 的物种×生命阶段矩阵，复核出生地分布而非
仅证明点在范围内。反事实包括：无标签公共知识被漏掉、标签 `all` 被错当 `any`、只到地下城门却得到
地下城内部知识、只走部分道路却知道全程时间、职业同名而没学过相应手艺、未到访地区知识、
不合年龄的职业/经历、无培训抵达、出生在不可居住单元、模型新增陌生人物、候选展示后目录被替换、
欢迎页先于完整提交，以及进程在工作区发布各阶段崩溃后的同预约恢复。

### 8.1 对抗审查重点

| 攻击点 | 如果不处理 | 本设计的收束 |

| 欢迎页使用候选套话冒充人生 | 自我介绍与最终经历不相符 | 正式介绍必须从完整事实投影，入驻只在提交后；慢时先显示可恢复的准备状态 |
| Episode 被错误赋予 Confidence | “记得清楚”被当作“所有命题可靠” | Episode 只有 I；Node、Assertion 才有 C/I；全部记录的 R/H 由 Memory 策略解析，Trust 和情绪另存 |
| 模型看到完整 Plan 或直接写事实 | Seed、未选知识和新事实进入故事 | 白名单投影输入；规范事实为权威；采用的措辞只成为对应 Episode 的表达，不另存展示资产 |
| 跨存储发布中途崩溃 | 出现孤儿工作区、重复额度或半只 Elfie | Memory 内原子提交，App 用持久 Admission 状态机恢复，Runtime 最后注册 |
| Reasoning 绕过 Memory 使用地球先验 | 初始化正确但回答仍被训练常识污染 | 唯一知识路径为 Memory → `RecallBundle` → Reasoning，缺失即未知 |
| 新目录自动刷新旧 Elfie | 已有记忆被后台改写 | 已提交 Elfie 与资料包彻底断开；旧 Elfie 变更只能经最终所有者的独立行为 |
| 问卷、Seed 或资料绑定被长期保存 | Profile/回执变成第二份生命事实源，可以重造或改写同一 Elfie | 创建输入只在未发布工作区存在；提交或终止失败后销毁，最小回执不可重建人生 |
| Infrastructure 生成知识、人物或故事 | 技术 Adapter 夺取 Elfie 生命语义并形成第二条生成路径 | `elfie/genesis` 独占语义编译；App 只协调，Infrastructure 只加载/保存强类型值 |

### 8.2 审查仍未关闭的输入与实施门

本稿确定了两条流程、源包职责、知识判定、个体生成顺序、外貌与最终所有权，**不宣称资料已经可发布、
代码已经符合或性能已经达标**。以下项目不应被设计文字掩盖：

1. 作者设定尚未逐事实登记 `creator_fact_id`，发布时需要可审查的覆盖清单；居民稿中若同一粗地点
   标签同时覆盖外观与内部，或宽职业标签覆盖不同手艺，现有标签粒度不足；
   如 B-06 中“地下城内部”与“地下城门外观”同用 `[地点：地下城]`。要逐项找出、在上游
   Markdown 审定后重编精简 YAML，不能在程序里补隐形规则。
2. `build/genesis/knowledge/elfaria.yaml` 的来源全文 SHA 已与现行 Markdown 一致，但 161 条的原文、
   标签和关系仍需逐项机器核验与人工抽查；`build/genesis/program.yaml` 的知识引用版本仍是旧值，
   资料包仍为 `draft`，空间网格/人生活动/难度概率等目标数据尚需审定；其中个人名字词库仍含
   `Saevi/Tovren/Myelle` 这类正式物种名，发布前需检查并去除作为个人名字的误用。B-06 的“已审定的地点图、
   像素比例”与 E-08 的“初始化基础知识”还混有作者/实现视角：在“无标签直接取得、描述原文不改”的
   规则下会原样进入 Elfie 记忆，必须先由上游知识稿改成居民可知的事实或移出知识正文。
3. 目标 `config/genesis/` 与现行 Configuration 1.4 的 `config/world/` + `config/species/` 注册布局不同。
   正式采用前须走配置治理、成员 Schema/加载器/发行路径和一个生产入口的迁移；不得长期保留双路。
4. 现行编译器只消费旧 `WorldKnowledgeFact`，其活动地点集合和路线选择不足以证明真实行程；候选通用
   `personal_story` 在提交前展示。它们是待实施差距，不是本稿已实现能力。Myelle 仍受物种发布与
   视觉资产门禁约束。
5. 完整人生生成至可交互欢迎的端到端耗时未知。先采集逐段测量，再由产品确定等待预算，决定同步
   等待还是同一预约的后台准备；这只改变编排与界面等待方式，不改变“完整提交后才入驻”。

实施遵循**原地演进**：保留当前候选/邀请/预约、已接受身份冻结、Profile/Selfhood/Memory 最终所有者、
Admission 恢复与 source-first Recall；在现有 `elfie/genesis` 编译器、配置加载器和 Adoption/Admission
路径上分别扩充并替换旧资料输入。一个切片只证明一条生产路径，不建第二 Genesis、双写 Memory 或
提交后重放人生。用户确认本稿后，再按仓库文档治理把已采纳的技术目标移入正式设计；本文仍是审阅稿。

| 目标责任 | 现有所有者/路径 | 确认的缺口 | 最小原地改动 | 验收证据 |
