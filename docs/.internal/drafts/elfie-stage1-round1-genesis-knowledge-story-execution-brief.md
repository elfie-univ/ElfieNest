# 第一批任务历史开工文档：知识密度与故事/初始化包（OPT-001）

> 状态：冻结的 OPT-001 历史执行简报；对应实现与旧 E2/E3 门已关闭，不再作为新 Genesis
> 任务的开工合同。
>
> 本文对应基线后的优化轮次 1（`OPT-001`），不是第一阶段验收中的 `E1` 或 `E2`。
> 目标是让新领养的 Elfie 从第一次聊天开始，就拥有可探索、可追问、可溯源的异星知识、个人过去和关系骨架。
>
> 现行创建边界以 ADR-0033、Elfie 2.3、Brain 1.5 与
> [Genesis v0.2](./genesis-core-kernel-design-v0.2.md) 为准。本文旧有 Canon、Manifest、Profile
> 来源字段和提交后重放措辞只说明当时实现，不能覆盖现行契约。

## 1. 用户目标

用户第一次与新领养的 Elfie 聊天时，能连续询问它的母星、物种、家乡、生活和过去；它回答的是这只 Elfie 已经拥有的知识和经历，而不是地球常识、临时编造或几条孤立词条。重复追问、换一种问法和进程重启后，核心事实仍保持一致；超出已知范围时明确说不知道。

完成后，用户应该能感受到“它来到地球以前已经真实生活过”，并能通过聊天逐步认识它，而不是从领养当天才开始存在。

## 2. 范围边界

### 本批次要做

- 冻结可版本化的 World Canon、Species Canon、地区/生活知识和未知边界；
- 把批准的公共知识编译为该个体可检索的 `KnowledgeSeed[]`；
- 生成 3–5 个互相关联的 `EpisodeSeed[]`，形成最小人生图；
- 生成 `RelationshipSeed[]`，表达自我、重要人物和领养家庭的关系骨架；
- 通过现有 source-first Memory 路径导入知识、经历、关系和证据；
- 确保多种问法、重启和不同 Elfie 隔离后仍能正确召回；
- 在 Memory 成为内容主干后，移除 Reasoning/Selfhood 中重复的丰富世界知识注入。

### 明确不做

- 不做正常聊天的持续学习、实体消歧和纠正链（`OPT-002`）；
- 不做长期压缩、遗忘、归档和增长耐久性（`OPT-003`）；
- 不做真实精灵巢、身体观测、活动或多精灵互动（`OPT-004`）；
- 不新增向量数据库、第二套记忆库、顶层 Brain 模块或新的事实源；
- 不让 Memory 直接读取 Profile、Communication History 或世界运行时状态；
- 不把未定义的政治、地理、天气、巢内活动或个人细节编成硬事实；
- 不自动回填或改写真实既有 Elfie；首版以新领养和隔离开发数据验收。

## 3. 固定模型和权威边界

### 三类记忆输入

| 输入 | 内容 | 规则 |
| --- | --- | --- |
| `KnowledgeSeed[]` | 世界、物种、地区和生活的公共知识中，这只 Elfie 实际知道的部分 | 带 `scope/topic/alias/source/version/certainty/eligibility`；“知道”不等于亲历 |
| `EpisodeSeed[]` | 这只 Elfie 的领养前个人经历 | 3–5 个有顺序、人物、地点、结果、感受和影响的 Episode；历史发生时间与写入时间分开 |
| `RelationshipSeed[]` | 人物、地点及其他实体之间的关系骨架 | 带角色、方向、熟悉/信任、共同 Episode 和来源；不得只存一个主人节点 |

`ProfileDraft` 与 `SelfhoodSeed` 是 Genesis 的其他最终 owner 提交材料，不属于上述三类记忆内容：
Profile 只保存严格外部客观档案，Selfhood 保存 Brain 内部身份/人格。创建期版本、来源绑定和 Seed
随事务销毁；事务外最多保留不可重建人生的最小技术回执。`personal_story` 只能是正式 Memory Episode
的受限展示投影，不能成为第四个事实源。

### 世界知识与个体记忆

```text
版本化 World/Species Canon
        ↓ Genesis 个体化选择与校验
KnowledgeSeed + EpisodeSeed + RelationshipSeed
        ↓ source-first Memory
RecallBundle → Reasoning
```

Canon 是公共来源，不直接替代个体 Memory；Memory 保存“这只 Elfie 实际知道、经历过、认识谁”。没有当前巢内观测时，不能回答今天的具体位置、天气、动作或刚刚发生的巢内事件。

## 4. 内容和初始化要求

### 世界/物种知识

首版先冻结问题覆盖矩阵，再编写约 40–80 条可独立引用的原子事实，至少覆盖：

1. 世界身份、已知范围和与地球的关系；
2. 物理/自然、昼夜、季节和生态边界；
3. 地理、聚落、家乡和生活地点；
4. 物种身体、感知、习性和共同常识；
5. 家庭、朋友、长老、礼貌、信任等社会习惯；
6. 食物、休息、劳动、教育和日常生活；
7. 技术、通信、赴地计划以及已知的地球差异；
8. 明确的未知、未定义和未亲历范围。

条目数量不是完成标准；每条必须能被检索、带别名/检索词、来源和版本，并能说明是 `known/partial/heard/unknown` 哪种个体知识状态。世界共同事实不能伪装成个人亲历。

### 个人过去和关系

每只新领养 Elfie 的最小人生图必须具备：

- 一个明确的家乡/生活地点；
- 1–2 个在多个事件中出现的重要人物；
- 3–5 个有先后顺序的关键经历；
- 至少一条“过去经历 → 当前性格或选择”的影响链；
- 至少一个离开母星、加入赴地计划或抵达地球的经历；
- 关系骨架覆盖自我、原生重要人物和领养家庭，并能关联到 Episode；
- 不确定的日期使用 `life_stage/temporal_label`，不伪造精确日期。

这不是五张互不相干的故事卡；人物、地点、结果、感受和因果要能互相引用。未保存的细节必须保持未知，模型不能在追问时临时写入新事实。

## 5. 固定处理流程

```text
校验 World/Species 版本与未知边界
  → 选择批准的身份/出生或生活地点
  → 生成 KnowledgeSeed 个体已知子集
  → 生成有顺序的 EpisodeSeed 与 RelationshipSeed
  → 校验 Canon、物种、年龄、地点、时间线、引用和冲突
  → 生成稳定 ID 与 InitializationManifest
  → 先通过 source-first Memory 导入并完成原子可见
  → RecallBundle 按类型返回给 Reasoning
```

实现规则：

- Genesis 只在领养时运行；使用现有结构化 reveal/模型调用即可，不另造一个后台“补写人生”的事实路径；
- 模型可以生成候选，但确定性校验负责 Canon 一致性、引用完整性、时间顺序和边界；不合格时整包失败，不提交半套生命史；
- 所有节点、关系、Episode 和证据使用 Manifest/seed 派生的稳定 ID；同一 Manifest 重放只能 upsert，不能复制；
- `EpisodeSeed` 写成运行期普通 Episode 合同，后续真实经历沿用同一读链；
- 首选复用当前 schema、Adapter、`RecallRequest` 和 `RecallBundle`。需要新增表、字段、索引、系统级 Port 或真实数据迁移时，先停下并按持久化审批规则单独处理。

## 6. 实施工作包

1. **内容和配置盘点**：确认 `config/` 的注册、版本和加载边界；冻结八类主题的问题覆盖表、禁止虚构表和公开物种范围。
2. **知识编译**：实现 World/Species Canon → `KnowledgeSeed[]` 的类型化编译，保留 scope、topic、alias、source、version、certainty 和未知状态。
3. **传记包合同**：扩展 Genesis 输出，使 `EpisodeSeed[]` 有人物、地点、时间标签、结果、感受、影响和来源；使 `RelationshipSeed[]` 可关联 Episode。
4. **一致性和幂等导入**：校验年龄/物种/地点/时间线/Canon，使用 Manifest 稳定 ID，通过 source-first Memory 导入，保证崩溃和重放收敛。
5. **检索接线**：验证 Knowledge、Episode、Relationship 都能由现有有界文本/主题/实体检索命中，返回带真实来源的 typed `RecallBundle`；不依赖向量库或模型检索。
6. **Prompt 收敛**：确认 Memory 命中后，删除重复的丰富世界/物种 Prompt 注入，只保留身份锚点、Canon 版本和硬未知边界。
7. **跨物种和评测**：对所有当前 `published` 物种使用同一合同测试；更新 OPT-001 台账证据和未完成范围。

## 7. 验收与交付门

### 世界知识门

- 冻结题库中事实检索 top-k 命中率至少 95%；硬身份、物种合同和未知边界题 100% 正确；
- 未覆盖知识、地球实时问题和精灵巢当前问题的伪事实为 0；
- 每个核心问题至少两种改写，连续追问至少三轮，重启后答案不矛盾；
- 移除重复丰富 Prompt 后，答案仍能从 Memory 的真实 `KnowledgeSeed` 命中。

### 个人故事门

- 每个验收用的新领养 Elfie 有 3–5 个互相关联 Episode、一个家乡地点和 1–2 个重要人物；
- “住在哪里、认识谁、最开心/困难的经历、为什么来地球、经历如何影响现在”至少三类问题可独立召回；
- 反复问、改写问法、重启和重复初始化后，人物、地点、结果、时间标签和因果关系保持一致；
- 半套提交、重复节点、错误地点、伪造日期和未保存细节固化为事实均为 0。

### 交付证据

必须通过 `E2`（异星知识）及 `E3`（领养前人生），并回归 `E1`；机器硬门全部 100% 通过。历史评测报告可以记录候选 SHA、测试所用资料/策略修订、事务内 Seed、预期与实际 Memory ID、逐例结果、重启结果、失败证据和剩余项；这些测试证据不能进入已提交 Elfie。完成后明确保留给 `OPT-002/003/004` 的内容；不能把“有几条故事词条”或“模型说得像”当作完成证明。
