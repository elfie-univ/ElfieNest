# Genesis 完整设计

> 状态：压缩审阅稿，三步准备、五步生成不变。`geography.yaml` 已同步 10×10 地理单元、地点宿主格、旱路/水路拓扑、区内小路规则和已确认的逐跳通行天数。正式契约优先，实施差距见 6.3。

**阅读入口：第 1 章看全貌，第 2、3 章看流程；第 4、5 章查边界与验收，第 6 章只在实现时查阅。**

## 1. 整体流程与最终结果

Genesis 做两件事：先准备可反复使用的生成资料，再为每次领养生成一只身份、外貌、人格和过去相互一致的精灵。

~~~text
第一阶段：准备资料，一次准备、多次领养
① 撰写基础资料
   世界设定 + 物种资料 + 外貌规则/资产
        ↓
② 整理并形成生成资料
   居民知识 + 世界空间、物种外貌、个体生成规则（人读源稿）
        ↓
③ 编译、对照、校验、发布
   config/genesis/ 下的一份版本绑定 GenesisSourcePackage

第二阶段：生成个体，每次领养执行
① 用户选择与候选生成
        ↓
② 接受候选，冻结身份、外貌与人格锚点
        ↓
③ 生成人生轨迹（LifeContext）
        ↓
④ 生成个人知识、关系、经历与自我（PersonalGenesisPlan）
        ↓
⑤ 联合校验、提交并完成入驻
   Profile + Selfhood + Memory 等最终结果
~~~

两阶段只通过**已发布资料包**衔接。第二阶段不读未发布源稿；提交后的精灵也不再依赖创建资料。

| 最终所有者 | 保存什么 |
| --- | --- |
| Profile | 稳定身份、姓名、物种、适用的性别、年龄/来源锚点及最终虚拟外貌 |
| Selfhood | 不可变身份核心，以及有界人格、价值与交互/表达倾向 |
| Memory | 本人实际掌握的知识、生活事实、认识的人、关系、亲历与来源证据 |
| Body/Brain 对应所有者 | 既有契约要求的身体/感知约束和能力起点；不凭生活技能授予工具权限 |

Genesis 不负责日常学习、实时巢状态或持续生成新经历，也不接管 Godot 的几何、移动和渲染。

## 2. 第一阶段：准备并发布生成资料

### 2.1 第一步：撰写基础资料

造物者写清三类设定：

- **世界**：区域、聚落、地点、道路、自然、社会、历史、赴地背景与未知边界。
- **物种**：身体、感知、生命周期、生活条件与能力范围。
- **外貌**：生命阶段、体型比例、脸部、毛色/标记、可用参数与资产。

资料可附地图、表格和图片；影响后续生成的事实要有出处和审阅责任。此时不写某只精灵的家庭、职业、人格或记忆。

### 2.2 第二步：整理并形成生成资料

把基础资料整理成四类**人读源稿，以 Markdown 为主**：

| 源稿 | 要讲清什么 |
| --- | --- |
| 居民知识 | 居民可知的具体事实，以及听说、亲历、未知等认识边界 |
| 世界与空间规则 | 哪里可以出生、居住、通行和生活；地图、人口、道路及耗时依据 |
| 物种、生命阶段与外貌规则 | 可以生成哪些身份、年龄和外貌组合，需要哪些资产 |
| 个体生成规则 | 家庭照护、学习、职业、迁居、命名、关系、经历和赴地如何成立 |

四类是内容职责，不强制拆成四个文件。世界、物种和外貌中的可知事实共同进入居民知识；抽样规则和生成约束进入规则源稿。缺失的条件或来源矛盾在这里解决，不凭空补人口权重。

**居民知识：一段一个单元，需要限制时才加中括号。**

居民正文中的每个独立段落或列表项都是一个完整知识单元，**不论有无标签**；标题、编写说明和来源附录不算知识。正文直接写事实；不同取得条件不能整体表达时，由作者拆分，不由编译器按句子切碎。

使用现有标签：地点、路线、职业、经历、掌握难度。无标签即无附加限制；多个条件标签表示同时成立，可替代路径须另行写明。地点外观与内部、路线部分与全程要区分清楚。这里只写人读标签，机器字段在第三步转换。

本步交付源稿、附件和来源/覆盖说明：造物者资料按源章节绑定，居民知识按正文单元对应；未知或排除内容须说明理由。稳定单元锚点及 ID 对应关系由这份说明承载，规则见 6.4.5；此时不生成 YAML。

### 2.3 第三步：编译、对照、校验、发布

1. **编译**：居民知识逐项转成知识 YAML；空间、物种、外貌和个体规则转成相应配置，绑定来源与稳定 ID。
2. **对照**：检查“基础资料 → 人读源稿 → 配置”的覆盖；不得丢失、重复、改写事实或扩大知识范围。
3. **校验**：检查字段/单位/引用、未知与权限边界，并证明每个可领养物种和生命阶段都有合法人生及赴地路径。只有字段、没有地图人口或规则数据，不能通过。
4. **发布**：冻结版本、成员清单与摘要，形成不可变的逻辑资料包；更新资料必须发布新版本。

包入口固定为 `config/genesis/program.yaml`，其余 YAML 和资产由清单引用。目录、标签转换和发布规格见 6.4。

## 3. 第二阶段：生成具体精灵

### 3.1 第一步：用户选择与候选生成

依据已发布资料和用户偏好，每批目标生成 5 位彼此可区分、后续人生确实可行的候选；随后邀请其中 1～3 位，不把邀请人数当作候选总数。

**先解析选择，再生成实际个体。**

物种、生命阶段、性别、外貌方向/优先项和已注册扩展选项先校验；“不限”在这里解析成实际值，未注册自由文本不能变成新规则。没有可行组合就解释原因，不偷改用户硬选择。

候选依次确定实际物种、年龄/阶段、性别、已支持外貌、人格锚点和原生名。外貌使用同一个实际年龄；差异要能在已支持参数和人格方向上体现，不能只换随机种子。有限预算内不足目标数量，就展示实际数量或返回无解。

五个相处问题**只用于受控推导候选人格**，不直接决定出生地、家庭资源或社会阶层；接受后下游只拿冻结锚点，不再拿原始答案。人格倾向不能绕过年龄、训练或职业资格。

**展示前证明可行，不提前编人生。**

每个候选至少存在一条合法的出生、照护、学习和赴地路径。展示只描述已确定的身份、外貌与人格方向，不预告尚未生成的家庭或职业。外貌能力和命名校验见 6.5.1。

### 3.2 第二步：接受候选并冻结身份、外貌、人格锚点

用户完成邀请、回信确认和命名，从愿意接受邀请的候选中确认一位；这些交互属于本步，不另增阶段。

邀请沿用现有 Adoption 的确定性匹配规则，回复为“愿意”或“再想想”；**回复状态由程序决定，模型只负责措辞**。同一邀请重试复用同一结果，已公布的回复不能被重抽改写；具体匹配与无有效回复处理见 6.5.1。确认领养不等于建立多年信任。

接受时原子检查候选有效期、摘要、资料包可用性及领养资格，并形成唯一预约，冻结：

- 候选身份、年龄、外貌、人格锚点及最终显示名；
- 精灵/预约标识、领养关系引用、幂等键和时间锚点（含规则所需的出生时期）；
- 资料包、策略、编译器及初始化映射版本、种子和私有创建工作区。

这些技术输入只放创建封套 `GenesisCompileEnvelope`。重复点击、恢复和重试只能继续这一次预约，不能换候选或重抽身份。原始问卷和邀请原文不进入人生轨迹、叙事模型或长期个人记忆。

### 3.3 第三步：生成人生轨迹

先把“在哪里、何时、和谁、具备什么条件”确定下来，再生成个人故事。

**出生位置 → 家庭照护 → 学习训练 → 职业/生活角色 → 居住与出行 → 赴地安排。**

这条链按时期推进：选学校、导师、工作或迁居时，就检查当时的住所、年龄、照护和路网，不在最后补一条路线来解释不可能的人生。

**出生地怎样影响后续资料。**

从已确认的可居住网格/地点中，按用户选择的物种均匀抽取允许区域，再在该区域内均匀抽取网格；区域名单是硬约束，不按镇中心、村落或逐格人口调权。绑定公共区域/聚落及合法私人住所。使用的是 Elfaria 地理资料，不是用户现实定位。

出生地给出当地的家庭、设施、教育和劳动机会；这些条件与年龄共同决定后续选择。它不直接决定人格、职业，也不自动赋予全区域知识。抽样分布、私人地点和路程计算见 6.5.2。

**生活轨迹必须在时间与空间上成立。**

- 家庭先确定成员/照护槽位，学习和工作必须有可达设施、导师及足够年限；未适龄或无资历者保持学习/无职业状态。
- 迁居有原因和连续时间线，不能同时在远处上学、工作。能力来自物种边界与实际训练，不由模型直接赋值。
- 日常可达不等于实际去过；地点区分听说、看见外观、进入、使用，路线区分部分和全程。接触事实必须有活动或行程支持。
- 赴地年龄至少 2 岁，并满足照护、本人同意和一次 3 个本地日的简单准备；不设置课程/模块体系。真实入驻、房间、当前位置和后续动作不由生成器提前虚构。

年龄沿用 V3 的简化口径：**在 Elfaria 生活了 5 年，就按 5 岁理解**，不按当地日长换算。到地球后每过一个地球年加一岁；本地日历用于生活/旅行时序，不另改年龄。缺少精确生日时保留未知，显示用日期须标“年龄投影”。

结果为 `LifeContext`：身份、出生居住、家庭、学习、职业、活动/行程、赴地安排及**允许的事件槽位**。槽位限定时间、地点、人物、前提和结果范围，不表示事件已经发生；第四步只能在这些范围内实现事件。结构见 6.5.3。

### 3.4 第四步：生成个人知识、关系、经历与自我

沿人生时间线完成：**判断当时知识 → 落实可接触人物 → 实现事件 → 更新知识和关系 → 形成自我投影**。

**知识只取本人有资格掌握的整条内容。**

无条件、无难度的知识必得；有条件先检查实际生活证据，有难度再按固定概率抽取。每条知识只有“取得完整正文／未取得”，不生成删节版；同一知识只用一个稳定随机值，重试或多个事件不能反复抽奖。听说、传说和未知边界按原文保留，难度不是事实可信度。

按时间记录已知内容：事件只能使用发生前已掌握的知识；新知识在学习或事件之后才可使用。不能以事件结果满足它自己的前提，也不能把领养时知道的事倒推成童年就会。必修培训和必达知识不得概率漏掉。

若事件没有取得后续职业必需的能力，就使依赖该能力的选择失效，回到第三步有界重算；不能靠补写故事保住不成立的职业。

**人物与经历从已有生活中产生。**

人物来自家庭、邻里、学习、工作和赴地接触槽位；年龄、地点、能力和关系方向必须相容。熟悉不等于信任，知道公共人物不等于认识本人，同名也不能跨精灵合并。

人物随家庭、学习和实际接触形成，不凑人数、不强造创伤。先以完整 Episode 覆盖实际发生的必要培训、出发、抵达和领养事件，再安排其他往事；每段写清时地人、过程、结果与影响。通常至少五段经历，幼体按实际生活减少，不设固定上限。住所、学习等非叙事生活事实仍须完整保留，不能替代必需事件的 Episode。

**自我与介绍分别处理。**

Selfhood 接收完整的身份核心和有界人格/价值/表达倾向，使用其所有者审阅的确定性映射；不能把故事、问卷或当前情绪塞进去，也不能反向改写已接受的人格锚点。经历与可变的人生认识归 Memory。

个人介绍只需回答：我是谁、来自哪里、过去与谁生活、一件确有的经历、为何来到这里；幼龄无适用经历时省略，不编造。程序先给规范摘要，模型可润色；经验证的经历措辞随对应 Episode 保存，欢迎页短介绍只临时投影已提交事实，不另存一份传记。

本步输出 `PersonalGenesisPlan`，汇总知识、人物/关系、事件、Selfhood 与提交证据。字段、知识时序和 Memory 交接见 6.5。

### 3.5 第五步：联合校验、提交并完成入驻

**先校验完整人生，再一次对外可见。**

联合检查冻结身份、时空可行性、人物关系、知识资格/取得时间、事件因果和最终所有权。通过后形成一次性 `GenesisBundle`，分别交给 Profile、Selfhood、Memory 及已登记的其他所有者。Memory 正式入口只接收知识、关系、经历三类 Seed；地点和生活命题须先归入这三类，不能另开写库入口。

**“完成生成”不等于“完成入驻”。**

Admission 协调三项持久结果：最终个体资料、Adoption 领养关系/额度、Nest 接纳/床位。三者都确认、资料可重开后才标记 `committed`，正式欢迎并开放交互；账户额度不是 Nest 床位。

最终文件已发布但 Nest 尚未接纳，仍是“入驻处理中”。只有上述提交已完成、后续运行连接失败，才显示“已入驻、正在连接”，并从最终所有者恢复。

接受后由同一预约驱动后台可恢复任务，前端显示当前阶段；关页再回来继续同一次创建。失败区分可重试和终止，不能以“重试”为名另造一只。成功或终止后清除问卷、封套、人生计划、Seed 和源包绑定，只保留正式事实/证据与最小技术回执。发布、取消和崩溃窗口见 6.7。

**把整条链连起来看。**

例如：在物种允许的区域中均匀抽取出生区域，再在其中均匀抽取网格 → 依据真实居住条件形成家庭与可选学徒经历 → 只在实际师傅、地点和时长成立时记录学习 → 经历只引用真实参与者 → 分别写入知识、关系、经历 → 正式召回。若当地没有可行条件，就不能补造学习、人物或经历。

## 4. 共同边界

### 4.1 版本与确定性

同一预约固定输入、身份/时间锚点、包、策略、编译器、所有者映射版本和种子，得到相同结构化事实或相同失败。措辞不决定事实；恢复复用已暂存文本。无解只在有限预算内回溯未冻结选择，不改身份和用户硬约束，算法见 6.6。

新包只影响未来候选；旧包须保留到相关预约结束。摘要不符或所需版本不可用时停止，不自动换包。显式撤销与最终激活按 6.7 的同一提交边界判定先后：撤销先发生则不再激活并补偿，激活先发生则保留已提交精灵，不刷新、重生或删除。

### 4.2 模型只表达，不决定事实

每次只给模型一个已批准的叙事视图、允许事实及引用，不发送完整计划、种子、隐藏坐标/权重、未选知识、邀请原文或其他精灵资料。用户字符串与源正文都是数据，不是指令。

输出逐项检查实体、数字、时间、引用和禁止事实；不能证明的细节丢弃，失败用规范摘要。模型不决定身份、人生、知识、关系、参数或权限；关键词检查不能代替事实校验。

### 4.3 提交后只认最终所有者

App 展示档案可读 Profile；普通 Brain 只读 Selfhood、Memory 和当前状态，**不读 Profile、Canon 或创建资料**。记忆沿正式 Memory → RecallBundle → Reasoning 路径使用，保留来源、时间与未知边界。

删除创建工作区/旧源包后仍可恢复，正式 Memory Evidence 不随临时资料删除。正常重启检查当前合法快照，不按出生时清单重建已经学习/变化的记忆。运行时资产仍由既有 resolver 解析最终外貌，资产缺失要报错，不能重抽外貌。

没有真实感知、工具结果或动作回执，就不知道当前位置、天气、当天活动或其他精灵状态；生成故事不能补这些实时事实。

## 5. 验收与实施准备

### 5.1 每一步必须证明什么

| 范围 | 验收重点与反例 |
| --- | --- |
| 资料撰写/整理 | 三类基础资料按源章节绑定四类源稿，居民知识按单元核对；无标签列表也入知识，说明文字不误入 |
| 编译发布 | 逐单元对应、ID 稳定、引用/版本/资产闭合；漏项、改写、未知范围被补全均拒绝 |
| 候选 | 符合硬选择且存在合法人生；未支持外貌、无照护幼体、无可行赴地组合不得展示 |
| 接受 | 回复与冻结结果稳定；并发点击、包切换、重复邀请不改变候选或多占额度 |
| 人生轨迹 | 出生分布与时空约束成立；零权重、断路、超时、设施缺失、亲属年龄冲突不能用默认值掩盖 |
| 个人内容 | 知识不越权、不反复抽奖、不倒流；师生接触不等于学会全部技能，事件不能自证前提 |
| 人物与叙事 | 不串联同名私人身份，不以领养推定亲密；必需事件先占 Episode 额度，不凑人数/经历、不让模型新增事实 |
| 最终交接 | Selfhood 完整可投影，三类 Memory submission 覆盖必要生活事实；地点/索引/Evidence 不泄漏未选知识 |

| 运行与断源 | 正式 Recall 能找到知识、人物、地点与经历；断开源包、新包发布都不改写已有精灵 |

### 5.3 怎样证明完成

- **覆盖**：每个发布物种 × 允许生命阶段 × 至少三个固定种子，另测年龄端点、明确/不限选项、概率 0/1、零权重和条件反例。结构约束全通过，越权知识与重复提交为零。
- **分布与体验**：出生分布、候选差异和知识比例使用事先审阅的样本量/容差，不测后改阈值；性能、冷启动、取消、并发和每个发布中断窗口分别验收。
- **记忆闭环**：验证三类 Seed 到最终记录/Evidence，再到正式 Recall；包括同义问法、稀有知识、人物/地点引用与时间先后，不只搜原文。断源测试保留必要运行时资产，资产缺失另测明确诊断。
- **证据与隐私**：发布保留清单/摘要/双向覆盖；隔离测试保留合成输入、版本、种子、各步摘要及恢复/召回结果。真实创建结束后只保留最终事实和最小回执，不把问卷、计划或种子留在日志、备份和错误附件。
- **收口**：在对应 Conformance 按 target、inventory、references、verification、residuals 记录证据和剩余项。设计审阅通过、资料可发布、代码/运行验收完成是三种状态，不能混称“最终完成”。

### 5.4 地理配置与路网验证门

地理资料在进入发布包前按固定顺序验证：

1. **结构**：只有一个 `geography.yaml`；恰好 100 个唯一网格，行列覆盖 `0..9`。区域矩阵为单一事实源，地形、可居住性、出生资格和物种资格按区域规则派生；不另存逐格人口数字。
2. **引用**：所有地点的宿主格/区域、道路节点和渡口都能解析到已登记单元；同格多地点不被合并；区域对象不被当成单点。
3. **旱路拓扑**：16 条路径逐项复核；派生结果必须是 32 个节点、35 条双向边；不存在未声明的跨区小路、湖面旱路或自动邻接边。
4. **水路拓扑**：渡口必须正好是 `R3C5、R1C5、R4C7、R0C7`，派生 6 条双向水路边；湖心岛通过普通渡运连接。
5. **可达性**：83 个可出生单元均须从迷雾镇中心可达；景点和设施按其实际通行方式校验，云冠城属于只能观测、不可进入的例外。
6. **时间与边界**：主路链中每对连续格计一个陆路跳数，区内四方向相邻小路也计一个跳数；每跳按 2 步行日计算，水域跳数按每跳 3 水行日计算。禁止公里、像素和直线距离；跨区只走显式主路或水路。
7. **人口与物种**：用户先选物种，再从该物种允许的区域均匀选一区域、再从该区域均匀选一格；中心不另加概率，人口不逐格分摊。物种分区名单是硬约束。
8. **人审对照**：将配置路网叠加到原始 Surface Map，逐条确认红线骨干、蓝线水路、四个渡口和所有地标；图片只做审阅证据，不能反向改写已确认拓扑。

| `species/catalog.yaml` | 文档/目录版本、技术 ID、正式显示名、状态及三个成员引用 |
| `species.yaml` | 版本、身份、身体/感知边界及资产语义引用 |
| `generation.yaml` | 版本、生命阶段、出生资格、区域因子及必要先验 |
| `appearance.yaml` / 资产 | 版本、控制范围、组合约束、可区分展示资源与 3D 语义绑定 |

全局地图、道路和人生规则只放共享规则；物种成员只加物种约束，不复制地图或个人事实。Godot 几何/导航/渲染、Selfhood 模板、Memory Retention、工具权限、Nest 当前状态和运行时默认值不搬进包。

新包的物种目录使用正式名 `saevi / tovren / myelle`；catalog 显式映射既有技术 ID `fox / dog / cat`。目录名不再借用动物名，技术 ID 与 Godot 绑定不随目录改名。旧运行配置路径已随生产切换移除。

  path: <resident-knowledge-source>

每个居民正文单元映射一条记录，无标签列表与段落同样处理。`description` 保留完整原文；允许规范化换行、列表符号和标签前缀，不改词句、事实或认识边界。不额外添加标题、主题分组、空属性、生成默认值或部分正文。

| 人读标注 | 机器表示 |
| --- | --- |
| `[地点：镇中心]`、`[路线：镇中心—Saevi 部落中心]` | `place / route`：登记 ID 和所需接触强度、路段范围 |
| `[职业：医者]`、`[经历：赴地]` | `vocation / experience`：实际工种/熟练程度或活动完成状态；培训也归 experience |
| 多个条件 / 明确的可替代路径 | `all / any`；不得推测替代路径或合并不同正文 |
| `[掌握难度：中等]` | `mastery_difficulty`；概率表归版本化策略，不是资格或 Confidence |
| 无标签 | 省略限制字段 |

`eligibility` 只允许以上四类叶子的声明式布尔树。名称须唯一解析到登记 ID；看外观、进入、使用及部分/完整路线分别判定。空树、未知操作符、悬空 ID、歧义、循环依赖或不支持的难度均阻止发布，返回源稿修正；居民稿不维护机器条件程序。

### 6.4.4 地理单一事实源、网格表与道路拓扑

地理资料只保留一个机器事实源：`config/genesis/knowledge/geography.yaml`。区域矩阵、地点、旱路/水路拓扑、均匀抽样规则和通行时间都从这个文件读取；人口不逐格分摊，特殊通道不建模。`program.yaml` 只登记入口、成员、版本和摘要，不复制地理字段。

地图图片只用于人审和来源对照，不用于从像素推导人口、坐标或道路。用户给出的 R/C 路径表是道路拓扑来源；原图红线/蓝线只验证它是否画对。

文件的顶层组织固定为“元数据 → 10×10 分区矩阵 → 区域规则 → 地点 → 路网 → 抽样与通行规则 → 校验摘要”；派生格属性由矩阵和区域规则计算，不复制出 100 份逐格人口记录：

~~~yaml
document_kind: geography_knowledge
schema_version: <integer>
knowledge_version: <version>
source_refs: [...]
grid:
  dimensions: [10, 10]
  region_matrix: [...]      # 唯一 100 格分区事实；格属性按 regions 派生
regions: [...]              # 区域地形、可居住性和物种硬性名单
places: [...]               # 点、区域和设施；区域引用分区或网格集合
network:
  land_backbone_paths: [...]
  water: {ferries: [...], edges: [...]}
  local_road_policy: {...}
population: {...}           # 用户选物种→均匀选允许区域→均匀选该区网格
travel_policy: {...}        # 每陆路跳 2 步行日；每水域跳 3 水行日
validation: {...}            # 网格、引用、路网边数和可达性校验
~~~

#### 网格分区

固定 10×10，共 100 个抽样单元。行号 `r0→r9` 为南到北，列号 `c0→c9` 为西到东。每个单元都有稳定 ID，例如 `u-r05-c04`，显示坐标为 `R5C4`。

分区只允许使用以下两级字段：

| 派生字段 | 含义 |
| --- | --- |
| `region_id` | 网格所属的最终子区：`A1/A2/B/C1/C2/C3/D/E/X` |
| `macro_region` / `terrain` | 从区域定义取得的大类和地形；不逐格重复维护 |
| `component_id` | 地表、水域、岛屿或外部组件归属 |
| `habitable` / `birth_eligible` / `allowed_species` | 从区域硬规则推导；不得由概率权重覆盖 |
| `place_ids` / `backbone_node` / `ferry_node` | 从显式地点、主路和渡口记录推导 |
| `local_road_eligibility` | 按同区、四方向相邻与河湖阻断规则计算 |

不展开成 100 条重复记录。`region_matrix` 是网格分区的唯一源；格子属性由区域定义和明确列出的地点、路网规则推导。人口抽样只用物种硬名单及均匀规则，不维护人口数、中心概率或逐格权重：

R5C4 的派生视图示意：`region_id=D`、`macro_region=mixed`、`terrain=mixed_settlement`、
`component_id=mainland_surface`、`birth_eligible=true`、`allowed_species=[Saevi,Tovren,Myelle]`；
`place_ids` 包含迷雾镇中心等同格地点，`backbone_node=true`。这些属性从矩阵、区域规则、
地点和路网计算，不保存成额外的 100 行数据。

地点条目只保存地点 ID 与单点格或范围格；同一网格可以有镇、区域、景点、渡口等多个地点，
不能因为同格就合并成一个地点。镇和澄心湖这种范围对象仍表示为区域/格集合，不能伪装成单点。

#### 道路拓扑

道路图以网格节点为基础，边必须显式登记或由明确规则生成。相邻网格不自动连路，直线距离、地图像素和“最近地点”不能补路。

**旱路骨干**：地理来源文档中的 16 条有序链是权威输入；程序只把每对连续格派生为双向边，不从坐标插入未声明格。共得到 32 个唯一骨干节点和 35 条唯一双向边。

~~~yaml
land_backbone_paths:
  - [R8C3, R7C3, R6C3]
  - [R6C3, R5C2, R4C2, R4C3]
  - [R6C3, R6C4, R5C4]
  - [R7C4, R6C4, R5C4]
  - [R5C4, R6C5, R5C6, R4C6, R4C7, R5C8]
  - [R5C4, R4C3]
  - [R4C3, R3C2, R2C2]
  - [R4C3, R3C3, R3C4]
  - [R5C4, R4C4, R3C4]
  - [R5C4, R4C5, R3C5]
  - [R3C4, R2C3, R1C3, R0C3]
  - [R3C4, R2C4, R2C5, R1C5]
  - [R0C3, R1C4, R1C5]
  - [R1C5, R0C3, R0C7]
  - [R0C7, R0C8, R0C9]
  - [R3C1, R3C2]
~~~

主路链一对连续格就是一个路网跳数；不插入未声明经过格，也不凭坐标跨格数另造边。

**区内小路**：只在同一 `subregion_id` 内生成，且必须满足：两个网格四方向相邻、都是可通行陆地、没有河流/湖面/禁行边、两格都允许小路。每个小路连接计一个跳数；跨子区、跨大类或跨水面不得以普通邻接补路。

**水路**：渡口固定为 `R3C5、R1C5、R4C7、R0C7`。四个渡口彼此互通，程序派生 6 条双向水路边。湖面单元不生成旱路边；湖心岛是普通水路目的地。水路每水域网格跳数计 3 个水行日，并需船或渡运，成本由上层服务规则处理。

不另设特殊通道或特殊边：湖心岛走普通渡运；地下城不属于当前地表路网；云冠城只能观测、不能访问。

#### 通行时间与寻路

道路不再以 `distance_km` 作为运行字段。时间不逐边人工填一套公里换算值，而按合法路网跳数统一计算：

~~~yaml
travel_policy:
  land_days_per_grid_hop: 2
  water_days_per_grid_hop: 3
~~~

旱路每个合法跳数计 2 个步行日；水路每个水域跳数计 3 个水行日，必须有船或渡运，服务成本由上层处理。骨干路径按链中连续节点计跳，不按坐标插入途经格；区内小路按四方向相邻连接计跳。地图像素和公里数均不参与计算。

寻路固定为：

1. 把出生单元、住所、景点或设施解析到其宿主网格/地点节点；同格地点保留各自节点。
2. 合并旱路骨干、合法区内小路和水路。
3. 水路须有可用船只或渡运；云冠城和地下城不由地表图接入。
4. 按边跳数对应的步行日/水行日计算最短合法路径；等价路径按稳定边 ID 决胜。
5. 返回网格序列、边序列和步行日/水行日；没有路径就返回 `unreachable` 及原因，绝不自动补边。

因此，出生地生成先按用户选择的物种均匀抽取允许区域，再在该区域内均匀抽取合格网格；不按居民中心、村落或逐格人口调整概率。地点归属与路网另由同一文件查询，不各自维护距离表。

地图逐张登记 `map_id`、版本、父图、语义范围、覆盖状态、坐标系/单位、独立边界、锚点、比例/分辨率、图层、资产/来源、生成器版本和审阅状态。子图不套用父图整幅边界；示意图标明不可测距，像素不能证明距离、人口或设施。

不把公里坐标、地图尺度或像素长度当作运行时通行输入。镇区、部族中心和村落是网格内的地点，不额外改变格子抽样概率；10×10 单元不是公共地名。未知区域可以保留，但可领养组合必须在已确认区域有完整路径，矩阵、地点和路网须实际齐备。

源稿的生命周期、亲属年龄、学习年限和历史年龄统一映射到 3.3 的一对一年龄口径；日历、旅行时长使用声明的本地单位，不用 `196 天 × 40 小时` 重算年龄，也不把地球领养时间伪装成本地生日。

领养候选与实际赴地年龄必须严格大于 1 个本地年；当前年龄为整数，最小是 2 岁。赴地前只需本人同意并完成一次 3 个本地日的简单培训，随后记录真实出发和抵达；不增加课程体系、陪同者或接收交接人。培训事实可写入个人经历，规则本身不进 Memory。

**6.4.5 来源、稳定 ID 与发布**

`coverage` 复用第二步的来源/覆盖说明，保存造物者**源章节 ID → 规则/成员引用**，以及居民**知识单元 ID → 源稿锚点 → YAML 单元 → 保留/未知/排除结论**。造物者来源绑定是章节粒度，不宣称逐事实 ID 覆盖；不另建平行账本。

居民源稿用紧邻单元的不可见 HTML 注释 `<!-- unit:<stable-anchor> -->` 固定锚点，锚点不属于正文/标签，也不产生知识。编译器只消费已审阅的锚点—ID 对应表；缺失、重复或无法定位时停止，不能由行号、段落序号或全文哈希重新造 ID。排版/重排保留 ID；语义修改升级版本，拆分/合并/删除在同一覆盖说明中记录旧新关系，供后续创建使用。

源资料发布对照同时证明“造物者源章节 → 规则/成员”和“每个居民正文单元 → YAML”。居民知识逐项区分完整保留、等义整理、缺失、失真和有理由排除；原稿到 YAML 不做措辞改写。漏项、重项、孤儿项、无源章节或来源摘要不符均阻止源资料发布；生产激活另需强类型消费者与语义/可行性验收。

`manifest` 显式列出相对路径、类型、成员版本、字节摘要、来源/覆盖引用与发布状态；二进制资产绑定所属成员版本。不同成员可有不同版本，但 Schema 必须兼容。拒绝缺件、重复路径、未声明必需资产、绝对路径、`..` 越界、符号链接逃逸和运行时网络补件。

总包摘要由规范入口内容及排序后的成员摘要计算，排除自身摘要；入口不递归列为自己的成员。源稿摘要只用于审阅溯源，发布包运行所需内容必须自足。接受冻结整个包及成员摘要，不只冻结知识文件。

物种技术 ID 与正式显示名由 catalog 映射；源包发布不改变物种可领养状态。`draft` 不可领养，`published` 须资料/校验/展示资产齐备，`retired` 不再新领养但已有 Profile 的运行资产仍须可解析。

### 6.5 个体生成与最终交接

**6.5.1 候选、名字与邀请**

外貌遵循现行外貌设计和物种资产契约：候选/赴地年龄至少 2 岁，实际年龄贯穿身份、外貌与生命阶段；使用已发布支持集中的颜色、局部色块/安全标记和年龄比例。Saevi/Tovren 的渲染与阶段外貌由用户决定免于复验、按人工接受处理；技术记录仍是首次受控启动在解析阶段失败，修正后的脚本未重新渲染。Myelle 仍因缺少正式运行模型而未完成。未实现的 morph、全脸变形或跨身体花纹不展示为选项。

原生名按物种规则稳定抽取，最终显示名由用户确认；校验长度、Unicode、控制符和保留词/分隔符。名字是数据，不是提示词或去重键。

本版**保留现有 Adoption 匹配行为**：一次邀请 1–3 位候选，按会话/候选的稳定评分与 0.8 门槛产生愿意名单；全未命中时由稳定保底评分选一位。该规则在公布回复前执行并绑定匹配策略版本，不改写已经公布的“再想想”。这里的双向确认是产品匹配结果加用户确认，不是模型自主作出的情感承诺。

只有有效的 `accepted` 候选可预约，`unsure` 不可接受。同一候选集重复提交相同邀请返回原回复，改变已发送邀请则拒绝；过期、包撤销或邀请校验失败不制造保底回复，而是提示重新选择/发起。邀请匹配归 Adoption，不进入人生生成规则或个人记忆；公布后因候选失效而无人可接受时，同样返回选择，不改旧回复。

**6.5.2 出生抽样与活动地图**

用户先选物种；系统在该物种允许的区域中均匀抽一个区域，再在区域内均匀抽一个可出生网格。镇中心、部落中心不额外加权，网格不保存人口计数；区域名单是硬约束。之后再检查住所、照护和完整人生路径；没有合法组合就报告无解，不吸附到最近地点。

单次抽网格或先按网格权重和抽区域、再条件抽网格，必须同分布。区域、聚落、坐标不能独立抽到矛盾结果，也不能把非法点吸附到最近城镇。私人住所只从当地许可原型实例化，ID 属本精灵命名空间；不新增公共村落、道路或设施。精确位置仅供生成校验，回忆使用本人可知地名/位置关系。

日常可达范围按每段居住期的年龄、照护、职责、地形、交通和往返预算计算。远行记录目的、同行/照护、权限、起止时间、方式、连接段、路网分段、休息与停留：

`行程时间 = 陆路跳数 × 2 步行日 + 水路跳数 × 3 水行日`。同格地点之间不另加距离；行程停留只有实际规则要求时才另计。

网格不是按地图比例测距。每个陆路跳数固定 2 个步行日，每个水路跳数固定 3 个水行日；渡运需要船或渡运服务，费用另由上层处理。当前没有按地形、负重、季节或天气调整天数的规则，不得擅加修正。

寻路使用同一份 `geography.yaml`：

- 旱路骨干使用 16 条有序路径派生的 32 个节点和 35 条双向边；
- 同一 `subregion_id` 内的四方向相邻可通行网格，才允许生成区内小路；
- 跨小区、跨大类或跨河湖，只能使用显式骨干或水路；湖心岛用普通渡运，云冠城不可访问；
- 每条路径返回网格序列、边 ID 和步行天/水行天；
- 无合法路径返回 `unreachable` 和阻断原因，不用“最近地点”“最近主路”或坐标直线距离补救。

接触值为 `heard_of / seen_exterior / entered / used`；路线保留实际路段与全程标记。经过不等于进入，赴镇培训不倒推童年就读，未知地下/古树/山地通路不从图像或传说补齐。

| `learning / vocation` | 一名真实师傅、一项手艺、实际学徒年限与师傅确认的操作能力；角色、熟练程度与工作点 |
| `mobility` | 居住区间、日常范围、行程分段、地点接触和路线穿越 |

不适用项明确为空；槽位只是可能事件，只有落实后的事实才能证明知识或关系。需要事件结果才能成立的学习/职业状态暂为受约束计划，不可提前作为完成证据；实现失败按 6.6 使依赖项失效并回溯。

家庭亲属年龄必须相容，需照护者有人照护；不套地球性别分工。导师只能教自己具备且实际教授的内容，知道方法不等于能执行。Body/Brain 只有既有契约明确接收时才获得启动值，其余保留为知识/实践事实。

| 个人计划成员 | 最小内容 |
| --- | --- |
| `PersonPlan` | 稳定 ID、姓名、物种、年龄带、住所、角色/职业、可证能力、接触时段与来源槽位 |
| `RelationshipPlan` | 双方 ID、方向、角色、熟悉度、Trust、Importance、共同上下文及变化证据 |

私人 ID 由精灵 ID 与稳定槽位派生，公共人物沿审阅 ID 引用，领养者只沿真实产品关系引用；不合并同名，不伪造公共人物私交或跨实例社交。弱联系不必分配 Episode，经历也不必都有戏剧性冲突。

**6.5.4 知识、时序与 Selfhood**

| 条件 | 难度 | 取得规则 |
| --- | --- | --- |
| 无 | 无 | 确定取得 |
| 有 | 无 | 条件满足即取得 |
| 无 | 有 | 稳定概率抽取 |
| 有 | 有 | 先满足条件，再稳定概率抽取 |

无条件基础知识在领养完成时必须具备；受众不符要改上游条件，不在生成器暗删。不虚构师傅/日期；取得时间未知的知识不能支持必须证明早期技能的事件。完成学徒经历只证明师傅确认具备实际操作能力，不代表掌握所有相关知识。

时间推进为 `known_before → 校验事件前提 → 事件/学习事实 → 新知识及关系变化`。同一事件内部学习也须有先后。学习/事件规则可引用前置知识 ID，形成无环依赖，但不向居民知识偷偷增加第五类条件。缺少来源或前置事实时停止，不临时写剧情补足。

Selfhood 按其所有者版本交付完整强类型 `SelfhoodState`：

- `identity_core`：ID、显示名、正式物种、来源世界/区域和固定居民角色，与 Profile 一致。
- `adaptive_self`：有界 Big Five、交互/应对/表达倾向、规范/价值及可选语言标记，仅经闭集映射初始化。

不包含经历全文、百科、当前关系/情绪/能量、能力权限、问卷、包绑定或最终提示词；本版不增运行时人格成长通道。缺字段、越界、未知映射或无法生成正式提示词投影即失败，不用全 0.5、通用人格、Profile 回读或模型修复兜底。

叙事按 `episode_id / fact_id` 返回措辞，仅取允许知识、时序、人物、感受范围与感官线索。规范摘要独立可用；采用的经验证措辞与 Episode 事实/Evidence 一同提交，不取代结构化权威。欢迎介绍由最终档案展示、自我和记忆的授权投影组合，不让普通 Brain 绕读 Profile。创建期投影版本/哈希绑定 Plan；恢复复用，终态删除，不新增长期自传。

**6.5.5 Bundle → 三类 Memory submission → 最终记录**

Bundle 是一次性强类型载荷：`ProfileDraft`、完整 `SelfhoodState`、三类 Memory Seed、契约要求的其他启动 Seed，以及 `InitializationManifest`。地点与个人事实可在编译中暂用 `PlaceSeed / SelfModelSeed`，但**不是额外的正式 submission 家族**。

| 生成内容 | 正式 Memory 输入 | Memory 物化 |
| --- | --- | --- |
| 已掌握居民知识 | `KnowledgeSeed`：稳定知识 ID、完整正文、取得阶段/类别、认识边界与本地证据 | 知识 Node / Assertion / Evidence |
| 非叙事生活命题：住所、学习、培训、自我认识等 | `KnowledgeSeed` 的本人已知事实投影，个人命名空间与来源范围区别于居民目录；不新增公共知识条目 | 有主体/关系/客体、时间区间或未知时间的 Assertion / Evidence |
| 人物与关系 | `RelationshipSeed`：人物身份、方向/角色、熟悉度、Trust、显著性、共同上下文及证据 | 人物 Node 与关系 Assertion / Evidence |
| 完整关键经历及其中事件命题 | `EpisodeSeed`：完整规范摘要/已采用措辞，时地人、结果、影响、因果与证据 | ClosedEpisode / Evidence，及其受证命题 |
| 本人知道或接触的地点 | 随以上三类 Seed 的类型化地点引用/受证描述携带，不独立提交 PlaceSeed | 地点 Node 与有依据的关系；知道名称不生成到访事实 |

KnowledgeSeed 的个人事实投影不承载另一份长篇传记；经历仍以完整 Episode 保存。现有代码把 KnowledgeSeed 限于居民知识的类型约束须按 6.3 调整，不能直接向旧入口塞入新结构。正式入口仍遵守 Memory 的三家族契约，不由 Genesis 写表。

地点引用包含稳定 ID、名称/审核别名、种类、父地点、公共/私人属性及本人可知描述；私人生活命题包含稳定 ID、事实、时段、取得/实践证据及相关人物/地点。所有需要记住的生活事实都必须有此映射，不能整存 LifeContext，也不能因未单列为 Episode 而丢弃。

`source_kind` 表示取得类别，`source_ref` 指向提交后仍在的本地 Evidence/事件，`record_schema_version` 表示最终记录格式。证据保留已选正文、必要人物/时间及语义来源，不保留整份源稿、条件树、抽取权重或随机数；公共知识 ID 是身份，不是回读包的外键。

Genesis 提供受规则限制的 Node/Assertion Confidence、Importance 和 Episode Importance；Episode 本身无 Confidence，Trust 与 Confidence 分开。Memory 校验并应用其正式 Genesis Retention 准入，拥有索引、强化与衰减；不恢复 CFHO 或自定义保留规则。

每个对象的 `recall_eligible`、别名和检索词只依据已提交内容；人物能力、地点简介、索引和 Evidence 都不能夹带未选知识。RecallBundle 保留类型/稳定 ID、正文、相关性、人物/主题引用、本地来源、记录版本、时间/经历及不确定性；技术 marker、回执、Seed 和未采用草稿不可召回。

`InitializationManifest` 仅记录清单 ID/状态、编译器与输出 Schema、预期所有者、输出 ID/数量/摘要及检查结果；包/策略/Seed/输入摘要只由 Envelope 绑定，不逐 Seed 复制。Memory 在自身 Unit of Work 中校验、去重、提交完整记录和 marker，App 不绕过入口改库。

### 6.6 确定性与有界失败

**随机与摘要**

算法固定为 `sha256-domain-v1`：对 `[算法版本, master_seed, 领域, 稳定对象/槽位ID, 领域策略版本, attempt_id, draw_counter]` 的规范 JSON 做 SHA-256。UTF-8、Unicode NFC、无额外空格、非 ASCII 直接编码；摘要按大端无符号整数解释。种子为 32 字节的小写十六进制，计数从零开始。

候选、年龄、外貌、人格、命名、出生、家庭、学习、职业、迁居/行程、人物、事件和知识 ID 各用独立领域。知识 `attempt_id=0`；回溯只重判资格，不重抽掌握概率。禁止进程随机哈希、无序遍历或共享推进的全局随机流。

离散项按稳定 ID 排序，用非负整数累计区间，总权重 `W∈[1,2^64−1]`。摘要整数须小于 `2^256−(2^256 mod W)` 才取模 W；拒绝时只增加本次 counter，受有限抽取预算限制。概率用审阅后的整数分子/分母同法判定，0/1 直接处理；非法/全零权重发布时拒绝，编译器与发布工具共用固定测试向量。

语义摘要统一 NFC、对象键排序、集合按 ID 排序、时间线保序、数字声明整数精度/单位、时间声明时区/精度，拒绝 NaN/Infinity。包含冻结身份、学习/事件的业务状态和发生时间；仅排除摘要自身、创建任务的非语义状态/技术完成时间、耗时、机器路径、日志及模型措辞。经历发生时间与数据库写入时间分开。源字节、语义内容、模型投影和最终文件摘要分别命名；模型投影绑定不可变 Plan，不能反过来影响 ID 或事实。

**回溯与错误**

回溯顺序：本槽位其他合法选项 → 直接上游未冻结选择 → 更上游生活骨架。修改后只作废依赖它的行程、人物、知识、事件和自我投影；`attempt_id` 稳定递增，预算固定。身份、年龄、外貌、人格锚点和用户硬选择不可回溯，也不能临时扩大预算或换种子。

| 错误 | 处理 |
| --- | --- |
| 输入/候选无效 | 接受前返回可修正原因，不建预约 |
| 包、版本、引用或必修内容错误 | 定位成员/规则并停止；不替换为别的包 |
| 约束无解 | 有界回溯后返回矛盾条件、规则 ID 和阶段，不套默认人生 |
| 模型投影无效 | 丢弃文本，用规范摘要，不重抽事实 |
| 存储/进程暂时失败 | 保持预约身份，核对已完成结果后继续 |
| 所有者校验/输出冲突 | 阻止可见，核验后决定恢复或终止 |
| 完整入驻后的连接失败 | 保持 committed，从最终所有者恢复 |

用户看到阶段、可重试性与可操作原因；日志只记脱敏错误码/规则 ID，不把技术故障写成人生经历。所需原编译器/映射版本不可取得时明确阻塞，不静默使用新版本。

### 6.7 入驻发布、恢复与清理

**发布顺序**

~~~text
reserved → compiling → staged → publishing → committed
~~~

1. **预留**：Adoption 原子预留成员额度，Nest 经自己的边界预留可用床位/接纳容量，均绑定同一预约；任一失败则撤销另一预留。Admission 不把两类额度合成自己的事实。
2. **暂存**：在私有工作区生成所有者资料。Memory 的正式 submission 将预期记录和 completion marker 在一个事务中提交；这里的提交不代表产品已经入驻。
3. **核验**：重开各所有者，校验引用、时序、知识、Selfhood 可投影性及清单/摘要；创建输入与最终文件分离。
4. **发布协调**：先将合法最终文件树在同一文件系统原子发布，再由 Adoption 幂等落定领养关系/额度、由 Nest 经 nest_session 幂等落定居民接纳/床位与持久状态；每项确认都绑定同一精灵/预约和执行身份。文件存在或单项落定不代表整体激活。
5. **最终激活**：三类持久结果全部核实，且资料包未先被撤销，Admission 才原子写入 `committed`；这是唯一产品可见点，随后才能欢迎、装配和启动 Runtime。
6. **清理**：成功或确定终止后清除创建输入/中间产物；失败待恢复时只在受限私有工作区保留必要资料。

这是跨所有者的有界协调，不是假定多个数据库能做一个事务。调用不确定时查询相应所有者的实际完成结果，不凭超时推断失败。Nest 接纳事实由 Nest 产生，Adoption 所有权由 Adoption 产生，App 仅协调确认和必要补偿；技术确认不成为第二份业务账。

预留与执行中状态保存在独立预约记录，不用最终业务表的 `pending/draft` 冒充完成；最终表只写本所有者已经落定的事实。App 统一按 `committed` 控制名单、归属授权、正式居民计数、Nest 快照装配/恢复、欢迎、Recall 入口和 Runtime；未激活结果只供协调器核验或补偿，读不到完成状态就不开放。容量核算仍计入有效预留，不把它算成正式居民。Nest/Elfie 不反向读取 Admission，App 通过既有边界提供已激活对象；禁止扫描最终目录或直接读局部完成记录绕过检查。

资料包撤销登记与 `committed` 判定须经过同一可串行化提交边界，按包可用性修订和预约执行令牌确定先后，不能先检查可用、再无条件提交。撤销先发生则保持不可见并补偿已落定项；激活先发生则只完成恢复/清理，不追溯撤销精灵。包可用性仍归配置发布所有者，判定所需包绑定只保留到预约终态；不把包依赖带入正常运行。

入驻成功命题在暂存时仅为待发布事实，与 Admission committed 同时对外生效；失败不能留下一段可召回的“已经入驻”。房间感知、身体位置和动作须等真实运行事实，床位分配不等于已经走到床边。

**并发、取消与恢复**

每次推进使用预约状态原子比较及递增执行令牌；所有发布写入校验令牌，失去令牌的旧执行者不得继续。锁过期只允许恢复同一操作。额度/床位预留、消费和释放分别幂等；处理中同一键配不同输入摘要拒绝，已 committed 的键只返回原结果。

| 中断窗口 | 恢复方式 |
| --- | --- |
| 编译未完成 | 使用同一 Envelope/Seed 和原版本继续，不换身份 |
| Memory 已暂存、其他资料未齐 | 核对 marker/清单，补完同一 Bundle 或清理确认无效的私有暂存 |
| 最终文件已发布，关系或 Nest 接纳未完成 | 保持 publishing，核对文件及各所有者回执，补完缺项；不能称为单纯连接失败 |
| 三项已落定，Admission 尚未 committed | 核验身份、Schema、完整性后重新通过撤销/激活判定；未撤销才记 committed，否则补偿，不凭局部回执直接激活 |
| committed 后 Runtime 失败 | 只从最终所有者重开，不需要 Envelope 或重新占用床位/额度 |
| 提交成功但清理中断 | 保留最小待清理状态，幂等清理，不回滚合法精灵 |

发布栅栏前取消，停止执行并清理私有结果、释放预留；栅栏后先核实是否已提交。确定未提交且要终止时，由各所有者补偿已完成的关系/额度/接纳，再清理或隔离未完成资料；补偿未确认前保持恢复状态，不能宣称已取消。已 committed 的移除另属产品操作，不能借取消 Genesis 删除。

重试耗尽区分可恢复暂停和确定终止；只有后者清理输入。候选有效期只约束接受前输入，不因恢复耗时推翻已接受预约或已完成发布。最终路径存在但完整性不明时隔离核验，不直接删除、覆盖或再造一只。同文件系统原子发布不可用时提前报环境错误，不降级成暴露逐文件复制。

**完整性与最小回执**

Memory marker 只证明自己的 submission 原子完成，不证明整个入驻；Admission committed 才控制整体产品可见性。两者用预约/输出标识交叉核验，marker 不可召回。

语义摘要只覆盖声明的业务输出与必要资产引用，排除回执/marker 自身；文件校验单独进行，不用数据库字节哈希冒充语义摘要。初始清单用于未完成发布恢复，不用于要求运行后的 Memory 永远等于出生快照。

`GenesisCommitReceipt` 只保留精灵/预约 ID、单向幂等键摘要、输出 ID/摘要/Schema、编译器修订、完成状态/时间与必要清理状态。它不保存输入摘要、包绑定、Seed、问卷或可重建人生的内容；正常恢复不得读取它来重新生成精灵。
