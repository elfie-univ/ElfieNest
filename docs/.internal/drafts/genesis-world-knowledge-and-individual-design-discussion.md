# Genesis 整体设计：资料准备流程与个体生成流程

> 状态：两个流程已并入 [Genesis v0.3](./genesis-core-kernel-design-v0.3.md)。本文保留为领域讨论来源，
> 不再单独定义当前流程；未决定的事项集中列在文末。
> 重点：资料准备流程中世界设定、居民知识和生成资料的组织。个体生成流程只说明输入、输出和主要依赖，具体算法另行讨论。
> 范围止于个体生成完成，不展开外貌、生成后运行、代码接口或存储实现。本文是已被 v0.3 吸收的领域
> 设计讨论稿，不覆盖现行契约，也不表示代码已经实现。

## 1. 目标与当前已明确的要求

最终要生成一个内部一致的精灵：它有确定的身份、人格、生活背景、人物关系和经历，并掌握与这些条件相符的知识。

我们构造世界与地球的差异，并利用大模型已有的通用知识，不重新编写地球百科。模型知道某件事，不等于这个个体应该知道；知识库没有逐条写某件事，也不等于个体一定不知道。

当前已明确的要求：

1. 造物者设定与居民认识分开，造物者知道的底层机制不自动成为居民知识。
2. 居民知识包含共同、地方、群体、专业与受限内容；不同个体的接触和掌握程度可以不同。
3. 先编写人读 Markdown，再生成语义对应的机器 YAML，不能各自维护相互矛盾的知识；人读版不采用逐条重复属性的卡片堆。
4. 物种同时具有客观构造与居民认识两个方面；生成配置可以组合构造规则并引用知识，不另造一份居民百科。
5. 个体生成要明确依赖与顺序：先确定生成后续内容所需的条件，再形成知识、关系和经历。
6. 前端已确定的参数约束后续生成；未指定的部分才按条件生成，不能重复抽取后改变已经接受的结果。
7. 外貌不参与本轮内在生成设计，不能由外貌推导职业、人格或知识。
8. 单一职业不能直接代表整个专业的完整掌握；需要考虑训练、水平、接触、知识难度等。
9. 不把“普通居民”设为含糊的角色或个人类型；按知识传播范围和个体背景直接描述。
10. 后续逐项讨论时，同时检查它对全流程的影响，未决定的内容不能因为写入本稿就被视为已批准。

## 2. 整体顺序：两个流程

两个流程分别编号为“步骤一、步骤二、步骤三”，不跨流程连续编号。跨节引用时使用“资料准备流程的步骤二”等完整称呼。

### 2.1 资料准备流程：准备可反复使用的生成资料

本流程由设计与资料维护过程完成，在世界、知识或规则变更时更新，不为每个新个体重新设计一遍世界。

| 步骤 | 视角与任务 | 内容与产出 |
| --- | --- | --- |
| 步骤一：编写世界设定 | 造物者怎样构造世界 | 世界设定 Markdown：自底向上的客观规律、环境、生物、物种、社会与地点设定 |
| 步骤二：编写居民知识 | 居民怎样观察和认识世界 | 居民知识 Markdown：可连续阅读的正文，说明受众、传播、重要性、学习难度与认识边界 |
| 步骤三：生成配置资料 | 把前两步的内容整理成生成器输入 | YAML 等配置：A．构造与生成规则；B．居民知识资产 |

这就是本稿重点讨论的三步。世界设定、居民视角、物种的两种描述、人读与机器表达的对应，以及生成资料如何汇合，均在这个流程内保留。

```text
步骤一：世界设定 Markdown ──→ 步骤二：居民知识 Markdown
           │                              │
           ↓                              ↓
步骤三：A．构造与生成规则 YAML       B．居民知识资产 YAML
                   两类配置共同供个体生成流程使用
```

“两类产物”是职责划分，不要求恰好两个文件。A 包含世界与物种的生成条件和规则；B 包含世界与物种的居民知识。物种生成配置可以引用 B，但不复制一套独立百科。

步骤一、二产出供人阅读和审定的 Markdown，步骤三才生成配置。B 是步骤二居民知识正文的 YAML 表达，保持语义对应，不在配置中另行创作知识；A 则结合世界设定与明确的生成规则形成。

### 2.2 个体生成流程：每次产生一个具体精灵

前端收集用户选择是这个流程的输入。仅接收已选参数还没有形成个体；生成过程需要补齐未定属性与生活背景，然后生成个人记忆。

```text
用户已确定的参数 + A．构造与生成规则
                  ↓
步骤一：生成个体基础与生活背景
                  │
                  ├── + A．构造与生成规则
                  └── + B．居民知识资产
                              ↓
              步骤二：生成个人记忆（知识、关系与经历）
                              ↓
                  步骤三：校验并完成生成
```

因此，资料准备流程的产物不是等到生成记忆时才全部读取：个体生成流程的步骤一已需要 A 来决定年龄范围、出生地点、生活路径等；步骤二进一步结合 B 确定这个人实际知道什么，并继续受 A 约束。

最终校验与结果交付是生成的收尾，不另设一轮人物创作。个体生成流程的简要说明见第 7 节。

## 3. 资料准备流程 · 步骤一：编写世界设定

### 3.1 审查结论

现有文档已经采用清楚的因果顺序：

**共同宇宙物理与化学 → 星球参数 → 环境与资源 → 生物演化 → 物种能力 → 社会与文化 → 具体聚落与人员分布。**

保留这一顺序、标题和简洁叙述方式。没有必要为适配本讨论而把它改成更抽象的章节名，也不要求每个主题都重复“是什么、为什么、条件、限制、影响”五段。

现有总纲已经要求后层建立在前层之上，能力写清范围、成本和限制；差异总览说明共同规律不必重复；附录提供新增设定的因果检查。这些要求足以支持内容审查，不必另套统一段落格式。

文内的七层是世界的因果层次；本文资料准备流程的三个步骤是资料整理顺序。引用时明确所指即可，不改动原文七层名称。

### 3.2 后续审查方式

以[世界设定第 1.5 节](../elfaria/elfaria-bottom-up-world-design.md#15-设定粒度与审查原则)为审查尺度：核心差异、宏观原则和必要共同事实明确即可；自然可推导的后果不逐项补写。只有不补会产生实质不同的核心结论、且现有原则无法排除时，才补最小的一条原则。

因此，不另写成长期学习、成熟后承担职责的通用过程，也不要求中继植物的养护手册或情绪恢复参数。能力已经说明可做什么与核心限制后，允许模型结合通用知识解释一般后果；不把“还能追问”作为未完成依据。

社会生活采用前工业、低流动、以本地家庭和小聚落为中心的原则。人口总量不等于个人交往范围；长老转述、少数往来者和有限广播提供外部消息。居民通常不熟悉全域，参加赴地计划可能才第一次到镇中心。这一宏观条件应贯穿知识组织与个体生成，不再为每一种地方生活情形另设规则。

世界文档中的出生点抽样算法等生成细节，后续区分客观空间事实与生成规则；当前不扩大为整份文档重写。

## 4. 资料准备流程 · 步骤二：编写居民知识

### 4.1 人读方式

保留现有按传播范围与生活主题组织的阅读入口：全体共通知识、地方与空间知识、群体与专业知识、文化与共同历史、地球默认差异等。确切目录在内容审阅中调整，不因追求分类对称而重写。

正文采用小节、连贯段落和短列表。共同的适用范围、传播程度和学习条件在小节开头说明一次，只有例外另作简短标注。专业和受限内容也应能供作者审阅，不能只保留公共概述。

本步骤只编写可阅读的 Markdown 正文；机器条目的定位和拆分在步骤三完成，不要求人按机器记录粒度阅读。一段正文可以映射多个机器条目；多个条目也可以合并呈现。保持可追溯与语义一致，不要求 Markdown 版面与 YAML 字段逐一同形。

### 4.2 需要保留的知识差异

下表是设计检查维度，不是要求每个知识点重复展示的卡片模板。

| 维度 | 含义 | 对个体生成的作用 |
| --- | --- | --- |
| 适用范围 | 哪个地区、物种、时期、情境成立 | 防止局部知识变成普遍事实 |
| 传播范围与普及程度 | 在什么人群中，接触或传播有多普遍 | 决定接触机会；“普及”暂用于承接讨论中的“推广程度” |
| 重要程度 | 对该人群的生活或职责有多关键 | 决定学习优先级和是否需要最低掌握要求，不能直接等于必然知道 |
| 学习条件与难度 | 需要什么前置知识、训练和实践，掌握有多难 | 同职业不同水平产生不同掌握结果 |
| 内容的依据与边界 | 观察、教导、记录、传闻或信念；哪些内容尚不可靠 | 防止听说变亲历、传说变客观事实 |

普及程度需要带人群范围，例如“维护者中普遍”并不意味着“所有居民中普遍”。传播、重要性、难度是不同维度；重要知识可能很难，高普及知识也可能只被粗略理解。

具体个体“掌握多少”是个体生成流程的结果，不是由知识条目预先为所有同职业个体固定的属性。必要的核心训练可以设最低掌握要求，其余知识保留个体差异；不能用独立随机漏项生成一个连基本职责都不具备的成熟从业者。

### 4.3 名称与表达

停止用“普通居民”充当角色类型。直接说“共同生活知识”“当地生活者通常知道”“受过相关训练者掌握”“该个体未学过此项”等。

角色、职业、教育背景、专业水平是个体条件。一个医者是否掌握中继培育，直接检查其相关学习与实践，不需要先把他重新归类成“中继方面的普通居民”。

传播广不等于每个人记得完整；受限不等于内容难；专业也不等于保密。这些条件允许交叉，不能压成一条高低等级。

### 4.4 阅读样式示意

以下只展示组织方式，不新增植物机制、操作步骤或具体概率。

> **中继植物的生活常识**
>
> 在使用中继植物的社区中，人们通常知道它的用途，也知道培育和维护需要相关训练；知道可以找维护者处理，不表示自己会培育。
>
> **中继维护者的学习与实践**
>
> 本节描述从业者在训练中接触的知识。基础养护属于日常工作中的常用内容；培育和复杂问题处理需要进一步学习与实践。不同训练阶段的维护者并不掌握全部内容。
>
> 后续分别整理基础与进阶内容，只在出现范围、难度或接触条件差异时补充说明。

同一主题可以在公共入口给出概述，再引用专业小节，不复制整段正文。无需为每条陈述打印完整属性表。

## 5. 资料准备流程 · 步骤三：生成配置资料

### 5.1 A．构造与生成规则

回答“在这个世界里可以生成怎样的个体，以及怎样形成差异”：包括物种、地区、生命周期、家庭、学习、职业等可行范围，生成知识、关系和经历时需遵守的条件，以及经过审定的抽样策略。

客观条件来自世界设定正文；概率、数量与抽样方式是显式设计的生成规则，应符合世界条件，但不必冒充世界中的自然定律。居民知识正文中的学习和接触条件也约束个人知识生成，两类资料通过引用衔接，不各写一套冲突的条件。

A 同时服务个体基础生成和记忆生成；作者机制、精确采样参数等生成专用内容不能直接成为居民记忆。

### 5.2 B．居民知识资产

回答“居民可能知道什么，在什么条件下接触和掌握”：将资料准备流程步骤二的居民知识 Markdown 转换为 YAML，包括共同、地方、群体、专业、受限知识和必要的世界差异。

B 保留适用范围、传播与普及程度、重要程度、学习条件与难度、认识边界等语义，供个体生成流程按已经形成的个人背景选取与个体化。它不是每个精灵都要完整接收的百科。

### 5.3 物种资料与人读内容的对应

物种生成资料可以引用居民知识并包含构造规则，但同一知识正文不在两个目录独立维护。发布状态也不能冒充世界事实，例如“某物种尚未开放生成”不表示它在世界中不存在。

当前配置契约使用 `config/world/elfaria.yaml` 与 `config/species/`。本文不预先创建新的 `knowledge/` 目录，也不冻结文件拆分方案。

人读文档与机器资料必须能互相对照；共享条件只描述一次，机器解析时可以展开。任何实质影响“谁知道什么”的条件都应能供人审查，不能隐藏在 YAML 默认值或代码常数中。

内容编辑方向确定为：先修改并审定 Markdown，再更新对应 YAML。转换允许拆分条目、展开小节共有条件和建立引用，但不能改写知识含义或增加未经审阅的世界事实。若转换中发现内容缺口，回到对应正文完善；具体转换工具与映射粒度另行确定。

## 6. 通用知识与世界差异

三类情况必须区分：

- 已批准沿用的通用知识：无需逐条写百科，可按知识领域、水平及适用条件描述。
- Elfaria 的特有事实和差异：必须有已审定的设定与居民知识依据。
- 尚未设定的特有事实、居民尚未发现的事实、某个个体没学过的内容：分别处理；未枚举的通用知识与自然推论不归入这些缺口。

例如医者需要明确其训练范围、经验水平、当地可用手段及精灵生理差异，不必复制完整医学教材；也不能因为模型掌握现代医学，就生成这个人知道所有现代疗法的结论。

复用通用知识不授权模型改变物种、身份、公共事实或个人经历。先形成个人知识范围与必要差异，生成后的具体应用不在本稿展开。仅写一个职业名尚不足以证明已经具备符合目标的知识表现。

## 7. 个体生成流程：输入、产出与主要依赖

本节只保留整体数据流和约束，具体生成算法及内部细分顺序尚待讨论。

### 7.1 输入：用户选择

区分用户已确定值、范围或偏好、尚未指定值。确定值直接采用，范围内才按条件生成；无可行结果时指出冲突，不偷偷改掉用户选择。输入收集不等于已经生成完整个体。

### 7.2 步骤一：生成个体基础与生活背景

**输入：用户选择 + A．构造与生成规则。**

**产出：确定的身份与人格锚点，以及出生、家庭、学习、职业水平、居住和活动范围等生活背景。**

例如，用户只选择物种和年龄范围，生成器需要根据规则确定实际年龄、可行出生地与家庭条件，再形成符合年龄和地方机会的学习及职业背景。用户已经给定具体年龄时，不再抽取另一个年龄。

这里形成的是个人生活的结构与条件，例如“曾接受哪类训练”；尚未展开具体记忆和故事。职业需要相应学习背景支撑；大五人格不等于专业能力；多种角色可以并存，未到适龄者不必有职业。外貌不参与这条依赖。

出生地、年龄、人格和学习路径之间的详细先后顺序，要按依赖关系确定，不预先规定所有属性都串行或独立抽样。A 中需准备哪些条件，可以由本节所需产出反查，但不能把 B 的居民知识全部提前塞给个体。

### 7.3 步骤二：生成个人记忆

**输入：步骤一生成的个人背景 + A．构造与生成规则 + B．居民知识资产。**

**产出：个人实际掌握的知识及边界、认识的人与关系、关键经历与其带来的变化。**

先依据生活与学习背景确定基础知识范围，再结合人物和时间线形成关键经历，最后汇总经历带来的新增知识与关系变化。事件只能使用当时已具备的知识与能力；长期学习不必为每条知识单独生成一则故事。

知识掌握先满足接触、训练和前置条件，再依据个人水平、实践、普及程度、重要程度与难度产生差异。同职业者不必掌握全部内容；概率不能绕过硬条件，也不能把基础与进阶知识独立抽成矛盾的组合。

### 7.4 步骤三：校验并完成生成

对齐身份、自我、知识、人物、地点和经历，形成完整结果。此处整理和校验已经生成的事实，不再重新生成另一套人生。

最终身份档案归 Profile，自我与人格归 Selfhood，知识、关系和经历归 Memory；创建期输入不成为长期第二份个人事实源。具体存储和生成后运行不在本稿展开。

“模板”尚待明确：若指个人最终描述，在本步骤形成；若指指导生成的通用模板，在资料准备流程准备。不能在含义未定时新增一种产物。

## 8. 两个流程的一致性要求

- 世界七层、资料准备三步、知识传播分类、个体生成步骤和最终所有者，是不同维度，不能相互替代。
- 家庭、教育、职业水平、迁居、路线、人物关系、经历中的学习及赴地准备不能因简化为“三层”而丢失。
- 公开地点和历史有统一事实；个人家庭、熟人和经历可以在批准范围内个体化，同名不自动表示同一人。
- 物种的身体条件不自动决定人格、职业和知识；参考个体 Lumi 不成为所有精灵的固定人生。
- 地图的客观空间、居民路线知识和出生点采样各有归属；图片不是可直接推导所有地理事实的来源。
- 生成器约束不进入居民知识；公众知道某项专业存在，不等于知道操作细节。
- 资料更新作用于后续创建，不让已经生成的个体因资料变动被重新解释或重造；本文不展开生成后的知识学习机制。

## 9. 后续讨论顺序与尚未决定的事项

建议按以下顺序逐项完善本稿，每项变化回查第 1、2、7 节，保证局部修改不破坏整体：

1. 按世界设定的粒度原则审查核心差异与实质矛盾；用中继植物贯通世界设定、居民认识与机器资料，不枚举所有可能的衍生知识。
2. 重点确定居民知识的阅读组织，以及普及、重要、难度和学习条件的表达，避免逐条属性卡片化。
3. 细化 Markdown 到 YAML 的映射方式，以及 A、B 的引用边界；不提前固定文件数量。
4. 再细化个体生成流程：用户参数、必要基础属性，以及年龄、出生背景、学习、角色、水平和人格之间的依赖。
5. 确定知识、人物和经历的时间顺序及“模板”含义；最后讨论具体概率、数量、字段和实施设计。

讨论中发现问题时直接更新相关正文及未决项，不为每轮对话复制一个新版本。批准后的领域结论回到相应正式资料；技术目标另按仓库规则进入已审阅设计，本文不升级为隐性的第二权威。
