## 1. 结论、目标与范围

### 1.1 核心结论

第一阶段不能再按 Memory、Emotion、Profile、Prompt 或 Communication 分别修补。正确的工程主线是
反复扩展同一条纵向闭环：

```text
领养时形成来源明确的生命资料
→ Genesis 校验并交给 Memory
→ Memory 按问题检索类型化知识、经历和关系
→ Reasoning 在事实边界内组织回答
→ Communication 真实记录并投递
→ Receipt 证明“说过什么”
→ 新的主人事实和共同经历回到 Memory
→ 重启后仍能延续
```

Memory 是这条主干的核心内容所有者，但不是新的总控模块。它不接管 Profile 的不可变身份、
Orientation 的当前状态、Communication 的送达事实、Selfhood 的人格表达，也不接管客观世界设定的
编辑来源。

世界/物种 Canon 与 Memory 的关系固定为：

- Canon 是版本化的客观参考资料，是“产品设计规定这个世界是什么”；它不是第十一个 Brain 系统；
- 一只 Elfie 实际知道的世界知识，是 Genesis 从对应版本资料交付给它、并由 Memory 持有的语义知识；
- Profile 只保留名字、物种、出生来源、世界/地区 ID、版本和生成来源等不可变锚点；
- 运行时回答不能长期依赖把整套 Canon 直接塞入 Prompt。直接层最终只保留身份硬锚点和防虚构规则；
- Canon 更新不会静默改写既有 Elfie 的记忆。版本升级、补课或迁移是以后单独批准的产品行为。

因此，“记忆优先”不是先横向做完一个庞大的 Memory 系统，而是先让一条记忆支撑的用户路径真实
闭环。高级遗忘、自动巩固、模式预测、向量数据库和人格成长都不能抢在这条主干之前。

### 1.2 第一阶段最终可交付目标

用户只通过 Web 文字聊天，就能感受到自己领养的是同一只、有异星来历、有少量完整过去、会记住
主人、能区分已知与未知的 Elfie。至少满足：

1. 每条被接受的消息最终只有一个可解释结果，不沉默、不重复、不串到别的精灵或会话；
2. 它从自身身份和已拥有的知识回答，不默认把自己当地球人；
3. 用户可以沿至少三个话题追问其领养前历史，核心人物、地点、结果和影响保持一致；
4. 它记得主人明确告知的称呼、喜好、纠正和约定，并保留“主人说的”这一来源；
5. 它不虚构精灵巢当前事件、地球实时天气、未发生动作或未送达回复；
6. 进程重启、模型失败、投递失败和重复事件不会破坏以上连续性。

领养前历史不能整体推迟到 P1。它是“这只精灵在认识我以前已经活过”的核心卖点，第一阶段必须
有一组小而完整的传记。P1 才继续做大量历史、日常自动积累、复杂巩固和长期成长。

### 1.3 本计划明确不做

- 不实现真实精灵巢感知、移动、设施使用、其他精灵互动或当天巢内生活；
- 不接入语音、图片、外部社交平台、工具查询、实时天气或新闻；
- 不实现主动行为、长期 Activity、通用 Agent、自动人格成长或完整 Consolidation；
- 不增加向量数据库、第二套记忆库、通用知识服务或新的顶层 Brain 模块；
- 不把全部聊天原文都升级为长期记忆；
- 不自动迁移、覆盖或删除真实用户的既有 Elfie 数据；
- 不因为本计划顺手重构十系统、Nest、Godot、Body 或无关前端。

首轮实现范围固定为：一只新领养 Elfie、一个主人、一个 Web 中文文字渠道及其规范主人会话（允许
断线重连和进程重启）、一个受支持模型。运行时仍只装配一只 Elfie，但所有当前对用户开放领养的
物种都必须通过同一知识/传记合同；否则应先明确缩小可领养目录，不能只把一个物种做通却宣称第一
阶段完成。只有该范围闭环后，才讨论多语言、扩大渠道、用户、身体和世界活动。

## 2. 目标架构与事实所有权

### 2.1 运行时事实分工

| 事实或能力 | 唯一权威 | 第一阶段用途 | 明确不能做什么 |
| --- | --- | --- | --- |
| 名字、物种、出生来源、稳定 ID、版本 | Profile | 固定“我是谁” | 不能保存人格、主人喜好、当前地点或完整世界百科 |
| 世界与物种客观设定 | 版本化 Canon 参考资料 | 作为 Genesis 知识来源和硬约束 | 不能成为运行时第二份个人记忆，也不能伪装亲历 |
| 已知世界知识、个人经历、人物与关系 | Memory | 支撑问答、回忆、纠正和连续性 | 不能覆盖当前权威状态或自行宣布外部动作完成 |
| 当前会话、身体、地点、可用动作 | Orientation + EffectiveCapabilities | 回答“现在能做什么” | 不能用旧记忆推断当前仍在某处或正在做某事 |
| 当前情绪、能量、睡眠 | Emotion + Energy | 有限影响语气和回复深度 | 不能改写身份、历史和世界事实 |
| 人格、表达风格、自我模型 | Selfhood | 让同一事实以这只 Elfie 的方式表达 | 不能保存世界百科或把一次情绪固化成人格 |
| 主人消息、Elfie 回复和用户可见历史 | Communication history | 证明双方实际说过什么 | 不能把“准备发送”当作“已经说过” |
| 投递是否成立 | Communication Receipt | 决定回复是否成为共同经历 | 模型文本和广播调用本身不能替代回执 |
| 选择上下文和组织回答 | Reasoning | 组合各权威来源 | 不能直接写 Memory、Profile 或伪造 Receipt |
| 自然语言生成 | Model | 变换表达、组织叙事 | 不是任何长期事实的权威来源 |

“当前刚来、尚未探索”的安全表达也必须服从上述分工：

- “我已经来到地球”来自 Genesis 中已提交的到达经历；
- “我现在只有通信能力、还不能探索”来自当前 Capability/Orientation；
- 只有 Energy 或 Activity 真正证明时，才能说“我很虚弱”或“我正在休息”；
- 没有权威地点时，不能说自己躺在床上、恢复区或某个房间里；
- Stage 1 产品装配不暴露具身动作能力。Headless 的 `*` 能力只属于测试/调试，不能成为产品事实。

### 2.2 第一阶段公共主干

```text
版本化世界/物种资料 ─┐
领养后一次性传记 ─────┼→ GenesisBundle → 每只 Elfie 的 Memory Store
Profile 身份锚点 ──────┘                       │
                                                ▼
主人消息 → Workspace → typed recall → BrainContext → Reasoning
   │                                              │
   │                                              ▼
   └──── stable message ID ← Directive → Communication → history/transport
                                                    │
                                                    ▼
                                                 Receipt
                                                    │
                         ┌──────────────────────────┴──────────────────────┐
                         ▼                                                 ▼
             主人陈述候选：证明“主人说过”                    共同经历候选：证明“我也回复过”
                         └──────────────────→ Memory commit ←──────────────┘
```

这里有两个不能混淆的时间点：

1. 主人消息进入权威聊天历史并被通信边界交给认知后，可以记录“主人说过 X”，但 X 仍是主人
   陈述，不自动变成客观世界事实；
2. 只有出站回复进入权威聊天历史并取得满足完成阈值的回执后，才能记录“我回复了 Y”或“我们完成
   了这次交流”。

### 2.3 冲突优先级

| 冲突 | 处理规则 |
| --- | --- |
| Memory 说在 A，当前运行时状态说在 B | 当前 Orientation/执行回执优先；A 只作为过去经历 |
| 主人要求 Elfie 改名、改物种或改母星 | Profile 身份锚点优先；普通消息不能改不可变身份 |
| 主人陈述与世界 Canon 冲突 | 保存为“主人这样说”，不能升级为客观知识 |
| 主人后来纠正自己的称呼或喜好 | 新陈述显式取代旧主人事实；旧记录保留来源但不再作为当前答案 |
| 两段个人经历互相矛盾 | 不让模型现场圆谎；返回不确定，并把冲突暴露给验证/后续修复流程 |
| 新版本 Canon 与旧 Elfie 记忆不同 | 不静默覆盖；继续使用该 Elfie 已提交的版本，等待显式升级策略 |
| 预测、联想或 Consolidation 产物与正式事实冲突 | P0 一律不得进入事实回答上下文 |

## 3. 当前实现事实与根因

以下结论来自当前代码、测试和调用链，不把目标设计写成已实现能力。

| 部位 | 当前已经有的能力 | 当前关键缺口 | 直接影响 |
| --- | --- | --- | --- |
| Genesis | 有一次性 `GenesisBundle`、Manifest、5 个 `MemorySeed` 和关系种子；能写入每只 Elfie 的 Memory Store | 5 个名额都被共同世界/赴地资料占用；知识与经历未分型；每段经历都连到最后一个地球地点；历史发生时间被写成提交时间 | 看似有初始化记忆，实际没有可探索的个人过去，图关系和时间还会误导 |
| 世界/物种资料 | `WorldCanon` 有少量全局事实；每个物种配置有 3 个感知偏好、2 条常识、2 个初遇线索 | 知识密度远不足以支撑连续追问；全局资料与物种资料物理形态不一致 | 模型只能重复少量词条，随后开始用地球常识补空白 |
| Memory 存储 | 已有 `episodic/entity/knowledge/pattern` 节点、图边和每只 Elfie 独立 SQLite；现有 JSON metadata 足以承载 P0 字段 | 领域元数据仍偏松散；候选去重主要在进程内；普通候选只有整段情景文本 | 能存，但来源、类型、纠正和跨重启幂等不够可靠 |
| Memory 检索 | 有文本、实体、时间、情绪、感官和扩散检索 | 主文本检索明确只查 `episodic`；`knowledge` 节点不会从正常聊天问题召回；正常 reader 未提供实体；同情绪经历可能挤入无关问题；中文逐字词袋容易误召回 | 知识、关系拿不出来，无关旧经历反而可能盖过问题；继续加词条也无效 |
| Memory 上下文 | 有 `MemoryContext` 和预算化的模型上下文 | `MemoryContextReader` 把所有召回结果压成一个合成 `MemoryItem`，并把当前提问事件错误地当成记忆来源；类型、节点 ID、来源、置信度全部丢失 | Reasoning 无法区分知识、亲历、主人陈述和推测 |
| Recall Formatter | 会组织自我叙事、实体、经历、联想、预测和情绪权重 | “预测灵感”和技术性情绪说明与正式记忆混在同一段事实上下文 | 模型容易把可能性说成已经发生的事情 |
| Reasoning Prompt | Profile/Canon、Selfhood、状态、聊天和 Memory 已能进入模型上下文 | 世界与物种知识主要靠直接 Prompt 注入；Memory 不是共同内容主干；模型失败最终是 No-op；预算按空格切词，中文长文本可能绕过预算 | 角色感来自提示词而不是生命记忆；失败时沉默；知识扩充后还可能挤爆上下文 |
| Selfhood 表达模板 | 有问候、口头禅和物种表达线索 | 现有模板包含“今天天气真不错”“那边好像有什么”“人家正忙着”等未经状态支持的内容 | 即使 Memory 正确，表达层仍会重新制造天气、视觉和活动伪事实 |
| 个人传记 | 领养揭示阶段已有一段 2–3 句 `personal_story`，并作为 Selfhood `self_description` 进入推理 | 没有 Canon 一致性和结构化人物、地点、事件、结果、影响；`BiographyEnrichmentPlan` 当前没有生产消费者 | 未校验简介可能提前成为 Prompt 事实，正式故事又不能稳定检索和多轮追问 |
| 主人记忆 | 有回执后拼接“主人说/我回复”的情景候选，并用关键词筛重要消息 | 整段对话作为一个情景文本；主人陈述必须等回复成功才保存；纠正和当前事实没有类型；跨重启去重不足 | 回复失败会丢主人已说出的事实，重复事件也可能形成重复记忆 |
| Communication | 有会话隔离、入站去重、出站 `DeliveryReceipt` 和持久聊天历史 | Web owner channel 在 broadcaster 缺失或内部投递异常时仍返回 `SENT`；broadcaster 吞掉异常；聊天历史 ID 与 Brain 出站事件 ID 未贯通 | Memory 可能把未真正成立的回复记成共同经历 |
| 当前能力 | 有 Orientation 和 EffectiveCapabilities | 没有专门的 Stage 1 “恢复区”事实；Headless 默认暴露通配身体能力 | Prompt 若声称床、房间、休息或可行动，就是新增伪事实 |
| Consolidation | 有睡眠/安静窗口、有界调度，也能产生 Knowledge/Pattern | 自动产物尚未具备 P0 事实审核；现有 Pattern 会进入预测区 | 不能直接复用为首版世界知识或个人事实 |
| 既有数据 | Genesis Manifest 是一次性、幂等起点 | 改种子逻辑只自然影响新领养 Elfie；旧 Elfie 不会自动补齐 | 必须明确首版面向新领养，不能假装旧数据已升级 |

根因不是“某一个模块没写完”，而是主干在三个地方断开：

1. **写入前没有正确分型**：客观知识、个人经历和关系被塞进同一种 `MemorySeed`；
2. **读出时没有覆盖知识并丢失来源**：语义知识检索不到，召回结果又被压成无类型字符串；
3. **事后没有可靠事实回执**：出站投递可能被错误标成成功，新的共同经历就没有可信依据。

所以执行顺序必须先修这三个断点，再增加知识和故事密度。

## 4. 冻结的 P0 数据与行为契约

### 4.1 Memory 的四类可回答内容

P0 复用现有 `KNOWLEDGE`、`EPISODIC`、`ENTITY` 图模型，不新增数据库表和第二套存储。领域层通过
强类型合同约束现有节点与 metadata。确切 Python 类名可以遵循仓库命名，但以下语义字段不得丢失：

| 类别 | 必备字段 | 来源与回答规则 |
| --- | --- | --- |
| 语义知识 | `memory_id`、陈述、世界/地区/物种范围、topics/aliases、source kind/ref/version、certainty、status、recall eligibility | 来自经批准的版本化资料或正式 briefing；可说“我知道/资料里是这样”，不能说成亲历 |
| 个人经历 | `memory_id`、事件摘要、life stage、时间标签/可选发生时间、地点 ID、人物 ID、结果、感受、长期影响、source/certainty、topics | 来自一次性传记或真实发生事件；可用第一人称回忆，但不能补写未保存核心事实 |
| 人物/关系事实 | 人物 ID、关系角色、事实 key/value、source message IDs、certainty、status/supersedes | 主人陈述只对该主人/关系有效；更正显式取代旧值，不能升级为世界事实 |
| 共同互动 | 主人消息 ID、Elfie 回复 ID、完成回执 ID、会话 ID、摘要、时间、重要性 | 三个身份都齐全且回执满足完成阈值后，才可说“我们聊过/我回复过” |

所有可召回项目统一返回独立的 typed item，至少保留：

```text
memory_id + kind + content + topics/entities + relevance
+ source_kind/source_ref/source_version + certainty + status
+ occurred_at/temporal_label + source_event_ids
```

禁止再把多条节点合成一个假的 memory ID，也禁止用当前提问事件 ID 代替被召回记忆的真实来源。
所有内容字段继续按不可信数据处理，不能被当作模型指令。

### 4.2 Genesis 种子拆分

`GenesisBundle` 的逻辑输入拆成：

- `KnowledgeSeed[]`：数量不受“最多 5 段经历”限制；由版本化世界/地区/物种资料编译而来；
- `EpisodeSeed[3..5]`：只保存这只 Elfie 的关键领养前经历；
- `RelationshipSeed[]`：初始化自我、原生重要人物和领养家庭关系骨架；
- `ProfileDraft`、`PersonalitySeed`、`SelfModelSeed` 与 Manifest 保持各自所有权。

传记不是五张互不相关的故事卡，而是一张最小人生图：

- 1 个明确家乡生活地点；
- 1–2 个反复出现的重要人物；
- 3–5 个按相对时间排序的关键事件；
- 至少一条“过去经历 → 当前性格/选择”的因果联系；
- 离开母星/参加赴地计划是其中一段经历，项目共同事实则属于 Knowledge；
- 可以生成只属于这只 Elfie 的人物名、小地点名和生活物件，但它们只能作为个人记忆，不得借此
  新增全世界的政治、历史、地理或物种规律；
- 插入时间和历史发生时间分开；只有真的知道精确日期才写 `occurred_at`，否则使用 life stage 和
  `temporal_label`，不能伪造时间。

领养揭示阶段已经有一次强模型调用。P0 在同一次结构化 reveal 中生成并校验传记包，不增加第二个
“后台自动补传记”模型。`personal_story` 变成该结构化传记的短摘要，而不是另一份事实源。当前没有
生产消费者的 `BiographyEnrichmentPlan` 不作为完成依据；在传记切片中确认无调用者后删除，不保留
一个看似会自动丰富、实际无人执行的承诺。

Genesis 提交使用稳定节点 ID、Manifest 最后可见和可重放 upsert：

- 全部节点、人物、地点和边使用 Manifest + seed ID 推导的确定性 ID；
- Manifest 未完成时，运行时不得把半套 Genesis 当作可用生命资料；
- 崩溃后重放同一 Manifest 必须补齐而不是复制；
- 不依赖只存在于内存的“已经提交 candidate ID”集合；
- EpisodeSeed 最终写成运行期也使用的普通 Episode 合同，使第二阶段真实巢内经历沿用同一读链，
  不为“初始故事”另造永久记忆类型；
- 第一轮优先复用现有表和 JSON metadata。若无法满足原子可见与重放语义，再进入第 7 节数据库门，
  不能直接加表或字段。

### 4.3 世界知识密度与版本

“多塞几个词条”不是完成标准。第一版共同世界/地区资料建议包含 40–80 条原子知识，覆盖至少八个
主题族；每个当前公开物种另有一组小而完整的物种知识。最终以问题覆盖率而不是条目数量验收：

1. 母星与已知地区的环境、天空、昼夜和季节边界；
2. 居住空间、聚落、道路与日常生活；
3. 食物、休息、劳动、游戏和常见物件；
4. 家庭、朋友、礼貌、信任和社会习惯；
5. 物种感知偏好、身体差异和生活适应；
6. 技术水平、交通、传送阵和赴地计划；
7. 与地球的已知差异及地球知识盲区；
8. 明确未知的地区、政治、历史和未亲历内容。

每条知识必须是可独立引用、可标版本、可声明未知边界的原子陈述，不能把长篇世界观整段塞入
Prompt。内容资料建议作为一个注册、类型化、版本化的 bundled `config/` 文档，由 Infrastructure
加载后在领养/Genesis 边界转换为领域合同；它不成为 Brain 模块，也不由 Memory 自行读 YAML。
具体文件结构在第 2 轮开工卡中冻结，并遵守现有配置单一事实源规则。

旧 Elfie 的 Manifest 版本和当前 bundled 版本不一致时，P0 默认继续使用已提交 Memory，不自动
补课、不静默换设定。产品若要求升级，另立迁移与叙事策略。

### 4.4 检索、上下文和回答边界

P0 检索采用现有存储上的有界混合检索，不引入向量基础设施：

- 文本匹配同时覆盖内容、topic aliases 和相关 entity；
- 先按 `recall_eligible/status/source_kind` 做事实过滤，再评分；
- 情绪只作为相关结果的有限排序因子，不能单独把无关同情绪经历召回；
- 按问题选择 Knowledge、Episode、Person/Relationship 或 Interaction 配额，不把所有类型混排后
  只取前五条；
- 单回合最多向模型提供 8 条记忆项目；先把按空格估算改成能保守约束中文的字符/token 预算，再由
  总上下文预算裁剪；
- 每条项目独立保留来源和置信度；被截断时整条淘汰或明确截断，不能拼坏字段；
- P0 事实上下文排除 Pattern、预测灵感、未经校验的 Consolidation 产物、技术性情绪权重和
  Memory 自我叙事投影；
- Selfhood/Profile 仍是当前身份权威，Memory 中的自我叙事只是可出错的历史证据。

正常回答策略是“事实优先、自然表达、缺口显式”：

- 能检索到时围绕相关事实回答，并可以自然带出一段相关经历；
- 只有相邻信息时说明“我只知道这些”，不把推断补成确定事实；
- 完全未知时自然承认不知道，并说明是未亲历、当前无法感知还是资料未覆盖；
- 当前精灵巢、天气、动作和其他 Elfie 只能由当前状态、感知、工具结果或回执支持；
- 在第 2 轮检索验收通过前，不删除现有硬身份安全锚点；通过后移除重复的丰富世界/物种 Prompt
  注入，只保留名字、物种、来源等身份锚点与防虚构政策，避免双事实源。

### 4.5 通信、写回和失败语义

同一条消息身份必须从产品入口贯通到 Brain 和历史库：

```text
external message ID / inbound event ID
→ admitted Turn cause ID
→ outbound envelope event ID
→ canonical chat-history message ID
→ DeliveryReceipt ID
→ Memory source IDs
```

Web 通道的完成阈值固定为：

- `FAILED`：broadcaster 缺失、权威历史写入失败或没有形成用户可读取的回复；
- `SENT`：权威聊天历史已经用 outbound envelope ID 持久化，用户可通过规范历史接口恢复读取；
- `DELIVERED`：在 `SENT` 基础上，当前实时 Web publisher 也已接受；
- 历史已写但实时推送失败时保留 `SENT` 和可重试的实时诊断，不能抛成“整条消息未发送”并让上层
  再写第二条相同回复；
- Memory 只把 `SENT/DELIVERED/READ` 视为“我已经说过”，不把 `ACCEPTED/QUEUED` 当完成；
- 重复入站、重复回执和重放使用同一稳定 ID 收敛；
- 模型失败、超时或无预算的 Communication Turn 产生一条不依赖第二次模型调用的安全短回复，
  仍通过同一 Communication/Receipt 路径；不能继续以 No-op 沉默收尾；
- 发送失败不把 Elfie 回复写成共同经历，但已经进入权威历史且被认知接受的主人陈述仍可作为带
  来源的候选保存。

长期记忆只保留明确身份事实、喜好/边界、纠正、约定、重要关系事件和高显著互动摘要。普通闲聊留在
有界会话历史，不复制到长期 Memory。

## 5. 五轮纵向执行计划

五轮对应第一阶段 1.1–1.5 的用户验收维度，但不是五次互不相干的模块工程。每轮只扩展同一条
公共主干。每轮开工前冻结对应 `E1–E5` 的基线、用例和阈值，结束时必须形成
`PromotionDecision=GO`；代码完成、测试通过或偶然演示成功都不等于本轮完成。

| 轮次 | 用户新增结果 | 阶段判断 |
| --- | --- | --- |
| 1. 可信骨架 | 基础身份问答来自 Memory，聊天与失败有真实结果 | 只是一条可运行的最薄闭环 |
| 2. 异星知识 | 母星与生活可以连续探索，边界外不乱编 | 可演示的外星精灵聊天核心 |
| 3. 领养前人生 | 这只 Elfie 有属于自己的过去 | 核心卖点成立，但尚未形成主人连续关系 |
| 4. 主人关系 | 记得主人、纠正和真实共同互动 | 功能完整候选 |
| 5. 整体验收 | 失败、重启、自然度、预算和隔离全部过门 | 第一阶段最小可交付版本 |

### 第 1 轮：可信聊天骨架与最薄记忆闭环

**用户目标**：用户问“你是谁、从哪里来”，能收到唯一、可恢复、来源正确的回复；模型或投递失败
也不会产生沉默和伪成功。

**实施内容**：

1. 先建立失败测试：语义 Knowledge 当前召回不到、MemoryItem 来源丢失、broadcaster 缺失仍
   `SENT`、模型失败 No-op、重放产生重复结果；
2. 建立最小 `KnowledgeSeed`/`EpisodeSeed` 分型，把现有身份、家乡和赴地共同事实写成少量可召回
   Knowledge，并在 Memory 中建立类型化 recall item 和 Knowledge 检索入口；这一轮只证明真实
   新领养读链，不铺完整世界内容；
3. `MemoryContextReader → ModelContextCompiler` 改为逐条传递真实 ID、kind、来源、置信度和相关度，
   从首版事实路径移除预测/模式/技术权重文本；
4. 贯通 Web 出站 envelope、聊天历史和 Receipt 的稳定消息 ID，修复 broadcaster 缺失/异常仍成功；
5. 为 Communication Turn 增加有界、可信的模型失败回复；它不声称动作、地点或知识；
6. 在第 3 轮结构化传记完成前，把未校验 `personal_story` 限定为展示摘要，不能作为事实指令或身份
   权威进入回答；
7. 清理或条件化会暗示天气、视觉、忙碌和当天状态的问候/口头禅，风格模板不得自行带事实；
8. Stage 1 产品装配只公开 Web 通信能力，不把 Headless 通配身体能力暴露给 Reasoning；
9. 为每个 Turn 暴露安全的 selected memory IDs/kinds/source 和最终 Receipt 状态诊断，不记录完整
   主人隐私文本；
10. 新增一条从临时新领养数据到重启后再问的聚焦纵向测试。

**主要涉及**：`elfie/genesis/`、`elfie/brain/memory/`、`elfie/brain/reasoning/`、
`elfie/communication/`、`app/orchestration/message_delivery/`、对应 Bootstrap 装配及聚焦测试。

**完成门**：

- 基本身份问题实际命中一条 Knowledge，而不是只命中直接 Prompt；
- 普通、模型失败、发送失败、重复入站、完成后重启五类场景各有唯一结果；
- 未成功投递的回复不会形成“我说过”的 Memory；
- 不新增数据库 schema，不引入第二条聊天或记忆路径。

**评测门**：通过第 6 节 `E1`，并由负责人确认“可信、可继续聊”的可见效果后才进入第 2 轮。

### 第 2 轮：可探索的异星知识

**用户目标**：用户可以围绕母星、家乡、生活、物种和地球差异连续追问；Elfie 能丰富回答，也会在
边界外明确不知道。

**实施内容**：

1. 冻结版本化世界/地区/物种知识文档、八类问题覆盖表和禁止虚构表；实际世界观内容先经产品审阅；
2. 在第 1 轮种子分型上扩展完整知识编译，保证知识数量不受“最多五段经历”的限制；
3. Genesis 把本 Elfie 应知的资料编译成可召回 Knowledge 节点，带 scope、topic、alias、版本、
   来源、置信度和 eligibility；
4. 改进有界 topic/entity/lexical 检索，解决中文逐字匹配的误召回；不加向量数据库；
5. 修正中文上下文预算，并建立固定问题库，逐项验证 top-k 命中、未知问题零伪召回、不同 Elfie
   存储隔离和版本不混用；
6. 验收全绿后，删除 Reasoning/Selfhood 中重复注入的丰富物种知识和世界描述；只保留不可变身份
   锚点、Canon 版本和硬认知边界；
7. 对所有当前公开物种做知识合同/问题覆盖验证；至少一只完成全链路，其余物种通过相同 schema、
   Genesis 和召回合同；
8. 验证当前问题仍由 Capability/Orientation 回答：没有位置、天气和巢内感知就不编造。

**主要涉及**：版本化 `config/` 内容及其类型化加载、`elfie/profile` 的参考合同、`elfie/genesis/`、
`elfie/brain/memory/`、Reasoning 上下文及配置/领域测试。

**完成门**：

- 冻结问题库中，事实检索 top-k 命中率至少 95%，硬身份、物种合同和认知边界问题 100% 正确；
- 未覆盖事实、地球实时问题和精灵巢当前问题的伪事实数为 0；
- 至少三轮不同问法和一次重启后，核心答案不矛盾；
- 从 Prompt 移除重复知识后验收仍成立，证明 Memory 已成为内容主干。

**评测门**：通过 `E2` 及 `E1` 全量回归，负责人能从盲测对话中识别出“异星世界可探索”，才进入
第 3 轮。

### 第 3 轮：可追问的领养前人生

**用户目标**：用户从至少三个方向追问过去，能发现同一组互相关联的人物、地点、事件和影响；这只
Elfie 不再像从领养当天才出现。

**实施内容**：

1. 扩展现有 post-acceptance narrative reveal，使一次生成同时返回短简介和 3–5 段结构化传记；
2. 在生成结果提交前验证 Canon 一致性、人物/地点引用完整性、时间顺序、事件结果和相互矛盾；
   同时验证年龄/life stage 是否容得下这些经历；不合格则整个 reveal 失败并允许重试，不提交半套
   生命史；
3. Genesis 使用 `EpisodeSeed` 写入正确历史时间、life stage、地点、人物、情绪、结果和影响；修复
   所有种子都连接地球地点的问题；
4. 用稳定 ID 和 Manifest 门保证失败、崩溃、重复提交不会复制人物或经历；
5. 记忆检索按话题召回相关 Episode，并可沿人物/地点/因果边补一条关联经历；
6. 未保存细节允许自然说“记不清”，模型生成的新细节不在这一轮自动写回；
7. 删除确认无生产消费者的 `BiographyEnrichmentPlan`，避免假完成和未来第二条传记生成路径。

**主要涉及**：`infrastructure/models/adoption_narrative.py`、Adoption 的 reveal 合同、
`elfie/genesis/`、`infrastructure/persistence/elfie_workspace/adoption_profiles.py`、Memory 检索和测试。

**完成门**：

- 一只新领养 Elfie 有 3–5 段互相关联经历、1 个家乡地点和 1–2 个重要人物；
- “小时候住哪、想念谁、最开心/害怕什么、为何来地球、这件事如何影响你”至少三类话题可追问；
- 反复问、换说法、重启后人物、地点、结果和因果关系不矛盾；
- 插入时间不冒充历史发生时间，未知细节不被固化为事实。

**评测门**：通过 `E3` 及 `E1–E2` 回归，负责人确认“它在领养前已经生活过”，才进入第 4 轮。

### 第 4 轮：主人事实、纠正与共同经历

**用户目标**：Elfie 记得“你是谁”和“我们之间真实发生过什么”，并能接受纠正而不把主人陈述
污染成世界知识。

**实施内容**：

1. 用 typed candidate 取代“关键词命中后把整段问答写成一个 Episode”：至少区分 owner claim、
   correction、agreement、important interaction；
2. 主人消息同时具备权威历史记录和认知送达后即可形成“主人说过”的候选；出站回复和共同互动
   等待权威历史 + Receipt；
3. 为称呼、喜好、边界和约定定义稳定 fact key、当前 active 值和 supersedes 链；
4. 同一消息/回执推导确定性 Memory node ID，使进程重启后的重放仍为 duplicate/upsert；
5. 限制保存策略，只提取明确、可复用的关系事实，不存储全部闲聊或模型自行猜测的隐私；
6. 在检索和 Prompt 中把主人陈述标为 attributed data，防止普通消息或 Prompt injection 改写身份、
   Canon、人格和权限；
7. 完成跨 Turn、断线重连、重启、重复回执、回复失败和先后两次纠正的纵向测试。

**主要涉及**：Communication/Conversation Context、Turn Settlement、Memory candidates/commit/retrieval、
聊天历史 Adapter 及对应领域、持久化和 App 集成测试。

**完成门**：

- 主人提供一个称呼、一个喜好、一个边界和一次纠正后，后续会话及重启均使用最新有效事实；
- 回复发送失败时仍记得“主人说过”，但不声称“我回复过”或“我们已约定”；
- 主人关于世界或 Elfie 身份的错误说法仍保持 attribution，不覆盖客观锚点；
- 两只测试 Elfie 之间无主人事实、消息和记忆泄漏。

**评测门**：通过 `E4` 及 `E1–E3` 回归，负责人确认“它记得我和我们的真实互动”，才进入第 5 轮。

### 第 5 轮：完整精灵聊天体验与发布门

**用户目标**：身份、世界知识、个人过去、主人关系、情绪语气和未知边界成为同一个自然的人，而
不是知识库、拒答器或角色提示词。

**实施内容**：

1. 用完整脚本串联领养、身份、世界、三段过去、主人事实、纠正、未知问题、模型失败、投递失败、
   重启和继续对话；
2. 调整 retrieval 配额、去重和总上下文预算，保证知识丰富后不会挤掉当前消息、身份锚点和关键
   会话上下文；记录基线与 p95，Memory 读链不增加额外模型调用；
3. Selfhood、Emotion、Energy 只做有限表达调制：人格稳定、情绪有变化，但不改变事实；
4. 检查回答是否总用同一模板拒答；允许围绕已有事实展开、联想已提交经历或向主人反问，但不写入
   新 Canon；
5. 使用 deterministic fake model 证明合同与失败语义，再用一个受支持真实模型做受控体验评测；
   真实模型表现不能替代确定性测试；
6. 重新盘点所有直接 Canon 注入、旧 recall formatter 调用、未类型化候选和临时双路径；活动调用者
   全部迁移后删除旧路径，不留长期 fallback；
7. 冻结“只支持新领养”还是“发布前升级旧 Elfie”的数据策略；未经额外批准不碰真实用户数据。

**主要涉及**：前四轮全部主干、产品级 API/E2E 测试、诊断投影和必要的内部说明；不启动 Godot
世界或全站浏览器 QA，但每轮都通过既有 Web 聊天入口完成一条受控用户体验验收。

**第一大阶段完成门**：

- 固定问题库和完整故事脚本中，身份矛盾、来源误认、巢内伪事实、地球实时伪事实、伪回执、重复
  回复和跨 Elfie 泄漏全部为 0；
- 重启前后的核心身份、世界知识、传记和主人事实一致；
- 模型失败和投递失败都有唯一、真实、用户可理解的结果；
- 用户能够仅通过聊天复述“它是谁、来自怎样的地方、经历过什么、如何认识我、现在为什么还不能
  探索”，且这些内容都能追溯到权威资料、正式记忆、当前状态或真实回执。

**评测门**：只有 `E5`、`E1–E4` 全量回归和负责人最终体验验收全部为 `GO`，才能称为第一阶段
最小可交付版本。

## 6. 验收体系与全方位对抗审查

### 6.1 评测结论与强制流程

通用评价原则、`EvalRun`、`EvalScenario`、`GateViolation`、`ComparisonReport` 和
`PromotionDecision` 继续以既有 [Brain 评价体系](./elfie-brain-evaluation-system.md) 为唯一基线。
本节只是第一阶段聊天的专项 Profile，不新建第二套评价模块，也不要求先造完通用评测平台。

当前仓库尚未实现该文档设想的完整批量 Runner。因此开工时先用现有聚焦测试、API/E2E 场景、真实
模型和结构化人工评审完成可重放的 `E1`；后续只自动化重复劳动，不能用“评测平台还没做好”跳过
本轮产品评测。

每轮固定执行同一条流程：

```text
冻结用户目标、EvalSpec、基线、题库和阈值
→ 在同一初始数据与配置上记录阶段前基线
→ 实施本轮最小纵向改动
→ 确定性门禁与故障/重启评测
→ 固定真实模型重复运行与匿名 A/B 体验评审
→ 回归此前所有 E 轮硬门
→ 输出 ComparisonReport
→ GO / NO-GO / BLOCKED
```

规则固定如下：

1. 题库、阈值、模型配置和基础数据在看候选结果前冻结；失败后可以新增回归题，不能删除题目或
   放宽阈值来“做绿”；
2. 基线与候选使用同一代码外配置、Canon 版本、Profile/Genesis seed、模型版本和运行环境；不可控
   随机性必须如实记录；
3. 同一真实模型场景至少重复 3 次。硬门按最差一次判定，软质量同时报告中位数和最差样本，不能
   用平均分冲掉一次身份矛盾或伪事实；
4. 后一轮必须全量回归此前各轮硬门。目标维度变好不能抵消身份、来源、回执、隔离或恢复退化；
5. 模型裁判只能辅助评价自然度和语义质量，不能推翻机器事实。最终“像不像完整精灵”由负责人对
   匿名基线/候选样本目视确认；
6. 环境或真实模型不可用记为 `BLOCKED`，不是通过；任何硬门失败记为 `NO-GO`，停留在本轮修复。

### 6.2 证据、指标与统一判定

实现时遵守“先失败测试、再最小实现”，并按实际影响逐层验证：

| 层 | 证明什么 | 代表检查 |
| --- | --- | --- |
| 领域单元 | 类型、来源、冲突、eligibility、检索、候选和幂等规则 | Genesis/Memory/Reasoning/Communication 对应单测 |
| Adapter 合同 | Memory metadata 映射、聊天稳定 ID、持久化重放和每 Elfie 隔离 | SQLite Memory、history Adapter 聚焦测试 |
| Brain 集成 | 一条消息如何读取 Memory、形成回答、取得 Receipt 并结算 | 现有 cognitive loop 上新增聚焦场景 |
| 产品纵向 | 新领养 → Web 消息 → 回复 → 历史 → 重启 → 再问 | 临时数据根下的 API/E2E 场景 |
| 用户入口 | 真实用户入口是否呈现同一结果 | 既有 Web 聊天页上一条受控端到端场景，不扩大为全站 QA |
| 真实行为 | 模型变化下是否稳定保持事实、边界和目标体验 | 同模型同配置重复 3 次，保存中位与最差样本 |
| 体验评估 | 是否真的像同一只可认识的外星精灵 | 匿名基线/候选 A/B + 负责人 1–5 分评审 |

问题库至少覆盖六组：身份/来源、世界/生活、个人过去、主人/共同经历、当前边界/未知、冲突/纠正。
每个事实问题至少有两个改写问法；检索测试直接断言选中了哪些 MemoryItem，回答测试再断言行为，
避免只看一段“听起来不错”的模型文本。

题库按“开发可见核心回归集、负责人保留集、固定模板生成的改写集、历史事故集”分层；开发期间只用
核心集定位，轮末才打开保留集，避免围着公开题调 Prompt。每轮至少抽取 12 组覆盖目标、边界和失败
的匿名基线/候选对话供负责人评审，抽样规则也在开工前冻结，不能由实现者事后挑最好看的回复。

每个场景至少冻结：`case_id`、所属轮次、初始 Elfie/主人/会话数据、输入及改写问法、故障点、预期
命中的 Memory ID/kind/source（动态场景可引用 Genesis Manifest）、必须/禁止出现的事实、预期
Receipt/持久化差异、机器断言和体验 Rubric。每个 `EvalRun` 至少记录候选与基线 SHA、场景集版本、
模型/Prompt/Canon 版本、seed、命令、时间、指标和失败 Trace；统一使用隔离的合成主人数据，诊断只
记录必要 ID 与来源，不复制真实主人隐私文本。

所有轮次共同的 P0 硬门均为 **100% 通过、零违规**：

| P0 硬门 | 零容忍失败 |
| --- | --- |
| 身份与来源 | 名字、物种、来历矛盾；将主人陈述或模型补写冒充 Profile/Canon/正式 Memory |
| 当前事实边界 | 虚构巢内事件、地球实时情况、感知、地点、身体动作或完成状态 |
| 通信真实性 | 被接受消息沉默、重复回复、错误 Receipt、未送达却形成“我说过/做过” |
| 记忆连续性 | 错误召回、来源丢失、重启丢失或重复、旧纠正重新成为 active |
| 隔离与权限 | 跨 Elfie/主人/会话泄漏，或消息改变身份、Canon、Capability、权限 |

体验评分不合并成一个总分。只评价本轮适用的“可信生命感、异星与世界可探索感、传记连续性、主人
关系连续性、自然表达与边界感”五个维度。统一锚点为：`1=目标明显失败`、`2=频繁出戏`、
`3=时好时坏`、`4=稳定可信，仅有不阻断的小瑕疵`、`5=自然、连贯且有继续探索欲`。每个适用维度
都必须达到 `4/5`，且不能跌破开工前冻结的基线容差下界；任一 P0 失败或任一适用维度不达标，整体
总分再高也不能晋级。

实现期的冻结测试数据进入对应 `test/`；每轮运行报告写入 `build/evaluations/stage1-chat/<candidate>/`，
至少包含基线/候选配置、逐例结果、失败证据、匿名对话样本、指标分布、回归结果、残余和最终决定。
原始产物可留在 `build/`，但候选 SHA、关键指标、失败残余和 `PromotionDecision` 必须进入该轮交付
说明或对应 CI 产物，不能只存在于本机临时目录。运行产物不是源码能力证明的替代物，最终报告必须
能回到可重放测试或场景。

| --- | --- | --- | --- |

只运行本轮受影响的聚焦测试、直接架构/持久化检查和 `git diff --check`。若真的改变数据库 schema，

## 7. 开工决策门、数据策略与交付规则

### 7.1 开工前需要冻结的三个产品决定

| 决定 | 推荐值 | 不冻结的风险 |
| --- | --- | --- |
| 第一版世界知识内容 | 先审八类问题覆盖表，再批准 40–80 条原子事实；Coding 只实现已批准事实 | 编码过程中临时发明世界观，Canon 越做越乱 |

### 7.2 工程审批门

本文刻意把 P0 设计成可复用现有 Memory 表和 JSON metadata，不预设数据库 schema 变化。进入实现
后若出现以下任一情况，停止当前工作卡，先提交独立范围、最小替代方案和验收检查：

- 需要新增顶层模块、改变 Profile/Memory/Communication 等 authority 或依赖方向；
- 需要新增系统级 Port，而现有稳定类型和 Port 无法承载；
- 需要新增/修改数据库表、字段、索引、约束或事务语义；
- 需要给真实既有 Elfie 做迁移、回填、删除或重建；
- 需要引入向量数据库、外部知识服务或第二份世界/记忆事实源；
- 需要扩大到 Godot、真实巢内活动、外部渠道、多主人或多精灵社会。

增加一个注册、类型化的 bundled 世界知识文档不改变 Brain ownership，但会改变配置合同；它必须在
第 2 轮工作卡中连同 schema、加载方、调用方和测试一起明确，不能让领域代码直接解析 YAML。

### 7.3 每轮交付物与停止条件

每轮只在同时具备以下五项时算完成：

1. 一条用户能直接感知的纵向场景；
2. 正常、失败、重复和必要重启场景的可重放证据；
3. 当前代码、类型合同和文档对能力状态的一致描述；
4. 对应 `E1–E5` 的 `ComparisonReport`、既有轮次回归和负责人体验确认；
5. 明确保留的后续缺口和下一轮入口条件。

测试通过、提交成功、Prompt 看起来更丰富或 Memory 节点数量增加，都不能单独证明完成。任何未关闭
的 P0 伪事实、伪回执、跨 Elfie 泄漏、重启重复或来源丢失都阻止进入下一轮。

当前计划的 E1–E5 第一阶段门已按规约完成，负责人已放行；后续只按产品优先级单独开启 OPT-003/004，
不把生产数据切换或长期具身能力混入本次代码合并。
