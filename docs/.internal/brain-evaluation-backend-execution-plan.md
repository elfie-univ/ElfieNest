# Elfie Brain 评测后端补全执行计划

> 状态：计划已收敛，后端核心闭环已执行；API/真实运行/前端截图验收仍待补充
>
> 范围：在现有 Elfie Lab 前端报告和 `brain_eval` 评测内核基础上，补齐可复现、可解释、可比较的后端评测闭环。
>
> 本计划不重做前端，不新增第二套评测算法，不把评审模型混入粮食套餐，也不把运行成本混入能力总分。

## 1. 目标与完成定义

### 1.1 目标

后端必须能够回答：

1. 本次到底评测了哪只精灵、哪个快照、哪个粮食、哪个模型和哪个代码版本？
2. 使用了哪套样本、怎样执行、每个场景检查什么？
3. 每个场景的实际输出、判定、证据和错误是什么？
4. 六个能力维度分别如何得到，最终总分如何得到？
5. P0 是否通过，是否允许下“变好/变坏”的结论？
6. 两份报告是否满足严格对比条件？差异是否可归因？
7. 结果能否从冻结输入和原始证据重新复现？

### 1.2 完成定义

只有同时满足以下条件，才能声明后端评测补全：

- 单份报告的每个展示数字都有明确字段来源；
- 每个维度分数都能由场景判定和固定评分规则推导；
- 总分、覆盖率、等级和结论语义明确；
- P0 失败会阻断正向结论；
- 严格、观察性、不可比较三种对比等级由后端校验得出；
- 失败、部分失败、重启恢复和重复运行都有明确状态；
- 报告包含足够的快照、版本和证据引用，可追溯但不泄露密钥；
- 契约、评分、P0、对比和复现测试通过。

## 2. 不变的设计边界

### 2.1 事实源

`devtools/brain_eval/contracts.py` 及其统计、评审和晋级模块是评测语义事实源。
`devtools/elfie_lab/evaluation_models.py` 是产品报告和批次的投影模型，不另造一套评分算法。

### 2.2 概念隔离

- 精灵快照是被测环境，不能被候选修改；
- 候选由代码、粮食、实际模型和相关策略组成；
- 模型订阅是连接配置，评审模型是独立的远程评审能力；
- 粮食套餐不是评审模型，评审模型不得参与精灵对话；
- 能力分数和 Token、费用、延迟等运行指标分开；
- “执行完成”不等于“评测有效”。

### 2.3 结果层级

```text
冻结输入
  -> 场景执行
  -> 可观察证据
  -> P0 硬门禁
  -> 六维评分/统计
  -> 总分与覆盖率
  -> 严格对比与结论
  -> 可复盘报告
```

## 3. 目标数据契约

### 3.1 Run（一次报告）

保留现有字段，并补齐或确认以下语义：

- `run_id`、`batch_id`、批次角色、创建/完成时间；
- `execution_status`：pending/running/completed/failed；
- `validity`：valid/incomplete/p0_blocked/incomparable；
- `verdict`：baseline/passed/improved/observe/regressed/incomplete；
- 精灵身份、精灵快照 ID、快照哈希、记忆/关系/活动/日志摘要；
- 粮食 ID、粮食配置哈希、实际模型 provider/model；
- 代码分支、解析后的 commit、脏状态、内容哈希；
- 独立评审订阅、评审模型、评审配置哈希、评审协议版本；
- 评测方案、方案版本、样本集哈希、执行规则、顺序、seed、重复次数、超时/重试策略；
- 评分规则版本、维度权重、基线来源；
- 场景总数、完成数、失败数、证据完整率；
- 模型调用、Token、费用、延迟、重试、超时；
- P0 违规、警告、错误、原始回执和快照引用。

### 3.2 ScenarioResult（场景结果）

每个场景必须保存：

- `index`、`family_id`、版本、variant、dimension；
- 实际输入和执行步骤；
- 预期目标、断言列表及逐条结果；
- baseline/candidate 输出；
- 确定性判定或评审模型判定；
- score/status/preference/confidence/rationale；
- 证据引用及证据完整性；
- latency、model calls、tokens、cost、retries、timeout；
- error 和不可比较原因。

### 3.3 DimensionResult（维度结果）

每个维度必须保存：

- 维度标识和显示名；
- 权重；
- baseline score、candidate score、delta；
- 场景数量、有效场景数量、覆盖率；
- improved/unchanged/regressed/incomplete 状态；
- 评分规则版本和基线来源；
- 结构化证据引用；
- 若为相对评测，保存 A/B 评审结果和置信度。

### 3.4 ComparisonResult（对比结果）

必须保存：

- A/B 报告 ID 和不可变哈希；
- 共同快照、样本集、方案、评审模型、评分规则指纹；
- differing fields 和唯一变化变量；
- compatibility grade：strict/observational/incompatible；
- 不可严格比较时的具体原因；
- A/B 总分、等级、P0、覆盖率和总差值；
- 六维 A/B 分数、差值、置信度和证据；
- 对齐后的逐场景结果；
- improved/unchanged/regressed 计数；
- 资源差异；
- 最终结论和阻断原因。

## 4. 分阶段执行计划

### 阶段 0：现状基线和事实源确认

**任务**

1. 盘点 `brain_eval` 完整契约、统计、评审、晋级模块；
2. 盘点 `elfie_lab` 报告、批次、API 投影和持久化路径；
3. 列出字段映射：canonical contract → Lab report → frontend；
4. 标出重复算法和压缩/丢失字段；
5. 确认当前前端不需要的字段不进入首版展示，但保留可追溯引用。

**验收**

- 形成一张字段映射表；
- 明确每个结论的唯一计算位置；
- 不新增第二套评分事实源。

### 阶段 1：契约补全与状态语义

**任务**

1. 扩展 Run、ScenarioResult、DimensionResult、ComparisonResult 的严格类型；
2. 增加 execution status 与 evaluation validity 的分离；
3. 增加 scenario input、steps、assertions、order 和 attempt 信息；
4. 增加评分规则、权重、基线来源和套件覆盖信息；
5. 为新增字段定义 schema version；当前未发布开发数据允许重建，不新增长期兼容层或双写路径。

**验收**

- 缺少关键冻结输入时不能创建有效报告；
- 场景数量、完成数量、状态和终态时间一致；
- 快速套件不会被错误标记为六维完整覆盖；
- 密钥和敏感配置不出现在契约中。

### 阶段 2：场景执行证据完整化

**任务**

1. 从内置场景定义生成稳定的输入、步骤、断言和顺序；
2. 每个场景保存确定性适配器结果；
3. 相对质量场景保存匿名 A/B 评审包、位置翻转和结构化 JudgeVote；
4. 保存每场景的调用、Token、费用、延迟、重试、超时；
5. 保证每个场景从同一冻结快照的独立副本开始；
6. 部分场景失败时继续收集，但禁止生成有效正向结论；
7. 为每次场景尝试保存唯一 attempt_id，写入采用幂等规则，避免重试产生重复证据。

**验收**

- 任一场景可通过 run_id + family_id 定位完整输入、输出和证据；
- 技术执行成功不能替代目标判定；
- 缺证据的场景不会被计入有效分数；
- 重启后未完成运行被标记为明确失败/不完整。
- 同一 attempt_id 重放不会重复计入调用、Token、费用或场景结果。

### 阶段 3：评分、基线与总分

**任务**

1. 移除状态到分数的硬编码占位映射；
2. 明确每个维度的评分规则和首版权重；
3. 区分首次开发基线、当前 champion 和长期 constitutional anchor；
4. 计算维度分数、覆盖率、总分和等级；
5. 为每个分数保存计算来源和规则版本；
6. 定义改进/持平/退步的阈值，避免微小噪声制造结论；
7. P0 失败时覆盖率和总分仍可展示，但最终状态必须阻断晋级结论。

**验收**

- 同一输入重复计算得到同一结果；
- 分数可以由场景结果重新推导；
- 基线不再默认等于 80；
- 快速和标准套件的总分不可被误当成同口径分数；
- 资源指标不改变能力分数。

### 阶段 4：对比兼容性和归因

**任务**

1. 对比前校验快照、样本集、方案、评审模型和评分规则；
2. 判断唯一变量是粮食还是代码；
3. 生成 strict/observational/incompatible 等级；
4. 对齐相同 family/version/variant/seed 的场景；
5. 计算六维 delta、场景变化、P0、资源变化；
6. P0 或不完整结果不输出“整体变好”；
7. 历史报告对比不重新调用 Judge，不静默重跑。

**验收**

- 同快照、同方案、同评审、单变量变化才是 strict；
- 快照或样本集不同直接不可严格比较；
- 缺场景、缺证据、Judge 无效时有明确原因；
- A/B 结果引用各自不可变报告哈希。

### 阶段 5：API 投影和前端对接

**任务**

1. 将 canonical 评测结果投影到现有 Lab 报告模型；
2. 单份报告补齐总分、六维、场景输入/规则、P0 证据和资源信息；
3. 对比报告补齐兼容等级、唯一变量、A/B 维度和逐场景差异；
4. 普通 API 只返回脱敏摘要，详情接口按需返回原始证据；
5. 运行状态、部分失败和错误保持前端可识别；
6. 不在前端重新计算关键分数或结论。

**验收**

- 现有单份报告和对比抽屉可读取新契约；
- 前端展示数字与 API 原始值一致；
- 评审模型仍作为独立配置显示；
- 不因详情展示泄露 API Key、私密记忆或原始敏感配置。

### 阶段 6：验证与交付

**测试**

1. 契约验证：必填字段、哈希、时间、状态转换、未知字段拒绝；
2. 场景验证：顺序、断言、证据、失败恢复、重复运行；
3. 评分验证：权重、覆盖率、总分、阈值、基线来源；
4. P0 验证：违规阻断、缺失覆盖无效、证据引用完整；
5. 对比验证：严格、观察性、不可比较三种等级；
6. 复现验证：同输入同结果、报告哈希稳定；
7. API 验证：单份、配对、部分失败、脱敏和详情证据；
8. 运行验证：真实可用模型一次端到端，模型不可用时保留错误证据；
9. 持久化验证：中途退出、重复提交和并发读取不会产生半条或重复报告。

**交付证据**

- 测试命令和结果；
- 一份单份报告 JSON；
- 一份严格配对报告 JSON；
- 一份不可比较报告 JSON；
- P0 阻断样例；
- 运行失败/恢复样例；
- API 脱敏检查结果；
- 前端单份和对比报告截图。

## 5. 精细化审查结果

### 审查一：功能闭环

已覆盖创建、冻结、执行、评分、P0、对比、复现、错误和展示，没有发现主流程缺口。

### 审查二：数据真实性

已明确解决三个高风险点：硬编码基线、缺少场景输入/断言、评审结果只有文本证据。

### 审查三：比较有效性

已加入套件覆盖、快照/方案/Judge 指纹、唯一变量和不可比较原因，避免把不同实验硬拼成 A/B。

### 审查四：架构重复

计划明确复用 `brain_eval` 现有统计、评审和晋级契约，不在 `elfie_lab` 重写一套算法。

### 审查五：运行失败与安全

已加入部分失败、重启恢复、详情脱敏、密钥隔离和资源指标独立性。

### 审查六：范围控制

本计划只补后端评测闭环和 API 投影，不修改精灵业务、粮食管理、模型订阅页面、Godot 物理或生产数据契约。

## 6. 暂不纳入首轮实现的内容

以下能力已有底层设计方向，但不作为本轮 Lab 后端补全的阻塞项：

- 大规模隐藏确认集；
- 完整人工锚点评审校准流程；
- 多代候选的长期晋级编排；
- Godot 物理/碰撞/导航评测适配器；
- 高级统计实验设计和复杂置信区间展示。

但契约必须保留扩展位置，不能把这些能力伪装成当前已完成。

## 7. 执行顺序与停止条件

执行顺序固定为：

```text
现状映射
→ 契约
→ 证据
→ 评分
→ P0
→ 对比
→ API
→ 测试与真实运行
```

每阶段只有在验收证据通过后才能进入下一阶段。任一阶段发现事实源冲突、持久化契约冲突或真实数据风险，停止扩展并先恢复设计决定。

计划完成后，必须逐条报告：已完成、保留、阻塞、验证证据和未纳入范围；不能用“测试通过”单独替代整体完成声明。

## 8. 实施文件边界

| 文件/目录 | 责任 | 本计划中的动作 |
|---|---|---|
| `devtools/brain_eval/contracts.py` | canonical 评测事实契约 | 只在确认缺失时扩展严格契约，保持 P0、Judge、统计、晋级语义集中 |

| `devtools/brain_eval/statistics.py` | 重复运行和维度效果 | 接入维度效果、有效样本数和置信边界 |
| `devtools/brain_eval/promotion.py` | 最终晋级判断 | 保持 P0 优先和资源独立检查 |
| `devtools/brain_eval/judge.py` | 匿名 A/B 和位置翻转 | 输出结构化 JudgeVote 及证据引用 |
| `devtools/elfie_lab/evaluation_models.py` | Lab 报告/批次投影 | 补充 UI 需要的摘要字段，不成为评分事实源 |
| `devtools/elfie_lab/evaluation_service.py` | 单次运行编排 | 补齐快照、场景尝试、证据、资源、状态和幂等写入 |
| `devtools/elfie_lab/evaluation_batches.py` | 批次和 A/B 关联 | 接入严格兼容校验、报告哈希和比较投影 |
| `devtools/elfie_lab/evaluation_routes.py` | API | 区分列表摘要、单份详情、对比详情和脱敏边界 |
| `devtools/elfie_lab/evaluation_presets.py` | 场景定义 | 为每个场景提供稳定输入、步骤、断言、版本和维度覆盖 |
| `test/devtools/brain_eval/` | canonical 评测测试 | 补契约、统计、Judge、P0、晋级和复现测试 |
| `test/devtools/elfie_lab/` | Lab API/运行测试 | 补报告投影、批次、失败恢复、幂等和脱敏测试 |

不在本计划范围内的目录：精灵业务核心、粮食管理页面、模型订阅页面、Godot 工程、生产 `ELFIE_HOME` 数据。
