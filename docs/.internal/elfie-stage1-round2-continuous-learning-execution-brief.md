# 第二批任务开工文档：持续学习与记忆整理（OPT-002）

> 状态：待实施
>
> 本文对应基线后的优化轮次 2（`OPT-002`），不是第一阶段五轮验收中的 `E2`（异星知识）。
> 目标是让正常聊天产生的真实信息，经过可靠的记忆整理后可以跨回合、跨重启使用。

## 1. 用户目标

用户在正常聊天中告诉 Elfie 新人物、新称呼、喜好、边界或一段经历后，Elfie 能在后续对话和重启后正确记住；多轮描述同一件事只形成一个有来源的 Episode；更正会取代当前有效值但保留旧来源；重复消息不会生成重复记忆；不同 Elfie 之间绝不串记忆。

完成后，用户应该能明显感受到“它记住了我和我们聊过的事”，而不是只复读当前上下文。

## 2. 范围边界

### 本批次要做

- 正常聊天已接受事件到 `ClosedEpisode` 的可靠落盘和幂等重放；
- Episode 到知识节点、实体、关系和 Assertion 的有来源整理；
- 新人物/地点/物件的实体消歧、别名和稳定 ID；
- 主人事实、关系事实、纠正、冲突和 `supersedes` 链；
- 重启、重复消息、模型失败和整理重试后的收敛；
- 通过现有 `RecallRequest → RecallBundle` 检索新记忆，并保留类型、来源、时间和置信度；
- 为上述行为增加确定性测试、纵向重放和本批次评测报告。

### 明确不做

- 不扩充 Genesis 的世界知识/个人故事密度（那是 `OPT-001`）；
- 不做长期压缩、遗忘、归档、增长耐久性（`OPT-003`）；
- 不做真实精灵巢、身体观测或多精灵互动（`OPT-004`）；
- 不新增向量数据库、第二套记忆库或新的顶层模块；
- 不把所有聊天原文都升级为长期记忆；
- 不让 Memory 直接读取 Communication History、Profile 或其他模块数据库。

## 3. 固定概念和权威边界

1. **事件边界属于上游。** `Workspace/Turn Settlement` 负责事件准入、回合边界和闭合；Memory 接收带稳定来源 ID 的已闭合事件。若连续几轮应合并为同一事件，修复事件边界拥有者的实现，不把原始回合分组职责偷偷移进 Memory。
2. **Episode 是一件有边界的事。** 它不是一条消息，也不是整段聊天历史；包含摘要/原文、发生时间或时间标签、参与者、地点、主题、结果和来源事件 ID。
3. **来源先于投影。** 先持久化 `ClosedEpisode`，再做候选抽取和图谱投影。投影失败可以重试，不能丢失 Episode。
4. **模型只做受限抽取。** 可使用注入的模型做候选抽取、归一化或整理，但调用必须在写事务之外；候选必须能回指原始 Episode，确定性代码负责校验、消歧、合并和最终写入。模型不可用时保留来源 Episode，不能用猜测补事实。
5. **热路径不依赖模型。** 检索、去重、状态判断、`RecallBundle` 组装和重放必须由现有确定性存储/索引完成。

## 4. 本批次的记忆对象

| 对象 | 用途 | 关键规则 |
| --- | --- | --- |
| `ClosedEpisode` | 保存一件完整的聊天经历或主人叙述 | 有界、有来源、可重放；不因投影失败删除 |
| `OwnerClaim` | 主人告诉 Elfie 的称呼、喜好、边界等 | 保留“主人这样说”的归因；不能升级为世界事实 |
| `RelationshipAssertion` | “谁与谁是什么关系” | 有方向、角色、强度/状态和证据；允许并存或冲突 |
| `Correction` | 对旧称呼、偏好或关系事实的更正 | 新断言进入 active，旧断言保留并标记 `superseded` 或 `conflict` |
| `InteractionEpisode` | 证明双方真实完成过一次交流 | 需要主人消息、Elfie 回复、规范历史 ID 和满足阈值的 Receipt；未送达不能写成共同经历 |

不在本批次把计划、长期目标、执行能力或未来承诺当作 Memory 事实；它们仍由对应的 Brain 系统负责。

## 5. 固定处理流程

```text
上游已接受并闭合事件
  → 持久化 ClosedEpisode（稳定 source/event ID）
  → 有界候选抽取（可选模型，写事务外）
  → 确定性校验与归一化
  → 实体解析/别名绑定（歧义则不猜）
  → Assertion/关系合并、纠正和冲突保留
  → 原子提交可重试的图谱投影
  → RecallRequest 做有界文本/实体/关系检索
  → RecallBundle 返回独立 typed items
  → Reasoning 组织自然语言；不由 Memory 代写叙事
```

实现时必须满足：

- 同一消息、事件或 Receipt 重放只产生一次有效记录；稳定 ID 不能只存在于进程内；
- 实体按 `elfie_id` 隔离，显示名称只是别名，不能直接当主键；
- 精确别名/规范化匹配优先；模型建议只能缩小候选，不能强行合并；无法判定时保留未解析实体或等待澄清；
- 合并不得覆盖不同来源、视角、极性、时间或冲突；
- 召回时优先当前 active 断言，同时向需要的场景暴露旧值、冲突和证据；
- `RecallBundle` 中每项必须保留真实 `memory_id`、类型、内容、来源、时间/时间标签、置信度和关联实体；
- 不通过关键词准入，不把当前问题的 ID 冒充记忆来源，不把模型输出直接当正式事实。

## 6. 实施工作包

1. **现状盘点与失败测试**：从入站事件、Turn Settlement、Episode 写入、整理 Worker、图存储到 RecallBundle 画出真实调用链；先固定重复、重启、歧义、纠正和模型失败的失败用例。
2. **Episode 闭合与 source-first**：补齐正常聊天事件的稳定来源、闭合边界、内容哈希和重放收敛；不改变 Workspace 的所有权边界。
3. **候选与实体解析**：实现有界候选抽取、实体规范化、别名绑定、歧义保留和确定性 ID；模型调用可重试但不能阻塞来源写入。
4. **关系/纠正投影**：实现 OwnerClaim、RelationshipAssertion、Correction 的证据绑定、active/superseded/conflict 状态和幂等合并。
5. **检索与恢复**：验证新记忆可按文本、主题、实体和关系召回；重启后仍能返回 typed `RecallBundle`，不泄漏其他 Elfie。
6. **诊断与台账**：只记录必要的 ID、类型、来源和状态；更新 `OPT-002` 的 target、inventory、references、verification、residuals 五类证据。

默认复用当前 Memory schema、Adapter、`RecallRequest` 和 `RecallBundle`。若实现需要新增表、字段、索引、系统级 Port 或真实数据迁移，先停在工作包边界，按持久化审批规则提交单独变更，不在本批次偷偷扩展范围。

## 7. 验收与交付门

固定场景至少包括：

1. 多轮对话描述同一件事，闭合为一个 Episode；无关话题形成独立 Episode；
2. 新人物先用正式名、后用昵称，再次询问仍指向同一实体；真正歧义时不乱合并；
3. 主人提供称呼/喜好/边界，随后纠正一次；重启后只返回最新 active 值，并能追溯旧来源；
4. 两条相互冲突的陈述都保留证据，回答不会把冲突编成确定事实；
5. 重复入站、重复整理、重复 Receipt 不产生重复节点或重复共同经历；
6. 模型抽取失败、进程中断后重试，Episode 不丢失且投影最终收敛；
7. 发送失败不形成“我已经回复过”，但已成立的主人陈述不因模型/发送失败丢失；
8. 两只 Elfie 使用相同名称时，实体、主人事实和检索结果完全隔离。

机器硬门全部 100% 通过：无丢失、重复、串线、错误归因、错误 active 值、伪共同经历或无来源事实；预期新记忆在重启后可召回。真实模型仅用于评估抽取稳健性和自然度，不能推翻机器事实门。报告需包含候选 SHA、场景集版本、模型/配置版本、逐例结果、失败证据、回归结果和剩余项。

本批次完成条件：聚焦测试和受影响持久化/架构检查通过；持续学习回归通过；`OPT-002` 台账证据完整；明确记录仍属于 `OPT-001/003/004` 的内容。完成后再与 `OPT-001` 做一次组合回归，不提前启动第三、第四批。
