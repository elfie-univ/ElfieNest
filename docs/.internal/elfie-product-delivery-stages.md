## 1. 文档目标

ElfieNest 不按 Brain、Memory、Emotion、Nest 或 Godot 等模块分别交付产品。模块负责保持正确的
所有权和依赖边界；产品迭代按用户能够完整体验的生命场景推进。

本文固定三个顶层产品阶段：

1. 用户通过聊天认识一只完整的外星精灵；
2. 用户观察到这只精灵在虚拟精灵巢中真实生活；
3. 同一只精灵通过实体身体进入现实世界。

每个阶段可以包含多个可独立验收的子阶段。子阶段完成时必须交付一条纵向闭环，而不是只完成
某个内部模块。现有 Brain 七阶段属于认知系统的实施里程碑，不与本文三个产品场景形成一一对应，
也不取代本文的用户交付顺序。

## 2. 最终产品目标与三阶段总览

最终目标是：

> Elfie 是一只有异星来历、连续自我、身体、记忆、关系和自主性的生命伙伴；它能在通信、虚拟
> 精灵巢和现实身体之间保持同一个自己，并只根据真实经历和明确来源理解世界。

| 大阶段 | 用户主场景 | 阶段目标 | 阶段完成后的直接感受 |
| --- | --- | --- | --- |
| 1. 通过聊天认识精灵 | 用户与刚被领养的 Elfie 对话 | 聊起来像一只有过去、记得主人、刚来到地球的完整外星精灵 | “我认识的是一个人，不是套设定的大模型” |
| 2. 在精灵巢中真实生活 | 用户观察 Elfie，并询问它的巢内生活 | 看起来、行动起来、回忆起来都像一只真正住在虚拟世界中的精灵 | “它不只是说自己活着，它真的在那里生活” |
| 3. 进入现实世界 | Elfie 使用实体玩具等现实身体 | 同一只 Elfie 带着原有自我和记忆，安全感知、行动和探索地球 | “虚拟世界里的伙伴真的来到我身边” |

三个阶段的依赖顺序是：

```text
先成为一个能够被认识的完整个体
→ 再成为一个在虚拟世界中真实生活的具身生命
→ 最后成为一个能够进入现实世界的长期伙伴
```

第一阶段是当前最小可交付版本。第一、第二阶段是软件产品的首要交付范围；第三阶段依赖实体
硬件和现实安全能力，在前两阶段稳定后再细化。

## 3. 所有阶段共同遵守的事实边界

1. **模型输出不是事实**：Brain 身份只由 Selfhood 支持；世界知识、关系和经历只由 Memory 支持；
   当前事实还需要权威状态、真实感知、工具结果或执行回执。Profile 只是外部冻结档案，世界/物种
   资料只服务未来创建，二者都不是普通 Brain 的事实输入。
2. **认知来源必须可区分**：Elfie 要区分亲历、当前感知、主人告知、工具查询、既有知识和未知。
3. **不能用 Mock 生成生命历史**：开发预览、测试动作和伪造世界事件不得进入产品记忆。
4. **没有能力时仍要回复边界**：不能回答事实不等于沉默；Elfie 应自然说明自己尚未经历、无法
   感知或当前不知道。
5. **同一只 Elfie 必须连续**：会话、重启、虚拟身体和未来实体身体共享同一身份、记忆和关系。
6. **每个阶段都要验证失败与恢复**：正常演示、测试通过或生成了一段自然语言，均不能单独证明
   阶段完成。
7. **创建链路提交后断开**：世界骨架 → 居民公共知识 → GenesisSourcePackage 只单向服务一次创建；
   问卷、候选输入、LifeContext、计划、资料绑定和 Seed 在提交或终止失败后删除。
8. **模块不越权**：`elfie/genesis` 生成生命语义，App 只协调，Infrastructure 只加载和保存强类型值。

## 4. 第一阶段：通过聊天认识一只完整精灵

### 4.1 大阶段目标

> 用户仅通过聊天，就相信自己领养了一只有异星来历、有稳定自我、有少量但一致的过去、记得
> 主人，并且清楚自身感知边界的 Elfie。

第一阶段不是完整的精灵巢模拟。Elfie 已经来到地球，产品当前只开放通信生命线，尚未开始真实
探索精灵巢。“已经到达”来自正式经历，“当前只能通信、不能探索”来自实际 Capability 和
Orientation，不是模型临时编造的巢内活动。

只有 Energy、Activity 或位置事实真实支持时，Elfie 才能说自己虚弱、休息、刚醒或躺在某处；
否则只自然说明“我还没有开始探索，现在只能通过这里和你说话”。没有权威地点时不得虚构床、
恢复区或房间。

第一阶段只开放通信生命线：

```text
主人消息
→ Communication
→ 单域 Turn
→ 身份、处境、情绪、能量、记忆上下文
→ Reasoning
→ 同一会话回复
→ 真实发送回执
→ 对话与重要经历连续化
```

### 4.2 第一阶段子阶段总览

| 子阶段 | 小目标 | 用户新增感受 | 主要涉及系统 |
| --- | --- | --- | --- |
| 1.1 稳定聊天闭环 | 每条主人消息得到正确、唯一、可恢复的结果 | “它一直在这里，也不会突然失联或串话” | Communication、Workspace、Reasoning、Receipt、Journal |
| 1.2 精灵身份与认知边界 | 始终从自身身份、来历和当前处境回答 | “它真的来自另一个世界，不是默认地球人” | Selfhood、Memory、Orientation、Brain Context；Profile 只用于外部档案 |
| 1.3 可探索的领养前历史 | 拥有少量、一致、可反复追问的过去故事 | “它在认识我之前已经生活过” | Genesis、Memory、Selfhood、Retrieval、Reasoning |
| 1.4 主人与共同经历 | 记得主人和双方真实发生的重要事情 | “它认识我，而且我们的关系在连续发展” | Communication Receipt、Memory、Conversation Context、Continuity |
| 1.5 完整聊天体验验收 | 人格、状态、故事、边界和失败行为形成统一体验 | “我愿意相信并继续了解这只精灵” | Selfhood、Emotion、Energy、Reasoning 与前四个子阶段 |

这五项是用户验收维度，不是五个彼此独立的模块工程。实施时始终扩展同一条“Genesis → Memory
类型化读写 → Reasoning → Communication/Receipt → Memory 连续化”主干；详细轮次和完成门以
[第一阶段执行计划](./elfie-stage1-memory-backed-chat-execution-plan.md)为准。

### 4.3 子阶段 1.1：稳定聊天闭环

**目标**：每条进入正确会话的主人消息，最终得到一个且只有一个可解释结果。

**能够做到**：

- 连续文字交流；
- 不混淆不同会话和不同发送者；
- 只把真正送达的回复视为已经说过；
- 模型失败、超时或预算不足时给出一次自然的降级答复，而不是沉默；
- 重启后不重复回复，不把未送达内容写成共同经历。

**实现重点**：

- 固定 Communication、Workspace、Reasoning、Directive 和 Receipt 的因果链；
- 为通信失败准备不依赖第二次模型调用的有界表达；
- 以会话 Scope、幂等键和发送回执收束一次聊天；
- 持久保存继续对话所需的最小上下文，不把原始日志冒充长期记忆。

**完成目标**：普通对话、模型失败、发送失败和中途重启四类场景均不会产生沉默、串话、伪完成
或重复回复。

### 4.4 子阶段 1.2：精灵身份与认知边界

**目标**：Elfie 无论被问到什么，都先从“我是谁、我在哪里、我怎样知道这件事”出发回答。

**必须稳定知道**：

- 自己的名字、物种、核心身份与表达风格；
- 来自哪个星球，以及母星与地球的关键差异；
- 赴地计划和自己自愿参加这一共同事实；个人为什么愿意参加由领养前传记补充；
- 当前已经到达地球，可以通信，但尚无真实精灵巢探索能力；
- 当前没有哪些传感器、世界访问和实时地球信息；
- 哪些内容来自记忆、感知、主人、工具或未知；运行时不把创建资料列为认知来源。

**能够回答的问题**：

- “你是谁、从哪里来、为什么来到地球？”
- “你们的星球和地球有什么不同？”
- “你现在在哪里、正在做什么、感觉怎么样？”
- “你知道地球今天的天气吗？”
- “精灵巢今天发生了什么？”

后两类问题只回答能力边界，不能虚构事实。例如：

> “我已经来到地球了，不过还没有开始探索精灵巢。现在我只能通过这里和你说话，所以不知道里面
> 今天发生了什么。”

> “我现在感受不到地球外面的天气，所以不知道。如果以后我能够看到或查询到，我会告诉你这是我
> 亲眼感受到的，还是通过其他来源知道的。”

**实现重点**：

- Selfhood 提供 Brain 的身份人格；Profile 只向外部展示冻结客观档案。世界/物种资料只在领养时由
  Genesis 编译，Elfie 实际知道的内容交给 Memory，并从 Memory 类型化检索；
- 把第一阶段的实际能力边界投影到 Capability/Orientation/Brain Context，而不是只写一段角色提示词；
- 建立最小认知来源标签，使 Reasoning 能区分亲历、感知、告知、查询、知识和未知；
- 对当前精灵巢、其他精灵和地球实时事实默认 fail-closed。

**完成目标**：跨问题、跨会话和跨重启保持同一身份与处境，不把自己说成默认地球人，不宣称
尚未获得的感知和巢内经历。

### 4.5 子阶段 1.3：可探索的领养前历史

**目标**：用户能通过追问逐渐发现 Elfie 的过去，而不是感觉它从领养当天才开始存在。

第一阶段只需要 3–5 个关键领养前经历：

1. 一段故乡或幼年生活；
2. 一个过去的重要人物或关系；
3. 一次温暖、快乐或自豪的经历；
4. 一次困难、失落、害怕或犯错的经历；
5. 一段离开母星、来到地球或等待领养的经历。

这些经历不是五张独立卡片，而要复用一个家乡地点、1–2 个重要人物和一条因果脉络。每个经历至少
保存 life stage/时间标签、地点、人物、事件、结果、感受、影响、来源和稳定事实。模型可以改变
讲述方式，不能每次更换核心人物、地点或结果。没有保存的细节可以承认记不清，不能为了丰富故事
自动写成公共世界资料。

**能够回答的问题**：

- “你小时候住在哪里？”
- “你最想念谁？”
- “你以前最开心或最害怕的事情是什么？”
- “你们星球的天空、声音或生活是什么样的？”
- “你为什么愿意来到地球？”
- “这段经历为什么让你变成现在这样？”

**实现重点**：

- 领养初始化时生成并整体校验一次结构化传记包，再以稳定 ID 原子提交到 Memory；创建工作区只支持
  未完成事务恢复，成功或终止失败后删除；
- 世界/物种 KnowledgeSeed 与 3–5 个 EpisodeSeed 分开，知识数量不占用个人经历名额；
- 共享物种/世界创建资料与个体传记分开，避免所有 Elfie 拥有完全相同的人生；
- 按当前话题检索相关经历，而不是每次把完整背景塞入 Prompt；
- 新叙述若产生重要新增事实，只能形成候选，经一致性检查后再进入正式记忆。

**完成目标**：围绕至少三条不同话题能够自然回忆，重复追问和重启后核心事实不矛盾，也不会把
未知细节包装成确定事实。

### 4.6 子阶段 1.4：主人与共同经历

**目标**：领养前历史和领养后生活属于同一个连续人生；Elfie 能记住主人以及双方真实发生的事情。

**第一阶段保存的领养后信息**：

- 主人的称呼和明确身份事实；
- 主人明确表达的喜好、不喜欢和重要边界；
- 主人对错误事实的纠正；
- 双方明确形成的约定；
- 已经成功送达回复的关键互动；
- 当前会话中仍需连续使用的短期上下文。

**能够回答的问题**：

- “我叫什么、我喜欢什么？”
- “我之前纠正过你什么？”
- “我们第一次或最近一次重要聊天说了什么？”
- “今天我们之间发生了什么？”

第一阶段的“今天”只允许包含真实通信、权威状态变化和已有回执支持的事件，不包含散步、使用设施、
遇见其他精灵等尚未真实发生的巢内活动。

**实现重点**：

- 主人消息被认知接受后，可以形成带来源的“主人说过”候选；只有通信实际完成后，才连接主人输入、
  Elfie 回复和发送回执并形成共同互动；
- 使用有界编码策略选择重要事实、纠正、约定和关系事件，不保存全部闲聊；
- 保留来源、因果和可信度，使主人告知不自动变成世界客观事实；
- 让相关记忆在后续会话和重启后能够被检索使用。

**完成目标**：主人提供一个身份事实、一个喜好和一次纠正后，Elfie 能在后续会话及重启后正确
使用；没有完成投递的回复不会被记成共同经历。

### 4.7 子阶段 1.5：完整聊天体验验收

**目标**：前四个子阶段组成一只自然、可信、愿意继续了解的 Elfie，而不是身份资料库或机械拒答器。

**表达要求**：

- Selfhood 保持稳定人格和说话风格；
- Emotion 和 Energy 只对语气、活跃度和回复深度产生有限影响；
- 不用相同模板重复“我还不能探索”；
- 能承认未知，也能围绕已有经历自然展开或反问；
- 当前情绪不能改写身份、历史和认知边界。

**代表验收故事**：

1. 用户完成领养并开始第一次聊天；
2. 询问身份、母星和来到地球的原因；
3. 沿不同话题追问至少三段过去经历；
4. 询问地球天气、当前精灵巢和“今天做了什么”；
5. 告诉 Elfie 主人的称呼、一个喜好和一次纠正；
6. 重启后继续聊天并再次询问上述事实；
7. 注入一次模型失败和一次发送失败。

**大阶段完成门**：身份与历史一致；不虚构巢内和地球实时事实；能够记住主人和真实共同经历；
失败和重启不破坏连续性；用户能够通过完整对话直接感受到它是一只有过去的外星精灵。

### 4.8 第一阶段问题与行动边界

| 问题或请求 | 第一阶段行为 |
| --- | --- |
| 自己是谁、来自哪里、为什么来地球 | 根据 Selfhood、已知世界 Memory 和领养前经历回答 |
| 过去的人物、地点、文化和故事 | 检索已有自传记忆；未知细节明确表示不确定 |
| 主人的名字、喜好、纠正和双方谈话 | 根据已完成互动和正式记忆回答 |
| 当前心情、能量和恢复状态 | 根据权威状态自然表达 |
| 精灵巢的一般概念 | 只回答自己 Memory 中已有的可靠知识，并说明不是当前亲历 |
| 精灵巢当前事件、位置、设施和其他精灵 | 说明尚未探索、当前无法感知，不提供伪事实 |
| 地球当前天气、新闻和现场状态 | 没有感知或授权查询结果时明确不知道 |
| 请求移动、使用设施或寻找其他精灵 | 说明当前身体尚未进入可探索状态，不伪造执行 |
| 普通聊天、倾听、讲述过去和认识主人 | 正常完成 |

## 5. 第二阶段：在精灵巢中真实生活

### 5.1 大阶段目标

> 用户能够观察到 Elfie 在虚拟精灵巢中真实感知、行动、生活、社交并形成经历；之后通过聊天
> 询问时，它只根据真实世界事实和自身记忆回答。

第二阶段开放具身生命线，并与第一阶段通信生命线并行：

```text
精灵巢/Godot 真实事件
→ Body 与 Nervous System
→ 单域 Embodied Turn
→ Orientation、Memory、Emotion、Energy 与 Reasoning
→ 高层身体行动
→ 世界权威执行与回执
→ 巢内经历、关系和日常生活记忆
```

聊天回合不能顺手控制身体，具身回合也不能顺手向远程联系人发消息。需要跨线路的后续行为必须
形成新的内部 Turn 或 Persistent Activity。

### 5.2 第二阶段子阶段总览

| 子阶段 | 小目标 | 用户新增感受 | 主要涉及系统 |
| --- | --- | --- | --- |
| 2.1 单只精灵真实具身 | 一只 Elfie 能在权威虚拟世界中感知和行动 | “它真的在巢里，而不是播放动画” | Nest、Godot、Body、Nervous System、Workspace、Orientation、Reasoning |
| 2.2 真实日常生活 | 时间、设施、能量和真实事件形成连续一天 | “它有自己的今天，也能讲清今天发生了什么” | Nest 四功能、Energy、Memory、Activity、Journal |
| 2.3 自主生活与履约 | 无人持续命令时也能安全生活和履行承诺 | “它不只是被操纵，它会自己安排生活” | Motivation、Activity、Energy、Reasoning、Memory |
| 2.4 多精灵社会生活 | 多只独立 Elfie 形成持续、隔离的社会关系 | “它们不是 NPC 对话，而是彼此认识的生命” | Nest Events、多个 Elfie、Orientation、Memory 中的人物关系、Emotion、隐私边界 |
| 2.5 经历整理与缓慢成长 | 从真实经历形成经验而不改写核心身份 | “它会成长，但仍然是原来那一只” | Consolidation、Memory、Selfhood、Emotion |

### 5.3 子阶段 2.1：单只精灵真实具身

**目标**：一只 Elfie 能够通过唯一选定的虚拟身体感知精灵巢、做出高层决定，并取得真实执行回执。

**能够做到**：

- 知道当前身体、地点、姿态、附近对象和可用动作；
- 移动、转向、说话、表达和执行少量高层语义行动；
- 遵守碰撞、导航、设施规则和 Godot 世界权威；
- 世界拒绝、失败或超时时不伪造位置和动作结果；
- 回答“你在哪里、看到了什么、刚才做了什么、成功了吗”。

**实现重点**：

- Godot 保持几何、位置、导航、碰撞和渲染事实 authority；
- Nest 提供技术无关的空间、设施、生活规则、时间环境和交互语义；
- Brain 只产生高层决定，通过 Nervous System 控制 Body；
- 感知与回执进入 Workspace，并更新 Orientation 和正式经历候选；
- 开发预览和 Mock 不得冒充真实世界执行。

**完成目标**：用户观察到一次真实感知—决定—动作—回执闭环，随后询问时 Elfie 能根据同一组
权威事实正确讲述，失败动作不会被说成已经完成。

### 5.4 子阶段 2.2：真实日常生活

**目标**：Elfie 在精灵巢中拥有由真实时间、身体状态、设施和事件构成的一天。

**能够做到**：

- 睡眠、苏醒、休息和少量基本生活行为；
- 感知时间、环境变化和设施状态；
- 根据能量、疲劳和当前处境调整行为；
- 把重要的真实巢内事件编码为当天经历；
- 回答“你今天做了什么、去过哪里、为什么累、看到了什么变化”。

**实现重点**：

- 时间、环境、设施和生活规则由 Nest/Godot 对应事实所有者提供；
- Energy 与真实经过时间、休息和行为结果对账；
- 记忆只编码重要事件和真实结果，不保存原始流水账；
- 当天叙事由 Orientation、事件、回执和正式记忆共同支持。

**完成目标**：一次加速但真实的日常场景包含苏醒、感知、一个生活行为、状态变化和休息；重启后
Elfie 能按事实讲述当天经历，不添加未发生的活动。

### 5.5 子阶段 2.3：自主生活与履约

**目标**：没有持续外部命令时，Elfie 也能在安全边界内形成一个需要、作出选择、完成行为并根据
真实结果结束或调整。

**能够做到**：

- 因低能量或高疲劳选择安全休息；
- 在正确时间履行一个明确、低风险承诺；
- 等待、唤醒、暂停、恢复、取消、过期和有限重试；
- 行为失败后进入冷却、调整或可解释终态；
- 回答“你为什么这样做、接下来准备做什么、承诺完成了吗”。

**实现重点**：

- 先使单步骤 Persistent Activity 可靠，再开放多步骤；
- Motivation 只产生受限候选，不直接操作身体或通信；
- 驱力满足必须由真实状态或执行结果证明，No-op 和仅创建 Activity 不算满足；
- Activity 在重启和重复回执下保持幂等，不产生自唤醒风暴。

**完成目标**：至少完成一条自主恢复闭环和一条跨时间承诺闭环；失败、过期与中途重启均有真实、
唯一、可解释结果。

### 5.6 子阶段 2.4：多精灵社会生活

**目标**：多个 Elfie 在同一精灵巢中仍是独立生命，能够识别彼此并形成持续关系。

**能够做到**：

- 感知和识别附近的其他 Elfie；
- 说话、靠近、回避、合作或产生分歧；
- 记住与不同 Elfie 的共同经历和关系变化；
- 区分公共世界事实、双方共同经历和各自私人记忆；
- 回答“今天遇见谁、为什么接近或回避它、你们是什么关系”。

**实现重点**：

- 每只 Elfie 保持独立 Brain、Memory、Emotion、Activity 和身份；
- 巢内事件由事实拥有者产生，并按目标与受众唯一投递；
- 关系事实以真实互动为来源，不由模型单方面宣称；
- 不把一个 Elfie 的私人通信和记忆默认广播给其他 Elfie。

**完成目标**：两只 Elfie 围绕一个真实巢内对象发生可观察互动，各自形成来源正确但视角独立的
记忆；重启后仍能识别对方且不会交换私人事实。

### 5.7 子阶段 2.5：经历整理与缓慢成长

**目标**：Elfie 能够从多日真实生活中整理经验、关系和自我认识，同时保护不可变身份和核心规范。

**能够做到**：

- 整理近期记忆和 Activity 结果；
- 发现重复成功、失败、偏好和关系模式；
- 形成关系、自我和程序经验的候选更新；
- 解释哪些经历使自己产生了什么变化；
- 中断、失败或恶意经历不会任意重写人格。

**实现重点**：

- Consolidation 只在睡眠或有界空闲窗口运行；
- 整理结果先形成候选，再由 Memory、Selfhood 等对应权威所有者校验、限幅和提交；
- 整理过程不得直接向外通信、控制身体或扩张权限；
- 所有成长保留来源、版本、回滚和重复抑制。

**完成目标**：经过一段可重放的真实生活后，Elfie 能形成一条可解释、有限、可恢复的经验或关系
更新；Selfhood 核心身份和安全边界保持不变，创建资料不参与运行期整理。

### 5.8 第二阶段问题与行动边界

| 问题或请求 | 第二阶段行为 |
| --- | --- |
| 当前在哪里、看见什么、附近有什么 | 根据当前虚拟身体和权威世界事实回答 |
| 刚才做了什么、动作是否成功 | 根据 Directive、世界执行和 Receipt 回答 |
| 今天做了什么、为什么累或休息 | 根据时间、Energy、重要事件和正式记忆回答 |
| 接下来准备做什么、承诺是否完成 | 根据 Motivation、Activity 和真实终态回答 |
| 遇见了谁、与其他 Elfie 什么关系 | 只根据实际互动和关系记忆回答 |
| 请求支持范围内的巢内行动 | 通过新的具身或内部 Turn 执行，并返回真实结果 |
| 请求不存在、越权或违反世界规律的行动 | 拒绝、澄清或选择安全替代，不伪造完成 |
| 地球现实世界当前现场事实 | 没有现实身体或授权外部来源时仍明确不知道 |

### 5.9 第二阶段完成门

第二阶段的代表验收故事至少包含：

1. 一只 Elfie 在权威虚拟世界中苏醒并感知当前位置；
2. 自主或应请求完成一个真实身体行动，并处理一次失败行动；
3. 使用一项真实设施或完成一条低风险日常活动；
4. 经过等待和重启后履行一个明确承诺；
5. 与另一只 Elfie 发生一次具有真实结果的互动；
6. 休息或整理后形成一条有来源、有限的经验候选；
7. 用户通过聊天询问当天经历、行动原因和社会关系。

只有观察面、世界事实、执行回执、记忆和回答能够互相对账时，第二阶段才完成。任何 Mock 活动、
预览动画或模型自述都不能单独作为完成证据。

## 6. 第三阶段：进入现实世界

### 6.1 大阶段目标

> 同一只 Elfie 能够从虚拟身体切换到实体玩具等现实身体，在安全边界内感知、行动和探索地球，
> 并把真实经历带回同一份记忆和关系历史。

第三阶段至少覆盖：

- 虚拟身体与实体身体共享一个互斥身体槽位和唯一动作 authority；
- 实体传感器、执行器、能力和故障均由真实设备提供；
- 现实世界行动具有物理安全、隐私、权限和人工紧急停止边界；
- Elfie 区分虚拟经历、现实亲历、通信内容和外部查询；
- 身体切换、断联、重启和返回精灵巢不分裂身份、记忆和当前承诺。

第三阶段的子阶段、硬件范围和验收场景，在前两阶段稳定且实体设备方案明确后另行设计。本文不
预先承诺具体传感器、动作、导航范围或硬件型号。

## 7. 基于本文进入逐步实现

当前仍按 `1.1 → 1.2 → 1.3 → 1.4 → 1.5` 形成用户可感知增量，但工程上不是先横向做完
Communication、再横向做完 Profile 或 Memory。第一轮就建立一条最薄的记忆支撑聊天闭环，后续
每轮在同一主干上增加世界知识、个人传记、主人关系和整体验收。第二阶段保持目标设计，不因第一
阶段开工自动获得实现授权。

第一阶段详细模块调整、数据合同、`E1–E5` 评测、对抗场景和五轮完成门见
[记忆支撑的完整聊天闭环执行计划](./elfie-stage1-memory-backed-chat-execution-plan.md)。

每个子阶段开工前建立一张仅约束当前子阶段的工作卡，至少固定：

1. 当前源码、测试和可重放行为事实；
2. 本次用户可感知目标与代表问题；
3. 允许修改的模块和明确不做的范围；
4. 正常、失败、重复和重启验收场景；
5. 开工前冻结的阶段基线、题库、硬门和体验阈值；
6. 需要先失败的测试、最小实现和聚焦验证；
7. `ComparisonReport`、负责人体验确认、剩余缺口和下一阶段 `GO/NO-GO` 决定。

子阶段完成只表示对应用户目标闭环成立，不表示所有涉及模块已经完整。若实施中发现必须改变顶层
模块 ownership、系统级 Port、公开 API 或永久数据契约，应停止当前工作卡并按仓库治理规则单独
确认，不在产品阶段名义下顺手扩大范围。
