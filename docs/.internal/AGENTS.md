# 私有文档目录规则

本文件只作用于 `docs/.internal/` 及其子路径。

## 固定目录

`docs/.internal/` 只允许以下三个一级目录，当前文档数量不足以支持更深层级，因此文档
目录内部保持扁平：

- `elfaria/`：Elfaria 的世界事实、居民知识、派生资料和参考个体；
- `product/`：产品愿景、整体故事、体验目标和产品阶段；
- `drafts/`：尚未定稿的领域草稿。

`elfaria/elfaria-world-images/` 只是现有世界设定的图片素材目录，不是新的文档分类；除
图片素材外，不要在这三个入口下再按主题或流程造目录。

不要创建 `private-designs/`、`execution/`、`history/`、`archive/` 或其他二级分类。

## 权威边界

私有只表示不发布到文档站，不表示这些资料在所属领域没有权威性：

- `elfaria/` 是世界与居民知识的领域资料源；
- `product/` 是产品意图、故事和体验目标的资料源；
- `drafts/` 没有权威性，不能覆盖代码、契约、已采纳设计或 Elfaria/Product 正式资料。

`.internal` 不承载代码设计。已采纳的技术目标进入公开 `docs/developer/designs/`，
不可违反的规则进入 `contracts/`，当前实现进入 `architecture/`，验收证据进入
Conformance、CI 或任务产物。

现有 `drafts/` 中保留的历史计划、执行简报和旧技术草稿是迁移期间的遗留材料，统一
标记为非当前依据；不得新增同类执行记录或把它们重新当成权威设计。

## 引用

私有资料可以链接公开设计。公开页面不得直接链接 `.internal`；公开设计如需追溯
Elfaria 来源，应使用稳定的资料标识和章节，而不是绑定私有文件路径。
