# 单精灵开发者调试平台设计

## 1. 文档目的

本文档定义 ElfieNest 仓库内“单精灵开发者调试平台”的产品边界、信息架构、交互方式、调试数据契约、技术结构、实施阶段和验收标准。后续实现以本文档为主要设计依据。

## 2. 背景与目标

`elfie` 模块的一次完整交互涉及感知过滤、脑干反射、丘脑上下文、注意力网络、记忆召回、模型决策、动作安全校验、执行器以及情绪和能量变化。开发者仅查看最终回复或终端日志，很难定位精灵行为异常究竟发生在哪一层。

本平台要把一只测试精灵从 ElfieNest 群体世界中单独取出，提供可反复使用的本地开发者实验环境。开发者可以：

- 直接与单只精灵进行文字或多模态交互。
- 查看每轮交互的结构化决策轨迹，而不是依赖零散日志。
- 比较交互前后的身体、情绪、能量和记忆状态。
- 通过正常感官刺激验证完整感知链路。
- 通过开发者状态注入快速构造边界条件和复现缺陷。
- 按时间顺序保留交互历史，并随时回看某一轮的完整上下文。

## 3. 非目标与强制边界

### 3.1 非目标

- 不是普通用户的聊天页面或产品功能。
- 不是 ElfieNest 群聊房间、Godot 客户端或精灵领养流程的一部分。
- 第一阶段不把 `elfie` 拆成独立发布的 `pip` 包。“独立”仅指可独立运行和调试。
- 不展示或存储模型不可验证的隐式思维链。平台展示的“思考”是可验证的决策轨迹。

### 3.2 隔离要求

- 必须使用独立启动入口、独立本地网址和独立前端资源。
- 必须使用独立测试数据和记忆目录，不得污染正式精灵的记忆或注册数据。
- Provider、模型、密钥和粮食策略复用本机公共 Runtime 配置，避免重复配置订阅和模型；测试精灵、记忆和会话仍必须独立存储。
- 禁止修改或复用 `elfienest/ui/static/` 下的普通用户前端页面。
- 禁止在普通用户导航、生产服务入口或安装后的用户界面中暴露本平台。
- 平台不得依赖 `ElfieNestEngine`、Godot、群聊房间或普通用户鉴权流程才能运行。
- 模型方案只保存模型名称和非敏感参数，不保存 API Key、Token 或其他密钥。

## 4. 核心设计原则

1. **结构化可观测**：调试数据由正式执行链路生成，不通过解析日志推断。
2. **时序一致**：每轮交互的输入、处理、输出和状态变化统一归入一个 `TurnRecord`。
3. **当前与历史分离**：左侧始终表示当前精灵，右侧始终表示选中的历史回合。
4. **真实与可复现并存**：同时支持真实模型模式和 Mock 可复现模式，界面必须清晰显示当前模式。
5. **不制造假象**：对尚未贯通主链路的视觉、听觉或环境通道，必须显示“未接通”、“降级”或具体 fallback 状态。
6. **配置与实验分离**：精灵默认配置与单次实验的临时覆盖分开，临时覆盖不默认写回正式配置。
7. **时间线就是导航**：中栏的交互时间线承担会话的前后导航，不再增加顶部会话或重放工具栏。
8. **连接配置与精灵实验分离**：网页只选择 Mock 或已配置的真实 Runtime；模型连接的录入、脱敏查看和连通性测试使用独立命令行工具完成。

## 5. 用户工作流

```text
启动独立开发服务
    ↓
直接进入左、中、右三栏实验室
    ↓
从左下角选择现有精灵，或新建测试精灵
    ↓
发送刺激或注入状态
    ↓
查看回复、决策轨迹和前后快照
    ↓
沿时间线继续交互，或点击历史消息回看详情
```

## 6. 信息架构

平台只有一个主工作页，不设独立的测试精灵库页、精灵画像页或交互页顶部菜单。所有日常调试都在左、中、右三栏中完成：

```text
左侧：这是谁    中间：发生了什么    右侧：为什么会这样
```

```text
┌──────────────┬──────────────────────────────┬──────────────────┐
│ 当前测试精灵  │ 交互时间线                    │ 选中回合详情     │
│              │                              │                  │
│ 头像、名称    │             开发者输入 →      │ 摘要             │
│ 身体、人格    │                              │ 处理链路         │
│ 核心认知      │ ← 精灵回复                    │ 状态快照         │
│ 默认模型      │   动作、表情、情绪摘要       │ 原始调试数据     │
│ 记忆概况      │                              │                  │
│              │ [多模态刺激编辑器]      [发送] │                  │
│ [精灵切换器]  │                              │                  │
└──────────────┴──────────────────────────────┴──────────────────┘
```

推荐桌面端默认尺寸：

- 左栏展开宽度约 `288px`，收起后保留约 `56px` 的精灵标识栏。
- 中栏自动占满剩余空间，建议最小宽度 `560px`。
- 右栏展开宽度约 `420px`，默认收起。
- 左右面板均可拖动调整宽度，并记住开发者上次的本地设置。

首次启动且没有测试精灵时，左栏显示空状态和“新建测试精灵”按钮。已有精灵时，则直接恢复上次选中的精灵及其最近会话。新建和管理操作由左下角精灵切换器打开局部弹窗，不跳转到另一个主页面。

## 7. 交互实验室详细设计

### 7.1 页面外框

交互实验室不设顶部菜单栏、会话工具栏或重放控制区。页面打开后直接进入左、中、右三栏，交互的前后顺序完全由中间时间线表达。

当前精灵、默认模型和当前状态在左栏展示；历史回合的选择与切换在中栏完成；选中回合的详情在右栏展示。不再为这些信息设计重复的顶部入口。

页面采用浅色实验台视觉：整体使用灰白和柔和绿色背景，正文使用深灰绿色，卡片和输入区使用白色或浅灰绿色。原始数据区也保持浅色高对比度，不使用整块深色终端背景。

### 7.2 左侧精灵栏

左栏负责展示当前测试精灵的最新画像和当前状态，不展示选中历史回合的快照。

左栏上部摘要包含：头像、名称、测试标识、身体形态、清醒状态、人格摘要、默认模型、记忆数量和最近实验时间。

详细信息使用紧凑折叠区：

| 折叠区 | 内容 |
|---|---|
| 基本画像 | 名称、描述、身体、数据规模和画像摘要 |
| 人格与表达 | 大五人格、性格描述、口癖、问候语、碎碎念和说话风格 |
| 核心认知 | 自我认知、主人关系、世界观、行为倾向和关系图谱 |
| 身体与能力 | 解剖形态、动作能力、关节限制、声音、能量和疲劳参数 |
| 模型方案 | 真实或 Mock 模式、默认模型、路由、温度、最大输出和工具权限 |
| 记忆概况 | 情景、知识、规律、实体、感官索引和记忆统计 |

“朋友圈”统一命名为“关系图谱”。初期只展示实际已有的主人、其他精灵和实体关系，不虚构为已有能力。

左下角固定放置精灵切换器，这是实验室内切换和新建精灵的唯一主入口。点击后向上弹出：

```text
✓ 艾菲-默认测试
  艾菲-本地模型
  小满-胆小性格
────────────────
＋ 新建测试精灵
  管理测试精灵
```

每只精灵拥有独立的记忆、会话和实验记录。切换后加载该精灵最近的调试会话。选择“新建测试精灵”时进入新建流程，创建完成后直接切换到新精灵。

### 7.3 中间交互时间线

对话方向遵循标准聊天习惯：

- 开发者输入或施加的刺激统一右对齐。
- 精灵输出的文字、动作和表情统一左对齐。
- 感知、思考和执行过程使用居中的细流程条，不伪装成聊天消息。

开发者输入气泡标记本轮包含的通道，例如 `[文字][视觉][触觉]`。精灵回复气泡的第一层仅展示高频信息：

- 回复文字。
- 动作和表情。
- 主导情绪及主要变化。
- 能量变化。
- 新增记忆数量。

展开“本轮摘要”后补充：模型、注意力网络、记忆召回、动作校验、总耗时和异常。完整 Prompt、模型原始返回和原始数据只在右侧详情显示。

### 7.4 右侧回合详情

右栏默认隐藏。点击输入、流程条或精灵回复时自动展开，并在中栏高亮对应内容。

点击位置决定默认焦点：

- 点击开发者输入：聚焦原始刺激、接收前状态和感知结果。
- 点击精灵回复：聚焦决策、执行结果和回复后状态。
- 点击中间流程条：聚焦完整处理链路。

右栏包含四个页签：

| 页签 | 内容 |
|---|---|
| 摘要 | 本轮输入、回复、模型、动作、表情、耗时和异常 |
| 链路 | 感知过滤、情绪识别、丘脑上下文、记忆召回、注意力、模型路由和动作校验 |
| 快照 | 处理前状态、处理后状态和字段差异 |
| 原始 | 原始输入、完整上下文、Prompt、模型原始返回和调试数据 |

右上角提供收起按钮。重新打开时恢复上次查看的回合和页签。右栏始终标记“历史回合·只读”，避免与左侧当前状态混淆。

## 8. 多模态刺激与状态注入

输入编辑器的页签用于编辑各通道，不表示通道互斥。已添加的通道组成一个多模态 `StimulusBundle`，在一个回合内统一发送。

| 通道 | 可编辑内容 | 首期实现要求 |
|---|---|---|
| 文字 | 内容、说话者、来源和突显度 | 走完整主链路 |
| 视觉 | 图片、视野来源和可选语义描述 | 显示处理能力、结果和降级状态；未贯通时明确标注 |
| 听觉 | 音频文件或听觉语义、声源、音量和方向 | 显示处理能力、结果和降级状态；未贯通时明确标注 |
| 触觉 | 撞击力、方向和抚摸频率 | 经正式感知链路处理 |
| 环境 | 温度、天气、重力、网络和突显度 | 对已接通和未接通字段分别标识 |
| 状态注入 | 情绪、能量、疲劳和睡眠状态 | 仅用于开发者构造边界条件 |

正常感官刺激与状态注入必须在视觉和数据上明确区分。使用状态注入的回合需显示永久标记，防止开发者将注入后的行为误判为精灵自然演化结果。

## 9. 调试数据契约

### 9.1 `TurnRecord`

`TurnRecord` 是平台的核心数据单元，代表一轮刺激从进入精灵到产生结果的全部记录。建议至少包含：

```text
TurnRecord
├─ turn_id / session_id / elfie_id / timestamp
├─ mode                  # real 或 mock
├─ stimulus_bundle       # 原始多模态刺激
├─ state_before          # 处理前完整快照
├─ perception
│  ├─ normalized_signals
│  ├─ filters
│  ├─ emotion_detection
│  └─ channel_status
├─ brainstem_reflex
├─ thalamus_context
├─ memory_recall
├─ prediction_and_attention
├─ model_call
│  ├─ provider / model / route_reason
│  ├─ prompt
│  ├─ raw_response
│  └─ timing / error
├─ decision
├─ action_validation
├─ execution_result
├─ state_after           # 处理后完整快照
├─ state_diff
├─ memory_writes
├─ warnings / fallbacks / errors
└─ timing
```

契约要求：

- 字段要允许部分阶段缺失，但缺失原因必须可观测。
- 不得包含 API Key、Token、密码或认证头。
- Prompt 和模型原始返回按调试数据处理，写入本地历史前必须清除密钥、认证头和其他敏感字段。
- 每个主要阶段都应有独立耗时和异常信息。
- Runtime 模型观察事件必须通过 `turn_id` 与精灵回合关联。

### 9.2 状态快照

快照至少覆盖：

- 能量、疲劳和睡眠状态。
- 八类情绪、主导情绪和表情。
- 当前注意力网络。
- 身体形态、动作意图、实际关节角度和限制。
- 记忆统计与本轮相关的记忆变化。

### 9.3 记忆调试信息

记忆详情需区分“本轮召回”和“本轮写入”，并可选展示：召回节点、匹配维度、分数、情绪权重、扩散联想、新增节点以及 episodic、entity、knowledge 和 pattern 等图谱类型。

## 10. 会话时间线与历史回看

平台不提供场景保存、自动重放、新旧结果差异比较或回归用例导出功能。开发者调试的主体就是当前会话中按时间排列的一系列 `TurnRecord`。

时间线遵循以下规则：

- 每轮交互一旦完成就自动写入当前测试精灵的会话历史。
- 中栏严格按发生时间从上到下排列，新交互出现在底部。
- 点击历史输入、处理流程或回复，只是在右栏打开当时详情，不改变现在的精灵状态。
- 历史回合是只读记录，不提供“从此处重放”或“回滚到此状态”操作。
- 切换精灵时切换到该精灵自己的最近会话，不混合不同精灵的时间线。

## 11. 技术结构与目录建议

平台建议放在仓库顶层 `devtools/elfie_lab/`，而不是 `elfie/` 包内或 `elfienest/ui/static/` 中。

原因是：

- 平台需要深入调用 `elfie` 内部状态，但本身不属于精灵运行时。
- 放入 `elfie/` 容易被误认为正式包能力，并可能进入发布物。
- 放入用户前端目录会破坏调试平台与普通用户产品的隔离。
- 顶层开发工具目录能跟随 `elfie` 演进，同时在包边界上保持清晰。

建议目录：

```text
devtools/
├── elfie_lab/
│   ├── __init__.py
│   ├── __main__.py           # 独立启动入口
│   ├── app.py                # 本地 Web 应用
│   ├── session.py            # 单精灵实验会话
│   ├── storage.py            # 独立测试数据存储
│   ├── schemas.py            # API 和调试数据契约
│   ├── runtime_adapters.py   # 真实与 Mock Runtime 适配
│   └── static/               # 独立前端资源
└── runtime_lab/
    ├── __init__.py
    ├── __main__.py           # Runtime 配置、连接测试和文字对话入口
    └── config_store.py       # 独立开发配置与密钥存储
```

启动命令建议：

```bash
uv run --no-sync python -m devtools.elfie_lab
```

启动后仅监听本地回环地址，例如：

```text
http://127.0.0.1:<开发端口>/
```

端口必须与普通用户服务的 HTTP `8000` 和 WebSocket `8765` 分离，具体默认值在实现时根据当前仓库端口占用情况确定。

默认测试数据可保存到：

```text
~/.elfienest/dev/elfie_lab/
├── elfies/                   # 仅测试精灵及其独立记忆
└── sessions/                 # 仅测试会话与 TurnRecord
```

单精灵调试平台直接复用本机公共 Runtime 配置：

```text
~/.elfienest/
├── config.yaml               # Provider、模型和非敏感参数
├── .env                      # API Key，文件权限为 0600
├── foods.yaml                # 当前粮食策略
├── model_evidence.yaml       # 模型验证证据
└── validations/              # 本地验证报告
```

网页只读取并调用上述 Runtime 配置，不负责录入密钥。测试和持续集成必须通过
`--runtime-config-dir` 或依赖注入使用临时目录，不得读写开发者的真实本地配置。

Provider、模型验证和粮食策略统一通过完整 Runtime Lab 配置：

```bash
# 进入完整 Runtime Lab 菜单
python -m runtime.lab

# 需要脚本化操作时，使用细粒度命令
# 隐藏输入密钥并保存某个开发模型连接
uv run --no-sync python -m devtools.runtime_lab configure

# 查看脱敏状态
uv run --no-sync python -m devtools.runtime_lab show

# 发送固定消息测试当前连接，或测试所有已配置连接
uv run --no-sync python -m devtools.runtime_lab test
uv run --no-sync python -m devtools.runtime_lab test --all

# 进入简单文字对话
uv run --no-sync python -m devtools.runtime_lab chat
```

启动后可在主菜单进入“Provider 与原始模型”和“粮食策略”，完成模型配置、
粮食策略更新、真实验证和历史回滚。正式运行和单精灵调试使用同一份 Runtime
配置，但测试精灵的注册、记忆、会话和实验记录不会进入正式精灵数据。

## 12. 核心模块改造要求

为保持现有调用兼容，对 `elfie` 核心的改造应采用可选参数或可注入观察器，不改变普通执行路径的返回语义。

首期至少需要：

- 允许测试精灵指定独立记忆存储位置。
- 为一次 `perceive_and_respond` 分配稳定的 `turn_id`。
- 允许可选的调试轨迹收集器记录各阶段结构化数据。
- 将 `attention_mode` 等已产生但目前未透出的决策数据纳入调试轨迹。
- 在数据生命周期内保留丘脑上下文、记忆召回、Prompt、模型路由、原始决策和动作校验结果。
- 将 Runtime 观察事件与 `turn_id` 关联。
- 支持完全可复现的 Mock Runtime，不要将 Ollama 不可用时的异常伪装成已成功 fallback。

## 13. 接口能力边界

具体 URL 可在实现时细化，但本地服务应覆盖以下能力：

- 列出、创建、复制、查看、重置和删除测试精灵。
- 获取精灵完整画像和当前状态。
- 创建、列出、恢复和重置实验会话。
- 发送 `StimulusBundle` 并返回对应 `TurnRecord`。
- 查询会话时间线、回合摘要和完整回合详情。
- 对当前测试精灵执行显式状态注入。

所有修改操作需有明确错误响应，不得静默失败。删除、重置和覆盖本地数据等操作必须二次确认。

## 14. 实施阶段

### 阶段一：可观测核心

- 定义 `TurnRecord`、`StimulusBundle` 和状态快照契约。
- 为 `elfie` 正式执行链路增加可选观察点。
- 支持独立记忆目录、`turn_id` 和 Runtime 事件关联。
- 建立真实 Runtime 与 Mock Runtime 的明确适配层。
- 为数据契约和观察点补充镜像目录下的单元测试。

### 阶段二：MVP 本地平台

- 实现独立启动入口和本地 Web 服务。
- 实现独立测试精灵存储。
- 实现左下角精灵切换器、首次启动空状态以及新建和管理弹窗。
- 实现交互实验室三栏布局、折叠面板和宽度记忆。
- 实现文字刺激、当前状态、交互时间线、四页签详情和状态注入。

### 阶段三：多模态与完整调试

- 接入视觉、听觉、触觉和环境通道。
- 在界面展示每个通道的处理、降级和未接通状态。
- 补齐记忆图谱、关系图谱和模型调用的详细观测。
- 补齐页面窄屏适配和完整可访问性。

## 15. MVP 验收标准

MVP 必须同时满足以下条件：

1. 开发者能使用独立命令启动平台，不启动 `ElfieNestEngine`、Godot、群聊房间、用户鉴权和正式 TTS 服务。
2. 平台仅监听本地回环地址，使用与用户服务分离的端口和资源。
3. 能从左下角创建、切换或使用默认测试精灵，且其记忆和会话数据与正式数据隔离。
4. 能在真实模型和 Mock 模式之间明确选择，Mock 模式不依赖外部服务。
5. 开发者发送文字刺激后，可在同一回合中查看精灵回复、动作、表情、情绪变化和能量变化。
6. 每轮都能查看感知、丘脑上下文、记忆召回、注意力、模型路由、Prompt、决策、动作校验、执行结果和处理耗时；未生成的阶段显示原因。
7. 可查看交互前后完整快照和字段差异。
8. 左栏始终表示当前精灵，右栏始终表示选中历史回合，界面不得混淆两者。
9. 右栏默认收起，可由消息或流程条打开；左右栏可收起，并保留本地宽度偏好。
10. 能执行显式状态注入，且界面和历史记录都永久标记该回合使用了注入。
11. 交互实验室没有顶部菜单栏，不提供场景保存、重放或差异比较入口。
12. 已有普通用户前端、主服务入口和现有测试保持兼容。

## 16. 测试与质量要求

- 自动化测试使用 Mock Runtime，不依赖 Ollama、Godot、TTS 或其他外部服务。
- 测试目录必须镜像源代码包结构，每个目录包含 `__init__.py`，并使用绝对导入。
- 需要覆盖数据契约序列化、独立存储、会话恢复、状态注入标记、敏感字段脱敏和异常链路。
- 页面实现后必须在真实浏览器中验证三栏布局、收起与恢复、精灵切换、消息聚焦、右栏四页签和窄屏降级行为。
- 开发服务的安全默认值必须是仅本地可访问，且不读取或回传认证缓存。

## 17. 待实现时确认的细节

以下项目不改变整体方案，可在对应阶段开始前根据现有代码实际情况确定：

- 独立本地服务的默认端口。
- Web 服务是否沿用仓库现有框架，或采用更小的本地依赖集合。
- `TurnRecord` 的具体 Python 类型和版本迁移方案。
- 图片和音频等较大资产在本地会话历史中的存储和引用方式。
- Prompt 与模型原始返回的默认保留周期。
- 窄屏下三栏是切换为抽屉、分层页面还是上下布局。

## 18. 当前结论

后续实现应从 `TurnRecord` 契约和 `elfie` 核心可观测改造开始，再建立独立本地服务和三栏交互页面。不应先制作一个只有聊天外观的页面，否则后续仍需重做数据契约和调试链路。
