# 精灵巢完整最终资产

> [English](README.md)

在仓库要求的 Godot 4.7 工程中打开 `res://rooms/estate/estate.tscn`。
当前场景只包含一份自包含的最终 GLB，内容是完整建筑、真实室内、露台和已批准庭院。
旧程序化房间、独立家具及主楼/小屋基线已从源码与导出输入中移除，可恢复备份位于工程外的
`build/asset_exports/retired-rooms-20261022/`。

| 资源 | 内容 | 大小 |
| --- | --- | --- |
| `ElfieNest-complete-final.glb` | Godot 兼容的完整建筑、室内、露台和庭院导出 | 251,670,216 字节 |
| `ElfieNest-complete-final.instances.bin` | 最终 GLB 重复实例的无损世界坐标变换 | 13,875,592 字节 |

`main.tscn` 通过原有 `rooms/nest.tscn` / `ModularNest` 接入完整资产，只加载一套，保留相机和
Observer 行为，替代旧长走廊房间的生成。15 个视角包含庭院、天空、主楼楼层及八间真实宿舍。
执行标准 Web 构建后，打开 `elfienest.html?mode=nest_lab`，可使用引擎内视角菜单和鼠标操作。
宿舍默认视角朝向近侧床椅，保证首个交互座椅在画面内，而不是位于相机背后。

日间渲染使用设计工作台的反射渐变、ACES 响应及资产局部灯位，灯具按参考日间输出的
8% 换算，并只让家具参与接触阴影投射。顶点着色阔叶及针叶树冠保留原始顶点和索引
缓冲，不使用导入器会削弱轮廓的自动 LOD；源颜色、粗糙度、贴图和实例变换均不变。
庭院相机对齐主楼 V050 正面参考机位（42 度视场角、两次 0.8 倍拉近）。

庭院实例按水平 16 米网格分块，每个绘制批次至多 128 个实例，仍共享原网格和材质。
只拆分变换以支持空间剔除，不移除几何；室内灯不照射庭院实例批次。Web 入口请求
高性能 GPU，实际设备由浏览器决定；使用独显可能增加耗电，但此请求不降低渲染质量。
源码侧后导入钩子将原始清漆、IOR、透射参数带入材质元数据，Web 无须在运行时读取
原始 GLB，也使用同一组参数；导入脚本本身不进入 Runtime 导出包。

`ModularNest` 根据最终模型的模块、楼层、家具元数据绑定运行时碰撞与锚点：32 张床、
32 把书桌椅、两处庭院座椅、八扇滑动门、主楼四层、八个露台和庭院。床位容量只激活
对应床椅的语义目录，不重建房间。复用源文件六组庭院碰撞代理，不把树叶烘焙进导航。
镜像几何采用正手性物理变换；包括隐藏 authority 在内的显示状态均不关闭碰撞。

所有导航区域同步后，逐个检查发布的接近点及通往庭院的路线，才报告世界就绪。真实转向
平台顶面提供内缩的导航补片，并连接实际梯段；角色仍以完整胶囊、重力与扫掠净空逐步行走。
`furniture.use` 先导航到模型绑定的接近点，再进入床位或座椅姿态；占用、取消和退出受阻
都有明确结果。展示端材质覆盖为 26 个源模型绑定的水体表面加入轻微湖面法线波纹、溢流、
喷流高光及涟漪和泡沫运动，不移动顶点、不改变碰撞几何。云彩运动仍是静态导出效果。
仅相机模式的 Nest Lab 不是自主生活验收。

角色动画对待机、行走和视觉朝向做平滑混合。已有床椅动作的视觉子节点与骨骼现在会渐变
进入、退出源模型接触姿态，睡眠时有轻微呼吸循环。这些程序化过渡没有新增独立攀床动画，
不改变物理接触、占用、退出净空或命令完成时机。中断时从当前显示姿态恢复，保持身体比例。

物理资源按完全相同的三角形字节跨渲染材质变体共享；从索引表面读取三角形，不为每个
渲染网格额外生成拾取 BVH。家具使用实际凸包。可见 GLB 未改变，没有减面或缩小贴图。
完整物理世界与真实角色的阶段 RSS 实测约 1.61 GiB，不代表峰值或浏览器/GPU 内存。
验收覆盖庭院往返、床椅使用、取消/占用，以及最大体型角色走真实主楼与露台楼梯。

`test_complete_estate_world.gd` 验证实际物理动作，`test_observer_real_actions.gd` 验证
严格语义回放与行走中暂停。`scripts/internal/diagnostics/verify_nest_runtime_e2e.py`
将真实 Gateway、NativeBody、Nest 姿态投影接到 `main.tscn`；居民身份使用验收夹具，
不等于 Brain/Provider 或自主生活验收。

GLB 内嵌了图片数据，没有外部贴图文件。由于 Godot 4.7 不支持源文件的
`EXT_mesh_gpu_instancing`，仓库副本移除了不支持的包装，并通过 `MultiMeshInstance3D` 和旁车
恢复全部 134 组、216,743 个实例。相同图片（224 → 91）、贴图引用（310 → 183）、材质
（1,123 → 471）和网格（2,140 → 2,016）改为共享。全部 8,507 个节点身份、元数据和变换均保留；
两级已淘汰的白色入口台阶节点不再引用渲染网格，BIN 与实例矩阵仍逐字节不变。此次变更是
共享资源加上已确认的入口台阶移除，没有缩小贴图或简化几何。当前桌面源最终导出
是 251,879,364 字节，SHA-256 为
`30c4f8e7889b03b7da61a68b23f7a640c901267ba0de8c314b4678cc819e8e32`。

Godot 优化副本 SHA-256 为 `5538b1f675cbc532c920eb7543e1b1fd7f16f2c097ab5180297b425148b8f973`。
共享步骤可用 `scripts/internal/build/optimize_estate_glb.py` 重放，写入独立输出，不改桌面源文件。

旁车 v1 每组按 `名字长度、实例数、名字、矩阵` 存储。此前读取顺序错误，把第一组的
2,418 个实例误读为 808,464,479 个，尝试申请约 36 GiB 缓冲。现已修正顺序，并在分配前校验
字段和文件长度，批量上传变换，保留表面材质覆盖和顶点颜色。未缩减几何或贴图。
在接入物理之前的聚焦无显示检查中，资产加载后 RSS 从 1,194.8 MiB 降至 951.4 MiB（减少 20.4%），
主场景 RSS 从 1,351.8 MiB 降至 1,101.1 MiB（减少 18.5%）。数字不包含浏览器及 GPU，
也不代表峰值上限。含类与资源预加载的验证进程耗时 4.05 秒，首次重新导入耗时 75.6 秒；
脚本内部计时不包含类预加载，不能用它声称几百毫秒完成加载。
聚焦测试同时核对全部实例数、每组首尾变换、顶点颜色及主场景相机目录。
