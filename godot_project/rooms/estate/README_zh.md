# 完整园区源码与功能回放

> [English](README.md)

`res://rooms/estate/estate.tscn` 通过 `rooms/nest.tscn` 加载唯一完整园区。
建筑、家具、基础网格和材质保留已提交基线，仅合入已确认的林间环路、回接支路、平滑地面分区、
沿路植物调整，以及九组保留灯具（E01–E02、R01–R07）。场景的 `source_sha256` 记录原桌面导出；
`integrated_model_sha256` 与 `instance_sidecar_sha256` 标识当前合入后的输入。

| 源资源 | 当前内容 |
| --- | --- |
| `ElfieNest-complete-final.glb` | 266,635,048 字节；在基线上选择性加入地形和灯具 |
| `ElfieNest-complete-final.instances.bin` | 134 组庭院实例、214,750 个实例；13,748,040 字节 |
| `estate_outdoor_lighting.scn` | 道路／广场引导、湖岸轮廓、四盏高杆灯及 24 盏林间灯 |
| `estate_spatial.res` | 匹配当前模型的碰撞、活动边界、原生导航及楼梯连接 |

运行时加载离线空间资源，模型、实例或灯光输入不匹配时拒绝旧资源。
道路、广场、草地与林间小路连通，种植区、水体、设施和简化树干继续受保护；
移动边界不进入感知射线的碰撞掩码。
十扇实际门（原有八扇及中央两扇）共用接近打开、延时关闭、中途反向和占用体积防夹。
显式默认开门接口已保留；把该策略接到世界昼夜时段仍是本次迁移之外的待接线项。

Nest 提供本地民用时间：06–18 白天、18–24 上半夜、00–06 下半夜。
普通灯具与原模型自发光受统一开关控制，下半夜保留引导灯及按使用情况照明的策略。
表面接受实际灯光，不含已否决的固定暖色增亮项。正式监控的时间与视角独立选择；
预览不改变 Nest 时间或居民状态。

常规目录包含一个庭院视角、主楼四层及八组卧室／露台视角；正式监控再加入园区／林间
通行范围和环路视角。保留环绕、缩放、有限平移、当前视角复位及精灵跟随偏移。

下拉菜单在一个独立视口中使用真实项目的局部场景。切换会销毁上一项的场景及其播放时钟，
包括尚未结束的等待；重播会从干净样例重新开始。单项初始化会直接把局部样例放在对应对象旁，
不作为连续路线或跳过行走成功的证明。顶楼到达与走下平台合并为原有完整回放；沙发位置、
睡姿和水景使用二级选择，每处水景均可选昼夜。25 个源动作与点头、摇头单独保留入口。
单独动作沿用既有物种适配并原地播放；源资产和已确认
的接触修正不变。正式监控不会启用该模式。

下拉菜单的到达项复用原到达预览的角色、七层光效、夜间照明，以及沿机台小台阶延长线的
固定正面机位，分为准备、蓄能、显现落台和走下台阶四阶段。准备阶段只依次点亮三圈天顶灯、
叶片大面积发光面和机台；蓄能阶段由同一顺时针角度驱动天顶跑光、叶片与活动内圈、台面
蓝环完成两圈，外底座和台阶保持固定。每片正面中间冰青、左右同蓝同亮，侧面延续蓝光，
背面保留原来的一条冰青竖线，不再使用流动斜纹；三路与
叶片等高、等宽的能量体汇成大竖直光柱。能量冲顶后由内向外照亮穹顶，保持全亮一秒，
再由独立的大光面从穹顶下行到平台，完成后才接原到达效果、出现精灵。
叶片自有陶瓷网格上的连续不透明发光面替代交叠的透明叶脉叠层。
到达时装置退光突出精灵；走下前台阶先预亮，再由地面内外灯槽依次接力。
源 GLB、碰撞资源、角色朝向及下台阶动作保持原样。完整预览 28.7 秒，只播放一遍，
随后保持在顶层地面可见。
骨骼动作源文件保存在 `characters/animation/`；组合到达效果保存在
`runtime/lab/estate_platform_cycle.gd`、`estate_event_effects.gd`、
`estate_arrival_lighting.gd` 和关联着色器中，由 `estate_event_review.gd` 布置场景。
自有叶片侧面发光层、宽能量柱、光核、上行光柱、穹顶光效和活动内圈定义在
`runtime/lab/estate_petal_charge.gd`；连续发光面由 `estate_arrival_inlay.gd` 装配。
对应着色器和共享机台时序都保存在同一目录。

显式连续巡游先复用领养到达效果，落地后将同一角色交给真实物理移动。播放、暂停、逐章检查、
从实际停止位置重试及清单均属于本地测试，不创建居民或世界事件；新一轮重启同一 Web 页面及
引擎，并防止重复点击，世界加载具有超时反馈。遇到首个未接入项或路线阻塞时停止，其余章节
保持待验。睡眠复用原有三种姿势和被子控制器：同一精灵实际走到测得的床边后，经现有家具
接触及视觉混合接口连续入床、起身和离床。采样姿势路径检查其他障碍，离床保留原有站立
胶囊检查；仅在家具接触期间沿用现有的站立碰撞体停用约定。
章节已播放不代表视觉验收通过，原片对照播放也不证明实际导航已通过。
室内门章节仅往返代表房间 M01 与中央大厅，不声称覆盖全部八扇门。实际行走保留已确认的
物种适配、原地待机／行走片段。中央楼梯侧墙、玻璃栏板、屋顶实体，以及电视、脚凳、软凳、
柜体等实体参与碰撞和离线导航烘焙。空间资源必须显式记录匹配的碰撞策略；即使旧资源继承了
脚本的新默认版本号，也不能因此绕过失效检查。
在连续巡游 URL 后加 `&autoplay=1`，可在加载校验成功后自动播放；它不会在正式观察器中启用巡游。

回放不伪造世界事件，也不代表自主生活验收。合入后的最终画面，包括椅子细化效果，
仍需在真实监控中统一确认。离开效果、扇形光束、规则湖面亮条、已撤销广场灯具，
以及攀爬／跳跃候选图库均未进入已选择的动作链。

离线创作使用仓库受控 Godot 入口：

```sh
bash scripts/quality/checks/godot_host.sh res://scripts/tools/bake_estate_lighting.gd
# 检查 build/estate-lighting-v4/estate_outdoor_lighting.scn 后发布到本目录。
bash scripts/quality/checks/godot_host.sh res://scripts/tools/bake_estate_spatial.gd
# 检查 build/estate_spatial/bake-report.json 后发布 estate_spatial.res 到本目录。
bash scripts/quality/checks/godot_host.sh res://scripts/test/test_estate_precompiled_spatial.gd
```

中间产物留在 `build/`；上述最终创作资源属于源资产。
Godot 导入缓存只保留本地并排除 Git。Web 产物仅由 `./developer.sh build-godot-web`
生成到 `build/components/godot-web/`。
